# 就医路径可寻址性、预约确定性与导航劳动：中国，1953–2025

> 状态：研究笔记；用于 `how-people-lived` 的 ordinary life / life-course / communications / institutions 交叉研究。
>
> 核心问题：**一个人生病以后，“医院存在”距离“这个人真正能在合适的时间走到合适的科室、见到能处理问题的人”中间，到底隔着多少层？电话、计算机、Web、手机和互联网医院分别改变了哪一层，又把哪些排队、验证和照护劳动转移到了别处？**

---

## 0. 本轮新增的不是“互联网医疗史”

仓库已经讨论过：

- 通信距离与异地家庭；
- travel bookability 与可逆迁移；
- procedural knowledge / option discoverability；
- 证件与行政记录；
- 家庭照护、职业中断与 re-entry；
- 网络招聘、住房、婚恋、汇款等把原本线下流程部分网络化的生活接口。

但医疗仍主要散落在“家庭支出”“照护”“疫情”“时间成本”的背景中。

缺少的问题是：

> **如果一个人已经知道“应该去看病”，他能不能在出门以前确定去哪里、找谁、什么时候去、需要什么凭证；又是谁替他完成这些导航和手续劳动？**

因此本篇不评价具体治疗，不提供医疗建议，也不讨论疾病疗效。

研究对象是 **care-seeking execution（就医执行）**：

```text
不舒服 / 需要复诊
→ 判断去哪里
→ 找医院 / 科室 / 医生
→ 确认出诊
→ 获得号源 / 时间槽
→ 身份与资格验证
→ 安排交通 / 请假 / 陪同
→ 到院取号 / 签到 / 缴费
→ 候诊
→ 诊疗 / 检查
→ 复诊 / 取药 / 后续安排
```

Internet 可能改变其中若干步，但不能默认改变全部。

---

## 1. 新变量一：care-path addressability

本篇使用 **care-path addressability（就医路径可寻址性）** 描述：

> 一个普通人在需要医疗服务时，能否识别并定位一个现实可执行的服务入口，包括医院、科室、医生、时间、地点和进入条件。

它至少包含：

```text
care-path addressability
= 知道存在某种服务
× 知道应该找哪个机构 / 科室
× 知道什么时候开放
× 知道如何取得进入资格
× 能承担到达与等待成本
```

因此：

- `hospital exists ≠ patient knows to go there`；
- `doctor listed ≠ doctor is actually available that day`；
- `appointment channel exists ≠ usable slot exists`；
- `slot exists ≠ this patient can complete identity / card / payment requirements`；
- `appointment obtained ≠ clinical encounter completed`。

这和仓库既有的 option discoverability 很接近，但医疗路径有两个额外特征：

1. 时间经常更紧迫；
2. 供给尤其是热门专家号具有强烈的时点稀缺性。

---

## 2. 新变量二：appointmentability

定义 **appointmentability（预约可执行性 / 预约确定性）**：

> 一个人能否在真正出发或到院以前，把未来某个医疗服务时间槽变成一个被机构认可的承诺。

它改变的不是医生数量，而是**出行前的不确定性**。

可以粗略写成：

```text
journey-before-certainty
    ↓
certainty-before-journey
```

对同城患者，这可能意味着：

- 不必凌晨去医院赌当天号；
- 更容易安排请假；
- 更容易安排老人、孩子或陪同人。

对异地患者，变化更大：

- 车票；
- 住宿；
- 家属请假；
- 是否值得跨城出发；

都可以围绕一个已确认时点来组织。

但这绝不能写成：

> “预约挂号解决了看病难。”

预约可以重新分配稀缺号源的取得方式，却不自动增加名医、床位或检查能力。

---

## 3. 新变量三：queue location——排队没有消失，只可能换位置

医疗信息化常被描述成“少排队”。

更准确的研究问题是：

> **哪一种 queue 消失了，哪一种 queue 被创造出来？**

可能存在：

```text
窗口队列
→ 电话占线
→ 网站登录 / 提交队列
→ 固定放号时刻竞争
→ 验证码 / 实名验证
→ App / 微信刷新
→ 候补队列
```

因此加入硬边界：

> **physical-queue compression ≠ scarcity elimination**

如果热门专家每周只开放极少号源，那么把窗口搬到 Web 以后，竞争仍然存在，只是从“谁更早站到门口”部分变成“谁更早知道规则、能在放号时在线、身份信息已经绑定、网络和设备工作正常”。

---

## 4. 新变量四：care-navigation labor

就医不是一个按钮，而是一串手续和空间移动。

本篇把这些非诊疗劳动暂称为 **care-navigation labor（就医导航劳动）**：

- 查科室；
- 查医生；
- 查排班；
- 打电话；
- 注册账号；
- 填身份信息；
- 抢 / 预约号；
- 取消或改约；
- 记住预约号；
- 办卡；
- 去窗口；
- 找楼层和诊室；
- 缴费；
- 排检查；
- 保存病历与结果；
- 再预约复诊。

其中相当一部分可以由患者本人以外的人承担。

因此还要追踪 **care proxy（就医代理人）**：

- 单位保健员；
- 家属；
- 电话接线员；
- 医院导医；
- 网络平台；
- 成年子女；
- 后来出现的商业陪诊人员。

这里的关键不是“谁更先进”，而是：

> **一个制度复杂到需要大量导航劳动时，这些劳动由谁来做？**

# 第一部分：Internet 以前，预约和远程导航已经存在

## 5. 1953：现场预约把“今天排队”换成“今天登记、明天看病”

2020 年《北京日报》利用本报历史资料回顾北京预约挂号史，并明确给出了 1953 年原始报道的日期、版面和标题。

据其转述，1953 年 1 月 22 日《北京日报》报道：北大医院在门诊量增加后实行现场预约。患者可以第一天挂第二天的号，也可以托别人代挂；复诊时医生还可以直接约好下一次时间。

这不是 Internet，也不是电话。

但它已经在做一件非常现代的事：

> **把未来服务容量预先分配给具体患者。**

所以预约史不能写成：

```text
窗口排队
→ 互联网预约
```

更长的谱系是：

```text
现场未来号
→ 单位 / 电话预约
→ 院内计算机预约
→ 电话 / Web
→ 统一平台
→ 手机 / 互联网医院
```

来源：北京日报 2020 年历史资料整理（其中引用 1953 年原报）：

<https://k.sina.cn/article_1893892941_70e2834d02000ryrc.html>

### 证据等级

- 1953 年原报：本轮未直接取得扫描件；
- 2020 年《北京日报》官方历史资料整理明确给出原报日期、版面、标题；
- 本篇对 1953 具体流程暂记 **B（后来由原报数据库整理的机构性二手复核）**；
- 若未来取得原报影像，可升级为 A。

## 6. 1954：电话预约已经存在，但“有电话”不等于任何个人都能直接预约

同一份《北京日报》历史资料整理还引用了 1954 年 1 月 21 日《实行电话预约挂号给病人带来很大方便》。

当时部分医院为公费医疗单位开展电话预约：

- 患病职工先在本单位填写通知；
- 由保健员或单位人员通过电话把各科挂号人数告诉医院；
- 患者再持通知按时就医。

这个案例对“技术可及性”特别重要。

因为它明确说明：

> **telephone appointment existed ≠ household telephone appointment existed**

电话已经进入预约链，但实际的 user interface 可能是：

```text
职工
→ 单位保健系统
→ 单位电话
→ 医院挂号系统
→ 通知单
→ 患者到院
```

而不是：

```text
个人在家拨号
→ 医院
```

这正好符合本仓库长期坚持的六层技术可及性原则：技术存在、机构可得、普通人经济可及、家庭拥有和日常行为整合不是同一个阶段。

来源同上：

<https://k.sina.cn/article_1893892941_70e2834d02000ryrc.html>

### 这改变了什么理解

Internet 以后常见的“自己查、自己约、自己填表”其实不是简单减少劳动，而是发生了 **navigation-labor transfer**：

- 过去一些导航劳动由单位保健员、医院人员承担；
- 后来更多步骤转给患者本人或家属；
- 再后来部分步骤又由平台、算法、客服和商业陪诊重新承担。

---

## 7. 1993：院内计算机先把“未来号源”变得可检索

《北京日报》历史资料整理引用 1993 年 5 月 21 日与 6 月 4 日原报：同仁医院实行计算机预约挂号，患者可提前一周预约科室和医生；报道保存了一名白内障患者在当天号源已满后，改约未来时点的现场反应，也记录了外地患者指定专家后由挂号员用计算机完成预约。

来源：

<https://k.sina.cn/article_1893892941_70e2834d02000ryrc.html>

### 重要边界

这里的“电脑预约”不是“家庭联网预约”。

更准确地说：

```text
患者到院 / 挂号员
→ 医院计算机系统
→ 检索未来科室 / 医生 / 时段
→ 生成预约
```

计算机首先进入的是**机构后台和柜台操作**。

这和后来银行、邮政、档案系统的历史一样：

> **backend digitization can precede household networking by years.**

# 第二部分：Web 进入以后，先出现的是混合流程，而不是“全程在线”

## 8. 1999：北京预约挂号“一卡通”——Web、电话、实体卡同时存在

2006 年一篇同时代回顾报道记载：北京市卫生局 1999 年 9 月推出预约挂号“一卡通”，50 多家医院后来加入；卡可以支持电话和网上预约。

来源：

<https://finance.sina.com.cn/xiaofei/consume/20060119/07102288409.shtml>

《北京日报》2020 年历史资料整理也引用 1999 年 9 月 17 日原报《网上挂号一卡通》，称当时北京卫生信息网上可预约多家医院；该卡还可以为亲友预约。

来源：

<https://k.sina.cn/article_1893892941_70e2834d02000ryrc.html>

这里至少有四层：

```text
实体预约卡
+ 电话
+ Web 页面
+ 医院内部号源系统
```

因此：

> **online booking ≠ paperless / cardless booking**

而且它还出现了一个生活史上很重要的能力：

> **一个家庭成员可以替另一个成员完成部分预约劳动。**

这使 health access 从“病人本人必须完成全部手续”开始出现更明确的 delegated workflow。

---

## 9. 2004：渠道存在，不等于成为主流

2006 年报道给出一个很好的 adoption denominator：

- 2004 年北京市各级医院门急诊量约 5035 万人次；
- 预约挂号量约 32.5 万人次。

若仅作数量比，约为 0.65%。

但必须注明：

- 门急诊总量与预约量的统计口径并非严格同一层级；
- 不能把这个简单比值当成精确“预约率”；
- 它只能说明：即使系统已存在多年，预约仍远未成为当时整体门诊的主渠道。

来源：

<https://finance.sina.com.cn/xiaofei/consume/20060119/07102288409.shtml>

这正是：

> `service exists ≠ service is behavioral default`

---

## 10. 2003 苏州：网页已经能选科室、医生和日期，但支付 / 取号仍在医院

2003 年 8 月，苏州大学附属第一医院推出网上预约挂号。

同期报道描述的流程非常具体：

```text
访问医院网站
→ 首次注册
→ 查科室和专家名单
→ 选择科室 / 日期 / 医生
→ 系统检查名额
→ 成功后获得号数
→ 就诊当天到指定窗口付费取号
```

如果名额已满，系统会要求改约其他时间；已预约者还可以查询或取消。

来源：人民网—江南时报经新浪保存：

<https://news.sina.com.cn/o/2003-08-02/1058491035s.shtml>

这条材料特别适合固定一个边界：

> **online reservation ≠ online clinical execution**

甚至：

> **online reservation ≠ online payment / check-in**

当时 Web 已经负责“未来时段的选择和锁定”，但医院窗口仍负责钱与正式取号。

# 第三部分：2007–2010，“扩张型未来”里的就医计划变得更可安排，但稀缺性仍然存在

## 11. 2007 广州：电话和上网都有，不代表热门专家号变得容易

2007 年《信息时报》关于广州预约挂号的调查指出，多家医院已经提供电话或网络预约，但热门专家号仍然高度紧张，甚至出现代排队、号托等现象。

来源（中国经济网稿经搜狐保存）：

<https://news.sohu.com/20070210/n248157052.shtml>

这个反例非常重要：

> **channel expansion ≠ capacity expansion**

如果最稀缺的是某个具体医生的时间，那么多开一个网页或电话入口，只改变竞争方式。

---

## 12. 2008：记者真实走了一遍“网站预约 → 到院取票 → 缴费 → 候诊”

2008 年 8 月，《西安晚报》记者在西安医院实际测试预约挂号。

在一家医院的网上预约中，记者：

- 选择科室和医生；
- 选择时间；
- 填写姓名、身份证和联系电话等信息；
- 获得预约确认；
- 到院后先在导医处换取预约凭证；
- 再去收费窗口缴费；
- 最后进入科室候诊。

整个医院内过程不到一小时。

但同一轮测试中，记者尝试另一家医院的网站，多次点击仍未能顺利打开；该院实际采用电话预约，而且预约前还需要先到院办理实名会员。

来源：中国新闻网保存的同期报道：

<https://www.chinanews.com.cn/jk/hyxw/news/2008/08-29/1365108.shtml>

这条材料同时证明两件事：

1. **Internet could compress queue time**；
2. **same-city hospital access remained technologically heterogeneous**。

同一个城市里，普通人可能面对：

```text
医院 A：Web 预约
医院 B：电话预约 + 先线下办卡
医院 C：现场窗口
```

所以不能把“2008 年已有网上挂号”写成“2008 年城市患者可以普遍网上挂号”。

---

## 13. 2008 太原：凌晨四点到医院，仍可能只是排进第一层队伍

同年《山西日报》报道，患者为挂牙科号凌晨 4 点多到医院，前面已经有人；挂到号以后，仍需再等两三个小时才轮到看诊。

来源：中国新闻网：

<https://www.chinanews.com.cn/jk/hyxw/news/2008/11-13/1447951.shtml>

这让“预约”在生活史里的意义更具体：

传统流程可能是：

```text
凌晨出门
→ 排挂号队
→ 得到号
→ 排候诊队
→ 看医生
```

预约把第一段部分压缩，却不保证第二段消失。

所以应区分：

- registration waiting；
- consultation waiting；
- test / payment / pharmacy waiting。

不能把“免排挂号队”写成“就医无等待”。

---

## 14. 2009：国家层面把预约诊疗从局部创新推向三级公立医院的制度要求

2009 年 9 月 30 日，卫生部发布《关于在公立医院施行预约诊疗服务工作的意见》。文件要求从 2009 年 11 月起，所有公立三级医院开展预约诊疗，二级医院逐步开展；医院应定期更新科目、医务人员专业和出诊时间，并推动分时段预约、实名预约。

来源：国家卫生健康委员会保存的原始政策文本：

<https://www.nhc.gov.cn/bgt/s9514/200909/d5b3893fff4747cdbf91154f5bf109c8.shtml>

### 证据等级

- **A：机构原始政策文本**。

### 这里发生的不是“Internet 普及”这么简单

预约开始从若干医院自己的便民项目，变成一种更普遍的门诊组织制度。

而且文件本身强调：

- 出诊表要更新；
- 预约与病案 / 连续管理衔接；
- 老人、外地患者等应得到重点安排。

这说明预约是**时间管理 + 资源分配 + 身份管理**，不只是网页功能。

---

## 15. 2009：实名制改变了“谁可以占一个号”

实名预约的目标之一，是减少倒号、恶意预约和资源占用。

但实名制同时意味着新的接口：

- 姓名；
- 身份证等有效证件；
- 电话 / 手机；
- 某些医院的就诊卡 / 患者 ID。

因此新增边界：

> **appointmentability can increase while identity burden also increases**

一个人不再必须凌晨站队，却可能必须先完成：

```text
实名信息准备
→ 卡 / ID 绑定
→ 电话验证
→ 网络账号
```

---

## 16. 2009 北京记者实测：不存在一个统一的“网上挂号流程”

2009 年《北京晚报》记者对多家三级医院预约系统做了同时代实测。

网络侧至少出现：

- 医院官网直接注册预约；
- 医院网页转第三方平台；
- 特定网站账号；
- 通过电子邮件提交姓名、身份证和联系方式；
- 首次必须先到院办理预约卡；
- 需要手机号做身份确认。

来源：

<https://news.ifeng.com/mainland/200910/1029_17_1410577.shtml>

<https://news.ifeng.com/mainland/200910/1029_17_1410577_1.shtml>

这意味着患者真正面对的是 **appointment interface fragmentation（预约接口碎片化）**。

同样写着“预约挂号”，背后可能是完全不同的执行路径。

---

## 17. 2009：网上“秒杀”专家号——数字排队第一次非常清晰地可见

2009 年广州同期报道记载，一名市民连续两周无法预约心仪的皮肤科名医；某些网上号源在放出后数秒内即被抢完。

来源：《广州日报》经凤凰网保存：

<https://news.ifeng.com/society/2/200910/1012_344_1384067.shtml>

这不是“互联网失败”的证据。

它证明的是：

> **排队已经可以从空间竞争转成时间同步竞争。**

过去是：

```text
谁更早到医院
```

现在还可能是：

```text
谁知道放号时刻
+ 谁能准时上线
+ 谁已经注册绑定
+ 谁的网络 / 系统响应更快
```

因此 `queue location` 是研究医疗数字化的重要变量。

---

## 18. 2010：异地患者开始能够“先锁定号，再跨城来”

2010 年一篇关于北京预约挂号实行四个月后的报道保存了具体患者路径：

- 一名患者在单位拨打 114，很快预约到中日友好医院之后某日上午的专家号；
- 另一名来自天津的患者中午抵达北京，凭预约条在协和医院取到此前预约的专家号。

来源：中国广播网 / 中新网报道经搜狐保存：

<https://news.sohu.com/20100118/n269657328.shtml>

这条材料对生活史的意义比“预约率上升”更重要。

它第一次很直观地展示：

> **intercity medical travel can be scheduled around a precommitted slot.**

于是异地就医的成本结构发生一部分变化：

```text
过去：先到北京 → 再赌能否挂上
后来：先确认号源 → 再决定何时到北京
```

当然，检查、复诊、住院是否仍需继续等待，是另一层问题。

---

## 19. 2005–2012“扩张型未来”新增一层：医疗也开始成为可预排的跨城项目

这一时期仓库已有“大学、工作、住房、迁移、旅行选项扩大”的证据。

医疗预约增加了一条不同的 expansion：

> **一个家庭可以更早知道下周某一天能否进入某家大医院的一条路径。**

这并不是“未来更乐观”。

更准确地说，是一些原本需要现场碰运气的流程变得更可计划：

- 是否请假；
- 谁陪同；
- 是否买车票；
- 是否订住处；
- 老人 / 孩子的照护如何安排。

这叫 **scheduleable care horizon（可排程的就医视野）**，而不是医疗资源自动变丰富。

---

# 第四部分：2011–2019，从“很多预约入口”到统一平台，再到数字稀缺

## 20. 2011 北京：统一平台要解决的首先是“入口碎片化”

北京市卫生局 2011 年说明，在此之前，各医院预约电话和网址不同，不方便群众记忆使用，因此要建设全市统一预约挂号平台，由 114 电话和网络平台共同提供服务、统筹号源数据。

来源：北京市卫生健康委员会保存材料：

<https://wjw.beijing.gov.cn/xwzx_20031/wnxw/201912/t20191214_1174492.html>

2011 年 7 月，统一预约挂号网站与 114 电话同步启动试运行。

同期报道：

<https://news.sina.com.cn/c/2011-07-27/151122886816.shtml>

这里的变化可以写成：

```text
hospital-specific addressability
→ city-level service addressability
```

患者不再必须先知道每家医院自己的网址、电话和注册规则，至少部分入口被统一。

---

## 21. 2018：预约可以把“凌晨四点出发”变成“提前一周确定”

2018 年南京儿童医院一条同期报道保存了一名外地家长的第一人称比较：过去她通常凌晨四点多从高淳出发去南京排队，现在可以提前一周网上预约，到院后几分钟完成挂号取号。

来源：江苏广电我苏网：

<https://www.ourjiangsu.com/a/20180721/1532160286730.shtml>

### 证据边界

这是单个受访者经验，不能外推所有家长。

但它非常有价值，因为它把 appointmentability 直接换算成日常时间：

> **一条数字接口改变了一个家庭必须几点起床。**

这正是本仓库关心的 ordinary-life scale。

---

## 22. 2019：号贩子也完成了从线下排队到线上占号的适应

2019 年《人民日报》报道北京整治号贩子时，明确描述：号贩子已经从线下排队转向利用网络设备占用线上号源，再通过退号和现场自助机等方式尝试完成转手。

同一报道中的一名山西患者说，首诊是一个月前用手机挂号，复诊则由医生直接预约。

来源：

<https://society.people.com.cn/n1/2019/0906/c1008-31339775.html>

这里有两条不同机制：

### 22.1 continuity improves

```text
首诊：患者手机预约
→ 复诊：医生诊间预约
```

这降低了重复抢号的成本。

### 22.2 scarcity actors migrate too

当号源分配数字化后，围绕稀缺资源的套利也会迁移到数字接口。

所以：

> **digitizing allocation does not make strategic competition disappear.**

---

## 23. 2015–2019“拥堵型未来”新增一层：未来时点可见，但热门时点依然拥堵

这一阶段很适合用 **visible-but-contested future slot（可见但竞争中的未来时点）** 描述。

与早期相比：

- 医生排班更容易查；
- 未来号源更容易看见；
- 手机可以在家操作；
- 复诊可以被医生直接接续。

但热门资源同时呈现：

- 秒抢；
- 固定放号时刻；
- 实名限制；
- 爽约规则；
- 候补；
- 反号贩技术。

因此“选项更多”不必然意味着“取得选项更轻松”。

---

# 第五部分：2020–2022，医疗路径本身成为 contingent

## 24. 2020：疫情不只是增加了线上咨询，而是改变了“正常门诊是否开放”的前提

2020 年初，多地普通门诊曾暂停或调整，互联网医院和线上咨询被用作替代入口。

例如武汉大学人民医院 2020 年 1 月 29 日公布：除急诊、发热门诊外其他门诊暂停，同时开放互联网医院免费图文 / 音频咨询。

来源：人民网湖北频道：

<https://hb.people.com.cn/n2/2020/0129/c192237-33749038.html>

这和此前的“网上挂号更省时间”不是同一种历史变化。

此前互联网主要优化：

```text
如何进入仍正常运作的医院
```

疫情初期则出现：

```text
原来的入口可能临时不存在
→ 需要替代路径维持咨询和连续性
```

这正是仓库所谓“偶发型 / contingent future”的医疗版本。

---

## 25. 2020：老年患者也可能通过线上问诊 + 药品配送完成一部分复诊链

2020 年《人民网》年度回顾保存一名 70 岁使用者的直接体验：从线上问诊到收到药品不到 24 小时；报道同时描述疫情期间互联网医院在线复诊、咨询和部分地区医保结算的发展。

来源：

<https://health.people.com.cn/n1/2020/1229/c14739-31982599.html>

### 重要边界

不能从这个个案写成：

> “老人普遍能独立使用互联网医院。”

数字技能、设备、账号、支付、家庭帮助和具体病种都可能限制使用。

但它证明：

> **对部分连续性医疗，clinical encounter 的一部分也开始离开实体医院。**

这已经超出“挂号网络化”。

---

## 26. 2021：互联网医院仍然需要网络、病史表达与家属协作

2021 年北京协和医院互联网医院试运行体验报道记录：

- 患者预约后需要上传既往病史资料；
- 有患者因为网络信号中断需要重新连接；
- 方言沟通困难时可由家属协助；
- 一位 80 多岁的老人在线就诊时由女儿陪同。

来源：人民网北京频道：

<https://bj.people.com.cn/n2/2021/0409/c233081-34667778.html>

因此：

> **remote care ≠ care without infrastructure or proxy labor**

线上诊疗会减少某些旅行，却增加或强化：

- 上传材料；
- 摄像 / 麦克风；
- 网络稳定；
- 文字表达；
- 家属协助。

---

## 27. 2022：成年子女可以在远处承担“替父母复诊开药”的代理劳动

2022 年《人民日报》报道，一名北京居民通过医院互联网医院 App 为八十多岁的父亲复诊开药；他明确比较说，以前自己需要请假半天去医院拿药，后来可以用手机办理并由药品配送到家。

来源（中日友好医院保存《人民日报》原文）：

<https://www.zryhyy.com.cn/zryhyyhlw/c104284/202202/ca09f55745104bc6a0d325b811ea739c.shtml>

这条材料把前几轮的 distributed household 与本轮医疗导航接了起来：

> **care can be physically absent but administratively active.**

成年子女不必每次亲自陪父母走完整个医院，也可以承担：

```text
挂号
→ 在线复诊
→ 支付 / 开药
→ 配送安排
```

的一部分。

这可以称为 **remote care proxy（远程照护代理）**。

---

# 第六部分：2023–2025，数字入口更多以后，新的问题是“多层系统真的连起来了吗”

## 28. 2023：预约平台开始从“号源入口”扩展到报告入口

北京市政府 2023 年材料称，北京 114 预约挂号平台升级后提供 270 家医院预约服务，并新增部分医院检验和检查报告查询。

来源：首都之窗：

<https://www.beijing.gov.cn/fuwu/bmfw/sy/jrts/202304/t20230409_2993366.html>

这说明平台角色逐渐从：

```text
帮我进医院
```

扩展到：

```text
帮我在多家医院之间找到服务入口
+ 取回部分就诊结果
```

但“平台可以查”仍不能外推成“所有医院、所有报告、所有患者历史都已互通”。

---

## 29. 2024：线上流程越长，跨层状态不一致越容易被普通人直接遇到

2024 年上海一篇现场报道记录，一名市民在互联网医院挂号后长时间等待医生响应，完成线上预约检查后，又在缴费环节遇到线上线下规则不一致；报道还总结了“线上约好线下不算数”等用户投诉。

来源：解放日报稿经人民网：

<https://sh.people.com.cn/n2/2024/0930/c176737-40996366.html>

这给 2023–2026 增加一个比“更智能”更重要的变量：

## 29.1 care-path consistency

```text
线上确认
≠ 线下系统必然识别
≠ 支付必然互通
≠ 检查时点必然同步
```

因此数字化成熟阶段的新成本可能是 **cross-layer coordination burden（跨层协调负担）**。

一个人面对的不再只是“有没有入口”，而是：

> **医院内部几十个系统对“我现在已经做到哪一步”是否有一致认识？**

---

## 30. 2025：当家属不在身边时，就医导航劳动开始更明确地成为一种可购买服务

2025 年江苏一篇同期采访记录职业陪诊人员：

- 帮老人签到；
- 确认诊室；
- 查看排队；
- 记录医生交代；
- 处理缴费、取药和转诊手续；
- 安抚并解释流程。

一名 74 岁患者说，自己长期复查，以往与女儿在医院里常常要转大半天。

来源：新华日报交汇点 / 中国江苏网：

<https://jsnews.jschina.com.cn/jsyw/202505/t20250520_s682bbed1e4b0e2f2f54c26f4.shtml>

### 不要浪漫化“临时家人”

这条材料不能证明：

- 陪诊行业已经普遍；
- 陪诊能替代家庭照护；
- 所有老人都有经济能力购买；
- 商业陪诊天然可靠。

它证明的是一种新的 household option：

> **当成年子女、伴侣或亲属不能到场时，一部分“陪着走完医院”的劳动可以被市场化。**

这和 1954 年单位保健员、2000s 电话客服、2020s App 形成一个很长的 care-proxy 谱系。

---

## 31. 2023–2026“防守型未来”新增一层：不是只找一个入口，而是准备 fallback

本轮材料不足以证明当代人普遍“因为悲观而多准备医疗渠道”。

但可以提出一个较窄、可继续检验的机制：**care-path redundancy（就医路径冗余）**。

现实使用者可能同时保留：

- 医院 App / 微信；
- 城市统一预约平台；
- 114 电话；
- 诊间复诊；
- 互联网医院；
- 家属代办；
- 必要时线下窗口或专业陪诊。

这不是“数字化失败”。

它类似基础设施中的 redundancy：

> 当某一路径失效、系统不同步、本人无法操作或家属不在场时，仍有另一条执行链可以把人送到真实服务。

是否已经形成普遍的“防守型医疗规划”，本轮证据不足，暂列 **D 级待检验机制**。

---

# 第七部分：海外比较——网络化就医导航不是 WWW 独有

## 32. 法国 1987：Minitel 已经可以把疾病信息和专门机构地址带进家庭

1987 年《Le Monde》报道法国 Chambéry 的 Minitel / vidéotex 服务，其中 SANTAL 项目面向血友病患者，提供疾病、预防、研究进展以及专门中心地址等信息，并与居家自我治疗的管理相联系。

来源：

<https://www.lemonde.fr/archives/article/1987/03/26/la-sante-par-l-ecran-le-service-telematique-de-chambery-permet-aux-hemophiles-de-traiter-a-domicile-leur-maladie_4052128_1819218.html>

### 可比较的不是具体医疗制度

不能把法国血友病项目直接类比中国挂号系统。

真正可比的是：

> **在 Web 之前，数字通信网络已经能把“应该去哪里、找哪个中心、有哪些信息”从机构内部目录变成家庭可查询的信息。**

这说明 care-path addressability 的网络化前史并不依赖 WWW。

---

## 33. 英国 1998–1999：NHS Direct 先是电话护理导航，后来才加 Web

NHS Direct 1998 年从三个地区电话试点开始，由护士通过计算机辅助决策系统提供健康信息和服务转介；1999 年扩展覆盖，并在年底推出 NHS Direct Online。

同期和学术来源：

<https://www.independent.co.uk/news/selfhelp-nhs-care-on-the-net-expanded-1131037.html>

<https://www.theguardian.com/uk/1999/dec/08/davidward.sarahboseley>

<https://www.cambridge.org/core/journals/psychiatric-bulletin/article/nhs-direct-a-telephone-helpline-for-england-and-wales/65028FFC4E4AC232DA509F3FFE83FE3F>

这里的谱系是：

```text
电话 + 护士 + 决策支持
→ 全国电话入口
→ Web 信息
→ 公共触摸终端
```

与中国不同，它主要解决的是“需不需要、去哪里、如何进入 NHS”的导航和分诊，不是简单的专家号预约。

但共同机制很清楚：

> **telecommunication can make the health system addressable before it makes treatment remote.**

# 第八部分：四个时期怎样比较

## 34. 2005–2012：expansive future / scheduleable care

新增机制：

- Web / 电话预约快速扩展；
- 三级医院预约制度化；
- 城市统一平台开始形成；
- 异地患者可以先锁定时点再旅行。

未来感不是“医疗越来越好”，而是：

> **一些原本必须到现场才知道结果的事情，可以提前几天知道。**

这是 ordinary planning horizon 的扩张。

---

## 35. 2015–2019：congested future / visible-but-contested slots

新增机制：

- 手机预约成为常见入口之一；
- 全预约医院增多；
- 诊间预约把复诊接起来；
- 但热门专家号依旧稀缺；
- 号贩和反号贩机制同时进入数字系统。

所以：

> **未来时点更可见，不代表更容易取得。**

这与这一阶段就业、住房和婚恋里的“选项很多、筛选和竞争也更多”非常相似。

---

## 36. 2020–2022：contingent future / care-channel substitution

新增机制：

- 普通门诊可能临时停运或调整；
- 线上咨询成为临时替代入口；
- 部分复诊、开药和配送可以远程完成；
- 家属代理劳动可以从“陪去医院”变成“替你操作线上流程”。

核心时间感是：

> **下周原来的医院流程未必照常运行。**

因此家庭需要能够切换渠道。

---

## 37. 2023–2026：defensive future / consistency and redundancy

本轮支持的较窄判断是：

- 多渠道已经是常态基础设施的一部分；
- 平台开始承载更多结果查询和连续服务；
- 但线上线下状态不一致仍会制造摩擦；
- 家属不在场时，专业陪诊等替代劳动开始更可见。

暂不把它写成“全民防守型医疗心态”。

更谨慎的表述是：

> **成熟数字系统时代，可靠生活越来越依赖接口之间能否衔接，以及人在接口失效时有没有 fallback。**

---

# 第九部分：把它放回“普通人有多少种活法”矩阵

## 38. 教育

学生 / 毕业生异地就医可能需要：

- 请假；
- 借助家长；
- 在陌生城市找医院；
- 处理校园医保 / 地方医疗入口。

本轮未深入，留作未来交叉。

## 39. 就业

预约确定性会直接影响：

- 需不需要请整天假；
- 能否把看病安排在某个时段；
- 是否必须连续缺勤。

2022 年替父亲取药的受访者明确把互联网医院与“以前要请假半天”比较。

## 40. 住房与迁移

异地医疗让 housing 与 care system 分离：

一个人可能住在：

- 高淳，去南京；
- 天津，去北京；
- 惠州，使用深圳医院线上复诊；
- 其他城市，由家属远程处理部分流程。

因此居住地不完全等于医疗服务地。

## 41. 婚姻家庭

家庭成员可以承担：

- 代预约；
- 陪同；
- 上传资料；
- 帮助视频沟通；
- 取药 / 配送；
- 后来甚至雇佣陪诊。

“谁陪你去医院”本身是一项家庭劳动分工。

## 42. 迁移

预约降低的是**盲目前往**的一部分风险，而不是异地就医的全部成本。

还需要：

- 交通；
- 住宿；
- 检查；
- 后续复诊；
- 家属时间。

## 43. 照护

本轮明确补充：

```text
caregiving
≠ 只在家照料身体
```

它还可以包括大量制度导航和信息操作。

## 44. 非正规劳动

2000s 号托、代排队以及 2020s 陪诊都说明：

> 当正式系统存在高摩擦时，会产生替别人完成“进入系统”的劳动市场。

两者不能混为一谈：

- 号贩涉及稀缺号源套利和治理问题；
- 陪诊可以是合法的流程协助和陪伴服务。

但它们都提醒研究者：**navigation labor 有经济价值。**

## 45. 长期中断

长期病程或反复复诊会把：

- 工作；
- 照护；
- 交通；
- 财务；
- 时间表

重新组织起来。

本轮只研究入口与流程，不推断具体疾病后果。

## 46. 证件与记录

预约系统逐渐要求：

- 姓名；
- 身份证 / 有效证件；
- 手机；
- 就诊卡；
- 患者 ID；
- 既往病历上传。

因此医疗数字化也是 identity interface 的扩大。

## 47. 通信方式

谱系至少包括：

```text
现场
→ 单位电话
→ 个人电话
→ 院内计算机
→ Web
→ SMS
→ 114
→ App / 微信
→ 视频
```

## 48. 互联网平台

医院官网并没有一直成为唯一入口。

长期存在：

- 医院自己的网站；
- 城市统一平台；
- 第三方平台；
- 114 电话；
- 微信 / App；
- 诊间工作站。

这是典型的 multi-channel infrastructure。

## 49. 信息获取

医生排班从院内公告 / 电话询问逐渐变成可远程查。

但：

> `schedule visible ≠ slot available`。

## 50. 社交关系

家庭和弱关系可能提供：

- 医院推荐；
- 代操作；
- 陪同；
- 交通；
- 住处。

网络并没有让这些关系自动失效。

## 51. 未来预期

预约系统把医疗的一部分变成可以写进日历的未来承诺。

疫情又证明这个承诺本身可能失效。

## 52. 线上 / 线下身份

网上预约账号、手机、身份证、就诊卡与现实患者必须最终匹配。

因此：

> **account identity ≠ patient physically present**

## 53. 平台消失与记忆保存

公开 Web 最容易留下：

- 医院介绍；
- 医生列表；
- 挂号教程；
- 新闻报道。

最难留下的却是：

- 当天到底剩几张号；
- 某人是否抢到；
- SMS / 邮件确认；
- 实际到院；
- 检查和诊疗结果。

这正是与 `old-web-archaeology` 的核心交叉点。

# 第十一部分：反例与后见之明风险

## 59. 反例一：电话预约比 Internet 早得多

因此不能写：

> “互联网首次让人提前预约医院。”

1950s 北京已经有制度化电话预约，只是访问结构与今天完全不同。

---

## 60. 反例二：计算机进入医院也早于家庭 Web

1993 同仁医院的电脑预约首先是院内后台 / 挂号员工具。

所以：

> `computerized appointment ≠ online self-service`。

---

## 61. 反例三：Web 预约存在多年后仍可能很少人使用

1999 北京系统存在，但 2004 预约量相对整体门急诊量仍很小。

所以：

> `available ≠ normal`。

---

## 62. 反例四：预约能省排队，但不能创造专家时间

2007–2009 的报道反复显示：专家号仍然稀缺。

所以：

> `better allocation ≠ more capacity`。

---

## 63. 反例五：线上诊疗不能简单写成“医院被手机取代”

2021 互联网医院体验仍需要：

- 网络；
- 病史资料；
- 视频 / 语音；
- 某些情况下家属协助。

大量首次诊断、检查、操作和急症仍依赖线下医疗体系。

本仓库不做具体医学适应证判断，只保留制度边界：

> **remote service is a layer, not the whole care system.**

---

## 64. 后见之明风险一：不要把 1954 电话预约写成“人人可打电话挂号”

当时的例子明确嵌入公费医疗单位和保健员体系。

---

## 65. 后见之明风险二：不要把 1999 网上挂号写成普通家庭常态

当时：

- 家庭计算机；
- Internet 接入；
- 数字技能；
- 预约卡购买；
- 具体医院加入情况

都构成限制。

---

## 66. 后见之明风险三：不要把“秒抢”写成电商语言天然进入医院

同期报道确实使用类似“秒杀”的媒体表达，但分析应回到资源分配：

> 某时刻开放的有限号源在极短时间内被预约完。

---

## 67. 后见之明风险四：不要把疫情期线上医疗的突增外推成长期替代率

危机期间使用增加，可能由：

- 普通门诊受限；
- 感染风险；
- 临时政策；
- 免费咨询

共同推动。

危机 adoption ≠ stable post-crisis baseline。

---

## 68. 后见之明风险五：不要把陪诊浪漫化成“新家人”

商业陪诊可能降低导航负担，但同时存在：

- 费用；
- 服务质量；
- 隐私；
- 责任边界；
- 地区可得性。

本篇只确认这种 labor arrangement 存在。

---

# 第十二部分：本轮改变了我们对“人怎么活着”的哪一点理解

## 69. “能看病”不是一个 yes/no 变量

普通人的 care access 至少需要拆成：

```text
知道哪里有服务
→ 知道找什么入口
→ 取得未来时间
→ 通过身份 / 卡 / 账号
→ 能到场
→ 有人处理流程
→ 真正见到医生
→ 完成后续
```

任何一层都可能失败。

---

## 70. 医疗数字化首先改变的是“在出发前知道多少”

对普通生活来说，最早最直接的收益往往不是远程治疗，而是：

- 医生是否出诊；
- 下周有没有号；
- 是否值得跨城；
- 大概要几点到；
- 家里谁需要请假。

所以网络首先扩展的是 **planning certainty**。

---

## 71. 排队是一种可迁移的社会技术

排队可以从医院大厅迁到：

- 电话线；
- 网站；
- 放号时刻；
- 手机；
- 候补算法。

研究者不能只看“大厅里人少了”，还要问新的等待在哪里。

---

## 72. 照护的一部分其实是制度导航

一个家庭照顾老人或孩子，并不只是喂饭、陪伴或身体护理。

它还可能是：

- 查医院；
- 挂号；
- 上传病历；
- 记住复诊；
- 请假；
- 带证件；
- 取药；
- 解释系统。

这部分劳动以前很容易在宏观统计里消失。

---

## 73. 远程家庭可以形成 medical co-presence

前面仓库已有：

- communication co-presence；
- financial co-presence。

本轮可增加一个谨慎概念：**medical / care co-presence（医疗 / 照护共在）**。

意思不是“人在远方也能完成全部照护”，而是：

> 一个人身体不在父母身边，却仍可以通过预约、线上复诊、支付、配送和信息协调，持续承担一部分医疗事务。

这改变了“同住才算在照顾”的简单图景。

# 第十三部分：与 old-web-archaeology 的交叉

本轮同步建立：

`old-web-archaeology/docs/HOSPITAL_APPOINTMENT_PORTALS_DYNAMIC_SLOT_STATE_AND_CLINICAL_EXECUTION_GAPS_1999_2011.md`

旧网侧重点不是医疗生活史，而是：

- 1999–2011 中文医院预约网站和统一平台；
- doctor schedule / slot inventory 这样的动态状态；
- 注册、实名、就诊卡和第三方跳转；
- 邮件 / SMS / 电话确认；
- 为什么公开页面幸存，不等于历史号源、预约和就诊结果幸存。

硬边界：

```text
appointment page survived
≠ historical schedule survived
≠ historical slot inventory survived
≠ booking succeeded
≠ patient arrived
≠ patient was clinically seen
```

# 第十四部分：仍未解决的问题

## 74. 缺一条真正连续的 1990s–2000s 普通患者链

本轮仍主要是制度、记者实测和媒体人物切片。

最高价值的新证据应是同一个普通人：

```text
先电话问
→ 到院排队失败 / 成功
→ 后来改用 Web / 一卡通
→ 跨城预约
→ 复诊
```

多个同期时间点的链条。

---

## 75. 1999 北京卫生信息网原始 capture 尚未恢复

本轮有：

- 1999 原报定位的后续数据库整理；
- 2006 同时代回顾；

但未取得可核验的 1999 HTML / screenshot / WARC。

因此旧网仓不能把页面 DOM、编码、浏览器依赖写成已知。

---

## 76. 2003 苏州医院预约页的历史 capture 仍值得找

同期新闻给出了原始域名和详细执行流程，但本轮没有取得对应 capture。

未来若找到，可核验：

- 表单字段；
- 字符集；
- URL 结构；
- session / cookie；
- 是否有脚本依赖；
- 预约 / 取消页面是否静态可存。

---

## 77. 缺农村 / 县域 / 基层医疗的对照

本轮证据明显偏：

- 北京；
- 广州；
- 苏州；
- 西安；
- 南京；
- 上海；
- 大医院。

不能外推全国医疗 access。

未来应主动寻找：

- 县医院；
- 乡镇卫生院；
- 村卫生室；
- 基层转诊；
- 早期 12320；
- 非智能手机 / 电话入口。

---

## 78. 缺“预约成功后到底少请了多少假”的连续时间账本

目前有零散第一人称：

- 凌晨四点出发；
- 请假半天取药；
- 网上预约后快速取号。

但还缺可比较的一日 time diary。

这是下一轮非常有价值的微观方向。
