# 从“先学会这门语言”到“先把这一页看懂”：语义可及性、翻译基础设施与跨语言生活选项（中国，1995—2026）

> Status: research package / cross-repo life-history note
>
> Technical companion: `tmzncty/old-web-archaeology/docs/ONLINE_DICTIONARY_WEB_TRANSLATION_MACHINE_TRANSLATION_AND_SEMANTIC_ACCESS_STATE_GAPS_2003_2015.md`
>
> Scope note: 本稿不是“中国机器翻译技术史”，也不把翻译工具的存在等同于普通人掌握外语。它研究的是：一个人已经能连接到某个信息、工作、旅行或社交场景以后，**语言本身是否仍然构成实际不可执行的接口障碍**，以及这种障碍怎样被纸本词典、电子词典、PC 软件、在线词典、网页翻译、移动语音/拍照翻译与生成式 AI 逐层改写。

## 0. 这次补的是 Internet access 与 information access 之间的一层

仓库已经研究过：

- 人是否能接入网络；
- 信息是否可搜索；
- 找到的信息是否能保存、订阅、再次取回；
- 远方的工作、教育、旅行和关系是否能在网络上被发现。

但这些能力仍然隐含了一个常被遗漏的前提：

> **看得见一个页面，不等于看得懂它；能收到一封邮件，不等于能准确理解其中的行动要求；能到达一座外国城市，也不等于能处理药店、车站、菜单、表格与口头问答。**

本稿把这层能力称为：

- **semantic accessibility / 语义可及性**：某个现实可达的信息对象，对特定语言能力的人是否可理解到足以继续行动；
- **language gate / 语言门槛**：行动路径存在，但需要先具备足够语言能力、翻译劳动或中介帮助才能通过；
- **translation-mediated executability / 翻译中介后的可执行性**：翻译不必完美，但足以让人完成下一步，例如理解按钮、药品用途、技术文档、表单、路线或基本对话；
- **semantic portability / 语义辅助可携带性**：词典/翻译能力是否从书桌、PC 移到 PDA、手机、浏览器和任何输入框；
- **language-learning deferral / 语言学习延后**：某些低风险任务可以先借工具执行，不必等到完整掌握一门语言以后才开始；
- **translation verification labor / 翻译核验劳动**：机器能产出结果以后，人仍需比对原文、切换引擎、查专业词、检查语境与承担误译后果；
- **semantic fallback / 语义回退**：保留原文、双语并排、离线词库、多引擎切换或人工复核，使翻译错误不成为单点故障。

最小边界：

```text
网络可达
!= 页面可加载
!= 字符正确显示
!= 识别出源语言
!= 能查出词义
!= 能理解句子
!= 能理解专业/制度语境
!= 能完成现实行动
!= 翻译结果可靠
!= 不再需要学习该语言
```

这条链补充了一个此前容易被“联网”总括掉的事实：

> **network reachability != semantic reachability。**

## 1. 前互联网与前大众互联网：语言中介本来就是基础设施

### 1.1 纸本词典、翻译者与外语教育早已承担“跨语言接口”

互联网没有发明翻译，也没有发明“普通人借助工具跨过自己不会的语言”。在纸本时代，一本双语词典、一本会话手册、学校外语课、出版社译本、单位翻译人员、旅行社导游、口译员，都可以把语言障碍部分外包。

区别在于这些方式通常有明显的：

- 携带成本；
- 查询成本；
- 等待成本；
- 专业领域限制；
- 人工中介成本；
- 更新时间差。

因此数字化真正值得追踪的，不是“翻译从无到有”，而是**翻译劳动如何靠近动作发生的那个瞬间**。

### 1.2 1995：便携电子词典先于大众移动 Internet

后来的产品史资料把文曲星首款 CC-100 上市时间放在 1995 年；一篇 2021 年教育硬件回顾称，文曲星把此前约 2000 元级别的电子词典价格压到约 300—400 元区间，并由此进入更广泛的学生消费市场。

来源：

- 蓝鲸教育/界面，2021，教育硬件回顾：<https://www.jiemian.com/article/6518745.html>
- 科普中国/人民网，2017，对文曲星及用户回忆的整理：<https://kpzg.people.com.cn/n1/2017/0207/c404389-29062441.html>
- evidence: **C/B：后来回顾，可用于产品谱系与价格线索；不能单独确定普及率。**

这里的历史意义不在品牌怀旧，而在于：

```text
纸本大词典
→ 便携电子词典
```

让查词从“回到书桌再查”变成“在教室、路上或电脑旁立刻查”。

这条变化与中国 1994 年全功能接入 Internet 是两条不同的时间线：1995 年一个学生能拥有电子词典，并不意味着家庭已普遍上网；反过来，科研网络已经存在，也不会自动解决普通人的英语阅读障碍。

### 1.3 1999：PC 本地词典/翻译软件降低了另一层成本

1999 年 10 月的中关村在线同期报道记录，金山《词霸2000》《快译2000》等软件以 28 元价格参与当时的低价正版软件竞争。

来源：

- 中关村在线，1999-10-26：<https://news.zol.com.cn/1999/1026/671.shtml>
- evidence: **B：同时代媒体；可证明产品、定价和市场事件，不证明每个家庭都安装。**

PC 本地词典的重要性在于：

- 不依赖每次查询都联网；
- 可以把鼠标取词、专业词库、例句等功能嵌入日常电脑使用；
- 对当时昂贵或不稳定的 Internet 接入尤其重要。

这提醒我们，不应把数字翻译史写成“纸本 → Web → AI”。中间长期存在：

```text
纸本
→ 专用电子词典
→ PC 本地词典/翻译软件
→ 在线词典/翻译
→ 混合在线+离线
```

## 2. 海外前史：Web 很早就开始把“翻整页”做成公共服务

### 2.1 1960s—1990s：机器翻译先是机构技术，不是普通生活工具

SYSTRAN 自身历史资料把其机器翻译系统追溯到 1968 年与美国空军合作；1970s 又进入政府/企业场景。这里应严格理解为工程与机构前史，不能写成普通家庭已经能够自由翻译网页。

来源：

- SYSTRAN company history: <https://www.systransoft.com/systran/>
- evidence: **A/B for company-reported chronology; not household adoption evidence.**

### 2.2 1997：Babel Fish 把机器翻译推到普通 Web 界面

SYSTRAN 公司史把 1997 年 AltaVista 的 Babel Fish 记为其开发的首个免费在线翻译服务；后来的 Microsoft Translator 官方迁移公告也证明 Babel Fish 在 2012 年仍作为一个用户服务整体迁移到 Bing Translator。

来源：

- SYSTRAN history: <https://www.systransoft.com/systran/>
- Microsoft Translator, 2012-05-30, *Welcoming Yahoo! Babel Fish users!*: <https://www.microsoft.com/en-us/translator/blog/2012/05/30/welcoming-yahoo-babel-fish-users/>
- evidence: **A：厂商历史/官方迁移公告；功能与服务沿革强，用户生活影响需另证。**

Babel Fish 的关键界面变化不是“翻译质量终于足够好”，而是：

> **用户可以把一段文字甚至一个网页 URL 交给公共 Web 服务，让机器先提供一个足以继续阅读的版本。**

这形成了后来几乎所有网页机器翻译的基本事务链：

```text
source text / URL
→ source-language selection/detection
→ translation backend
→ translated representation
→ user interprets
→ user optionally follows links / acts
```

因此，中国 2000s 在线词典与网页翻译不是孤立现象，而是全球 Web 从“跨国可达”继续走向“跨语言可读”的一部分。

## 3. 2003—2007：中文 Web 的“语义入口”从词条走向网络语境

### 3.1 2003：在线词典成为独立 Web 服务

海词当前官方网站页脚保留“自 2003 年 11 月 27 日开始服务”的自述。

来源：

- Dict.cn current site: <https://sh.dict.cn/>
- evidence: **A-current/C for service self-history; exact 2003 UI still需历史 capture 验证。**

在线词典与本地软件的差异不只是“不要安装”。它使：

- 学校/网吧/办公室不同电脑都能查同一服务；
- 词库更新可以发生在服务端；
- 查询日志、网络例句和后来出现的账号词本开始成为平台状态。

但它也引入新的依赖：

```text
能打开网页
!= 查询 backend 工作
!= 词条仍是当年的版本
!= 当年所有浏览器/编码都能得到相同结果
```

这部分技术保存问题写入 companion old-Web 文档。

### 3.2 2006—2007：搜索引擎开始直接生产“网络释义”

2006 年 12 月新浪科技报道网易测试“有道”，当时已包括网页搜索、博客搜索和词典；2007 年 9 月网易发布有道桌面词典测试版时，官方稿特别强调“网络释义”、网页取词以及利用 Internet 更新词汇。

来源：

- 新浪科技，2006-12-15：<https://tech.sina.com.cn/i/2006-12-15/13341290786.shtml>
- 网易官方 PR，2007-09-19：<https://www.prnasia.com/story/5436-1.shtml>
- 网易官方 PR，2007-12-11：<https://www.prnasia.com/story/7350-1.shtml>
- evidence: **A/B：同期官方发布 + 媒体观察；官方规模/优势宣称不当人口事实。**

这是一处很重要的 old-Web 转折：

```text
词典出版社预先收录的世界
→ 搜索引擎从正在变化的 Web 中抽取新词、例句和搭配
```

也就是说，Internet 不只是“运送词典”，开始参与**决定什么算一个值得解释的新词**。

## 4. 2005—2012：扩张型未来——“世界在变大，但不必等英语完全学好才进去”

### 4.1 2008：一名用户已经把 Google Translate 的语言扩展理解成“以后会更好用”

2008 年 5 月 11 日，博客园用户“丁学”在 Google Translate 改进后写下同期体验，注意到中文与更多语言之间的互译，并评价以后使用会方便得多；随后用一句中文流行表达测试机器翻译效果。

来源：

- 博客园，2008-05-11：<https://www.cnblogs.com/dingxue/archive/2008/05/11/1191900.html>
- evidence: **A：同时代第一人称；证明一个技术用户当时的期待与试用，不外推总体。**

这是一条很适合保留的“同时代未来想象”：

> 2008 年的使用者已经把“更多语种互译”理解成未来 Web 会变得更容易使用，而不是今天回头替他们宣布“机器翻译革命”。

### 4.2 同月：谷歌—金山合作把本地词典、全文翻译、网页翻译接起来

2008 年 5 月金山与 Google 发布联合品牌免费词霸。同期试用资料把它描述为同时保留本地词典能力，并加入整句、全文、网页翻译及网络交互。

来源：

- 同期产品试用稿，2008-06-20：<https://www.duote.com/tech/1/32.html>
- 同期合作消息的博客园转载/第一财经来源：<https://www.cnblogs.com/anlyren/news/1170471.html>
- evidence: **B：同期产品/媒体材料；功能较强，用户规模数字应视为企业口径。**

这时“语言辅助”已经从一个词扩成了多个粒度：

```text
word
→ phrase/sentence
→ paragraph/document
→ whole webpage
```

粒度越大，越可能让一个人先获得“够用的意思”；但也越容易把局部词义错误放大成语境误解。

### 4.3 2008—2009：离线与在线并非互相替代，而是在解决不同的可及性问题

2008 年一名新浪博客用户整理 MDict 词库时，把大量英汉、专业技术、百科与金山词库放进 PPC 存储卡，合计数百 MB；这类材料证明，在移动 Internet 尚未成为默认条件时，一部分用户主动把语言资源整个搬到掌上设备。

来源：

- 新浪博客，2008-03-27：<https://blog.sina.com.cn/s/blog_504329e101008zbh.html>
- evidence: **A：同时代个人材料；属于技术用户，不能代表普通学生。**

2009 年博客园一份“在线词典大全”又列出爱词霸、沪江小D、海词等，并记录网页划词、Firefox 插件、QQ/MSN 机器人等接入方式。

来源：

- 博客园，2009-06-24：<https://www.cnblogs.com/yppjava/archive/2009/06/24/15690523.html>
- evidence: **A/B：同时代用户整理；证明工具生态与使用评价，不证明市场占有。**

这两条材料合起来说明：

> 扩张型未来不是“全部上云”。普通人更现实的愿望往往是：**不管此刻有没有网、用哪台设备、在哪个应用里，最好都能立即把陌生语言变得稍微可读。**

### 4.4 2008 的程序员材料同时给出了一个反例：翻译工具并没有取消语言能力的职业价值

一篇 2008 年博客园转载的程序员英语文章明确描述：软件技术文档大量来自英文，专业术语翻译不一致会影响理解；作者认为金山词霸等工具可以降低阅读原文门槛，但反对长期只依赖汉化资料。

来源：

- 博客园，2008-09-02：<https://www.cnblogs.com/hellohuan/archive/2008/09/02/1281696.html>
- evidence: **B/C：同期转载，原作者链不完整；可证明当时圈内流传的职业判断，不能视为程序员总体调查。**

这条反例非常重要：

```text
translation lowers entry cost
!= language expertise becomes worthless
```

机器/词典更像把“完全看不懂”推到“可以先工作”，而高风险专业理解、术语稳定性和直接交流仍然保留语言能力的价值。

### 4.5 2012：移动使用已经被 Google 自己视作主要增长方向

Google Translate 官方博客 2012 年回顾称：其统计机器翻译路线在 2006 年公开，此时已覆盖 64 种语言，月活跃用户超过 2 亿，移动流量同比增长超过四倍；文中直接把旅行场景称为语言障碍尤其突出的地方。

来源：

- Google Translate official blog, 2012-04: <https://translate.googleblog.com/2012/04/>
- evidence: **A：官方功能与公司口径使用数据；不是独立人口调查。**

扩张型未来到这里出现了一个清楚的空间变化：

```text
书桌上的翻译
→ PC 屏幕里的翻译
→ 浏览器里的翻译
→ 跟着身体进入街道、车站、商店和海外旅行
```

## 5. 2015—2019：拥堵型未来——翻译从“查一下”进入持续工作流

### 5.1 2018：不会当地语言的人可以把翻译设备租进旅行基础设施

2018 年国庆，北京日报采访的王琳赴美国旅行时，在携程租用带网络能力的翻译机；她在药店买药时直接用机器翻译，并报告对方能够理解。

来源：

- 北京日报/人民网转载，2018-10-15：<https://media.people.com.cn/n1/2018/1015/c40606-30340243.html>
- evidence: **B：同期媒体第一人称；只是一名旅行者。**

这条材料证明的不是“出国已经不需要外语”，而是一种新的生活路径确实可执行：

> **一个人可以在并不掌握当地语言的情况下，先完成某些低复杂度但现实重要的现场事务。**

例如：

- 问路；
- 买药；
- 看菜单；
- 解释简单需求；
- 识别招牌/包装。

这降低了跨境生活的“最低语言启动资本”，尤其对短期旅行者和不打算先接受多年语言教育的人有意义。

### 5.2 但同一时期也暴露新的依赖：翻译工具自己需要网络、识别与电量

2018 年对旅行翻译硬件的同期评测把“联网”直接列为现实障碍之一。

来源：

- 新浪数码/cnBeta转载，2018-03-13：<https://www.cnbeta.com.tw/articles/tech/706385.htm>
- evidence: **B：同期评测。**

所以：

```text
有翻译设备
!= 当前网络可用
!= 语音识别成功
!= 翻译 backend 可达
!= 电量足够
!= 对方愿意等待
```

移动翻译降低一种依赖，同时制造了网络、电池、麦克风、服务端模型和隐私的新依赖。

### 5.3 2019：对开发者而言，“读英文”开始可以被嵌进 IDE/截图工作流

2019 年 OSCHINA 上一名插件开发者说明，他长期想做一个工具，让“英语差”的开发者也能理解英文注释，并把翻译直接放进 JetBrains 系列 IDE 的操作路径。

来源：

- OSCHINA，2019-12-04：<https://www.oschina.net/p/probie>
- evidence: **A/B：开发者同时代自述；证明一个需求与工具实现，不代表开发者总体。**

同年 iText 开发者则把 OCR 后自动翻译用于英文 PDF、未翻译字幕和未汉化游戏。

来源：

- 少数派，2019-05-05：<https://sspai.com/post/42616>
- evidence: **A/B：开发者同时代产品/使用场景说明。**

这时变化已经从：

`我遇到生词 → 打开词典`

转成：

`我正在读/写/编程/玩游戏 → 翻译在当前工作流旁边发生`

本稿把它称为 **translation-friction compression / 翻译摩擦压缩**。

拥堵型未来的代价是：入口越多，人越容易把大量外语内容都纳入自己的“应该读/应该会”的范围，语言门槛降低并不自动减少信息过载。

## 6. 2020—2022：偶发型未来——语言接口突然成为公共服务与跨境生意的临时基础设施

### 6.1 2020：检疫场景把机器翻译从个人便利推到公共服务接口

2020 年 4 月，有道翻译官推出检疫特别版，为机场、酒店、居家、宣法等场景提供双语用语卡与对话翻译；同期报道明确称广州市公安局将其用于入境检疫排查。

来源：

- 人民网，2020-04-07：<https://gongyi.people.com.cn/n1/2020/0407/c151132-31664540.html>
- evidence: **B/A-ish：同期机构/产品部署报道；证明部署存在，不代表所有检疫点。**

这里出现的不是“疫情让大家突然更爱翻译”，而是一种更窄也更可靠的转折：

> 当跨境人口流动仍存在、但临时规则快速增加时，**语言理解本身成为公共卫生程序能否执行的一部分。**

### 6.2 2020—2022：跨境线上生意把语言门槛变成平台后台问题

2022 年中国日报一篇带明显平台宣传色彩的材料描述了阿里国际站中小商家借助平台翻译与海外买家沟通，并引用平台调查称大量卖家对小语种缺乏能力。

来源：

- 中国日报，2022-05-12：<https://caijing.chinadaily.com.cn/a/202205/12/WS627ce993a3101c3ee7ad50aa.html>
- evidence: **B-low / platform-mediated secondary reconstruction：可证明平台把翻译作为跨境交易基础设施宣传和部署；规模数字不可当独立人口事实。**

即使降低证据等级，这条材料仍然指向一个重要结构：

```text
过去：不会客户语言 → 需要翻译人员/代理商/先学语言
后来：平台可以先翻商品、询盘和消息 → 小商家先试着进入陌生语言市场
```

这并不等于文化、谈判、合同与售后误解消失；只是“第一次尝试跨境交易”的启动门槛下降。

### 6.3 本轮没有发现“2020 以后翻译彻底替代语言学习”的证据

这是一个应主动留下的反例。

疫情期间机器翻译进入检疫、在线学习、跨境沟通，说明工具的重要性上升；但：

- 高风险医疗/法律语境仍可能需要专业翻译；
- 技术/学术语境仍需要术语核验；
- 长期移居与深度社交仍需要语言能力；
- 自动翻译错误可能在用户完全不懂源语言时最难被发现。

因此本稿拒绝把偶发型未来写成“AI 终于取消巴别塔”。

## 7. 2023—2026：防守型未来——不是只追求“全自动”，而是让翻译可核验、不中断、可回退

### 7.1 2023 以后：双语并排本身是一种防错结构

沉浸式翻译从 2023 年开始把网页、PDF、字幕等做成原文—译文双语对照，并允许用户选择不同翻译引擎。当前官方页面仍以“双语对照”作为核心设计之一。

来源：

- 项目 GitHub：<https://github.com/immersive-translate/immersive-translate>
- 当前产品页：<https://www.immersivetranslate.net/>
- evidence: **A-current：证明当前产品设计，不证明总体用户行为。**

与早期“把原文整个替换成中文”相比，双语并排保留了一个很重要的 fallback：

> **译文不可信时，原文仍在那里。**

这是一种 `semantic fallback`，尤其适合术语、数字、姓名、代码和高风险句子。

### 7.2 2024—2026 的故障材料提醒：翻译层自己会成为新故障域

沉浸式翻译的公开 GitHub issue 保存了真实使用故障：

- 2025 年有用户报告版本升级后翻译请求数量异常放大，耗尽服务配额；
- 2026 年有用户报告目标语言设置为英语，却得到中文或混杂语言结果；
- 另有用户报告翻译后网页按钮行为受到破坏。

来源：

- 2025-03-15 issue #2673：<https://github.com/immersive-translate/immersive-translate/issues/2673>
- 2026-08-18 issue #4042：<https://github.com/immersive-translate/immersive-translate/issues/4042>
- 2025-04-26 issue #2818：<https://github.com/immersive-translate/immersive-translate/issues/2818>
- evidence: **A：公开 issue 第一人称故障报告；个案，不代表发生率。**

于是必须固定：

```text
page works
!= translated page works
!= requested target language honored
!= translation quota sufficient
!= interaction semantics preserved
```

翻译层越“透明”，人越容易忘记它其实是另一个会失败的中间系统。

### 7.3 2025：跨语言尝试可以先发生，语言学习不再总是进入陌生市场的前置条件

2025 年少数派一名开发者写自己准备把金融 AI 产品推广到印尼时，完全看不懂印尼语；浏览端可以靠翻译插件理解当地 Reddit 内容，但发帖/回复仍需把文字复制进 ChatGPT 等工具。他随后开发内联翻译工具，以减少在应用间切换，并记录一名做海外业务拓展的朋友日常在 WhatsApp 与西语、葡语、俄语客户沟通时也存在同样工作流。

来源：

- 少数派，2025-08-25：<https://sspai.com/post/102042>
- evidence: **A/B：开发者同时代第一人称 + 一个朋友的二手转述；后者降为 B/C-low。作者有产品利益关系，使用动机证据强，产品效果宣称需降级。**

这条材料非常适合描述防守型未来中的一种新生活路径：

> **“先用很小成本测试另一种语言市场，验证值得不值得投入，再决定是否进一步学语言、雇译员或本地化团队。”**

本稿把它称为 **cross-language option preservation / 跨语言选项保留**。

它并不是“人人都可以全球创业”，而是把过去必须提前支付的某部分语言资本，变成可在验证之后再追加的成本。

### 7.4 同时，人开始要求翻译不要打断原来的生活流

同一时期少数派的 iOS 翻译工具文章直接把“频繁切换 App 会割裂阅读体验”当作设计问题。

来源：

- 少数派，2025-09-03：<https://sspai.com/post/102214>
- evidence: **A/B：开发者/产品作者同时代说明，有利益关系。**

这显示 2020s 的问题已经从：

`有没有翻译？`

变成：

`翻译能不能像输入法、字幕或浏览器渲染一样待在背景里？`

当中介越来越隐形，**核验能力反而更重要**。

## 8. 这条历史线怎样改变“四种未来”

### 8.1 2005—2012：扩张型未来

典型语义：

> “更多网页、更多语言、更多设备以后都能看懂一点。”

机制：

- 免费/在线词典增多；
- 网页整体翻译出现；
- 本地 + 在线混合；
- PDA/手机把语言辅助带离书桌；
- 不必等到完整掌握外语以后才第一次接触外文世界。

未来被想象成**外部世界持续扩大，而且理解成本会继续下降**。

### 8.2 2015—2019：拥堵型未来

典型语义：

> “我已经可以把更多陌生语言内容塞进同一天，但仍要判断什么值得读、什么翻得对。”

机制：

- OCR、网页、IDE、语音、旅行硬件把翻译嵌入工作流；
- 外语内容不再天然被排除在信息待办之外；
- 多引擎、多入口、多平台本身增加工具选择与核验劳动；
- 机器翻译可让人完成低风险任务，却不能自动解决专业理解。

### 8.3 2020—2022：偶发型未来

典型语义：

> “规则突然变了、人员还在跨境流动，先让双方把眼前这件事说清楚。”

机制：

- 翻译进入检疫和临时公共服务；
- 线上跨境交易把翻译放进平台后台；
- 语言服务同时遭遇订单冲击与远程化；
- `translation available != physical/service system executable`，工具仍受现实制度约束。

### 8.4 2023—2026：防守型未来

典型语义：

> “我可以借 AI 先跨过去，但最好保留原文、可切换引擎、能回退，而且不要让翻译成为新的单点故障。”

机制：

- 双语并排；
- 多引擎；
- 本地/离线 fallback；
- 翻译直接嵌入网页、输入框、聊天；
- 用翻译先低成本试验跨境工作/市场，再决定是否做长期投入。

这里的“防守”不是拒绝全球化，而是**不再把一个不透明的自动译文当作唯一真实版本**。

## 9. 普通人因此多出哪些“活法”

### 9.1 学习：先接触原文，再决定要不要把外语学深

电子词典和网页翻译让学习者更早接触原版材料；这既可能促进语言学习，也可能形成依赖。

不能写成：

`机器翻译出现 → 学外语没必要`

更稳妥的是：

`机器翻译出现 → 第一次访问外语材料所需的最低能力下降`

### 9.2 就业：部分职业的信息入口不再被“英语不过关”完全封死

技术文档、代码注释、招聘页面、客户消息可以先借工具理解。

但：

- 高阶职业晋升；
- 谈判；
- 专业写作；
- 法律责任；
- 术语准确性

仍可能需要真实语言能力或人工专业翻译。

### 9.3 迁移/旅行：短期行动可以先于语言熟练发生

问路、购物、药店、住宿、简单沟通的最低语言资本下降。

这对：

- 中老年旅行者；
- 临时商务出行；
- 语言跨度很大的短期旅行；
- 第一次试探某个国家/城市

尤其重要。

### 9.4 非正规劳动与小生意：跨境客户第一次变得“可试一单”

自动翻译把商品描述、询盘、简单售后部分平台化，允许小商家先处理少量跨语言交易；但合同、纠纷和文化语境仍可能暴露严重风险。

### 9.5 兴趣社群：一个人可以进入自己不会语言的论坛、游戏、视频和 fandom

2019 OCR 翻译未汉化游戏、2020s 网页/字幕双语化都表明：语言不再严格决定“哪些文化产品属于我的可达世界”。

但平台推荐和翻译仍会选择性地决定哪些内容更容易跨语言传播。

## 10. 新的制度与数据接口

翻译工具越深地进入生活，越需要把下面几层分开：

```text
source content
→ language detection
→ OCR/ASR (if needed)
→ segmentation
→ translation engine/model
→ terminology/glossary/context
→ rendered translation
→ user verification
→ downstream action
```

任何一层失败都可能产生“看起来很流畅但实际上错了”的结果。

尤其要避免：

- OCR 错字被翻译系统流畅地继续解释；
- 人名、数字、药名、地址被错误本地化；
- 专业术语被日常词义替换；
- 低资源语言质量远弱于主流语言；
- 用户完全不懂源语言，因而最无法发现错误。

生成式 AI 时代的新问题不是“翻译还有没有错”，而是**错误可能比早期机器翻译更自然、更不显眼**。

## 11. 反例：这不是一条“语言障碍持续消失”的单向进步史

### 11.1 网络本身可能不可用

2018 旅行翻译器评测已经把联网视为现实限制。海外旅行恰恰常发生在漫游、SIM、Wi-Fi、电量最不稳定的时候。

### 11.2 专业语境仍需要人类知识

2008 程序员材料已经指出专业词翻译可能混乱；2024 针对科学文本的研究也继续发现生成式 AI 翻译与人工翻译在语言特征和质量上存在差异。

参考：

- Fu & Liu, 2024, *Humanities and Social Sciences Communications*: <https://www.nature.com/articles/s41599-024-03726-7>
- evidence: **academic research; not ordinary-user first person.**

### 11.3 低资源语言并不平等

机器翻译的语言覆盖数量不能等同于每种语言都有同等质量。2023 年有关 ChatGPT 翻译低资源语言的研究发现性别代词与职业偏见等问题。

参考：

- Ghosh & Caliskan, 2023: <https://arxiv.org/abs/2305.10510>
- evidence: **academic evaluation; specific tasks/languages.**

### 11.4 翻译层会破坏原网页行为

2025 Immersive Translate issue 显示翻译后页面按钮可能失效。一个“语义更可读”的页面可以同时变得**功能上更不可执行**。

所以必须保留：

> **semantic accessibility != transactional executability。**

## 12. 海外比较：哪些是中国特有，哪些是共同变化

### 更普遍的 Internet/个人计算共同变化

- 1990s Web 把机器翻译做成公共在线服务；
- 2000s 搜索、词典与网页翻译融合；
- 2010s 移动、语音、OCR 把翻译带入现实空间；
- 2020s 翻译逐步嵌入浏览器、聊天、输入法、会议和内容消费；
- translation backend 的平台依赖、停服、质量差异和隐私成为共同问题。

### 中国材料中更突出的历史结构

- 大众 Internet 普及与英语教育、电子词典/词霸软件长期并行，而不是一个阶段彻底取代另一个；
- PC 本地工具、网吧/学校多终端环境使“无需安装/可在线查”与“离线仍可查”长期同时重要；
- 有道等中文搜索服务把“网络释义”做成对高速变化英文互联网词汇的本地化回答；
- 2020s 中国商家“出海”与平台内自动翻译把语言能力进一步变成商业基础设施的一部分。

不能把这些写成“中国人英语不行所以靠机器”；更合适的比较单位是：

> **任何非英语母语互联网用户在全球知识、软件、商务和旅行体系中，都可能面对“网络已经接通，但语义还没有接通”的第二道接入门槛。**

## 16. 后见之明风险

### 风险 1：把 1994 中国接入 Internet 写成“从此可以读全球 Web”

错误。至少还要经过：

```text
physical/network access
→ household/device access
→ page rendering/encoding
→ search/discovery
→ language comprehension
→ practical use
```

### 风险 2：用今天的神经/LLM 翻译质量倒写 2008

2008 用户面对的是当时的统计/规则系统和当时网页。必须保留当时“好笑、能看懂大意、但不可靠”的实际体验。

### 风险 3：看到 2018 翻译机就宣布“出国不需要英语”

个案只证明一部分事务可由设备辅助。医疗、法律、长期关系、危机处理仍然不同。

### 风险 4：把翻译产品公司用户量当普通人口采用率

厂商 MAU、请求量、安装量只能作为产品规模口径，不能直接转成家庭或职业总体。

### 风险 5：把“支持 100/200 种语言”当成所有语言等质量

覆盖表不是质量分布。

## 18. 这一轮改变了什么

上一轮以前，我们很容易把 Internet 的扩张写成：

> “越来越多人能连接到越来越远的地方。”

这一轮补上了一层：

> **连接只是第一道门。一个人在屏幕上看到远方以后，还要能把那一页、那句话、那张药盒或那位客户变成自己能继续行动的意思。**

纸本词典让人慢慢跨过这道门；电子词典把门带到身上；在线词典让词义跟着 Web 更新；网页翻译试图一次搬走整面墙；手机、语音和 OCR 又把这套中介带进现实空间。到 2020s，一部分人甚至可以先用机器翻译测试一个陌生语言市场，再决定要不要支付长期学习、雇翻译或本地化的成本。

但这并不是“语言差异消失”。真正成熟的跨语言生活更像：

```text
机器先帮我跨过去
+ 原文仍然可见
+ 我知道什么时候必须核验
+ 工具失效时还有 fallback
+ 高风险事务仍知道什么时候要找人
```

因此，互联网扩大“普通人有多少种活法”的方式之一，并不是人人突然学会了更多语言，而是**越来越多生活路径不再要求“先把一门语言学到足够好”才能第一次试着走进去。**
