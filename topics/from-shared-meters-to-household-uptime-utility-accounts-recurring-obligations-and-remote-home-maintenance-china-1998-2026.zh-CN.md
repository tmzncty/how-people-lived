# 从合表分摊到后台自动续航：公用事业账户、重复性义务与家庭行政在线时间，中国 1998–2026

> 状态：研究笔记；用于 `how-people-lived` 的住房 / 家庭独立 / 通信基础设施 / 制度接口交叉线索。
>
> 核心问题：**一个住宅什么时候不只是“有水、有电、有燃气”，而是变成一组必须由某个具体家庭持续抄表、收账单、付款、迁移、销户和证明的个人化服务账户？这些重复性义务怎样改变独立生活、跨城迁移、代际支持和一个家庭维持正常运转所需要的劳动？**
>
> Cross-project companion: `tmzncty/old-web-archaeology/docs/UTILITY_BILL_ACCOUNT_BINDING_PAYMENT_AND_SERVICE_CONTINUITY_STATE_GAPS_2003_2015.md`

## 0. 本轮研究的不是“水电煤发展史”

仓库已经分别研究过：

- 自来水、卫生设施、电气化等物质基础设施；
- 汇款与家庭之间的钱如何跨距离流动；
- 家庭宽带的地址绑定、装机和销户；
- 搬家、租房、买房与家庭组装；
- 网上银行、远程文书提交和政务记录复用。

这里补的是此前没有单独建模的一层：

> **基础设施已经接到住宅以后，谁负责把这个住宅长期维持在“制度上仍然可用”的状态？**

一间房每天能继续有电、有水、有燃气，除了管线、设备和供应能力，还可能依赖：

```text
service connection
× 正确的 meter / household mapping
× 有效的 utility account
× 账单被生成并被看见
× 付款渠道可用
× 付款工具 / 余额 / 授权有效
× 公用事业后台正确销账
× 搬家时过户 / 结清完成
× 出错时仍有 fallback route
```

因此本篇使用两个工作概念。

### household administrative uptime — 家庭行政在线时间

指一个家庭为了让住宅持续可用，需要长期维护的账户、合同、缴费、过户和记录状态。

### recurring-obligation labor — 重复性义务劳动

指那些不是一次性完成、而是每月或每个账期必须重新注意、核对和处理的家庭事务，例如：

- 水费；
- 电费；
- 燃气费；
- 后来的宽带、电话、物业等。

独立生活因此不只是“自己挣钱、自己住”，还包括**自己持续维护一套不会自动消失的后台义务**。

## 1. 更早的前史：一块总表可以把六七户人的生活绑在一起

1998 年《生活时报》关于北京居民配电改造的同期报道，在解释老旧住宅为何难以承受空调、微波炉等新增负荷时，回溯了一个非常具体的旧式大杂院计费场景：20 世纪 60 年代以前，一个住六七户人的大院可能只有一块 2.5 安培总表；每月总电费再按各户灯泡等用电器的瓦数折算分摊。到 1990 年代，家电数量和功率已经远超这套制度的原始假设，合表计费、总分表不一致和费用分摊开始造成纠纷。

来源：
- 《生活时报》1998-09-22，《“9950”工程解下市民用电的悬丝之剑》：
  https://www.gmw.cn/01shsb/1998-09/22/GB/745%5ESH12-215.htm

证据等级：
- **B：同时代报道；其中 1960s 场景为报道中的历史回溯，只能证明这种具体住宅实践确实被当时记者记录，不能外推所有北京家庭。**

这一场景说明：

> **meter ≠ household。**

基础设施进入院落以后，仍然可能由多人共享一个计量与结算接口。

这时家庭真正承担的不是独立账户，而是 **collective settlement（集体结算）**：

```text
一个总表
→ 总额
→ 院落内部再分配
→ 某个人收钱 / 对账
→ 再向供电系统结算
```

因此“每家都通电”与“每家都是公用事业的独立客户”是两个历史阶段。

## 2. 1998：一户一表把家庭变成直接服务账户

1998 年北京配电设施改造的同期报道写得非常明确：单元式楼房改造时同步实行“一户一表”，供电部门与**每家每户**签订供用电合同，并采用卡式电表售电，或试验自动抄表与电费储蓄自动划拨；与此同时，平房、筒子楼等因为拆迁和改造条件不同，当时并不一律实施一户一表。

来源：
- 《生活时报》1998-08-28，《每户先来2000瓦》：
  https://www.gmw.cn/01shsb/1998-08/28/GB/720%5ESH2-2804.htm
- 《生活时报》1998-09-22，《“9950”工程解下市民用电的悬丝之剑》：
  https://www.gmw.cn/01shsb/1998-09/22/GB/745%5ESH12-215.htm

证据等级：
- **B：同时代媒体对政府/供电部门改造方案的报道。**

这里出现了 **service-account individuation（公用事业账户个体化）**：

```text
院落 / 单位总表
→ 户内分摊
```

逐步转成：

```text
具体住宅
→ 独立电表
→ 独立合同
→ 独立账单 / 储值或扣款
→ 独立欠费与结算责任
```

它扩大了家庭控制权，也把更多持续管理责任直接交给家庭。

而且这个过程不是全国同一天完成。2003 年江苏农村电力体制改革的同期材料仍把“销售、抄表、收费、服务到户”作为改革成果来强调。它提醒我们，城市单元楼、旧胡同、农村住宅、单位自管大院的账户个体化节奏可以完全不同。

来源：
- 中国政府网/地方材料保存的农村电力改革报道（2003）：相关同期制度报道，需在后续数据化时进一步补地区级覆盖率。

### 反例：submeter 不一定等于 direct account

2007 年南宁一宗居民纠纷里，住宅虽然装有分户电表，但仍由物业在总表之下收费，业主质疑这是否真正达到“一户一表”。

来源：
- 同期媒体报道，2007，南宁“一户一表”争议：后续应补原主管部门合同/计量规则作交叉确认。

这给研究增加一条硬规则：

> **apartment submeter ≠ direct utility account。**

看到每户有一块表，不能直接推出住户已经直接和供电企业结算。

## 3. Internet 以前，自动扣款已经开始把“每月去缴费”搬进后台

1998 北京方案已经提到“电费储蓄自动划拨”。这意味着重复义务的自动化并不是移动支付或 Web 首次创造的。

这次使用 **obligation automation（义务自动化）** 描述：

> 用户不必每个账期都主动完成完整的“看到账单 → 去网点 → 排队 → 付款”链，而是预先建立长期授权，让后续账单在满足条件时自动结算。

但：

```text
autopay mandate exists
≠
debit always succeeds
```

仍可能失败于：

- 账户余额不足；
- 银行卡/存折变更；
- 授权关系失效；
- 搬家以后户号改变；
- 公用事业与银行之间的数据或协议变化。

因此“后台自动”不是劳动消失，而是**把劳动从每月操作转成长期账户维护和异常处理**。

海外比较也支持这一点。英国支付基础设施机构 Pay.UK 的制度史记录，Bacs 的前身在 1968 年开始运行，Direct Debit 于 1970 年推出；Direct Debit 此后长期被用于能源、电话等周期性家庭账单。

来源：
- Pay.UK, Heritage: https://www.wearepay.uk/who-we-are/heritage/
- Pay.UK, Bacs payment system / Direct Debit: https://www.wearepay.uk/what-we-do/payment-systems/bacs-payment-system/types-of-transactions-made-on-the-bacs-payment-system/

证据等级：
- **B/C：支付系统运营机构今天保存的制度史；适合确定制度节点，不是 1970 年普通家庭第一人称。**

所以跨国共同变化不是“Internet 发明自动交账单”，而是工业化城市家庭产生越来越多周期性合同以后，支付系统不断尝试把它们从人工提醒转成后台基础设施。

## 4. 2005：缴费渠道变多，家庭开始维护一个 channel portfolio

2005 年上海的同期报道已经能看到非常密集的缴费路线共存：

- 银行代扣；
- 网上银行；
- 电话银行；
- 银行 / 邮政柜台；
- 便利店；
- 多媒体自助终端；
- 专门的公共事业缴费平台。

一篇 2005 年《新民晚报》报道描述，上海银联在居民区等位置部署自助终端：用户插银行卡、扫描账单条形码后完成付款；上海银联清算资金，再把成功交易的条码信息传给公用事业单位用于销账。报道还指出，搬家以后住户往往需要修改账单地址、重新办理自动代扣，而很多传统缴费点的营业时间又与上班族工作时间冲突。

来源：
- 《新民晚报》2005-07-14，上海公共事业自助缴费报道：
  https://finance.sina.com.cn/money/bank/bank_card/20050714/15331797230.shtml

证据等级：
- **B：同时代媒体；技术链按报道措辞保留，不推断后台数据库具体 schema。**

这里出现两个新变量。

### payment-channel portfolio — 缴费渠道组合

“可以交费”不能只问有没有一种渠道，而要问一个家庭现实中有多少 fallback：

```text
营业厅
+ 银行/邮政
+ 便利店
+ 电话
+ 自助机
+ Web
```

渠道越多，单个端点关门或本人没空时越不容易断掉。

### barcode-to-ledger bridge — 条码到后台销账桥

纸账单上的条码开始把一个物理对象与后台账单状态连接起来。

但必须区分：

```text
终端显示“付款成功”
≠
资金清算已经结束
≠
utility ledger 已经 durable write-off
≠
未来不会出现错账
```

这些是不同状态。

## 5. 2005 的反例：便利与身份/银行卡暴露可以同时增加

2005 年重庆一户一表改造的同期报道中，居民秦女士担心申请材料要求身份证复印件和银行卡信息，担忧个人资料风险；供电方则解释，银行代扣属于自愿选择，优势是可以免去每月到营业厅排队。

来源：
- 《重庆晚报》2005-09-13，同期报道：
  https://news.sina.com.cn/s/2005-09-13/06286928936s.shtml

证据等级：
- **B：同期第一人称 + 供电方回应。**

这给“数字化 / 自动化 = 更方便”增加一个必要反例：

> **convenience ≠ voluntary trust。**

账户越个人化、自动化，普通人越可能需要向银行和公用事业系统交出：

- 姓名；
- 身份证；
- 银行账户；
- 住宅 / 户号；
- 长期扣款授权。

所以一项重复劳动减少时，新的 **credential exposure（凭证暴露）** 与信任判断可能同时增加。

## 6. 2009：付款人、账户持有人和实际居住者开始明显脱钩

2009 年一份近同时代用户操作文章留下一个很好的生活场景：作者长期租房，自己已经习惯通过建设银行网银缴水电费；后来父亲拿来两张欠费单，让作者在网上一起处理。文章逐步记录了支付宝“生活助手”和建设银行网银的缴费路径，包括选择水/电/燃气、输入条形码或账单信息、核对返回金额，再通过网银账户付款。

来源：
- 2009-04-19 发布、今天由第三方技术站保存的用户操作文章：
  https://www.leadto.com.cn/technews/1316.html

证据等级：
- **B-：近同时代用户流程材料；当前 host 并非本轮验证过的 2009 historical memento，不能据此恢复原始 DOM / charset / endpoint。**

2009 年宁波支付宝公用事业缴费的同期报道又明确说，用户只要知道父母的户号/账单号，也可以替父母缴费。

来源：
- 2009-12-15 同期报道：
  https://business.sohu.com/20091215/n268972071.shtml

这里出现 **payer–resident decoupling（付款人—居住者脱耦）**：

```text
payer
≠ account holder
≠ resident
```

这和“汇款给父母”不是同一件事。

汇款是：

```text
给父母一笔可自由使用的钱
```

远程代缴是：

```text
直接把某个具体住宅的一项 obligation extinguish
```

于是跨城家庭可以形成新的分工：老人仍住在原住宅，成年子女在另一座城市工作，但子女可以直接维护父母住宅的一部分行政在线时间。

这里的 `户号 / 条码` 也获得一种新的意义：它是**住宅服务关系的可远程寻址符号**。

## 7. 2009–2014：Web 扩大了可达性，也制造了新的平台依赖

2009 年中国互联网协会等同期材料记录，支付宝的公共事业缴费逐步进入上海、北京、重庆、合肥、成都等城市，支持水、电、电话、宽带等不同类别；但城市、缴费单位、支付工具和实时销账能力并不完全一致。

来源：
- 中国互联网协会，2009-09-01，支付宝公共事业缴费报道：
  https://www.isc.org.cn/article/8429.html
- 中国互联网协会，同期相关报道：
  https://www.isc.org.cn/article/8463.html

证据等级：
- **B/B+：同期行业机构/平台材料；“实时销账”等效果是平台方口径，不是独立的私人交易审计。**

因此：

> **platform has utility-payment feature ≠ my city + my biller + my account is supported。**

2014 年上海“付费通”与支付宝公共事业缴费渠道中止的争议又说明，用户看到的前端功能可以在底层公用事业账户仍然存在时突然消失。付费通方面称，支付宝高频账单查询给其 EBPP / 公用事业计费系统带来压力；支付宝方面对此原因和利益关系有不同说法。

来源：
- 人民网财经，2014-03-21：
  https://finance.people.com.cn/n/2014/0321/c70846-24704406.html
- 中国新闻网，2014-07-01：
  https://www.chinanews.com/cj/2014/07-01/6336169.shtml

证据等级：
- **B：同期争议双方/媒体材料。原因存在争议，不能把任何一方的技术解释写成已证实事实。**

这产生 **channel-contract dependency（渠道合同依赖）**：

```text
utility account still exists
+ utility service still runs
```

完全可能同时发生：

```text
my familiar third-party payment entrance disappears
```

Internet 因而不仅减少了端点，还创造了新的端点依赖。

## 8. 2015–2019：买下一套房，也意味着接过一串服务账户

2019 年广州、江门等地推进二手房转移登记与水、电、燃气联动过户的同期材料，把“独立家庭”背后的协调工作暴露得很清楚。

以前，房屋产权变更完成以后，水、电、燃气仍可能需要分别：

- 取号；
- 排队；
- 重新提交身份证件；
- 提交产权 / 购房材料；
- 提供银行卡；
- 填不同申请表；
- 等各单位分别更新账户。

江门的同期政务材料把旧流程概括为多套重复材料和多张表格；改革后通过数据共享和一个窗口把这些事项合并。

来源：
- 人民网/广州日报，2019-04-25，《亲测广州一窗通办水电煤气过户》：
  https://house.people.com.cn/n1/2019/0425/c164220-31049087.html
- 南方日报/南方+，2019，江门水电气过户“一窗通办”：
  https://pc.nfnews.com/78/2930430.html

证据等级：
- **B：同期媒体实测 + 政务流程材料。**

这补出 **service succession（服务账户接续）**：

> **property ownership transfer ≠ utility-account transfer。**

住房在法律上已经换主人，不代表：

- 旧欠费已经结清；
- 水表/电表/燃气表与新家庭已经正确绑定；
- 新的银行代扣已经生效；
- 账单投递地址已经改变。

因此 2015–2019 “拥堵型未来”里，家庭形成不只是凑够首付或租金，还越来越像一个**多账户协调项目**。

技术真正减少的是 coordination cost，而不是把这些制度关系变得不存在。

## 9. 2020–2022：危机证明“欠费状态”与“物理服务状态”可以被政策暂时拆开

2020 年疫情期间，多地水、电、燃气服务推出线上办理、无接触服务，并实行不同形式的“欠费不断供”。长沙 2020 年 2 月的同期措施就包括水电气网上办理以及疫情期间欠费不停供。

来源：
- 长沙晚报，2020-02-13：
  https://www.icswb.com/h/152/20200213/642898.html
- 四川在线/泸州，2020，同期无接触公共事业服务：
  https://luzhou.scol.com.cn/shms/202002/57470569.html

证据等级：
- **B/B+：同期地方官方或主流媒体。**

这是一条非常有价值的状态反例：

```text
account in arrears
≠
service must be physically cut immediately
```

在平常时期我们很容易把“欠费 → 停供”想成自动物理规律；疫情措施证明，中间实际上还存在：

- 政策；
- 宽限期；
- 催缴；
- 系统规则；
- 人工例外。

我把这一层叫作 **billing–service policy decoupling（账务—服务政策脱耦）**。

偶发型未来里，社会维持普通生活的一种方式，就是暂时允许账务时钟和基础设施时钟不同步。

## 10. 2023–2026：防守型未来不仅需要自动化，还需要 fallback redundancy

今天大量水电气事务已经可以通过运营商 App、支付宝、微信和在线政务完成；自动扣款也继续把“每月想起来交费”搬到后台。

这形成一种 **background household maintenance（后台家庭维护）**：

```text
系统有账户
→ 系统知道账单
→ 已有授权 / 支付方式
→ 账期到来自动或远程完成
→ 本人只在异常时介入
```

这很符合“防守型未来”的时间感：不是每个月重新做一次决定，而是尽量把普通生活变成**只要没有报警就继续运行**。

但 2026 年上海一个同时代第一人称案例说明，数字化默认并不能替代所有旧端点。一名 74 岁居民长期习惯步行约 150 米到便利店缴水、电、燃气费，因为不会使用智能手机，也喜欢保留纸质凭证；便利店停止代收四个多月后，他形容自己一时不知道该怎么办。报道后，当地又恢复了 600 多家便利店的公共事业缴费服务。

来源：
- 2026-02-09，同期报道（川观转上观相关调查）：
  https://cbgc.scol.com.cn/news/7270222
- 人民网上海，2026-02-13，便利店缴费服务恢复：
  https://sh.people.com.cn/n2/2026/0213/c176737-41502718.html

证据等级：
- **B：同期媒体第一人称 + 后续服务恢复。该个案明确属于数字渠道使用困难的老年人，不能外推所有老年人。**

所以防守型未来还需要 **analog fallback as infrastructure（模拟后备渠道作为基础设施）**。

一个成熟系统不能只问：

> 主流用户是否有最快的 App？

还要问：

> 当手机号、App、银行卡、数字技能、平台接口或本人能力其中一项失效时，还有没有第二条路？

冗余本身就是可靠性。

## 11. 四种未来：公用事业账户怎样进入不同的时间感

| 时期 | 普通人的主要问题 | 本专题观察到的机制 |
|---|---|---|
| 2005–2012 扩张型未来 | “我能不能自己在城市里住、下班后也把家维持起来，还能远程帮家人？” | 多渠道缴费、网银/平台、户号远程寻址、付款人—居住者脱耦 |
| 2015–2019 拥堵型未来 | “房子、贷款、产权、水电气、银行卡和工作能不能一起协调完？” | 多账户成年生活、过户协调、一窗通办、数据复用 |
| 2020–2022 偶发型未来 | “窗口关了、不能出门时，住宅还会不会继续运行？” | 无接触办理、线上缴费、欠费不断供、账务—服务脱耦 |
| 2023–2026 防守型未来 | “怎样让普通义务尽量在后台自己运行，同时保留失败后的替代路径？” | 自动扣款、远程账户维护、异常处理、模拟渠道冗余 |

这四种时间感不是互相替代。

同一座城市里可以同时存在：

- 自动扣款的年轻租户；
- 让外地子女代缴的老人；
- 仍到便利店缴费的人；
- 因搬家而需要重新绑定所有账户的人。

## 12. 它怎样改变“独立生活”的定义

以前“独立”经常被写成：

```text
有收入
+ 离开父母家
+ 自己租/买房
```

本专题建议再加一层：

### administrative household independence — 家庭行政独立

一个人能够持续处理：

- 住宅服务账户；
- 账单；
- 自动扣款；
- 欠费异常；
- 过户；
- 销户；
- 服务恢复；
- 与房东 / 前业主 / 公用事业单位之间的责任边界。

但这种“独立”仍可能依赖别人。

一个独居青年可以让父母帮忙交费；一个老人可以让外地子女直接维护家中账单；租户可以由房东保留户名、自己只支付实际费用。

因此：

> **independent residence ≠ socially self-contained household。**

基础设施账户反而让跨家庭协作变得更细颗粒：不必给一整笔生活费，也可以只接管某一项固定义务。

## 14. 后见之明风险与反例

### 风险 1：把“一户一表”写成纯粹技术升级

它同时是：

- 计量升级；
- 合同关系改变；
- 责任边界改变；
- 账单和欠费的个体化。

### 风险 2：把“网上缴费”写成纸账单和线下渠道瞬间消失

2000s 真实状态是长期共存；纸条码甚至会成为网上 / 自助缴费的输入。

### 风险 3：把“付款成功”写成“公共事业后台已经正确销账”

交易平台页面、银行清算、公用事业账务和物理供给是不同状态。

### 风险 4：把数字渠道普及写成所有人的成本都下降

对不会智能手机、缺银行卡、缺稳定账户或偏好纸凭证的人，线下端点减少可能增加成本。

### 风险 5：把代缴浪漫化成“远程孝顺”

代缴只是家庭协作的一种技术能力。它可能来自照护，也可能来自数字技能差异、身体限制、财务依赖或单纯方便。

## 15. 仍然不知道什么

1. 1990s–2000s 不同城市/城乡一户一表、直供直抄到户的实际覆盖速度；
2. 一个真实家庭从“物业代收”切到“公用事业直收”的完整账务体验；
3. 2005–2012 普通租户第一次学会自己维护水电气账户的年龄与路径；
4. 远程代父母交账单在跨城家庭中到底有多常见；
5. 自动扣款失败以后，一般家庭平均需要多少人工修复；
6. 二手房交接时，旧欠费、最后一次抄表、户名变更和银行卡解绑最常在哪里出错；
7. 线上渠道替代实体缴费点后，对不同年龄、收入、数字技能群体的时间成本如何变化；
8. 一个家庭到底维护多少个“必须不能掉线”的周期账户。

这些问题都不能用平台用户量直接代替。

## 16. 下一步：建立 household-obligation ledger

后续最有价值的不是再统计“线上缴费占比”，而是沿一户普通家庭追一条 20–30 年的义务链：

```text
第一次独立电表
→ 谁抄表 / 谁收钱
→ 第一次自己去营业厅
→ 第一次银行代扣
→ 第一次网上查到水电费
→ 第一次替父母远程缴费
→ 第一次搬家后发现旧户号/旧代扣没有关闭
→ 第一次买房同时过户水电气
→ 疫情时如何维持服务
→ 今天哪些账单已经完全在后台运行
→ 哪个备用渠道在 App / 手机失效时还能用
```

这会补齐一个此前被“有房”“有水电”遮住的问题：

> **一个时代让普通人拥有多少种独立生活，不只看住宅和基础设施是否存在；还要看一个人有没有能力、时间和可用接口，把维持那间住宅的几十次小义务年复一年地接住。**
