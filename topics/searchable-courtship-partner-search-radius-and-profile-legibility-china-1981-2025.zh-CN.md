# 1981–2025：伴侣怎样变成“可搜索的人”——征婚广告、婚恋数据库与亲密关系的双向漏斗

> 核心问题：普通人寻找伴侣时，究竟是在什么范围内“遇见人”？报纸、书信、婚介所、熟人介绍、BBS、婚恋网站、即时通信、App、直播和线下活动，怎样改变一个人能够发现、比较、联系和真正见面的潜在伴侣？
>
> 本专题不是“中国婚恋观史”，也不把“网上认识”自动解释为“互联网改变了爱情”。研究单位是 **partner-search infrastructure（伴侣搜索基础设施）**：一个人怎样把“我想认识谁”变成可执行的发现、接触、筛选、见面与关系形成过程。
>
> 它与本仓已有的几个问题直接相连：
>
> - 工作与居住会限制现实社交半径；
> - `reachability` 决定两个陌生人建立联系后能否持续沟通；
> - `residential seriality` 与迁移会改变“同城/异地”是否可执行；
> - `institutionally elicited futures` 说明人生计划会被制度和表格组织；这里进一步问：**亲密关系候选人本身什么时候也被组织成可填写、可筛选、可排序的字段？**
>
> 旧网 artifact 的专门证据合同见：
> <https://github.com/tmzncty/old-web-archaeology/blob/main/docs/DATING_PROFILES_SEARCH_FILTERS_OFF_PLATFORM_HANDOFF_AND_RELATIONSHIP_OUTCOME_GAPS_2002_2012.md>

## 结论先行

这一轮材料支持七个新的分析概念。

### 1. partner-search radius：伴侣搜索半径

伴侣搜索半径不是地图上的公里数，而是：

> **一个人在其时间、通信、交通、社会关系和制度条件下，现实中能够发现并尝试联系多少潜在伴侣。**

它可以通过不同系统扩张：

```text
亲属 / 邻里
→ 同学 / 同事 / 单位
→ 朋友介绍
→ 婚介所 / 相亲角
→ 报纸征婚 / 笔友栏目
→ BBS / 个人主页 / 门户交友
→ 专业婚恋数据库
→ 社交平台 / App / 小程序 / 直播
```

但：

> **larger search radius ≠ higher relationship probability**

能看见更多人，只证明候选集合扩大，不证明更多人会互相喜欢、见面、建立关系或结婚。

### 2. introduction stack：介绍栈

网络渠道并没有把熟人介绍一次性替掉。

2019 年同期材料显示，同一个人可以同时使用：

- 家人和亲戚介绍；
- 单位同事介绍；
- 校友会活动；
- 相亲角；
- 婚恋网站；
- 微信公众号；
- 平台组织的线下活动。

因此更准确的变化是：

> **new matching channels accumulate on top of older channels**

而不是 `traditional matchmaking → Internet dating` 的单线替代史。

### 3. profile legibility：个人资料可读性 / 可字段化

报纸征婚已经要求把一个复杂的人压缩成几行信息；数据库进一步把这种压缩变成结构化字段：

```text
age
location
education
occupation
income
height
marital status
housing / family background
interests
personality test
partner requirements
```

一旦成为字段，就可以：

- 搜索；
- 过滤；
- 排序；
- 推荐；
- 自动匹配。

这是一种新的 **mate legibility（择偶可读性）**。

但必须坚持：

> **profile legibility ≠ person legibility**

一个字段化档案只能使某些特征更容易被比较，不会把一个人的生活、性格和关系能力完整呈现出来。

### 4. reciprocal-selection funnel：双向选择漏斗

“注册婚恋网站”离“形成伴侣关系”很远。

更有用的状态机是：

```text
profile exists
→ profile visible
→ discovered / recommended
→ clicked
→ one side expresses interest
→ other side notices
→ reply / reciprocal interest
→ off-platform contact
→ first meeting
→ repeated meetings
→ relationship
→ co-residence / marriage (if desired)
→ relationship persists or ends
```

每一步都可能停止、撤回或绕路。

因此：

> **match ≠ mutual interest**  
> **message sent ≠ reply**  
> **reply ≠ meeting**  
> **meeting ≠ relationship**  
> **relationship ≠ marriage**

### 5. rejection-cost compression：拒绝成本压缩

网络降低的不只是“找到人”的成本，也可能降低一次失败尝试的社交成本。

2019 年一名受访者明确说，他面对陌生人时较腼腆，但网上主动说话没有收到回复，也不会像线下面对面那样感到丢脸。

这意味着：

> **lower social cost per attempt can raise the number of attempts without raising the success rate per attempt**

这和就业研究中的 `application throughput` 很相似：尝试次数可以迅速增加，而互相投入注意力仍然稀缺。

### 6. choice abundance ≠ intimacy abundance

2024 年同期报道中，一名使用者每天分几个时段登录三个平台查看推荐，另一名使用者会不断修改个人主页并处理大量推荐对象。技术把“今天还能看谁”变成高频动作，却没有自动消除疲惫、模糊感、距离、时间、线下化学反应和现实条件。

因此：

> **more candidates ≠ more intimacy**

“选择多”与“关系容易形成”是两个完全不同的变量。

### 7. social clock + search infrastructure：社会时钟与搜索基础设施可以叠加

催婚、年龄预期、亲属期待早于互联网；平台也没有创造这些脚本。

但当平台让“找对象”变成一个随时可以登录、筛选、打卡和查看推荐的动作时，社会时钟可以被转译成一套可执行的日常任务。

这仍然不是因果简化：

> **platform availability ≠ desire to marry**

有人使用平台是因为真心想进入关系；有人只是扩大渠道；有人被家庭压力推动；有人明确更喜欢单身或低压力社交。

# 1. Internet 以前：陌生人伴侣搜索并不是网络发明的

## 1.1 1981：一则报纸征婚把熟人之外的候选人变成可联系对象

后来采访材料反复记录：1981 年 1 月 8 日，《市场报》刊登丁乃钧的征婚启事。此前他已经接受周围人的多次相亲介绍，但没有结果，于是写信给报纸，希望公开征婚。

来源：

- 《新中国公开征婚第一人：70个字震动世界》，《环球人物》相关采访，经新浪保存，2009-10-09：
  <https://news.sina.com.cn/c/sd/2009-10-09/133118795423_2.shtml>
- 《新中国首个征婚启事在媒体刊登始末》，2010-02-07，经新浪保存：
  <https://news.sina.com.cn/c/2010-02-07/023419644434.shtml>

### 证据等级

**C：事件发生近三十年后的采访 / 回顾。**

它可以可靠提示“报纸征婚作为熟人介绍之外的渠道”这一研究问题，但不应仅凭这些后来文章复原 1981 年原版页面、完整信件或全国影响规模。

### 为什么重要

报纸已经可以完成一种前互联网的 `stranger discovery`：

```text
个人写信给编辑部
→ 编辑决定刊登
→ 报纸把简短自述复制给大量陌生读者
→ 感兴趣者通过邮政联系
→ 后续书信 / 见面
```

也就是说，真正的历史谱系不是：

```text
熟人介绍
→ Internet 突然让陌生人相识
```

而是：

```text
熟人网络
+ 报刊 / 婚介 / 笔友栏目提供陌生人可见性
→ 网络继续降低搜索与回复成本
```

## 1.2 纸媒搜索的速度限制：候选人可见，但反馈是异步的

报纸征婚把候选集合扩到发行范围，但它仍受：

- 出版周期；
- 版面；
- 编辑筛选；
- 邮政延迟；
- 地址隐私代理方式；
- 交通与见面成本

约束。

因此前互联网伴侣搜索已经能跨地域，但其状态更新速度很慢：一个人是否已有对象、是否还在回复、条件是否改变，很难实时同步。

可以把这一阶段理解为：

> **wide publication + slow state refresh**

# 2. 2002：从报纸栏目的固定格式，到网页里的长自述

2002 年一篇同期评论做了一个非常小、但方法上很有价值的比较：作者分别从北京、南京、广州三份报纸和一个名为“交友驿站”的网站各取 30 份征婚样本，比较其写法。

作者观察到：报纸广告更常按年龄、学历、经济状况、婚史等固定栏目压缩信息；网站样本由于较少受到版面限制，描述往往更长，出现更多对爱情、家庭生活和个人感受的叙述。作者同时指出，其网站样本中的征婚者高度年轻化，认为这与当时上网条件有关。

来源：

- 自由亚洲电台特约评论《征婚广告里的中国人（一）》，2002-08-30：
  <https://www.rfa.org/mandarin/pinglun/88525-20020830.html>

### 证据等级

**B：同期评论 + 非随机小样本。**

它不能用来估计全国征婚人口年龄结构，更不能把作者对地区“保守/开放”的价值判断当作统计结论。

但它可以支持一个窄而重要的媒介 claim：

> **web page space changed what could be written about the self.**

### 它改变了什么理解

“数字化个人资料”并不一定从一开始就让人更像数据库。

早期 Web 的低版面成本反而允许：

- 更长的自述；
- 叙事性经历；
- 对家庭和感情的主观想象。

后来专业婚恋网站把这些内容重新拆成结构化字段、测试和筛选条件。

因此旧网里同时存在两股相反方向：

```text
纸媒版面限制 ↓ → Web 自述变长
专业平台结构化 ↑ → 人又被拆成可比较字段
```

这不是简单的“互联网让人越来越数据化”。

# 3. 2006–2008：伴侣候选人开始真正成为数据库查询结果

2006 年《中国青年报》报道百合网新版时，已经明确把心理测评和智能匹配作为网站核心设计之一。

来源：

- 《网络创业再度走红 百合网打造新婚恋交友平台》，中国青年报，2006-01-24，经新浪保存：
  <https://tech.sina.com.cn/i/2006-01-24/1004828139.shtml>

到 2008 年，同期报道已经直接保存了普通用户的操作：一名用户在世纪佳缘搜索栏输入年龄、学历、月薪等标准，几秒后得到几十名符合条件的候选人；他把“自主搜索、随时登录、选择更多”视为自己经常使用网站的原因。

来源：

- 中国青年报 2008-03-03 稿件的同期转载：
  <https://www.dzwww.com/xinwen/guoneixinwen/200803/t20080303_3228860.htm>

### 证据等级

**B：同期新闻，其中包含同期第一人称使用描述。**

这个案例不能证明 2008 年青年普遍如此找对象，但它能直接证明：

> 对一部分当时的真实用户，伴侣搜索已经是一次字段查询，而不只是浏览分类广告。

### 新的日常动作

```text
想到“我想认识怎样的人”
→ 把要求翻译成字段
→ 搜索
→ 扫描结果
→ 打开个人资料
→ 决定是否联系
→ 过一会儿重新登录
```

这使“择偶标准”从模糊的家庭/个人语言，部分变成了可以执行的查询条件。

# 4. 2008 的“扩张型未来”：更多可探索的人，但不能用行业问卷代表所有青年

《2008 中国网民婚恋调查报告》相关页面称，有 154,386 份有效答卷，其中 45.5% 的调查参与者表示使用过婚恋网站为主的网络征婚方式。

来源：

- 中国互联网协会当前保存的报告页：
  <https://www.isc.org.cn/article/12735.html>
- CCTV 同期转载：
  <https://315.cctv.com/20080216/101787.shtml>

### 证据等级

**B：同期行业/协会发布材料。**

### 关键限制

这不是全国人口随机抽样。

材料自己说明调查混合线上与线下、实际参加答卷 225,343 人、有效 154,386 人；报告又与婚恋服务行业机构紧密相关。

因此：

> **survey respondent share ≠ population prevalence**

尤其不能把标题式的“网恋将成主流”直接当作历史事实。

### 但它仍然改变了什么？

它足以说明：到 2008 年，专业网络婚恋已经大到能够形成大规模行业调查和稳定的用户实践，不再只是少量技术爱好者的实验。

配合上面的同期个人搜索案例，可以更谨慎地写“扩张型未来”的一种行为形态：

> **未来伴侣也开始像工作、学校和住房一样，出现一个可以主动扩大搜索半径、反复探测更多选项的界面。**

这并不意味着当时的人更愿意结婚；它只说明“认识谁”这一步的候选空间被扩张了。

# 5. 2011–2012：平台开始把“真实性”做成制度接口

随着候选集合扩大，一个新的问题变得显著：

> 我看到的这个档案到底是谁？

2012 年初的同期报道记录，百合网开始推动后台实名：用户可以对平台完成真实身份认证，但前台仍显示昵称，以试图同时兼顾身份核验和公开隐私。

来源：

- 《百合网推行实名制 “搅局者”还是“变革者”》，第一财经日报，2012-02-03，经搜狐保存：
  <https://business.sohu.com/20120203/n333580998.shtml>
- 《婚恋网站交友“实名制” 专家称最应该也最适合》，中国妇女报，2012-01-18，经中新网保存：
  <https://www.chinanews.com.cn/sh/2012/01-18/3613977.shtml>

同年调查报道又发现，仅凭姓名、身份证号等做认证仍可能被冒用；行业内也公开争论“实名”到底能解决多少欺诈问题。

来源：

- 《婚恋网站“实名制”华而不实》，新闻晚报，2012-07-23，经新浪保存：
  <https://news.sina.com.cn/o/2012-07-23/125924827239.shtml>
- 《网络欺诈困扰相亲网站 中国最大婚恋网站“打假”》，中新社，2012-07-12：
  <https://www.chinanews.com.cn/cul/2012/07-12/4028373.shtml>

### 新的 verification ladder

以后不能只写：

```text
verified = true / false
```

而至少需要拆：

```text
self-asserted profile
→ phone bound
→ identity-name match
→ real-person / photo check
→ education / occupation check
→ marital-status check
→ income / property claims
```

这些层可能完全不同步。

因此：

> **real-name identity ≠ full-profile truth**

这也是为什么婚恋数据库既扩大搜索，又生产新的信任劳动。

# 6. 2015–2019：“拥堵型未来”可以表现为渠道很多，但线下转化仍然困难

2019 年《中国青年报》一组同期采访特别适合这一问题。

调查对象 1,972 名单身青年高度城市化：一线城市 33.0%，二线城市 48.5%，农村仅 0.3%。因此这里不能把比例外推成全国青年总体。

但其中的第一人称材料非常具体：

- 一名受访者曾在半个月里见 6 个相亲对象，来源包括家人、亲戚、单位同事和公园相亲角；
- 另一名受访者同时参加家里安排的相亲、校友联谊、婚恋平台和平台线下活动；
- 一名科研工作者因为工作忙，在空余时间按所在地和年龄筛选候选人；
- 一名腼腆受访者认为，网上主动联系后即使无回复，社交难堪感也更低；
- 一名受访者发现，自己真正会在线下见面的对象多数仍来自熟人介绍，平台认识的人常常只是加微信后偶尔聊天。

来源：

- 《78.8%受访单身青年在婚恋交友平台注册过》，中国青年报，2019-09-19：
  <https://zqb.cyol.com/html/2019-09/19/nw.D110000zgqnb_20190919_1-08.htm>

### 这组材料新增的不是“婚恋网站流行”

而是三个生活机制。

#### A. introduction stack

旧渠道没有死：

```text
家人 / 亲戚
+ 同事
+ 校友会
+ 相亲角
+ 平台
+ 微信
+ 平台线下活动
```

同一个人可以同时运行很多条“认识人”的路线。

#### B. rejection-cost compression

网上不回复的失败，比面对面拒绝更容易被当成一次低成本尝试。

这可能让人发起更多联系。

#### C. conversion bottleneck

平台把“认识一个人”变得便宜，却没有同比例地增加：

- 对方愿意回复的时间；
- 双方真正线下见面的时间；
- 地理可达性；
- 关系相处能力；
- 对长期生活的兼容性。

因此 2015–2019 的拥堵，不必理解成“没有选择”。

在婚恋领域，它甚至可能表现为：

> **搜索结果和渠道越来越多，但真正能够持续推进的一对一关系仍然是低吞吐量活动。**

# 7. 2020–2022：“偶发型未来”——关系基础设施在不能见面时承担业务连续性

2021 年《中国青年报》对 2,001 名 18–35 岁单身青年的调查中，62.4% 表示此前一年交友以线上为主；报道同时保存了几条同期生活记录：

- 一名医护工作者因疫情期间工作忙、线下活动少，通过公众号征友帖认识一名女生，主要在下班后线上交流；
- 一名事业单位员工被同事介绍多个相亲对象，但在不方便见面时主要通过微信长时间互动；
- 一名 90 后在居家办公期间通过团队竞技手游认识后来男友，最初关系建立在组队、聊天和视频之上。

来源：

- 《疫情下的“网恋” 74.0%受访单身青年每天要花1小时以上“云交友”》，中国青年报，2021-02-25：
  <https://zqb.cyol.com/html/2021-02/25/nw.D110000zgqnb_20210225_2-10.htm>

### 证据限制

这仍是媒体调查样本，不是全国单身青年普查；“每天线上交友一小时”等数字不能外推到所有人。

### 时代机制

疫情的历史新意不是“第一次有人在网上恋爱”。

更准确的是：

> **online relationship channels temporarily became continuity infrastructure when ordinary meeting routines were constrained.**

这和同期的远程办公、在线教育类似：已经存在的数字能力，因为现实场所突然不稳定而承担了更大的日常功能。

但关系仍然不是纯数字流程。

报道中的人仍然期待、尝试或最终发生线下见面。

因此：

> **online continuity ≠ permanent dematerialization of intimacy**

# 8. 2023–2025：“防守型未来”不能被简化成“更着急结婚”

2024 年《工人日报》的一组同期人物材料提供了非常好的反例。

其中一名使用者每天在通勤、午休、睡前分别登录多个婚恋平台查看推荐；另一名使用者进入职场后因为时间和精力有限，选择网络平台追求搜索效率，并不断修改自己的个人主页以提高匹配竞争力。平台会定时推送候选人，用户按年龄、学历、工作等迅速做判断。

报道同时指出：得到前所未有的选择，并没有让建立亲密关系自动变容易。

来源：

- 《5个年轻人的互联网相亲简史》，工人日报，2024-10-16，经中新网保存：
  <https://www.chinanews.com.cn/sh/2024/10-16/10302217.shtml>

这组材料适合增加一个新的时间资源概念：

## relationship search workload：关系搜索劳动

当伴侣搜索成为高频平台动作，一个人一天的一部分时间可能被切成：

```text
看推荐
→ 快速筛选
→ 修改主页
→ 回复消息
→ 加微信
→ 安排见面
→ 见面后复盘
→ 再次打开推荐
```

“有一个很大的候选池”本身也需要劳动。

### 2025：部分青年又在主动降低“条件盘问”的显著性

2025 年同期报道中的“轻相亲”案例显示，一些参与者偏好兴趣活动、线上配对后完成任务、再转线下，而不是把第一次见面完全做成条件核对。

来源：

- 《青年青睐“轻相亲” 73.9%受访者表示周围有人尝试过》，中国青年报，2025-03-31：
  <https://news.cyol.com/gb/articles/2025-03/31/content_wdbX9RURVJ.html>

这不能证明全国青年“反感传统相亲”，调查样本也不是全国人口样本。

但它构成一个重要反例：

> **more profile data does not imply that people always want more explicit filtering.**

一部分人反而希望通过共同活动、兴趣和较低目的性的场景，重新获得不容易在字段里看到的信息。

因此“防守型未来”在婚恋上至少存在多种互相矛盾的策略：

- 更高效筛选，减少试错；
- 更严格验证，降低被骗风险；
- 放慢目标性，避免过强压力；
- 接受单身或延迟进入关系；
- 同时保留多种线上/线下渠道。

不能写成单一“结婚焦虑上升”的故事。

# 9. 海外对照：Minitel 说明“普通人数字找对象”甚至早于大众 Web

1995 年 D-Lib Magazine 对法国 Minitel 的同期综述记录：

- 法国当时约有 700 万台 Minitel；
- 约五分之一家庭可以直接使用，邮局和许多工作场所也提供接入；
- 系统提供超过 26,000 项在线服务；
- 服务类型明确包括 computer dating、home banking、shopping、政府服务和图书馆目录；
- 终端从 1982 年开始随普通电话服务推广。

来源：

- Jack Kessler, “Digital Life Outside of Internet — Minitel,” *D-Lib Magazine*, December 1995：
  <https://www.dlib.org/dlib/december95/12kessler.html>

### 证据等级

**A/B：1995 年同期专业刊物对当时系统的描述。**

它不能单独告诉我们某一个法国普通人的完整恋爱生命史，却足够打破一个常见后见之明：

> **networked partner search is not inherently a World Wide Web phenomenon.**

网络式陌生人交往、商业约会和家庭终端的组合，在法国 Minitel 体系中已经有大规模公共接入条件。

### 中国与海外共同点

共同变化包括：

- 候选人从熟人网络扩展到网络中的陌生人；
- 自我介绍成为远程可读信息；
- 搜索 / 分类降低发现成本；
- 数字通信降低第一次接触成本；
- 信任、隐私和欺诈成为新的平台问题。

### 不能抹掉的制度差异

中国材料还必须单独研究：

- 家庭和亲属介绍的持续作用；
- 单位 / 校友会 / 工会等组织性渠道；
- 婚介市场监管；
- 婚恋网站的身份认证方式；
- QQ / 微信等通用 IM 作为关系从网站退出后的主要通道；
- 房屋、城市、工作与家庭脚本对关系可执行性的具体约束。

不能把法国 Minitel 或美国 online dating 的模型直接套成中国历史。

# 10. 平台把“社会时钟”变成可执行任务，但不产生人的愿望

婚恋平台与人生脚本之间最容易出现因果过度。

### 可以说

- 婚恋平台让一个被催婚的人可以立即注册、筛选和联系；
- 平台把年龄、地区、教育、职业等条件变成可执行过滤器；
- 推荐机制让“今天还可以再看一批人”成为持续动作；
- 身份认证把一部分信任判断制度化。

### 不能说

- 平台导致青年更想结婚；
- 使用平台的人都认同标准婚姻脚本；
- 候选变多必然降低焦虑；
- 平台匹配成功就意味着关系稳定；
- 一个时期出现更多婚恋服务，就能证明当时“婚恋观更保守/开放”。

更稳妥的模型是：

```text
social clock / family expectations / own desire
+
work schedule / city / housing / mobility
+
search infrastructure
+
communication infrastructure
+
trust / verification
+
mutual attention
+
offline meeting capacity
=
relationship path that may or may not execute
```

# 11. 反例：搜索半径扩大以后，旧渠道和低技术渠道仍然可能更有效

2019 年的同期案例已经提供了强反例：有人线上认识很多人，却真正见面的相亲对象仍以熟人介绍为主。

因此不能写：

> Internet replaced matchmakers.

更准确的是：

> Internet increased the number and type of matching routes, but routes had different conversion rates and different trust costs.

类似地，2025 年“轻相亲”把活动重新做成读书、运动、旅行、游戏和线下社群，并不代表互联网退场；很多活动仍由公众号、小程序、线上报名和匹配组织。

这是一种 **digital coordination + embodied evaluation**：

网络负责把陌生人找来，身体共在负责判断“这个人相处起来到底是什么样”。

# 12. 历史可见性：正式婚姻比“差一点成为关系的人”更容易留下档案

传统档案特别容易保存：

- 结婚登记；
- 户籍 / 家庭关系；
- 婚礼照片；
- 公开婚讯；
- 最后写进传记的配偶。

却很难保存：

- 看过但没点开的档案；
- 发出却没有回复的消息；
- 聊了三天后消失的人；
- 加了 QQ / 微信但没有见面的人；
- 见一次后彼此决定不继续的人；
- 曾认真考虑过、后来撤回的关系路线。

因此又出现一种与 `route attrition` 类似的偏差：

## relationship-possibility survival gap：关系可能性存续缺口

> **final spouse record ≠ historical partner-option set**

一个人的正式生命史只写下“后来和谁结婚”，不等于那几年只存在过这一条亲密关系未来。

数字平台理论上产生了大量中间状态，却又因为登录、隐私、删除、动态推荐和站外迁移而很难进入公开档案。

这正是与 `old-web-archaeology` 的交叉点。

# 15. 后见之明风险

## 风险 A：把 1981 写成“传统中国第一次允许自主婚恋”

不成立。

一则著名公开征婚只能证明一种公开媒介动作及其争议，不能替代更复杂的婚姻、恋爱和介绍史。

## 风险 B：把 2008 写成“互联网已经成为所有人的主要择偶方式”

不成立。

当时 Internet 的人口分布本身高度不均；行业/在线调查又有强烈自选择。

## 风险 C：把字段筛选写成“理性婚恋”或“功利婚恋”

不成立。

字段化首先是数据库的技术需求和平台交互形式；人完全可以用字段寻找感情，也可以在线下条件明确的相亲中寻找感情。

## 风险 D：把实名制写成“真实身份问题被解决”

不成立。

身份、照片、学历、职业、收入、婚史和意图是不同 claim。

## 风险 E：把 2020–2022 线上交友写成永久数字化

不成立。

疫情材料恰恰说明线上关系经常仍把线下见面作为重要后续。

## 风险 F：把 2023–2025 写成统一的“婚恋降级/恐婚”

不成立。

同期材料同时存在主动找、低压力找、被家庭催、接受单身、追求高效率、厌倦高效率等互相矛盾的路径。

# 17. 本轮改变了我们对“人怎么活着”的哪一点理解

过去可以把普通人的伴侣关系写成一句：

> “他后来和某某结婚。”

但这句话几乎删除了关系形成之前的大部分真实生活。

一个更接近实际的生命历程可能是：

```text
周围人介绍过几次
→ 在报纸 / BBS / 网站 / App 看过很多人
→ 主动联系过一些
→ 大量没有回复
→ 少数转到电话 / QQ / 微信
→ 更少的人真正见面
→ 有人见一次就结束
→ 有人相处几个月
→ 某一条成为长期关系
→ 也可能最终没有进入婚姻
```

互联网最确定的改变之一，不是“让人找到了真爱”，而是：

> **它让一个普通人在有限时间里能够发现、筛选和尝试联系的陌生人显著增多，并把这种搜索的一部分变成可重复的数据库操作。**

与此同时，真正的亲密关系仍要求互相注意、信任、身体共在、时间协调、地理可达、家庭协商和长期相处。

所以本专题最终增加的不是“互联网婚恋”这个类别，而是一条更一般的生命史原则：

> **observed spouse ≠ historical partner-option set; searchable people ≠ livable relationships.**

这也是为什么普通人最后只有一个婚姻状态，却可能在生命中真实走过很多条没有进入正式记录的亲密关系未来。
