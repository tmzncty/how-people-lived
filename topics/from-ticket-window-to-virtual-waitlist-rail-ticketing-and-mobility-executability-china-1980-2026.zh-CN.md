# 从售票窗口到虚拟候补：铁路票权、排队迁移与出行可执行性（中国，1980–2026）

## 研究问题

铁路已经修到某座城市、时刻表上有一趟车，并不等于一个普通人就能在自己需要的日期真正坐上它。

这一专题追踪一个容易被交通史和迁移史同时压扁的状态：

> **一个人想去某地以后，怎样取得一份足以让这次移动真正发生的有限乘车权？**

这里把它称为 **mobility executability / 出行可执行性**。

它不同于：

- 线路是否存在；
- 列车是否开行；
- 城市是否可到达；
- 车次是否可以查询；
- 旅客是否有钱支付；
- 最后是否真正出发。

仓库已有：

- 2012 网络购票与容量竞争；

1. **1990s–2008：公众 Web 购票以前，计算机联网怎样先进入窗口后台，而普通人仍用身体和时间取得票权；**

3. **2019–2026：候补怎样把抢票从主动刷新改成委托等待，并进一步把多个可接受行程编码成组合；**

## 1. 先拆开“铁路可达”和“我能走”

至少区分：

1. **physical capacity**：现实列车有多少运输能力；
2. **inventory allocation**：其中多少票额在某时点、区间、渠道可售；
3. **inventory visibility**：窗口/电话/网页显示什么；
4. **request opportunity**：旅客有没有排到提交请求的机会；
5. **seat entitlement**：是否真正取得有效乘车权；
6. **travel credential**：纸票、身份证或电子记录能否用于进站；
7. **actual boarding**：最终有没有上车。

因此：

> `地图上通铁路 ≠ 这天有车 ≠ 这个渠道有票 ≠ 我看见有票 ≠ 票分给我 ≠ 我能进站 ≠ 我真的走了`。

本稿的新研究单位是 **seat entitlement / 座席取得权**。

## 2. 1996–1999：家庭还没有网上买票，窗口背后已经先数字化

### 2.1 1996：目标是“一窗能卖更多方向”，不是让旅客在家下单

1996 年 12 月《人民日报》同期报道铁道部加快计算机售票网络建设，计划在两年内实现全国联网，使旅客能在一个购票窗口购买不同方向、不同车次的车票。北京站、北京西站等当时已经使用计算机售票系统和软纸票。

来源：

- 《铁路部门加紧建设计算机售票网络 两年内将实现全国联网》，人民日报，1996-12-20（当前为报纸数字化副本）：https://cn.govopendata.com/renminribao/1996/12/20/5/

证据等级：

- **B-high / contemporaneous newspaper reproduction**。正文为同期新华社/人民日报内容，但当前载体不是官方原版扫描。

### 2.2 地方部署不是一次完成

黑龙江数字方志记录：

- 1996 年哈尔滨、哈尔滨东、滨江、香坊 4 站窗口开始计算机售票；
- 1997 年扩到 36 个车站、180 个窗口；
- 1998 年 31 个较大站实行计算机联网售票，占当地铁路局车票发售量 80% 以上。

来源：

- 黑龙江史志网数字方志：https://www.hljszw.org.cn/home/book/info/get_id/402711.html

证据等级：

- **A/B-high institutional retrospective compilation**。

### 2.3 1999 全国联网也不等于“普通家庭已经互联网购票”

新华社后来引述铁路客票系统建设者称，1999 年客票系统 3.0 投用，实现全国联网售票。

来源：

- 新华网《春运40年：从一票难求到“互联网+”出行》，2018-02-01：https://www.xinhuanet.com/politics/2018-02/01/c_1122350190.htm

证据等级：

- **C-high / institutional retrospective**。

### 新机制：**backend digitization before household access / 家庭接入以前的后台数字化**

这时真正变化的是：

```text
旅客
→ 仍然去车站/代售点
→ 窗口工作人员操作计算机
→ 计算机连接区域/全国客票系统
```

不是：

```text
旅客家中电脑 → 全国铁路系统
```

所以中国铁路数字化必须继续区分：

- 站内计算机售票；
- 区域联网；
- 全国联网；
- 电话订票；
- 地方公众 Web 试验；
- 12306 全国互联网售票；
- 手机独立购票；
- 电子客票/身份证闸机。

这些是不同的 clocks。

## 3. 2001：计算机联网扩大售票半径，却没有消灭稀缺

2001 年《中国青年》春运现场调查已经记录珠三角多地“电脑联网售票处”；工作人员会一早尝试通过联网系统取得票额，但热门日期仍可能长期无票。

来源：

- 《透视春运：究竟暴富了谁掠夺了谁》，中国青年，2001-02-22（新浪转载）：https://news.sina.com.cn/c/191970.html

证据等级：

- **B / contemporaneous field report**。
- 原文带有较强评论立场，本稿只采用“电脑联网售票点存在且仍可能没有热门票”这一可观察层，不照抄其宏观因果解释。

### 新机制：**access substitution without capacity creation / 渠道替代不创造运力**

联网可以让一个窗口卖得更远，却不能自动增加某趟热门列车的座位。

所以：

> **“信息化售票”与“票变得容易买”之间没有必然等号。**

这一点后来同样适用于 12306。

## 4. 2008：票权取得本身就是一项生活劳动

### 4.1 通宵排队：成功者付出的时间不会出现在火车运行时刻表里

2008 年 1 月 16 日央视《经济信息联播》报道上海站春运购票高峰。一名购票人直接说：

> “我过来排了一夜，买到了。”

同一报道里，一名重庆旅客问兰州 17 日或 18 日“哪一天都可以”，窗口回答没有票；继续问西安，也没有。

来源：

- 央视同期报道，新浪转载，2008-01-16：https://news.sina.com.cn/c/2008-01-16/212214758672.shtml

证据等级：

- **B-high / contemporaneous broadcast report + direct speech**。

这条材料保留下来的不是“春运很挤”这么一句话，而是一个人的实时 **itinerary elasticity / 行程弹性**：

```text
17日直达兰州
→ 18日也可以
→ 西安也可以
→ 仍无票
```

普通人面对稀缺时会主动放宽日期和目的地，不是僵硬地只找一个车次。

### 4.2 六小时窗口等待之后，返乡仍然可以被取消

2008 年 1 月 19 日南海网报道，海南大学大一学生“小李”与两名同乡在 1 月 11 日凌晨约 2 点赶到车站，排到上午 8 点，窗口却告知目标车票已售完。她接下来连续多日尝试，票越来越贵，最后考虑放弃回家。

来源：

- 南海网同期报道，新浪转载，2008-01-19：https://news.sina.com.cn/c/2008-01-19/165213290025s.shtml

证据等级：

- **B / contemporaneous first-person media interview**。

这个个案不能代表所有大学生，但能证明：

> **“春节回家”不是买不起火车票才会失败；即使愿意付标准票价、愿意凌晨去排队，也可能因为没有取得票权而取消。**

### 4.3 替代策略是一个组合，不只是“再排一次”

同月粤海铁路材料建议学生：

- 尝试分段购票；
- 先去广州再换乘；
- 使用学生团体票/专列；
- 无票时改其他交通方式。

来源：

- 南海网，2008-01-16：https://news.sina.com.cn/c/2008-01-16/080213268718s.shtml

### 新概念：**ticket-access labor / 票权取得劳动**

一次铁路旅行的真实时间成本应包含：

```text
获知预售规则
+ 到售票点
+ 排队
+ 重复尝试
+ 改日期/区间/交通方式
+ 最终旅行时间
```

而不是只看列车“运行 12 小时”。

这补进了普通生活时间账本里此前缺失的一项劳动。

## 5. 2011–2015：只做桥接，不重复既有 bookability 专题

仓库已有 `bookability-travelability-and-reversible-mobility-planning-china-2011-2022.zh-CN.md`，已经覆盖 2011–2015 的：

- 12306 实名注册；
- 网上锁席与支付；
- 纸票交换/身份证直刷；
- 账户 + 身份 + 浏览器 + 支付的 transaction stack；
- 系统高峰负载；
- App 与验证码。

本轮只增加一个跨仓连接：

### **queue relocation / 排队迁移**

2008：

```text
身体 → 火车站广场/售票厅 → 窗口
```

2011–2015：

```text
电脑/手机 → 查询 → 登录 → 提交 → 服务器并发/验证码/支付
```

旅客不一定再站在寒风里，但等待并没有消失，而是部分变成：

- 刷新；
- 服务器排队；
- 浏览器/证书问题；
- 支付超时；
- 验证码；
- 票额在提交前变化。

具体 2011–2015 状态证据不在本稿重复铺陈；本轮新建的 `old-web-archaeology/RAIL_TICKETING_12306_IDENTITY_PAYMENT_QUEUE_AND_ELECTRONIC_TICKET_STATE_GAPS_2000_2015.md` 专门处理这条 Web 状态链。

## 6. 2019：拥堵型未来的新变化不是“票不稀缺了”，而是人可以把等待交给系统

### 6.1 候补把主动刷新变成后台队列

2018 年 12 月 27 日起，12306 在部分春运紧张方向试点候补；2019 年 5 月 22 日扩展到全部旅客列车。

机制是：

```text
目标车次/席别无票
→ 用户提交需求
→ 预付款
→ 系统保存队列
→ 退票/新增票额出现
→ 自动兑现
→ 通知用户
```

来源：

- 12306《候补购票操作说明》，2019：https://www.12306.cn/mormhweb/zxdtzz/201905/t20190521_598004.html
- 新华社/人民网，2019-05-22：https://society.people.com.cn/n1/2019/0522/c1008-31097646.html

证据等级：

- **A**：12306 操作规则；
- **B-high**：新华社/人民网。

### 新机制：**inventory-linked delegated waiting / 与票额相连的委托等待**

这不是一般“提醒我有票”。系统本身持有：

- 等待顺序；
- 乘车日期；
- 车次/席别；
- 预付款；

并在库存变化时直接完成兑现。

于是：

```text
过去：人持续守着库存
现在：基础设施替人持续守着库存
```

这个机制与已有 `queues-waiting...` 专题交叉，但在铁路里它直接决定一段现实移动能否成立。

### 6.2 主渠道已经在线化，但不能把“84%”写成人口比例

2018-12-23 至 2019-01-20，铁路各种渠道共售票约 3.83 亿张；同期报道引铁路数据称，12306 日均售票约 1110.2 万张，占总售票量 84.1%。

来源：

- 科技日报/人民网，2019-01-23：https://finance.people.com.cn/bank/n1/2019/0123/c1004-30586318.html
- 人民网，2019-01-21：https://society.people.com.cn/n1/2019/0121/c1008-30581139.html

证据等级：

- **B-high / contemporaneous official statistics reported by state media**。

严格限制：

- 这是票张渠道占比，不是“84.1% 的中国人都网上买票”；
- 一个账号可以为亲友买多张；
- 窗口、自动机、电话仍存在；
- 特殊证件、异常情况仍可能要求线下处理。

## 7. 2019 同时代人的未来：第三方“加速”与官方候补同时存在

2019 年春运同期报道中，大学生已经在官方候补、微信里的第三方“加速”链接、同学互相转发之间来回尝试。报道保留了两种相反经验：

- 有人通过官方候补买到票，因此不再需要反复查票；
- 也有人每天查看第三方“加速”状态、比较不同加速规则，却并不确定它是否真的增加成功率。

这说明拥堵型未来的注意力问题是：

> **不仅要争一个稀缺席位，还要判断哪个渠道的“更快”是真能力，哪个只是营销。**

因此把既有搜索/来源验证研究接进交通：

### **allocation-provenance work / 分配来源判断劳动**

旅客需要理解：

- 谁掌握真实库存；
- 谁只是替我自动提交；
- 谁提供候补队列；
- 谁只是显示一个漂亮的“加速等级”。

## 8. 2020–2022：本轮不重复“可成行性”专题，只保留一条必要的结构连接

既有 `bookability-travelability...` 已经详细讨论：

- 2020 免费退票与行程撤销；
- 2021 预售期压缩；
- 已买票但列车/政策变化导致行程仍可能失效；
- `booking confirmation ≠ travelability`。

本稿只保留一个与票权历史相关的转折：

### **ticket-right / paper-object decoupling / 票权—纸票脱耦**

2020 年 6 月，电子客票覆盖全国 2400 多个车站、官方预计覆盖 95% 以上铁路出行人群。可自动识读证件可以直接作为进出站凭据，行程信息提示不再是乘车凭证。

来源：

- 新华社/中国政府网，2020-06-21：https://app.www.gov.cn/govdata/gov/202006/21/459904/article.html

证据等级：

- **A/B-high institutional contemporaneous**。

长期结构因此从：

```text
我持有一张纸票
```

更多转成：

```text
后台存在有效运输合同记录
+ 我的身份凭证可被识别
+ 车站系统在线并接受
```

这不是“没有凭证”，而是乘车权载体从纸转向身份+数据库。

## 9. 2023：在线系统已经成为默认，但“余票”仍然不是一个静态事实

2023 年中秋国庆售票高峰，用户报告页面一边显示“余票充足”，一边出现“前方排队711人”。12306 客服解释，同一时点可能有超过余票数量的人同时提交，系统要按提交顺序处理。

来源：

- 每日经济新闻，2023-09-14：https://www.nbd.com.cn/articles/2023-09-14/3019795.html

证据等级：

- **B / contemporaneous media + customer-service explanation**。

### 新区分：**inventory visibility / allocation race gap / 票额显示—分配竞争缺口**

实时系统里：

```text
10:00:00 页面显示100张
10:00:01 150人同时提交
```

因此“有票”本身也是一个带时间戳的 UI observation，不是对未来几秒的保证。

这也是 old-web 仓票务状态模型必须单独建模的原因。

## 10. 2024：防守型未来把“哪一天都行”正式编码成机器可执行组合

2024 年 1 月 11 日，12306 升级候补：

- 每名旅客可提交的待兑现候补订单从 2 个增至 6 个；
- 每个订单最多 9 名乘车人；
- 从相邻 2 个乘车日期、最多 10 个组合，扩展到预售期内任意 3 个日期、累计最多 60 个“日期+车次”组合；
- 最晚兑现时间从开车前 2 小时延后到 20 分钟；
- 用户可选择接受新增列车，系统自动匹配。

来源：

- 新华社，2024-01-11：https://www.news.cn/politics/20240111/4171fcf3f18f4d0d96799bf093c7c083/c.html
- 人民日报，2024-01-12：https://paper.people.com.cn/rmrb/html/2024-01/12/nw.D110000renmrb_20240112_6-07.htm

证据等级：

- **A/B-high institutional contemporaneous**。

### 新概念：**travel-plan portfolio / 行程方案组合**

这和 2008 那个窗口对话形成非常强的 16 年对照：

2008：

> “17 号没有，18 号呢？兰州没有，西安呢？”

2024：

> 把多个日期、车次、席别以及“接受新增列车”一次提交给系统。

也就是说，原本靠人在窗口一项项放宽的 **itinerary elasticity / 行程弹性**，后来能够被数据库显式表达。

防守型未来的语法因此不是：

> “计划 A 一定会发生。”

而是：

> **“我先维护一个可接受结果集合，只要其中一条路兑现，我就能走。”**

## 11. 2025：分配过程越自动，普通人越会寻找“黑箱能不能被我影响”的解释

2025 年春运出现所谓“候补文学”：一些用户给 12306 微信公众号发送候补订单和返乡愿望，希望“求兑现”。一名深圳到邓州的受访者说，系统只显示约 35% 候补成功概率时自己“心里咯噔了一下”，看到社交媒体有人通过留言后成功，也去尝试。12306 回应，候补由系统自动按规则处理，留言无法人工干预兑现。

来源：

- 潮新闻/央视网，2025-01-16：https://news.cctv.com/2025/01/16/ARTIn1OBaYoyOiQzmVJgdx5m250116.shtml

证据等级：

- **B / contemporaneous first-person interview + official correction**。

### 新概念：**opaque-allocation folk theory / 不透明分配的民间解释**

物理窗口时代可以看见：

- 前面还有多少人；
- 售票员在做什么；
- 窗口说“没票”。

候补时代看到的是：

- 预估成功率；
- 等待状态；
- 后台什么时候有退票/增开并不可见。

于是人会自然寻找一种能把黑箱重新人格化、可解释化的办法。

它不是“技术落后”的证据，而是：

> **自动化基础设施把过程隐藏以后，普通人仍然需要一种关于“它为什么给我/不给我”的因果模型。**

## 12. 海外对照：法国 Minitel 说明远程火车预约早于 Web

### 12.1 1989：同一中央预约系统可以有窗口、旅行社、自动机和家庭终端多种前端

法国 1988–1989 年关于 TGV 订票的一份政府答复记录，预订可以通过：

- 车站窗口；
- 授权旅行社；
- 自动设备；
- Minitel；

完成，并说明各种来源最终进入同一个预约中心。

来源：

- 法国政府问答数字镜像：https://politique.pappers.fr/question/reservations-billets-sncf-tgv-QSN58433

证据等级：

- **B-high**：政府议会答复的公开数字镜像；如后续取得 Sénat 官方原文可升 A。

### 12.2 1990：SOCRATE 的设计明确包括 Minitel 接入

1990 年 7 月《Le Monde》同期报道 SNCF 启用 SOCRATE 新预约中心，称当时约处理每年 5000 万次 reservations，并预计 1995 年达到 1.3 亿；系统可从车站终端、旅行社、自动机以及 Minitel 接入。

来源：

- Le Monde, 1990-07-12：https://www.lemonde.fr/archives/article/1990/07/12/la-sncf-inaugure-un-nouveau-systeme-de-reservation_3991275_1819218.html

证据等级：

- **B-high / contemporaneous press**。

### 12.3 2002：Minitel 与 Web 长期并存

2002 年《Le Monde》仍记录大量法国用户通过 Minitel 查询银行、订火车票和购物；巴黎—波尔多单程预约在 `3615 SNCF` 和 Web 上都约需 3–4 分钟，而 Minitel 的优势之一是终端快速启动、不必等 PC 开机和拨号连接。

来源：

- Le Monde, 2002-09-08：https://www.lemonde.fr/archives/article/2002/09/08/le-net-face-au-minitel_4261196_1819218.html

### 比较结论

远程电子预约不是 WWW 发明的；“中央库存 + 多前端渠道”也不是中国特有。

中国案例更值得比较的是：

- 春运的巨大峰值；
- 全国实名制；
- 身份证与闸机；
- 超大规模实时网络售票；
- 候补将需求队列直接接入退票和增开票额。

因此“Internet 改变了什么”不能写成：

> “以前只能窗口，后来第一次能远程订票。”

更准确是：

> **远程预约早有前史；开放 Web、家庭互联网、移动端、数字身份和自动候补把它扩展成一个更普遍、持续、实时的个人行程基础设施。**

## 13. 四种未来：只保留本稿真正新增的对照

### 2005–2012：扩张型未来

- 2008 仍可能为一张返乡票通宵排队；
- 同时普通人已经主动尝试改日期、改目的地、分段走；
- 2011 后远程 bookability 开始迅速扩张。

核心感受：

> **“以后也许不必为了得到一个远方位置亲自去窗口耗一夜。”**

### 2015–2019：拥堵型未来

- 网络已经是主渠道；
- 稀缺仍在；
- 第三方抢票/加速与官方候补并存；
- 人要判断谁真正连接库存。

核心感受：

> **“入口都在线了，但所有人也一起挤进同一个入口。”**

### 2020–2022：偶发型未来

由既有 `bookability-travelability...` 详细覆盖：票已经买到也不保证未来行程仍有效；退改、预售期、列车状态都可能临时改变。

### 2023–2026：防守型未来

- 不再只赌一趟车；
- 候补维护多个日期/车次/席别；
- 甚至接受未来才新增的列车；
- 把“只要能走就行”的弹性提前写进系统。

核心感受：

> **“我不需要确信唯一计划会实现，但要尽量让自己保有至少一条可兑现的路。”**

## 14. 它改变了我们对“普通人怎么活”的哪一点理解

### 14.1 地图上的铁路不是生活中的铁路

交通史画一条线，生活史还要问：

- 票怎么买；
- 提前多久；
- 谁能在开售时到窗口/电脑前；
- 买不到以后有没有替代路线；
- 失败几次后会不会直接取消旅行。

### 14.2 家庭团聚是一个有票额约束的生活行为

“春节回家”不仅由家庭情感决定，还受到：

- 放假日期；
- 预售期；
- 运力；
- 可购渠道；
- 购票劳动；
- 替代路线成本。

因此同样想回家的人，现实结果可以完全不同。

### 14.3 数字化没有让稀缺消失，而是让人更早、更远程、更组合化地处理稀缺

变化可以概括成：

```text
身体守窗口
→ 设备守网页
→ 系统替人候补
→ 系统替人同时守多个可接受方案
```

这不是“排队消失”，而是 **waiting topology / 等待拓扑** 改变。

### 14.4 人生 optionality 可以被基础设施编码

2008 的“哪一天都行、别的站也行”是口头策略；

2024 的 60 个组合是机器可读策略。

因此 `optionality` 不只是价值观，也可以成为基础设施中的数据结构。

## 16. 反例与后见之明风险

### 不要写成“12306 让春运不再难买票”

它显著改变售票劳动，但高峰运力稀缺仍可能存在。

### 不要把 1999 全国联网售票写成家庭互联网购票

那首先是铁路内部/窗口端数字化。

### 不要把 2008 个案外推成所有旅客都排通宵

它证明的是路径存在与成本可能性。

### 不要把 2019 网络票张占比写成人口使用率

一个人可买多张，也可能多渠道使用。

### 不要把 2024 多方案候补写成人人都会选满 60 个组合

制度容量只证明能力存在。

### 不要把法国 Minitel 写成“法国普通家庭人人都用它订票”

它证明远程电子订票机制早于 Web，需要另找使用分布才能讨论普及。

### 不要把今天的稳定 UI 倒投回 2011

2011–2015 的浏览器、证书、支付、验证码细节由既有专题和 old-web companion 处理。

## 17. 已证实 / 高概率 / 仍不知道

### 已证实

- 1990s 中国铁路计算机联网售票先在窗口/后台扩张；
- 2008 同时代旅客真实投入通宵/多日购票劳动，且无票可改变返乡计划；
- 2019 官方候补把部分反复查询转成后台持续排队；
- 2024 候补可同时表达多日期、多车次、多席别和新增列车接受条件；
- 法国 Minitel 在 Web 以前已可作为 SNCF 远程预约前端。

### 高概率

- 中国长途铁路生活史中，票权取得劳动曾长期是“返乡/迁移总时间成本”里一个被低估的组成部分；
- 网络化主要改变稀缺资源的进入方式和等待方式，而非自动消除稀缺；
- 防守型未来越来越倾向把弹性提前编码为可接受结果集合。

### 仍不知道

- 1990s 不同地区普通人窗口/代售/电话的真实组合频率；
- 2000 前后地方网络售票试验到底有多少普通用户实际完成交易；
- 同一个普通人从 1990s 排队到 2010s 12306、再到 2020s 候补的完整长期经验；
- 不同年龄、网络条件和证件类型在候补时代的成功率差异；
- 多方案候补是否会显著改变人们实际选择的出发日期和到达站。

## 18. 下一份最高价值证据：ticket-access ledger

下一步不应再堆“12306 一年卖多少票”，而应追一名普通人的长期票务序列：

```text
第一次长途坐火车
→ 谁告诉她什么时候卖票
→ 哪个窗口/代售点
→ 排多久
→ 没票时改日期还是改路线
→ 第一次电话订票
→ 第一次在电脑上买票
→ 是自己的电脑/银行卡还是借来的
→ 是否仍去窗口换纸票
→ 第一次用手机买
→ 第一次身份核验卡住
→ 第一次官方候补
→ 今天会同时提交多少备选方案
→ 候补失败后改汽车/飞机、延期还是不走
```

这条 ledger 最终能回答：

> **一个时代真正给普通人的移动自由，不只取决于铁路开到了哪里，还取决于在她必须出发的那一天，有限的乘车权怎样被分到她手里。**

## 19. 本轮饱和判断

本稿在核对既有 `bookability-travelability...` 后主动删除了对 2011–2022 主体的重复铺写，只保留互补段。

本轮真正新增的是：

- **backend digitization before household access**；
- **ticket-access labor**；
- **seat entitlement as lived mobility constraint**；
- **itinerary elasticity 的 2008 同时代第一人称证据**；
- **inventory-linked delegated waiting**；
- **travel-plan portfolio**；
- **opaque-allocation folk theory**；
- **Minitel/SNCF 的前 Web 对照**。

因此仍然有新的生活路径/通信基础设施转折与跨国差异；“连续无实质新增”维持 **0**，不触发 closure。
