# 从“号码记在本子上”到“换手机联系人还在”：个人通讯录、社会记忆可携带性与关系数据保管（中国，约 1980s—2026）

> 本文研究的不是“电话什么时候普及”或“手机号为什么变成长期身份”本身，而是另一个普通生活问题：**一个人怎样保存“我认识谁、以后怎样再找到他”的可操作记忆；换设备、换单位、搬家、毕业和换工作以后，这份社会记忆能不能一起带走。**
>
> 与旧网考古的技术 companion：[`tmzncty/old-web-archaeology`](https://github.com/tmzncty/old-web-archaeology) 中的 `CONTACT_LIST_ADDRESS_BOOK_VCARD_SYNCML_WEB_SYNC_AND_SOCIAL_MEMORY_STATE_GAPS_1998_2015.md`。

## 1. 为什么“通讯录”值得进入生活史

普通人的社会关系并不只存在于头脑里。

要维持一段以后还能调用的关系，至少需要保存某种可寻址信息：住址、单位、固定电话、寻呼号、手机号、电子邮件、QQ 号，后来还可能有多个平台账号。

因此可以把个人通讯录看成一种 **portable social memory / 社会记忆可携带性基础设施**：

> 人离开原来的地点、设备和组织以后，过去认识的人仍然能够被重新找到。

这与“手机号可携带”不同。手机号专题研究的是**别人怎样找到我**；本专题研究的是**我怎样保存并带走一整组“以后还能找到别人”的地址**。

也与同学录、黄页不同。公开名录保存的是一个组织或平台愿意公开/共享的人群索引；个人通讯录保存的是某一个人的私人关系集合，里面常常同时混有家人、同学、客户、房东、老师、医生、同事、一次性业务联系人和多年没再联系的人。

### 本文使用的几个分析变量

- **social-memory portability / 社会记忆可携带性**：换设备、地点或账号以后，联系人集合是否仍能使用；
- **contact-custody labor / 联系人保管劳动**：抄写、录入、导出、备份、合并重复项、删除失效号码、处理同步冲突等劳动；
- **relationship addressability / 关系可寻址性**：过去认识的人是否仍有一个可调用的地址；
- **stale-contact drift / 联系信息陈旧漂移**：号码、单位、邮箱已经变化，但本地记录没有更新；
- **social-graph exposure / 社交图暴露**：通讯录从私人记忆工具变成 App 可读取、上传和计算的关系数据；
- **contact-permission blast radius / 通讯录授权故障半径**：一次“允许访问联系人”可能暴露的不是用户本人一条数据，而是一整组第三人的姓名、号码和关系线索；
- **social-memory custody / 社会记忆保管权**：用户能否知道这份联系人数据在哪里、导出、恢复、撤回或删除。

## 2. 前互联网时期：联系地址首先是“地方”与纸面记录

### 2.1 有电话，不等于每个人都有个人化的可移动联系地址

1980 年《华盛顿邮报》报道，北京重新出现可公开获得的电话号码簿；该号簿首先大量列出办公室、学校、医院、工厂和企业，而不是今天智能手机里“一人一条”的私人联系人图谱。

来源：

- *The Washington Post*, 1980-09-10, “Telephone Directory Published for Peking”: <https://www.washingtonpost.com/archive/national/1980/09/10/telephone-directory-published-for-peking/54342e84-83ad-4c06-ba50-9ddf695e089e/>

2008 年新浪科技回顾电信史时给出的数据是：1978 年全国电话普及率约 0.38%，1982 年北京出现首批投币式公用电话；在家庭电话普及前，公用电话是许多市民的重要日常入口。

来源：

- 新浪科技，2008-11-03，《80年代，电话走进生活》：<https://tech.sina.com.cn/t/2008-11-03/17222552910.shtml>

这两条证据不能直接证明某一个普通人具体怎样记朋友号码，但足以约束一个重要的基础条件：早期“找人”通常更依赖地点、单位、家庭、公用电话和纸面记录，不应倒着用后来“一人一手机号”的经验解释 1980 年代。

**D 级合理推断**：在这种环境中，个人的社会记忆更容易分散在记忆、纸质电话本/地址本、名片、组织名册和各种地点型电话号码里。这里仍需要更多 1980s—1990s 的普通家庭实物、日记或同时代生活材料来量化。

### 2.2 1990 年代末：社会记忆先变成“本地数字对象”，不必先上网

2001 年《南方日报》的 PDA 购买指南把“通讯录、计划”等个人信息管理明确列为 PDA 的基本用途；同年国内 PDA 市场已经存在商务通、名人、联想等多类产品。

来源：

- 南方网/《南方日报》，2001-07-12，《PDA全攻略：分类、购买指南》：<https://tech.sina.com.cn/h/n/75588.shtml>
- 《生活时报》，2000-10-20，《掌上电脑拉开价格战商务通产品全线降价》：<https://www.gmw.cn/01shsb/2000-10/20/GB/10%5E1502%5E0%5ESH7-2018.htm>

这说明一个非常重要的前 Web/早期 Web 中间层：

```text
纸本通讯录
→ 本地电脑/PDA里的数字通讯簿
→ 手机/SIM/终端本地通讯录
→ PC 与手机之间导入导出
→ 网络端保存和跨设备同步
```

**数字化先发生，联网同步后发生。** 不应把这整条链都简写成“云通讯录出现”。

## 3. 全球侧的技术前史：联系人先变成可交换、可同步的标准对象

### 3.1 vCard：把“一个人的联系信息”做成跨系统对象

IETF 在 1998 年发布 RFC 2426（vCard 3.0）。标准可以表达姓名、地址、多个电话号码、电子邮件、照片等字段，而且 RFC 自己就提醒：vCard 信息会过时，可用 `REV` 表示上次更新。

来源（A，原始标准）：

- RFC 2426, September 1998: <https://www.rfc-editor.org/info/rfc2426/>

这为生活史提供一个很好用的提醒：

> **contact file survives != person is still reachable at that address**

数字记录比纸更容易复制，并不等于它天然不会过期。

### 3.2 SyncML：问题从“能导出”进一步变成“不同设备怎样保持一致”

2000 年 Ericsson、IBM、Lotus、Motorola、Nokia、Palm、Psion、Starfish 等共同推动 SyncML，目标是让远端数据和 personal information 跨网络、平台和设备同步。

来源（A/B，组织同期公告）：

- SyncML Initiative, 2000-05-10: <https://www.globenewswire.com/fr/news-release/2000/05/10/1845116/0/en/SyncML-Initiative-Announces-Wide-Support-and-New-Aggressive-Development-Schedule.html>

这条海外前史说明：联系人跨设备迁移不是“中国云盘/超级 App”特有的问题，而是个人计算从“一个人长期守着一台机器”转向“一个人拥有多个终端”时出现的共同工程问题。

但标准存在不等于普通人已经使用。对中国普通生活必须继续看终端价格、手机能力、运营商服务、PC 可及性和实际用户操作材料。

## 4. 2005—2012：扩张型未来——“我可以换机器，但不用重新失去过去认识的人”

### 4.1 2008 年第一人称操作材料：换手机仍然是一项手工数据工程

2008 年 9 月，一名飞利浦 TM700 用户在 3533 手机世界留下同时代操作记录。他发现手机 PC 助手虽然能同步，却形成“闭环”，不能方便地把已有电话簿批量导入；于是转而使用中国移动“号簿管家”。文章描述该服务为基于 Web 的联系人管理系统：手机可以把本地电话簿同步到网络端，网络端又可以导出为电脑本地文件再导回。

来源（B，同时代用户式技术记录）：

- 3533 手机世界，2008-09-07，《给飞利浦TM700导入电话薄》：<https://www.3533.com/news/2008/9/7/85679.htm>

中国移动现存业务说明也把号簿管家描述为可通过 Web、WAP、短信、SyncML、人工等方式管理个人号码簿，并允许终端进行无线同步存储；手机丢失后，号码簿档案仍可在 Web 端找到。

来源（A/B，运营商现存说明，页面当前日期不清，故不用于单独确定首发时间）：

- 中国移动宁夏，“A+业务 / 号簿管家”：<https://www.nx.10086.cn/support/brand/gotone/vipclub/hyfw/110000004662.html>

这一组材料表明，2008 年的“换手机”不是今天意义上的自动迁移。一个人可能需要知道：旧手机能导出什么格式、PC 助手是否支持导入、网络地址簿能否做中转、同步方向是否正确。

这就是 **contact-custody labor**。

### 4.2 一个容易被忽略的生活分层：商务/技术用户先获得“联系人跟人走”

号簿管家、PDA、PC 助手等服务首先要求兼容终端、数据线/网络、一定技术能力或特定运营商服务。它们的存在证明可用路径已经出现，不等于 2008 年所有手机用户都进入同样的无摩擦同步生活。

因此应继续区分：

1. 手机里能存号码；
2. 手机可以与 PC 交换；
3. 运营商/网站提供远端号码簿；
4. 用户设备兼容；
5. 用户实际启用同步；
6. 换品牌/换系统仍能迁移；
7. 这种迁移成为默认预期。

### 4.3 2010—2011：从“备份电话簿”到“账号承载社会记忆”

2010 年 11 月，搜狐转载手机中国对 QQ 同步助手 PPC 版的同期报道：用户可以用 QQ 号登录，在 Symbian、iPhone、Android、Windows Mobile 等不同平台之间导入导出联系人，并备份短信、通话记录等。

来源（B，近同时代媒体）：

- 搜狐数码/手机中国，2010-11-17，《联系人同步必备 QQ同步助手PPC版发布》：<https://digi.it.sohu.com/20101117/n277693943.shtml>

2011 年 QQ 通讯录材料进一步把“云备份”“跨手机品牌同步”作为核心卖点；同年一份产品稿还明确给出 Web 端 `pim.qq.com`，用户可以从 PC 查看和管理联系人和重要短信。

来源：

- cnBeta，2011-07-14，《QQ通讯录安全版问世：“云备份”联系人永不丢失》：<https://www.cnbeta.com.tw/articles/soft/148779.htm>
- 电脑商情在线，2011-12-07，《S60V3 QQ通讯录3.1：云备份收藏夹永不丢失》：<https://www.cbinews.com/desktop/0RCMO1>

“永不丢失”是产品宣称，不能当事实。但产品结构本身已经足以证明一个重要变化：

```text
联系人属于手机
→ 联系人可被复制到网络
→ 联系人逐渐属于账号控制下的一份远端状态
```

因此“换手机”逐渐从重新录入关系网络，变成登录旧账号并取回关系网络。

## 5. 2015—2019：拥堵型未来——不怕丢了，但开始怕错、怕重复、怕被别人读走

### 5.1 2017—2019 第一人称：换机焦虑下降，同步错误仍然存在

腾讯 QQ 同步助手的 App Store 页面保存了多条同期用户评论：

- 2017-12-29，一名用户说经常换手机和设备“不怕了”，但也提到有时会出现部分联系人莫名被删除，并不确定是否为自己的误操作；
- 2018-08-08，一名用户说换机器时首先会在新机安装该软件，因为不再担心电话号码丢失；
- 2019-10-05，一名用户说自己多年使用，换手机、换号或误删时会依赖恢复，并会定期更新手机号资料。

来源（A/B，平台当前保存的同时代用户评论；只能证明这些用户的自述，不代表总体）：

- Apple App Store，QQ同步助手：<https://apps.apple.com/cn/app/id389481236>

这些评论特别适合纠正“云同步 = 问题消失”的想象。新的问题是：

- 是本机覆盖云端，还是云端覆盖本机？
- 同名联系人要不要合并？
- 一个号码换了主人以后，旧条目还应该存在吗？
- 一次误删会不会同步扩散？

于是社会记忆的风险从 **single-device loss** 转向 **synchronized-state error**。

### 5.2 2019 年的更大反转：私人通讯录变成平台可以索取的“关系图”

2019 年 5 月，App 专项治理工作组解释，Android 的 `READ_CONTACTS` 权限可使 App 读取手机通讯录，并公布 100 款常用 App 的权限情况。

来源（A，监管机构）：

- 中国网信网，2019-05-24，《百款常用App申请收集使用个人信息权限情况》：<https://www.cac.gov.cn/2019-05/24/c_1124538535.htm>

同年 8 月，新京报联合国家计算机病毒应急处理中心检测 109 款 APK，报道称 57 款（51.8%）包含超出其基本业务范围的读取联系人代码。这个样本不能外推成“所有 App”，但能证明通讯录权限已经成为移动互联网治理中的现实问题。

来源（B，媒体+机构检测）：

- 中新网/新京报，2019-08-20：《APP安装包暗藏玄机：超半数留索取用户通讯录“后门”》：<https://www.chinanews.com.cn/cj/2019/08-20/8931620.shtml>

### 5.3 2019 年第一人称反例：“我的通讯录”其实同时包含别人的隐私

2019 年 1 月，《国际金融报》/人民网记录了吴娜（化名）的同时代经历：一个并不熟悉的朋友在现金贷平台逾期后，通讯录里的家人、朋友、同事、商业伙伴乃至只有一面之缘的人都接到催收电话；吴娜自己并未借款，却被卷入催收。

来源（B，同时代采访）：

- 人民网，2019-01-07，《爆通讯录“撸口子” 现金贷乱象何时休？》：<https://money.people.com.cn/n1/2019/0107/c42877-30506615.html>

2019 年 7 月，全国信息安全标准化技术委员会相关实践指南又明确提出：金融借贷 App 如需紧急联系人，应允许用户手动输入两个常用联系人，而不应强制读取整个通讯录。

来源：

- 人民网，2019-07-02，《想贷款就要交出通讯录》：<https://money.people.com.cn/n1/2019/0702/c42877-31207363.html>

这改变了我们对“个人数据”的直觉：

> **个人通讯录并不是只属于一个人的个人信息。它是一张由许多未必同意上传的第三人共同组成的关系图。**

因此通讯录权限的 `blast radius` 天然比“读取我的昵称”更大。

## 6. 2020—2022：偶发型未来——手机成为基础入口后，“不给整个通讯录”开始被制度化

2021 年四部门发布《常见类型移动互联网应用程序必要个人信息范围规定》，明确 39 类常见 App 的必要个人信息范围，并规定运营者不得因为用户拒绝提供非必要信息而拒绝其使用基本功能。

来源（A，官方）：

- 中国网信网，2021-03-22：<https://www.cac.gov.cn/2021-03/22/c_1617990996835955.htm>

这里真正重要的不是某一条权限清单，而是治理逻辑发生变化：

```text
早期：为了方便，最好把全部联系人交给同步/社交工具
后来：App 能读联系人，所以用户只能在“全给 / 不给”之间权衡
进一步：基本功能不应天然以获得整本通讯录为前提
```

在疫情和移动服务进一步成为工作、办事、出行基础设施的时期，退出 App 本身的成本上升，因此“非必要权限能否拒绝”比纯粹自愿安装工具时代更重要。

这里仍需要更多 2020—2022 的普通用户日记/论坛材料，来区分法规出台与普通用户实际感知之间的距离。

## 7. 2023—2026：防守型未来——从“备份整本通讯录”转向“只给这一个联系人”

### 7.1 海外防守机制：权限粒度开始从整个通讯录缩小到联系人子集

Apple 在 2024 年 WWDC 介绍 iOS 18 的 Contacts Limited Access：用户不再只有“整个通讯录全给 / 完全不给”两种选择，而可以只允许某个 App 访问选定联系人，并可后续增加或修改。

来源（A，平台官方开发文档）：

- Apple Developer, WWDC24, “Meet the Contact Access Button”: <https://developer.apple.com/videos/play/wwdc2024/10121/>
- Apple Support, “Control access to your contacts on iPhone”: <https://support.apple.com/guide/iphone/control-access-to-contacts-iph9536aa9a5/ios>

这说明一个跨国共同方向：

> 早期个人信息管理追求“所有联系人在所有设备都一致”；成熟后的隐私设计又开始追求“一个 App 只应该看它此刻真正需要的那几个联系人”。

同步的目标是扩大可达性，隐私防守的目标则是重新缩小可见面。

### 7.2 中国用户仍然在同时处理“怕丢”与“怕交出去”

当前官方 QQ 同步助手仍把云端备份、换机恢复、自动备份、误删找回等作为核心功能；App Store 的开发者隐私披露显示联系人仍是其可能处理的数据类型。该披露是开发者自报，Apple 明确说明未经其独立验证，因此这里只用于说明当前产品的数据关系，不用于证明具体后台行为。

来源：

- Apple App Store，QQ同步助手：<https://apps.apple.com/cn/app/id389481236>

与此同时，2025 年 App Store 上若干名称/图标相近的非腾讯“同步助手”应用出现用户投诉，用户担心自己误把通讯录授权给并非预期的应用。此类评论只是**同时代用户指控/风险感知**，不能据此断定对应 App 实际实施了盗取；但它们说明防守型未来里一个新的普通生活问题已经成形：

> 过去只要会备份就够了；现在还必须先判断“我究竟把整本社会记忆交给了谁”。

因此 2023—2026 的“防守”不意味着普通人不再依赖云同步，而是**在继续依赖迁移便利的同时，开始要求更细授权、更清楚的数据保管主体、更好的导出/删除能力和更小的错误半径。**

## 8. 四种“未来”的比较

| 阶段 | 普通人的核心愿望 | 通讯录技术提供的未来 | 新出现的代价 |
|---|---|---|---|
| 2005—2012 扩张型 | 换手机/丢手机以后别失去所有联系人 | Web 号簿、账号备份、跨平台同步 | 导入导出、兼容性、同步方向等维护劳动 |
| 2015—2019 拥堵型 | 多设备、多 App 里联系人都可用 | 自动云同步、去重、恢复 | 状态冲突；一处误操作同步扩散；通讯录成为平台关系图 |
| 2020—2022 偶发型 | 手机服务不可避免时仍能拒绝不必要权限 | 法规开始把“最小必要”写入 App 数据关系 | 规则与真实实现之间仍有落差 |
| 2023—2026 防守型 | 既不要丢联系人，也不要整本交给每个 App | 更细粒度授权、恢复/导出/删除、平台身份辨别 | 保管权、产品真伪、云端残留和第三人隐私成为新家务 |

这张表是机制比较，不是总体情绪测量。要判断每一时期有多少人真正这样感受，仍需要更系统的调查、论坛样本和生命周期访谈。

## 9. 它怎样改变人生路径，而不仅是“换机方便”

### 9.1 就业与非正规劳动

销售、自由职业、个体经营、临时项目型工作者的机会常常散落在大量弱联系里。联系人不必每天使用，却可能在几年后成为下一份订单、下一份工作或一个求助入口。

因此通讯录备份保护的不只是号码，而是一部分 **weak-tie option value / 弱关系选择权**。

这仍需行业访谈和具体职业材料进一步量化，不能把销售人员的经验外推给所有人。

### 9.2 迁移

一个人毕业、跨城就业或频繁搬家以后，若联系人集合可以跟着设备/账号走，迁移就不必同时意味着社会关系“重置”。

这与手机号可携带互为镜像：

- 手机号长期不变：旧社会能继续找到你；
- 通讯录长期可迁移：你还能继续找到旧社会。

### 9.3 长期中断与重新进入

育儿、照护、生病、失业、转行或几年不在某个行业以后，一个仍然可用的旧联系人集合可以降低重新进入成本。

但联系人仍存在不等于关系仍存在：

`contact survives != tie remains strong != other person is willing/able to help`

这条边界尤其重要，避免把“有号码”浪漫化成“有社会资本”。

### 9.4 社交关系的历史可见性

纸质私人通讯录很少被公开保存；手机联系人数据库、云端通讯录又通常在登录墙之后；即使旧 Web 保存了“导入”“同步”“找回”的公开帮助页，也几乎不会保存真实联系人行。

因此历史学家很容易看到：

- 产品说可以保存 5000 个联系人；
- 一个 Web 地址簿有哪些按钮；
- 某 App 请求 `READ_CONTACTS`；

却很难看到普通人真正保存的那 80、300 或 1500 个关系到底是谁、多久没更新、哪些在某次换机时消失。

这里必须把缺失本身当成结构性事实，而不是为了完整性去重新暴露真实普通人的私人关系图。

## 11. 反例与后见之明风险

1. **不要写成“云通讯录出现以后再也不会丢联系人”。** 同步错误、账号丢失、平台退出、错误覆盖、号码失效仍存在。
2. **不要把“联系人还在”写成“关系还在”。** 数字地址和社会关系强度不是同一个变量。
3. **不要把读取通讯录等同于已上传整个通讯录。** 权限、代码存在、实际读取、上传、长期保存必须分别证明。
4. **不要把一款 App 的用户评论外推成总体。** App Store 评论只能证明这些用户的同期经验。
5. **不要把 1998 vCard / 2000 SyncML 写成中国普通家庭已经同步联系人。** 它们是全球技术前史。
6. **不要把通讯录只当用户自己的隐私。** 它也包含大量第三人的联系信息。
7. **不要把更细权限自动写成隐私问题已解决。** 用户仍要理解主体、授权目的、云端保留和导出删除路径。

## 12. 本轮新增了什么理解

过去研究迁移时，我们常问：

> 人搬到另一座城市以后，旧朋友还能不能找到他？

这轮补上了另一半：

> 他还能不能找到那些旧朋友？

一个写在纸本上的旧号码簿、一个 SIM 卡、一台 PDA、一份 `.vcf`、一个运营商 Web 号簿、一个 QQ 同步账号，看起来只是不同年代的工具，实际都在解决同一件生命历程问题：**把过去建立的社会可达性带进下一段生活。**

但当这份社会记忆从私人本子变成可被 App 一次读取的数据库，它也同时发生了性质变化：以前丢失通讯录主要伤害“我以后找不到别人”；后来错误授权或泄露却可能伤害“通讯录里那些根本没有参与授权的人”。

于是联系人同步的成熟不能只看恢复率和换机速度，还要看三件事能否同时成立：

1. **我换设备以后仍能找回过去；**
2. **我能知道并控制谁替我保管这份过去；**
3. **我保存别人，是为了以后联系他们，而不是自动获得把整张关系图交给第三方的权利。**

## 13. 仍未解决

- 1980s—1990s 中国普通家庭纸质地址本/电话本的实际持有率、更新习惯与代际差异；
- 早期 GSM 手机中 SIM 与机身电话簿容量、中文姓名字段和换机迁移的具体普通用户经验；
- 号簿管家 2005—2010 的精确上线范围、地区差异、资费与活跃使用规模；
- `pim.qq.com` 2009—2012 的合格历史 capture、页面字段、编码、登录/导入/导出事务；
- 同一联系人在号码更换、二次放号后发生 stale-contact drift 的普通用户处理方式；
- 联系人云同步对跨城就业、销售职业和长期中断后再进入的实际效应；
- 2023—2026 中国移动操作系统/厂商对“部分联系人授权”的具体普及情况与用户接受度。

初稿由 AI 辅助整理；事实性结论应继续按仓库方法以可定位来源复核。
