## 0. 为什么这是一份增量包，而不是新建“地图史”

本轮开工时重新读取了仓库当前索引、方法文档和近期提交。代码关键词查重最初没有命中地图专题，但 `topics/README.md` 已明确列有：

- `searchable-city-routefinding-local-search-and-navigation-china-1983-2026.zh-CN.md`

该文已经系统研究：

- 人工/纸质城市可读性；
- 1999—2000 中文在线地图；
- POI 与本地搜索；
- route externalization；
- 手机 GPS；
- 2019 地图找房与通勤；
- 2020 路线模型和现实状态分离；
- 2024—2025 双人通勤找房；
- MapQuest 海外对照。

因此本轮**不保留第二篇重复的“大地图史”**，只把能够实质改变既有结论的新证据作为增量包保存。

本轮新增的核心问题是：

> **当“陌生城市可以提前搜索”已经成为背景以后，地图什么时候开始不只表示空间，而开始表示“此刻还能不能这样行动”；当人越来越依赖它以后，导航故障、离线 fallback 和平台对移动行为的再利用又怎样进入普通生活？**

由此补入四个概念：

- **operational map / 运行态地图**：道路几何之外，还包含拥堵、人流、公交满载、封闭、开放、安全/服务状态等“今天能不能这样走”的信息；
- **navigation dependency / 导航依赖**：路线认知被长期外包后，定位、数据或客户端故障会产生比早期“少一个辅助工具”更大的生活冲击；
- **map-edge / 地图边缘空间**：主干道路高度可读，但园区、村庄、小区内部、医院/校园入口等仍可能数据稀疏；
- **movement exhaust / 移动轨迹排放**：导航、搜索、到店等行为在帮助用户行动的同时，也成为平台可再利用的数据对象。

## 1. 前互联网基线得到两条更早、可定位的新证据

已有主文从 1983 年北京 44 路“活地图”展开。本轮把前史再向前压实，但不把它扩大成纸地图史。

### 1.1 1979 年北京游览图：交通知识已经能被压缩进一件随身物

荷兰国立博物馆收藏一份 1979 年 3 月出版的北京游览图。馆藏 metadata 记录其由地图出版社出版、新华书店北京发行所发行，并包含公共交通、终点站/旅行社列表以及郊区公交和长途汽车线路图。

来源：

- Rijksmuseum, *Tourist map of Beijing*, 1979：<https://www.rijksmuseum.nl/nl/collectie/publicatie/Tourist-map-of-Beijing--12c88bf17d672791a79c08bdb0879e77>
- evidence: **A，实体出版物馆藏 metadata**

它只能证明这种物件存在及其内容形态，不能证明普通来京者的拥有率或实际使用率。

但它补强了主文的一个基线：

> **数字地图没有发明“把陌生城市装进随身媒介”；它后来改变的是查询、更新、定位和途中纠错的方式。**

### 1.2 1982 北京站“地名询问服务点”：真正的 resolver 可能是一名人类

北京日报 2025 年利用集团历史报刊数据库回溯到 1982-03-29 原报：北京站出站口曾设地名询问服务点，由熟悉地名的工作人员帮助外地旅客把旧地名、新地名与公交换乘对应起来。

来源：

- 北京日报客户端历史数据库整理，2025-02-27：<https://xinwen.bjd.com.cn/content/s67bfa0a8e4b068c68f104f2d.html>
- evidence: **B/C**，后来报社数据库整理，已定位原报日期；本轮未独立取得原版完整扫描

这条证据比“人会问路”更具体。它说明今天 geocoder/name resolver 解决的部分问题，以前可以由一个人完成：

```text
旅客说出旧称/俗称/模糊地名
→ 工作人员识别实际地点
→ 翻译成当时可执行的地址/站点
→ 给出公交换乘
```

所以 `geocoder` 不是凭空创造的新需求，而是把一部分既有的人类地名解析劳动数据库化。

## 2. 2008：新增一条真正同时代的“多地图交叉核验”与未来想象

2008-04-24，博客园用户 KymoWang 在当天的公开日志里回忆：最早使用 668map，后来常用 Mapbar 与 Mapabc；他认为二者公交更新不如 8684，并在当天查询北京酒仙桥时第一次发现 City8 的 360° 实景。最后还期待未来出现更真正的三维地图。

来源：

- <https://www.cnblogs.com/Kymo/archive/2008/04/24/1170077.html>
- evidence: **A，同时代公开第一人称；单个技术型用户，不代表一般网民**

这条材料没有推翻主文，反而把“扩张型未来”具体化成三个新点。

第一，**一个人当时可能不是“选一个地图”，而是在几个不完整数据库之间分工**：

```text
Mapbar/Mapabc：通用地图
8684：更关注公交更新
City8：实景补充
```

第二，2008 年实际使用者已经把 **data freshness / 数据新鲜度** 当成 route executability 的一部分。

第三，这名用户当时的未来想象仍然明显偏“再看见更多”：从 2D 查询走向 360°、再走向更完整的 3D 城市。这个未来想象是 2008 当时留下的，不是 2026 的怀旧投射。

因此主文里的扩张型未来可进一步写成：

> **不仅是“陌生地方也能去”，还是“城市本身似乎会被越来越完整地搬进屏幕”。**

## 3. 海外对照：2009 年真正的共同转折是 route document → live service

Google 官方地图博客在 2009-10-28 宣布 Android 2.0 上的 Google Maps Navigation。官方当时特意把它与此前“写成列表的 driving directions”区分：新系统使用 Internet-connected GPS，提供语音引导、自动重新规划、Google 搜索、较新的地图/商户数据和实时交通。

来源：

- Google Maps official blog, 2009-10-28：<https://maps.googleblog.com/2009/10/google-maps-navigation-comes-to-android.html>
- evidence: **A，厂商同期产品公告；能证明功能声明，不能证明普及率**

这条海外材料和中国 2011—2013 手机地图变化组合起来，说明更一般的互联网时代转折不是“某国发明导航”，而是：

```text
route plan as document
→ route plan as continuously recomputed service
```

Web 时代一个人通常在出发前得到答案；live navigation 第一次允许系统在“你已经偏航”以后仍继续工作。

## 4. 2018—2019：拥堵型未来新增的不是“更会找房”，而是地图基础设施的可信度与边缘覆盖

已有主文已经很好地证明 2019 年地图/地铁找房与通勤时间进入住房选择。本轮补的是另一条成熟期机制：**一旦路线计算成为背景，人开始关心“这份实时数据到底有多可信、城市哪些角落仍在地图之外”。**

### 4.1 2018：路线价格也是陌生城市可执行性的一部分

腾讯地图 App Store 保存一条 2018-07-18 的同期评论。用户自称“天然路痴”，认为地图让出行容易，但在陌生城市打车时，希望地图把不同路线和价格一起比较，因为自己不知道当地线路和价格。

来源：

- Apple App Store, Tencent Maps reviews：<https://apps.apple.com/cn/app/id481623196?platform=ipad&see-all=reviews>
- evidence: **A-ish，平台托管同期第一人称；身份/经历不能独立核验，不可外推总体**

它提醒我们：

> **route executability 还包含 cost legibility。**

“地图能算出路线”与“普通人敢在陌生城市选择这条路线”之间，可能还隔着费用是否可预期。

### 4.2 2018：成熟依赖以后，数据更新延迟会直接进入使用体验

同一 App Store 页面保存一条 2018-10-04 评论：用户认可语音识别和免手操作，却抱怨实时数据更新慢，并以某封堵路段和另一地图相比晚约一周反映为例。

来源同上。

这只是一个人的观察，不能推出平台全国更新速度。

但它保存了一个很明确的时代变化：

2005 的主要问题还可以是：

> “系统有没有这条路线？”

2018 的问题已经可能是：

> **“系统知不知道今天这条路已经不能走？”**

### 4.3 2019：地图成熟以后，差异转移到园区、村庄和小路

腾讯地图 App Store 保存 2019-08-22 的评论。用户比较百度与腾讯时说，大地方导航区别不大，但园区、村庄和小路覆盖存在差异，有些地方在另一张地图里仍然较空。

来源：

- Apple App Store, Tencent Maps reviews，同上
- evidence: **A-ish，同期第一人称；不可推成全国覆盖率**

这补出 **map-edge / 地图边缘空间**：

```text
城市主干道高度可读
!= 园区可读
!= 村庄可读
!= 小区内部可读
!= 医院/校园入口可读
```

因此“地图已经大众化”与“所有空间都同等可读”必须继续分开。

## 5. 2020—2022：主文的“路线模型会失效”还可以再推进一步——地图成为运行态基础设施

已有主文用 2020 年“地图显示封路、现场却开放”的记者核验，证明：

```text
地图路网可计算
!= 地图状态最新
!= 行政允许通行
!= 现场实际开放
```

本轮补到的是另一面：地图平台开始主动把**临时运行状态**塞回路线决策。

2020-03-10，经济日报/人民网采访北京市民“小范”。她描述自己出门前会查看目的地人流热力图、公交地铁满载率，再决定出行方式，并选择标注测温消毒的车辆。

来源：

- 经济日报/人民网，2020-03-10：<https://travel.people.com.cn/n1/2020/0310/c41570-31626149.html>
- evidence: **B + 同期受访者第一人称**

这里出现的不是“更精确地图”，而是 **operational map / 运行态地图**：

```text
道路在哪里
+ 现在有多少人
+ 公交现在多拥挤
+ 某种服务现在是否运行
+ 今天采用哪种方式风险/成本更低
```

同篇报道还引用平台自身搜索数据观察复工后的花店、人才市场等地点搜索变化。平台数据只能代表被平台观测到的用户行为，不能外推中国全体人口。

2020-04-08，人民网又使用高德交通数据描述武汉解除离汉通道管控后的早高峰交通恢复。

来源：

- 人民网，2020-04-08：<https://finance.people.com.cn/n1/2020/0408/c1004-31666127.html>
- evidence: **B，底层为平台 aggregate data**

这产生了新的历史可见性：

> **过去普通人“今天又开始上班/出门”的恢复主要留在日记、车票、单位记录里；移动平台以后，导航与通勤行为的聚合痕迹也能被拿来观察社会恢复。**

但仍应写成 `platform-observed mobility`，不能写成“所有人的移动”。

## 6. 2023—2026：防守型未来新增两条线——失败 fallback 与移动数据保管

### 6.1 2025 第一人称：导航故障在陌生道路上已经可能成为安全/连续性问题

高德地图 App Store 保存一条 2025-07-07 的评论。用户报告车机导航黑屏、GPS 信号丢失和高架附近误判偏航，并明确说在高速和陌生路段会带来安全风险。

来源：

- Apple App Store, Amap reviews：<https://apps.apple.com/cn/app/id461703208?platform=iphone&see-all=reviews>
- evidence: **A-ish，平台托管同期第一人称；具体故障未独立复现，不能外推故障率**

这补出了 **navigation dependency / 导航依赖**。

早期在线地图是一个“额外帮忙”的工具；当空间认知大量被持续导航接管以后，故障本身会成为新的生活风险。

因此成熟基础设施重新需要 fallback：

- 记住大方向；
- 保留关键地址/电话；
- 道路标识能够独立工作；
- 离线地图；
- 多源交叉核验；
- 必要时重新向人问路。

海外当前产品也出现同构的防守性能力：Apple Maps 公开说明支持下载离线地图并进行离线逐步导航。

来源：

- Apple Maps App Store 当前产品说明：<https://apps.apple.com/cn/app/id915056765>
- evidence: **A，当前产品能力；不能证明使用率**

所以防守型未来不是“回到纸地图”，而是：

> **在高度联网的系统中重新购买一点断网以后仍然能行动的能力。**

### 6.2 2026：地图开始直接产品化一个标准人生转场

2026-08-27，高德上线“大一新生开学指南”。同期报道与 App Store 活动说明称其覆盖 1300 多所高校，并把：

- 行李/证件清单；
- 报到时间；
- 到校公交/地铁/打车路线；
- 宿舍、教学楼、食堂、图书馆、医务室等校园地点；
- 城市探索；

放进同一个入口。

来源：

- 新浪科技，2026-08-27：<https://finance.sina.com.cn/tech/shenji/2026-08-27/doc-iniptnux9039006.shtml>
- 中关村在线，2026-08-27：<https://news.zol.com.cn/1238/12388489_all.html>
- 高德地图 App Store 当前活动说明：<https://apps.apple.com/cn/app/id461703208?platform=ipad>
- evidence: **A/B，当前产品说明 + 同期报道**

这并不说明 2026 新生都依赖高德，也不说明过去学校没有迎新、纸质指南和老生帮助。

真正的新机制是 **life-transition orchestration / 人生转场编排**：

```text
我要带什么材料
→ 什么时候到
→ 怎么从车站到学校
→ 从哪个校园入口进
→ 宿舍/食堂/医务室在哪里
→ 第一次怎样探索这座城市
```

一个“去外地上大学”的标准人生节点，开始被地图平台当成一整个可产品化的状态转换，而不只是一条路线。

### 6.3 2026：地图不只让城市可读，也让人的移动变得可读

高德地图当前 App Store 产品说明称，“扫街榜”会使用真实用户的导航、搜索、到店等行为数据，并结合其他信号形成本地商户榜单。

来源：

- 高德地图 App Store 当前产品说明，同上
- evidence: **A（厂商公开声明）；只能证明其宣称的数据利用逻辑，不能独立验证算法权重、效果或公平性**

这补出 **movement exhaust / 移动轨迹排放**：

```text
1979：地图告诉我别人画出的城市
2008：地图数据库告诉我某地在哪里
2018：很多运行数据帮助系统告诉我现在怎么走
2026：我自己的搜索/导航/到店行为又成为下一层空间推荐的输入
```

于是空间基础设施产生了一个明显反转：

> **当人越来越不需要认识路，路线系统开始越来越多地认识人的移动。**

这把地图史与仓库已有的账号、身份、隐私和历史可见性问题接了起来。

## 7. 本轮对四种未来模型的增量修正

| 时段 | 已有主文结论 | 本轮新增修正 |
|---|---|---|
| 2005–2012 扩张型 | 城市可提前搜索，手机 GPS 把路线带到途中 | 用户已经在多个地图数据库间交叉核验，并把未来想成更完整的实景/3D 城市 |
| 2015–2019 拥堵型 | 地图与房租、就业、通勤约束叠加 | “哪条路现在可信”、费用是否可预期、哪些小空间仍 map-edge 成为成熟依赖后的问题 |
| 2020–2022 偶发型 | route model 与现实状态可能突然分离 | 地图反过来吸收人流/满载/运行状态，成为 operational map；平台 mobility data 也成为社会状态代理指标 |
| 2023–2026 防守型 | 地图帮助保存可接受通勤/住房方案 | 还要处理离线 fallback、导航失效、移动数据保管；地图开始编排入学等 life transition |

这仍然不是“每个时代的人格”。同一年里，高度依赖导航的司机、从不使用智能手机的老人、乡村居民、网约车司机、第一次离家上学的新生和熟悉本地几十年的居民会生活在不同地图制度中。

## 8. 对重点矩阵的真正新增

| 维度 | 本轮新增机制 |
|---|---|
| 教育 | 地图开始把“去大学报到”从路线扩成证件、时间、校园内部和城市冷启动的一体化 transition interface |
| 就业 | 运行态地图降低陌生地点执行不确定；平台 search/navigation aggregate 还能观察人才市场等地点需求变化 |
| 住房 | 成熟阶段不只算通勤，还暴露 map-edge 与路线实时可信度 |
| 迁移 | `geographic cold-start cost` 继续下降，但高度导航依赖创造新的 failure mode |
| 照护 | 医院/院区/入口仍可能位于 map-edge；路线存在不等于正确入口可达 |
| 非正规劳动 | 对司机、骑手等，地图已从辅助工具接近核心工作基础设施，故障的代价更高 |
| 长期中断 | 离线/多源 fallback 决定一个长期不用地图或换设备的人能否重新行动 |
| 证件与记录 | 2026 入学指南把“证件要准备什么”与物理路线放进同一入口，制度接口与空间接口开始合流 |
| 通信/社交 | 问路并未消失；高度数据化后仍需要人类在 map-edge 补洞 |
| 信息获取 | 地图从静态几何变成运行状态与排序系统 |
| 未来预期 | 从“更多地方看得见”转向“关键时刻系统失效时我还有没有退路” |
| 线上/线下身份 | 搜索、导航、到店把线下移动转成账户/平台可观察事件 |
| 平台消失与记忆 | 未来需要研究收藏地点、轨迹、离线包和导出/删除边界 |

## 9. 反例与边界

### 9.1 地图不能把远距离变近

路线优化不消灭票价、油费、通勤时间、夜间班次、身体行动能力与城乡公共交通差异。

### 9.2 地图不能自动把“可到达”变成“可进入”

医院挂号、校门权限、单位门禁、办事材料、营业时间仍是独立状态。

### 9.3 问人没有消失

校园小门、院区、市场内部、临时施工、地方俗称等仍可能需要现场经验。更准确的变化是：

> **常规本地知识越来越数据库化，边缘与最新变化继续由人补洞。**

### 9.4 movement data 丰富不等于普通人的生活被完整记录

平台只看见：

- 使用该平台的人；
- 开启/产生相应事件的人；
- 被系统保留并纳入统计的数据。

因此 `platform-observed mobility != total ordinary mobility`。

## 10. 历史可见性与隐私

前互联网时代最难保存的是：

- 某人在哪个路口迷路；
- 问了谁；
- 为省钱换了哪条线；
- 谁在电话里一步步指路。

这些大量普通路线几乎天然不入档案。

移动平台时代反过来可能保存非常细的：

- 搜索；
- 起终点；
- 路线偏好；
- 实际轨迹；
- 到店；
- 收藏地点；
- 位置共享。

因此研究质量不能用“恢复了多少私人轨迹”衡量。

本仓应优先保留：

- 公开第一人称；
- 聚合数据；
- 产品字段/状态；
- 路线系统的执行边界；

而不是重新公开可识别个人的细粒度历史移动。

## 11. 尚未确定

1. `movement exhaust` 在不同平台上究竟保留多久、用户能否导出或删除，需要独立的数据保管研究，不能从产品说明推断。
2. 2018—2019 App Store 评论只证明个别用户真实提出这些问题；还缺更系统的用户调查来估计普遍程度。
3. map-edge 在乡村、工业园、医院、校园和城中村中的差异，需要用多时点地图数据或正式测绘研究量化。
4. 运行态地图在 2020—2022 之后哪些图层成为永久功能、哪些只属于危机临时层，需要产品版本史进一步拆分。
5. 导航依赖是否真的降低长期空间记忆能力是认知科学问题，本轮不作推断。
6. 2026 大一新生指南目前证明“产品化存在”，不能证明它改变了新生迁移结果或降低了辍学/迟到等结果。

## 12. 本轮真正改变了哪一点理解

已有主文已经回答了：

> **陌生城市怎样变得可以在到达前搜索和计算。**

本轮新增的是下一步：

> **当这件事成功到成为背景以后，地图开始承担“此刻城市还怎样运行”，并且开始把使用者自己的移动重新吸收进城市模型。**

这让普通人的空间生活出现了新的两面性。

一面是，初到陌生城市的人越来越可以**先行动，再在途中纠错**；甚至一个新生入学这样的标准人生转场，也开始由同一个地图入口帮助编排。

另一面是，当路线记忆长期外包给持续联网的基础设施以后，人需要重新考虑：

- 没网怎么办；
- GPS 错了怎么办；
- 地图没覆盖园区小路怎么办；
- 我走过的路线由谁保存；
- 我的导航和到店行为会不会又变成别人下一次看到的城市。

所以“数字地图让城市更可读”之后，新的历史问题已经变成：

> **城市越来越容易被我读懂时，我也越来越容易被城市的信息系统读懂。**
