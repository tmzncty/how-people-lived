# 1998–2002：从 BP 机到网络寻呼——“联系栈”、通道切换与移动可达性

> 核心问题：大众 Internet 到来时，人们是不是把 BP 机、固定电话等旧联系方式整齐地“换成”了 QQ / OICQ？还是在一段时间内同时携带多种联系方式，并在不同媒介之间接力完成一次联系？

## 结论先行

1998–2002 年更适合被理解成一个**混合通信生态**，而不是“寻呼时代结束、互联网时代开始”的单线替代。

至少要区分三种能力：

1. **可达（reachable）**：别人离开固定地点后仍能把“请联系我”送到他身上；
2. **可对话（conversationally connected）**：双方可以直接持续交换信息；
3. **可持续识别（persistently identifiable）**：别人以后还知道该通过哪个稳定地址找到“同一个你”。

传统单向 BP 机主要强化第一种能力；固定电话和公共电话承担回拨后的对话；Email、ICQ/OICQ 又逐渐增加跨终端的持续身份与在线交流。

所以：

> **mobile reachability came before always-on mobile conversation。**
>
> 一个人可以先变得“随时可被叫到”，很久以后才变得“随时可以直接对话”。

与此同时，早期 Internet 并没有立刻删除旧媒介。更常见的历史单位可能是：

> **contact stack（联系栈）**：同一个人同时拥有电话、BP 机、手机、Email、ICQ/OICQ 等若干入口，每个入口承担不同功能。

## 1. 1990 年代末：寻呼的社会分布明显早于 Internet

1999 年 3 月的 *South China Morning Post* 报道称，中国大陆自 1997 年起已成为世界最大的寻呼市场，当时约有 **6000 万**寻呼用户；报道同时指出移动电话正在逐步侵蚀这个市场。

来源：
https://www.scmp.com/article/276019/paging-firms-expected-show-further-growth

而 CERNET 保存的中国互联网发展记录引述 CNNIC 第三次调查：截至 **1998-12-31**，中国约有 **210 万 Internet 用户**、74.7 万台联网计算机；到 **1999-06-30**，Internet 用户约 400 万。

来源：
https://www.edu.cn/english/cernet/introduction/200603/t20060323_4285.shtml

这两个数字的日期、统计口径不同，不能做精确比例运算，但足以说明一个量级事实：

> **在 Internet 用户仍主要是少数城市、教育程度较高、需要电脑和接入条件的人群时，寻呼已经覆盖了大得多的社会人口。**

这意味着研究“互联网怎样进入普通生活”时，不能把它想成进入一个此前完全空白的通信世界。它进入的是一个已经有固定电话、公共电话、寻呼、手机、纸质通讯录和单位/家庭联系方式的生态。

### 证据边界

- 6000 万寻呼用户来自同期媒体引用行业预测/市场信息，不是人口普查；
- Internet 数字来自 CNNIC 统计体系，定义与寻呼订户不同；
- 这里仅用来判断社会分布的**数量级差异**，不计算“寻呼是互联网的多少倍”。

## 2. BP 机改变的是“人在哪里都能被叫到”，不是直接把电话装进口袋

单向寻呼的生活动作通常不是完整对话，而是：

```text
某人需要找你
→ 呼叫你的 BP 机
→ 你在移动状态中收到号码/短信息
→ 找固定电话、单位电话、家庭电话或公共电话
→ 回拨
→ 才开始真正的对话
```

因此 BP 机把一个重要变量从**地点**转向了**人**：

过去：

> 要找到某人，先要猜他在哪个电话旁边。

寻呼普及时：

> 可以先把“有人找你”送到人身上，再由他去寻找可通话的电话。

这是一种很独特的中间状态：

> **reachable ≠ conversationally connected**

它对迁移、外勤、销售、临时工作、约见、家庭联络都可能有意义，但具体人群分布仍需要按职业、收入、城市分别研究。

## 3. 同时代 OICQ 教程留下了一张非常清楚的“联系栈”

2000 年 4 月 14 日，《软件世界》在新浪科技发表《中文网络寻呼机--OICQ》。文章开头把当时通讯录里常见的联系方式并排列出：

- 电话；
- BP 机；
- 手机；
- E-mail；

然后说网络发展后，朋友名下还会再增加一行 ICQ。

同一篇文章把腾讯 Open ICQ / OICQ 描述为“中文界面的虚拟网络寻呼机”，并列出搜索在线用户、实时信息、语音交流和**无线寻呼**等功能。

来源：
https://tech.sina.com.cn/soft/2000-04-14/133.html

这是一个特别重要的近同时代生活证据，因为它不是后来把媒介排成“BP 机 → QQ”的怀旧时间线；它直接呈现了 **2000 年当时人的并存想象**：

```text
电话
BP机
手机
E-mail
ICQ / OICQ
```

也就是说，新媒介最初常常表现为**通讯录多一行**，而不是旧的一行立即消失。

### OICQ 的“网络寻呼”隐喻为什么值得认真对待？

今天容易把“网络寻呼机”当成宣传修辞，但当时它把新技术解释成已经熟悉的生活动作：

- 我不必知道你当前在哪台电脑旁；
- 我通过一个号码寻找“你”；
- 在线时可以实时联系；
- 不同通信系统之间还尝试建立转发/寻呼桥梁。

这说明 Internet 进入生活时，经常先借用旧基础设施的**概念、习惯和社会模型**。

但功能存在不等于普遍使用。我们目前只能可靠证明：2000 年这一版本/教程把无线寻呼整合列为能力；尚不能由此推出多数 OICQ 用户真的经常使用 OICQ→BP 机转发。

## 4. 一个 2000 年留言簿个案：Web 页面可以只是联系链的第一跳

`sickbaby.org` 当前仍保存一组标有 2000 年日期的历史留言簿页面。页面自述这是“朋友们以前在留言簿里的文字”。

在 **2000-10-05** 的一条留言中，一名留言者询问朋友是否仍在长沙，并留下自己的寻呼联系方式，请对方看到网页留言后呼他，同时提到共同朋友也在想念对方。

来源：
https://www.sickbaby.org/undesay18.htm

为避免不必要地重新传播普通人的历史联系方式，本仓**不复制原 BP 号码或个人邮箱**。

这个个案不能代表所有早期网民，也不能在未验证 hosting continuity / WARC 的情况下证明当前字节就是未经修改的 2000 年 HTTP 对象。但它至少保存了一个具有明确内部时间戳的生活动作：

```text
Web 留言簿
→ 对方以后上线看到留言
→ 使用 BP 机联系
→ 后续可能再转电话/线下见面
```

这里 Web 并不是完整通信系统，而更像一个**路由表面（routing surface）**。

同一页的其他留言还反复出现 Email、电话、聊天室、网吧、线下见面等渠道。这支持一种更稳妥的理解：

> **early online sociality often depended on channel handoff。**
>
> 一次关系互动可以从网页开始，却在电话、寻呼、Email 或真实地点完成。

## 5. 新分析单位一：contact stack（联系栈）

以后重建 1995–2005 的一个人，不宜只问“他有没有上网”。

更有用的是记录当时可用的联系方式组合：

```yaml
contact_stack:
  home_phone: unknown
  work_phone: unknown
  public_phone_access: likely
  pager: yes/no/unknown
  mobile_phone: yes/no/unknown
  email: yes/no/unknown
  icq_oicq: yes/no/unknown
  bbs_id: yes/no/unknown
  homepage_or_guestbook: yes/no/unknown
```

并分别问：

- 哪个入口可以随身收到提醒？
- 哪个入口适合长对话？
- 哪个入口成本最低？
- 哪个入口依赖单位/学校？
- 哪个入口换城市后还能保留？
- 哪个入口朋友最可能已经知道？

这比“Internet user / non-user”更接近真实通信生活。

## 6. 新分析单位二：channel handoff（通道切换）

一次联系可以在多个媒介间依次迁移：

```text
报纸/网页看到信息
→ Email 询问
→ BP / 手机通知
→ 电话确认
→ 线下见面
```

或者：

```text
朋友在留言簿发现你
→ 留 BP 联系方式
→ 你下次上网读到
→ 呼机提醒
→ 公共电话回拨
→ 约定见面地点
```

因此研究“互联网改变了什么”时要避免一个常见错误：

> **web-mediated action ≠ web-contained action**

Web 可能只承担：

- discovery（发现）；
- directory（联系人目录）；
- asynchronous message（异步留言）；
- identity pointer（身份指针）；

真正的同步沟通和行动仍由电话、寻呼、手机、单位、车站、餐馆等完成。

## 7. 海外对照：Internet 与 paging 的融合是共同历史，不是中国特例

1998 年 8 月，BellSouth Wireless Data 在美国推出 nationwide Interactive Paging Service，配合 RIM Inter@ctive Pager 950，用户可以用寻呼设备收发 paging 和 E-mail，还能读取、编辑、转发邮件。

来源：
https://www.wirelessdesignonline.com/doc/bellsouth-launches-interactive-paging-service-0001

1998 年 9 月 *Wired* 报道 Fujitsu ByeDesk：用户在 Web 主页注册后，可以把 Email、股票报价和网页更新转发到手机或 pager；信息也可从移动设备经服务器重新进入 Internet。

来源：
https://www.wired.com/1998/09/email-email-everywhere/

所以共同机制是：

> **1990 年代末的“Internet + pager/mobile”并不是两个时代首尾相接，而是大量系统主动尝试桥接。**

中国案例的特殊性需要另行解释：

- 单向寻呼人口规模特别大；
- Internet 用户基数当时仍小得多；
- 公共电话、家庭/单位固定电话在回拨链中仍重要；
- PC、拨号和网吧的接入环境与美国两向 pager / 企业移动邮件市场不同。

因此不能把 RIM/美国企业移动邮件的生活经验直接投射到中国寻呼用户。

## 8. 历史可见性：档案最容易保存“第一跳”，最难保存整条联系链

Web archive 很容易保存：

- 一个留言；
- 一个“联系方式”字段；
- OICQ 下载页/教程；
- 一个 Email 链接；
- “BP 机”这一字段标签。

但它通常看不见：

- 对方是否真的呼了这个号码；
- 呼机是否仍有效；
- 收到寻呼后从哪部电话回拨；
- 电话中说了什么；
- 是否约成了线下见面；
- 联系人是否后来换号；
- 没有被 Web 记录的纯电话/寻呼关系。

所以：

> **archived contact artifact ≠ complete communication event**

以及：

> **historical web visibility can overrepresent the web-facing edge of a mixed offline/online communication chain。**

这和前一专题提出的 `archived web page ≠ web-native historical content` 相互补充：旧 Web 不仅会保存从更早媒介迁入的内容，也会保存一条跨媒介生活链中的某一小段。

旧网考古方法文档：
https://github.com/tmzncty/old-web-archaeology/blob/main/docs/CONTACT_STACK_AND_CHANNEL_HANDOFF_1998_2002.md

## 9. 它怎样改变“普通人怎么活着”的理解？

### 9.1 移动性不是等智能手机出现才突然发生

在能随时进行完整移动对话以前，人先获得了**移动可达性**：离开家/单位后，别人仍能把一个提醒送到你身上。

### 9.2 新媒介常先增加选项，而不是立即替代旧媒介

2000 年一个人的社会连续性可能同时由：

- 家庭/单位固定电话；
- BP 机；
- 手机；
- Email；
- OICQ；
- BBS / 留言簿；

共同维持。

所谓“互联网生活”因此可能建立在大量非 Internet 基础设施之上。

### 9.3 关系的连续性来自“路由能力”，而不只来自某个平台

真正重要的问题变成：

> 朋友还知不知道通过哪条链找到我？

而不是：

> 我是不是已经注册了某个平台？

这与此前的 portable account identity、contact-endpoint lifecycle、portable network capital 可以接起来：人在换城市、换单位、换终端时，能不能维持一组仍然有效的联系人路由，本身就是一种生活能力。

## 10. 反例与后见之明风险

1. **不要写成“BP 机必然进化成 QQ”。** 技术谱系和社会采用并非单线，许多寻呼用户未必在同一时期成为网民。
2. **不要把所有寻呼机当成同一种设备。** 数字寻呼、汉字寻呼、单向/双向能力不同，地区服务也不同。
3. **不要把 OICQ 的无线寻呼功能存在写成普遍行为。** 目前缺少使用率和用户日志。
4. **不要把一个留言簿个案写成典型人口。** 它只证明这种 channel handoff 在同时代至少真实出现过。
5. **不要把当前幸存页面自动当成字节级原始 2000 Web 对象。** 需要 Wayback/WARC 或历史镜像进一步核验 hosting continuity。
6. **不要因为早期 Internet 可连接 BP 机就说通信“无缝”。** 设备、资费、接入时间、电话回拨、服务覆盖都构成摩擦。

## 11. 证据等级

### A / A-like — 同时代制度记录与幸存内容

**CNNIC 第三次互联网统计（CERNET 历史页转录）**

- 用途：1998-12-31 Internet 用户/联网计算机数量级；
- 限制：当前引用页面为后来的机构历史汇编，若需要最严格 A 级数字，应继续定位原始 1999 报告扫描/HTML。

**sickbaby.org 留言簿（内部时间戳 2000-10-05）**

- 用途：证明幸存页面中存在 Web 留言 → pager 联系的同时代生活动作；
- 限制：当前 host continuity 和 byte identity 尚未独立验证；不得重新发布普通人的历史号码。

### B — 同时代/近同时代二手材料

**《软件世界》/新浪科技，2000-04-14**

- 用途：证明当时通讯录的“电话/BP/手机/Email/ICQ”并存想象，以及 OICQ 无线寻呼能力的产品描述；
- 限制：教程证明 feature/representation，不证明 usage rate。

**SCMP，1999-03-19**

- 用途：寻呼市场规模与移动电话侵蚀趋势；
- 限制：行业报道，不等于官方订户普查。

**BellSouth Wireless Data，1998-08-27；Wired，1998-09-04**

- 用途：海外 paging ↔ Internet / E-mail 融合的同期对照；
- 限制：企业/高端移动数据市场与中国大众单向寻呼环境不同。

## 12. 我们还不知道

- OICQ 无线寻呼具体支持哪些寻呼网络、地区和资费模式；
- 有多少 OICQ 用户实际使用过该桥接功能；
- 1998–2002 不同城市、职业、收入群体的寻呼/手机/Email/QQ 联系栈分布；
- 普通人一次关系互动平均会经过多少个媒介；
- BP 机退出后，旧联系人如何迁移到手机、QQ 或 Email；
- 哪些人因为号码/平台迁移而永久失联；
- 什么时候个人主页/论坛/SNS 的 profile schema 普遍删除“BP 机”字段；
- Web archive 对“通讯录式页面”与真实通信行为之间的偏差有多大。

这些问题比再写一条“QQ 在某年超过寻呼机”的替代史更有研究价值。
