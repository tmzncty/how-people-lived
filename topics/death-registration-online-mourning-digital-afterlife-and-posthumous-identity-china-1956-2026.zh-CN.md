# 从死亡证明到“账号还活着”：死亡登记、远程追思、数字身后身份与生命终点接口（中国，1956—2026）

## 研究问题

人的死亡是生物事件，也是一个需要被多个制度、亲属网络和媒介系统分别“知道”的事件。

本专题不讨论殡葬观念的一般历史，而追问四个更窄的问题：

1. 一个人死亡以后，医院、公安、民政、社保、公积金、银行、平台和亲友网络分别在什么时候、凭什么把这个人从“在世”状态改成别的状态？
2. 当亲属不在墓地所在城市，甚至不在同一国家时，邮政、电话、报刊、Web 纪念馆、社交平台和政务网络分别怎样改变哀悼的可达性？
3. 互联网出现以后，为什么会出现“现实中的人已经死亡，但账号、头像、生日提醒、聊天记录和个人页面仍继续存在”的新型状态不一致？
4. 当一个人主动提前安排数字遗产、账号、照片、游戏角色或宠物照护时，是否意味着标准的“死后由配偶/子女处理一切”脚本正在让位于更明确的个人预先安排？

本专题与 `old-web-archaeology` 的交叉包：

- `../old-web-archaeology` 对应文件：`DIGITAL_MEMORIAL_PROFILE_GUESTBOOK_ACCOUNT_DEATH_AND_POSTHUMOUS_STATE_GAPS_1998_2015.md`

核心判断不是“互联网让人永生”，而是：

> **生物死亡、法律/行政死亡、社会关系中的死亡、平台账号状态和历史记忆从来不是同一个状态。数字化把这些原本较少同时可见的不同步暴露了出来。**

## 证据合同

### A：原始 / 同时代证据

- 当时的政府规定、平台规则、服务页面、报刊采访、用户自述、同时代网页；
- 明确发布日期与当时功能状态。

### B：近同时代二手证据

- 新闻机构对平台和殡葬服务的调查；
- 有可核对对象和时间的行业报道。

### C：后来回顾

- 平台、机构、用户多年后的历史回忆；
- 只用来建立线索，不能替代当年的页面、规则或使用率。

### D：研究者复原 / 推断

- 从多个状态和材料中推演的机制；
- 必须明确标注，不能写成当时行动者已经这样理解。

个人材料只保留解释机制所需的最少身份信息；不因为页面仍公开就扩大传播普通逝者和亲属的敏感信息。

## 一、先拆开“死亡”这件事

至少应区分：

```text
biological death
!= medical death certificate issued
!= death registered in a health system
!= household registration cancelled
!= funeral/cremation completed
!= pension or welfare stopped
!= bank/estate process completed
!= platform informed
!= platform account protected/deleted/memorialized
!= friends and weak ties know the person died
!= online traces disappear
```

因此建立以下概念：

- **death-state propagation / 死亡状态传播**：一个部门或关系网络确认死亡以后，这个状态怎样传播给其他系统；
- **posthumous identity continuity / 身后身份连续性**：本人死亡后，账号、作品、照片、角色、好友关系和页面是否继续存在；
- **mourning addressability / 追思可寻址性**：不在墓地现场的人能否找到一个稳定对象进行纪念；
- **memorial executability / 追思可执行性**：知道有纪念渠道是否真的能完成献花、留言、上传照片、参加仪式等行为；
- **posthumous agency / 身后自主安排**：本人是否能在生前指定数字内容、财产、账号、宠物或联系人在死后的处理方式；
- **death-interface burden / 身后接口负担**：亲属在悲痛状态下需要跨多少部门、材料、证明和账号处理事务。

## 二、互联网以前：死亡早已是一张通信与制度网络，而不是一个瞬间

互联网以前，普通家庭依靠亲属上门、电话、电报、书信、单位通知、报纸讣告和墓地本身传播死亡信息。不同关系圈得到消息的速度天然不同：同住亲属可能立即知道，异地亲戚需要电话/电报，旧同学和工作关系甚至可能几年以后才偶然得知。

中国现代死亡管理也长期存在多部门接口：医学证明、户籍、殡葬、福利和继承各有自己的凭证与权威。

本轮不把后来全国电子联办制度倒投到早期，而只保留一个方法性起点：

> **在没有 Web 的年代，死亡状态也必须在多个现实制度之间传播；数字政务后来首先改变的是这些接口的传递方式，而不是创造“死亡登记”本身。**

这也意味着研究旧报纸讣告、单位名录和户籍资料时，不能因为某处仍把一个人列为成员，就推断他当时仍然在世；不同记录的更新时延本来就不同。

## 三、1990s 末—2004：中文 Web 把“纪念地点”从墓地复制到页面

### 3.1 中国网上纪念并不是 2020 年才出现

2007 年新华社报道回顾，中国网上纪念馆在 1990 年代末已开始出现，但早期受到带宽、网民规模和用户硬件等限制；2004 年民政部门已经倡导互联网祭扫。该报道同时指出，当时国内已有一批专门纪念网站，但规模不大。

来源（A/B 边界：2007 年同期报道对稍早历史的回顾）：

- 新华网转载，《中国开始流行网上祭奠先祖》，2007-04-03：
  https://tech.sina.com.cn/i/2007-04-03/10221446100.shtml

这里必须严格区分：

```text
online memorial site exists
!= household has a computer
!= household has Internet access
!= user knows the site
!= user accepts online mourning
!= user uses it instead of visiting a grave
```

2007 年报道甚至直接记录了反对者：有人认为网络拜祭不够严肃，扫墓的意义仍在亲眼看逝者安息的地方。互联网因此增加的是一种分支，而不是替换传统路径。

### 3.2 世界范围内同样出现“墓地 → 可寻址页面”的转译

海外至少有一个很早且仍可核对的 Web 对照：World Wide Cemetery 自述创建于 1995 年，核心对象就是把 obituary/eulogy 转成独立、可持续访问的 Internet 页面。其现行网站仍强调固定纪念页与交互留言页的区分。

来源（C：站点自身历史回顾；当前站点可观察事实为 A-current）：

- World Wide Cemetery：https://cemetery.org/
- Our Story：https://cemetery.org/our-story/

这说明 1990s 中期 Internet 已经提供一种新的 **mourning address**：亲友不必知道墓园的地理坐标，也可以通过 URL 找到同一个纪念对象。

但 URL 的“永久”只是运营承诺，不是自然属性。

## 四、2005—2012：扩张型未来——异地生活不再必然切断祭扫

### 4.1 一条很清楚的迁移—追思链：河南 → 杭州

2008 年新华社报道采访到一名从河南到杭州工作五年的年轻人。过去祭祀需要回老家；当年他在祭祀网站录入逝者生平、经历、遗嘱和影像，建立网页，之后可以在祭日或平常随时打开。

来源（A/B：同期采访）：

- 新华网转载，《网上祭祀遭遇现实尴尬》，2008-04-05：
  https://news.sina.com.cn/c/2008-04-05/073615294595.shtml

这不是“网祭替代返乡”的人口统计，而是真实存在的一条生活路径：

```text
离乡工作
→ 墓地留在故乡
→ 返乡需要时间与交通成本
→ Web 建立一个可反复访问的纪念地址
→ 异地日常也能继续追思
```

因此 Internet 对迁移家庭的意义不只在“活着的人还能联系”，也在于**离开故乡以后仍能维持对死者的关系实践**。

### 4.2 2008 年：一个纪念馆甚至可能是一个人在网上唯一使用真名的地方

《南都周刊》2008 年同期报道一名 27 岁广州人：妹妹去世后，他付费建立纪念馆，让外地同学朋友能参与纪念；报道还提到，这个纪念馆是他在网络世界中唯一留下真名的地方。

来源（A/B）：

- 《南都周刊》，《虚拟祭祖：市场经济进驻虚拟墓地》，2008-04-09：
  https://news.sina.com.cn/c/2008-04-09/164415322655.shtml

这带来一个很重要的 **online/offline identity inversion**：

- 早期互联网其他地方可以使用网名；
- 纪念馆却要求或鼓励把逝者姓名、亲属关系、照片和人生故事重新带回真名世界。

所以“旧网匿名文化”不能泛化到全部中文 Web。

### 4.3 2010 年：异地读书者把网祭从节日扩展到平常

2010 年同期报道中的一名在武汉读博士的女性，因为科研项目繁忙、连续两年无法回家参加重阳祭祖，注册免费网上纪念馆，上传祖父照片、相册、背景音乐和文字；她此后并不只在清明/重阳进入，而是基本每周查看照片并留言。

来源（A/B）：

- 《网上祭祀发展十年仍不温不火》，2010-10-20：
  https://news.sina.com.cn/o/2010-10-20/113418259489s.shtml

这说明 URL 不是简单把“一年一次上坟”原样搬上网。低进入成本可能把追思从**节日性、地理性仪式**改成更高频、私人化的记忆访问。

但同一报道又提供了重要反例：十年后网上祭祀仍“不温不火”，传统观念、收费和网站本身不稳定都限制采用。

### 4.4 纪念网站自己的寿命成为新的脆弱点

同一 2010 年报道采访一名前从业者：部分投资者发现项目难盈利后撤站，服务器关闭会让用户资料全部流失，用户又缺乏维权渠道。

这产生一个此前实体墓碑没有完全相同的新风险：

```text
physical memorial inaccessible because distance
versus
online memorial disappears because provider exits
```

因此建立 **memorial-host dependency / 纪念托管依赖**：一个人为了让纪念摆脱地理距离，却把它交给了一个可能比墓碑寿命更短的运营商。

### 4.5 “建立网墓”也需要身份权威，否则纪念可以变成骚扰

2010 年福建一名仍在世的人被朋友恶搞建立“网墓”，本人发现后要求网站撤除，并公开提出实名制问题。

来源（A/B）：

- 中国新闻网转载，《活人被网上祭拜引发网墓实名制热议》，2010-04-06：
  https://news.sohu.com/20100406/n271327157.shtml

由此不能把 `memorial page exists` 写成 `subject is deceased`。

至少要区分：

```text
page created
!= creator is authorized kin
!= subject identity verified
!= subject is actually deceased
!= biography is accurate
```

## 五、社交平台时代：人死了，账号为什么仍“活着”？

专门纪念网站需要亲友主动建馆；SNS 则反过来：**逝者生前已经留下一个关系图、照片库和持续更新的个人页面。** 死亡以后首先出现的问题不是“建不建馆”，而是已有账号应该变成什么。

海外 2009 年 Facebook 是一个干净的比较点。Facebook 当年宣布 memorialized profile：亲友需要报告死亡并提供讣告/报纸材料；纪念化后禁止登录，但保留页面并允许朋友留言。该规则的直接背景之一是推荐算法会提示用户去“重新联系”已经死亡的朋友。

来源（A/B，2009 同期报道）：

- The Guardian, 2009-10-27:
  https://www.theguardian.com/technology/2009/oct/27/facebook-user-memorials

这里出现了一个全新的状态问题：

> **算法并不知道“死亡”这个社会事实，除非有人把它翻译成平台能验证的状态。**

于是：

```text
person deceased
!= platform informed
!= proof accepted
!= account memorialized
!= recommendation systems stop treating the account as an active person
```

当前 Facebook 帮助文档仍明确区分 memorialized account：显示 Remembering、原内容按原隐私设置保留、不能登录，并不再进入 People You May Know、广告和生日提醒等公共推荐位置。

- Facebook Help Centre：https://www.facebook.com/help/1017717331640041/

当前规则不能倒推 2009 年全部细节，只能说明这种“身后账号状态”后来持续制度化。

## 六、2015—2019：拥堵型未来——数字生活已经多到必须问“死后谁来收尾”

2018—2019 年中国公共讨论开始非常直接地把 QQ、微信、微博、支付宝、云盘、游戏账号和数字内容放进“数字遗产”问题。

2018 年新华社在讨论德国社交账号继承判决时明确指出，中国用户同样面临账号、聊天/文件、虚拟财产与隐私之间的冲突。

- 人民网转载新华社，《人死后QQ、微信号怎么办？无法回避的“数字遗产”》，2018-07-22：
  http://it.people.com.cn/n1/2018/0722/c1009-30162369.html

2019 年中国新闻网又把问题具体拆成 QQ/微信/微博/支付宝、云盘、游戏账号等对象，并提醒财产价值、人格/隐私价值和平台协议不能混为一谈。

- 人民网转载中新网，《互联网身后事：我的QQ微博微信支付宝能传家吗？》，2019-05-07：
  http://it.people.com.cn/n1/2019/0507/c1009-31070693.html

这一阶段最重要的不是得出“数字遗产都可以继承”，而是恰好相反：

```text
I can access it while alive
!= I own the account itself
!= heirs can log in
!= heirs can inherit every message/photo
!= platform will preserve it indefinitely
!= friends whose messages are inside consent to inheritance
```

标准遗产脚本遇到平台账号以后开始失灵：一只手表交给继承人，并不暴露第三人的私人通信；一个社交账号则同时包含本人、联系人、平台和支付/身份系统的多重权利。

这构成 **inheritance / privacy conflict**，不能通过“账号也是财产”一句话消解。

## 七、2020—2022：偶发型未来——不能到墓地以后，远程追思从小众选项变成连续性设施

### 7.1 2020 年清明：线上纪念不再只是“新潮”，而是现场渠道中断后的替代路径

北京 2020 年清明期间显著减少现场祭扫，同时提供网上祭扫、预约代祭扫和家庭追思。同期采访中，一名市民和家人计划为父母开网上家庭追思会，上传照片、写话，向父母“汇报情况”。

来源（A/B）：

- 《北京晚报》转载，《网上云祭扫同样可以追思缅怀》，2020-03-29：
  https://bj.people.com.cn/n2/2020/0329/c82840-33911923.html

广州同期不仅有网站，还出现家族视频会议“云拜祭”、书信寄语、工作人员代祭等并行方式。

- 《广州日报》转载，《书信寄哀思 视频云拜祭》，2020-04-03：
  https://sn.people.com.cn/n2/2020/0403/c378296-33924240.html

因此疫情的关键不是“发明网祭”，而是 **fallback elevation / 备用路径升格**：

> 一个 2000s 已存在但长期小众的媒介，在物理通道突然失效时，短暂承担了维持家庭仪式连续性的任务。

这与远程办公、网课类似，但又有不同：死亡纪念没有“补课”意义，错过特定周年/清明的情感时间也可能不可替代。

### 7.2 社交账号终于获得明确“逝者状态”

2020 年 9 月微博宣布逝者账号保护机制。对疑似逝者账号，需要反馈者提供本人身份证明、与逝者关系证明和死亡证明；审核后账号进入保护状态：不能登录、不能新发/删除内容，也不能更改状态。

来源（A/B，官方公告的同期转载）：

- 新京报转载，《新浪微博将对逝者账号设置保护状态》，2020-09-17：
  https://news.sina.com.cn/c/2020-09-17/doc-iivhuipp4825831.shtml
- 央广网补充采访，2020-09-18：
  https://china.cnr.cn/xwygd/20200918/t20200918_525267714.shtml

央广网采访还记录微博方面称其从 2017 年开始搭建逝者账号保护机制，并强调不会把长期不活跃账号直接等同于逝者。

由此固定一条极重要边界：

**`inactive account != deceased person`。**

平台不能只根据几个月没有登录就把一个活人“数字死亡”；反过来，一个已经死亡的人也可能因为无人提交证明而长期保持普通账号状态。

## 八、2023—2026：防守型未来——从“死后家属想办法”到“我提前安排退出”

### 8.1 数字遗产开始进入年轻人的预先安排

2023 年《法治日报》采访一名刚满 18 岁的人，她把多年压岁钱和游戏账号一起写进遗嘱，称立遗嘱是“未雨绸缪”。

- 《法治日报》，2023-03-22：
  https://epaper.legaldaily.com.cn/fzrb/content/20230322/Articel04002GN.htm

2024 年一篇对年轻立遗嘱者的同期采访又出现更广的非标准安排：有人把虚拟资产、社交媒体账号写进遗嘱；一名选择不婚的作家还专门为三只猫安排财产和朋友作为遗产管理人。

- 半岛新闻，《年轻人立遗嘱？》，2024-03-31：
  https://news.bandao.cn/a/1711899178722559.html

这里不要浪漫化“年轻人都在立遗嘱”。这仍是一个高度选择性的登记样本，绝不能外推全国青年。

真正值得留下的是新的**路径类别**：

```text
本人提前安排
→ 不必默认只有配偶/子女是身后事务执行者
→ 朋友、手足、遗产管理人也可能成为执行角色
→ 数字账号、创作劳动、宠物照护等进入安排
```

这直接撞击标准人生脚本：如果一个人未婚、无子女、与朋友共同生活，制度和平台是否允许她指定真正信任的人，而不是强行寻找一个不存在的“默认家庭角色”？

### 8.2 现实制度也开始把“身后多个部门”重新压缩成一个入口

湖南 2022 年公布的改革把死亡证明、火化证明、户口注销、医保/养老待遇、公积金、驾驶证等多项事务整合为“身后一件事”，并规划线上、掌上办理。

- 湖南省政府，2022-12-20：
  https://www.hunan.gov.cn/hnszf/hnyw/zwdt/202212/t20221220_29164767.html

山西 2024 年进一步提供线上/线下二选一入口，把多个部门的数据与业务联办。

- 山西省卫健委，2024-06-19：
  https://wjw.shanxi.gov.cn/xwzx/szyw/202406/t20240619_9591018.shtml

2026 年国家卫健委等部门又要求加强死亡医学证明信息登记与电子证照管理；自 2026 年 7 月 1 日起使用全国统一死亡证明，并以公民身份号码为主要编码，推动卫健、公安、民政之间的信息协作。

- 国家卫生健康委，2026-02-27：
  https://www.nhc.gov.cn/guihuaxxs/c100133/202602/9daacc59b8494be99a04e1b1fcc69247.shtml

由此产生 **death-state orchestration / 死亡状态编排**：过去亲属拿着纸质证明逐个让不同机构“知道”一个人已经死亡；成熟数字政务试图让一次确认触发多个后续状态变更。

但这不等于“一次死亡状态自动传到所有私人平台”。国家行政死亡记录、银行/保险业务和微博/微信等私人平台仍是不同权威域。

### 8.3 防守型未来的新自由：不是把自己留得更久，而是有权指定什么留下、什么消失

2024 年关于年轻人数字遗产的第一人称材料里，有人明确把网络账号理解为现实中不愿表露的一部分自我，担心“人走了，号还活着”；这显示数字身后问题不只有继承价值，也有**退出意愿**。

- 《新周刊》转载，2024-01-27：
  https://www.thepaper.cn/newsDetail_forward_26149908

2025 年对数字遗产的同期讨论仍不断出现直播账号、创作账号、游戏账号等安排；但平台协议、隐私和继承规则并未因此自动统一。

- 长江云新闻，2025-04-09：
  https://news.hbtv.com.cn/p/4515068.html

因此本专题把成熟阶段的目标称为 **posthumous exit sovereignty / 身后退出主权**：

> 生前获得账号和长期数字身份是一种能力；同样重要的是，本人能否提前选择死后由谁接管、哪些内容继续公开、哪些仅交给特定人、哪些最终删除。

这不是“数字永生”，反而是对自动永久化的防守。

## 九、四个时期的时间感比较

### 2005—2012：扩张型未来

关键词：**异地仍可参与、URL 作为纪念地点、日常化访问。**

普通人的新能力是：离乡工作、异地读书、海外生活以后，不必等下一次回乡才能进入纪念关系。

但扩张期也埋下托管风险：网上纪念馆比墓碑更容易跨距离，却可能因为服务器和商业模式失败整体消失。

### 2015—2019：拥堵型未来

关键词：**账号太多、数据太多、所有权/隐私/继承纠缠。**

人的生活分散在 QQ、微信、微博、云盘、游戏、支付工具等多个系统。死后的问题从“留下哪件物品”变成“有多少平台需要逐一处理”。

### 2020—2022：偶发型未来

关键词：**物理祭扫中断、备用媒介升格、账号死亡状态制度化。**

疫情证明线上追思并非只是一种审美选择；当身体不能到场时，它可以承担家庭仪式的连续性。

与此同时，平台必须显式处理“人已经死亡而账号仍在”的状态不一致。

### 2023—2026：防守型未来

关键词：**提前安排、联办、退出、最小化亲属事后协调劳动。**

新的未来想象不是“我要把自己永久留在网上”，而越来越包括：如果未来突然终止，我希望重要的人知道哪里有我的资料、谁能处理它、哪些东西不要被自动暴露、哪些关系不必由默认配偶/子女承担。

## 十、跨国比较：哪些是中国特有，哪些是平台时代共同问题

### 共同变化

1. **远程纪念早于社交媒体。** 1995—1996 已出现专门在线 memorial；中国 1990s 末—2000s 初也出现专门纪念网站。
2. **SNS 创造“已有个人页如何死亡”的问题。** Facebook 2009 memorialization 与微博 2017—2020 逝者保护都属于把现实死亡翻译成账号状态。
3. **平台必须验证死亡，但不能用 inactivity 替代 death。**
4. **数字遗产同时牵涉财产、人格和第三方隐私。** 继承规则不可能简单照搬钥匙、家具和存款。
5. **最珍贵的记忆可能依赖寿命更短的商业基础设施。** 网站停运、账号政策变化、登录系统迁移都会让“永久纪念”变成脆弱承诺。

### 中国材料中特别值得继续追踪的部分

1. 公共殡葬/清明政策对网络祭扫的主动倡导；
2. 大规模跨地区劳动迁移与“墓在故乡、人常年在外”的结构；
3. 户籍、社保、医保、公积金、驾驶证、殡葬等多个行政状态逐步被“身后一件事”联办；
4. 私人平台账号状态与国家死亡登记之间仍然不是自动同步关系。

## 十一、反例与后见之明风险

### 反例 1：网上纪念从来没有简单替代墓地

2007—2010 同期材料都保存了明确不接受网祭的人；一些地区多年使用量也没有明显增加。

所以不能写：

> 宽带普及以后人们开始转向网上扫墓。

只能写：

> 部分异地、年轻或愿意使用网络的人获得了一个新的并行渠道；采用高度不均。

### 反例 2：页面可访问，不等于平台确认这个人真的死亡

恶搞“网墓”、错误纪念页和社交账号长期活跃都说明：

`memorial-like page != verified death record`。

### 反例 3：账号“继承”不能和账号内数据全部继承画等号

聊天记录同时包含第三人通信；平台账户可能只有个人使用权；部分数字财产可转移而身份本身不可转移。

### 反例 4：服务器保存得久，不等于记忆更完整

平台可能保存正文却丢失图片、Flash、音乐、留言、计数器、好友图谱和私信；也可能保存账号但未来登录认证失效。

### 反例 5：年轻人立数字遗嘱的报道不能外推一代人

遗嘱库样本天然是主动前往机构的人群。它适合证明“这种路径存在并扩大”，不适合估算全国年轻人比例。

## 十二、它改变了我们对“人怎么活着”的哪一点理解

一个人的生活史并不在死亡那一刻整齐结束。

现实里，家属还要让医院、公安、民政、社保、银行和墓园逐一知道这个人已经离开；社会关系里，有人当天知道，有人几个月后才听说；Internet 时代里，账号甚至可能继续生日提醒、出现在搜索结果和旧群聊里。

因此生命历程必须增加最后一个长期阶段：

> **从“本人活着并维护自己的身份”到“本人不再能操作，而身份、财产、作品、关系与记忆由别人和多个系统继续处置”的转换。**

互联网首先把墓地之外的追思地址带给异地生活者；社交平台随后让本人已经存在的数字生活在死后继续残留；而成熟阶段的制度问题又反过来变成——怎样把这种残留从自动结果变成可选择、可验证、可退出的安排。

这使“普通人有多少种活法”多出一个常被标准家庭脚本遮蔽的问题：

**一个未婚、无子女、最信任朋友而不是亲属、拥有大量数字创作或需要安排宠物的人，也应该能够设计自己的生命终点接口。**
