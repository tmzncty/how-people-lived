# 从“我需要帮助”到“有人能找到我”：紧急呼叫、位置可读性与求助可执行性（中国，1986–2026）

> 交叉研究包：通信史 × 城市基础设施 × 残障可及性 × 生命历程 × 数字平台史。
>
> 本文不讨论具体医疗处置建议，而研究一个基础设施问题：普通人在最没有时间、最不熟悉环境、最难完整表达自己的时刻，怎样把“我需要帮助”转化成一个可以被某个机构受理、定位、派遣并实际到达的事件。

## 0. 本轮为什么值得新增

仓库已经分别讨论了电话家庭可达性、手机号码、地图、网约车、院前医疗、数字照护等对象，但尚未把“紧急求助可执行性”作为独立生命基础设施建模。

这里最重要的新问题不是“有没有 110/120”，而是：

**`help needed != help request executable != location legible != case dispatchable != responder arrived`**。

它直接影响若干不符合默认“稳定家庭 + 熟悉地址 + 能清楚说话”脚本的人：

- 独居者；
- 刚到陌生城市的迁移者、旅客和学生；
- 在高速、公园、乡村道路等没有门牌场所的人；
- 听力/言语障碍者；
- 当时无法持续说话、无法完整描述位置的人；
- 身边没有家属代为说明的人。

因此，紧急通信史不是“电话号码变先进”的附录，而是“一个人能否在脱离家庭保护后仍被公共系统找到”的生命历程问题。

## 1. 核心概念

### 1.1 help-seeking executability / 求助可执行性

知道一个号码只是最前端。完整链条至少包括：

`需要帮助`
→ `知道该联系谁`
→ `有可用通信终端`
→ `呼叫/消息进入网络`
→ `正确机构接收`
→ `接警/调度人员理解事件`
→ `能够确定位置`
→ `能够回拨/继续联系`
→ `生成可派遣事件`
→ `正确单位收到派遣`
→ `找到现实中的人/地点`
→ `实际到达`

任何一步都可能失败。

### 1.2 location legibility / 位置可读性

“人有地理位置”与“机构能利用这个位置”不是同一件事。

历史上可用的位置表示包括：

- 家庭固定电话登记地址；
- 街道、门牌、楼栋、房间；
- 路口、地标、单位名称；
- 路灯杆等公共设施编码；
- 基站/小区位置；
- GPS/手机定位；
- 微信位置；
- 视频中的建筑、路牌和环境。

关键边界：

**`location data exists != dispatcher receives it != dispatcher can interpret it != responder can navigate to it`**。

### 1.3 address-description labor / 地址描述劳动

在自动定位以前，求助者本人常常必须承担一项被基础设施默认掉的工作：把自己所在的现实空间翻译成调度员和司机都能执行的地址。

这项劳动在家中往往不显眼；一旦人在陌生道路、校园、长途车、高速、旅游地，或因紧张/病情无法连续表达，就会突然成为系统瓶颈。

### 1.4 modality portability / 求助模态可携带性

语音并非对所有人和所有现场都可用。短信、文字、图片、定位、视频的价值不是“功能更多”，而是允许求助在不同身体能力和危险场景之间转换模态。

因此：

**`universal number != universal usable interface`**。

## 2. 前互联网：统一短号码本身已经是一场接口革命

### 2.1 中国：110 服务台早于大众互联网

广州市公安局的现今官方回顾显示，1986 年 1 月 10 日广州建立全国首个 110 报警服务台。最初系统依靠电话、转接/录音设备和无线电调度，后来才逐步进入计算机联网阶段。1987 年公安部要求大中城市推广建立 110 服务台。

证据等级：**C（后来的官方机构回顾）**。它足以固定制度时间点，但不能拿来证明 1986 年普通家庭电话拥有率、接通率或全国覆盖。

来源：
- 广州市政府/广州市公安局，2023，《广州110风雨三十七载守护羊城平安》：https://www.gz.gov.cn/xw/zwlb/bmdt/sgaj/content/post_8756604.html
- 广州市公安局，2021，《“您好，广州110”——三十五载不忘初心》：https://gaj.gz.gov.cn/jmhd/zxft/content/post_7096155.html

北京急救中心现今机构介绍则记录：中心 1988 年 3 月 25 日正式运转，同时开通“120”急救电话。

证据等级：**C（机构回顾）**。

来源：https://www.120beijing.cn/channel/173

这里必须守住一个时间边界：

**1980s 已有统一紧急短号码与专业调度体系 ≠ 中国普通人已经接入互联网。**

它说明的是公共通信基础设施已经开始把“找当地派出所/医院电话号码”压缩成一个更短、更容易记忆的入口。

### 2.2 海外对照：911 说明“统一入口”远早于 Web

美国 National 911 Program 的历史材料记录，第一通 911 于 1968 年 2 月在 Alabama 拨出；在统一号码以前，人们需要知道当地警察、消防或急救部门各自的普通电话号码。

证据等级：**C（现今官方历史回顾）**。

来源：https://www.911.gov/about/the-national-911-program-celebrates-50-years-of-911/

Haleyville 市政府页面还保存/转载 1968 年当地报纸关于首套 911 系统的同期照片与报道，可视为“现今机构托管的同时代原件影像”。

来源：https://www.cityofhaleyville.com/education-community-development/first-9-1-1-call/

跨国共同机制因此不是“互联网让人第一次远程求助”，而是更早的：

**复杂组织被压缩成一个普通人能记住的入口。**

## 3. 固话到手机：可移动的人把“位置”问题重新制造出来

固定电话与住址具有天然但不完美的绑定关系。手机则把“号码属于谁”和“人现在在哪里”拆开。

美国 FCC 1997 年关于无线 E911 的正式文件明确指出：与有线 E911 可显示号码和位置不同，当时无线 911 呼叫的电话号码和位置不能自动显示，许多无线呼叫者难以准确描述自己的位置。FCC 因而要求逐步提供回拨号码、基站位置和更精确的自动位置识别。

证据等级：**A（同期监管原始文件，FCC 97-402）**。

来源：https://docs.fcc.gov/public/attachments/FCC-97-402A2_Rcd.pdf

这提供了一个极重要的海外对照：

**移动通信扩大了“任何地方都能求助”的范围，同时破坏了固定电话时代“电话大致告诉机构你在哪里”的隐含假设。**

中国也出现同类问题，但不能把美国 E911 的制度时间线直接投射到中国。中国材料必须逐地、逐系统核实。

## 4. 2005–2012：扩张型未来——让更多身体、更多场景进入求助系统

### 4.1 “三台合一”不是号码消失，而是后台组织重组

2007 年公安部发布会材料显示，到 2006 年底，在需要推进“三台合一”的 2087 个县市级公安机关中，1743 个已不同程度实现；合一后 110 平台集中受理 110、119、122，群众拨打其中任一号码都可接入统一平台。

证据等级：**B（同期公开发布会转述）**。

来源：https://news.sohu.com/20070109/n247504535.shtml

它说明“统一入口”还能继续向后台推进：

`普通人记住哪个号码`
与
`机构内部究竟由哪个部门接、转、派`
可以被部分解耦。

但“83.5% 县市级单位完成不同程度合一”不能写成“全国每个地方、每一类警情都完全同质化”。

### 4.2 2009：12110 把“不能说话”从例外变成正式接口需求

2009 年公安部相关消息显示，“12110”被确定为全国公安机关统一公益性短信报警号码。当时上海、天津、浙江等地已全面开通，另有部分地市和县级市开通，但公安部明确表示要按各地条件逐步开展。

证据等级：**B（同期法制媒体/官方转述）**。

来源：https://www.npc.gov.cn/WZWSREL25wYy9jMi9jMTg4L2MyMTkvMjAxOTA1L3QyMDE5MDUyMl8xNzA3OTMuaHRtbA%3D%3D

它的主要需求之一来自听力/言语障碍者，以及“不方便出声”的特定现场。

同年《大河报》保存了特别有价值的同时代普通人材料：

- 一名长途车乘客回忆看到诈骗行为，却担心公开拨电话被发现；他曾尝试让接警员直接听现场声音，效果有限，因而期待短信报警。
- 一名在郑州打工者回忆自己在公交车上看到窃窃行为但因担心人身风险保持沉默，并问“我究竟能做些什么”。
- 受访市民同时担心短信延迟、丢失、信号问题以及警方如何快速找到发信人。

证据等级：**B-个人材料（同期媒体采访中的第一人称回忆；真实路径证据，不具人口代表性）**。

来源：https://news.sina.com.cn/c/2009-01-13/071115024341s.shtml

这里新增的并不是“短信更先进”，而是一条生活路径：

**`我看见危险，但开口本身会增加风险 → 静默文字入口使求助变得可能`**。

### 4.3 短信同时暴露新的状态差

2009、2012 年警方提示都强调短信可能延迟或丢失，在紧急情况下语音仍通常是优先入口；短信需要尽量写清地点、时间和事件，并等待确认。

2012 年承德还将路灯杆编码作为位置接口：报警人只需报出杆号，后台即可把一个普通人难描述的道路空间翻译成调度坐标。

证据等级：**B（同期政府/媒体信息）**。

来源：https://www.chengde.gov.cn/art/2012/1/11/art_360_72899.html

因此：

**`SMS sent != SMS delivered != 12110 platform received != operator read != event located != police dispatched`**。

“多一种入口”不等于“这个入口拥有和语音完全相同的时延与可靠性”。

## 5. 2015–2019：拥堵型未来——从统一号码转向“把现场带进调度台”

### 5.1 2018 烟台 @110：视频、实名、位置和证据进入同一个入口

烟台市政府 2018 年说明显示，“烟台公安”微信公众号中的 @110 需要先在个人中心实名认证，随后可进行实时音视频报警；平台目标之一是让接警员直接看到现场，并保存相关音视频。

证据等级：**A/B（同期地方政府/警方功能说明）**。

来源：https://www.yantai.gov.cn/art/2018/4/16/art_12307_958319.html

同期报道还显示，腾讯地图位置服务可支持现场位置上传。

来源：https://isd.ifeng.com/6297063/news.shtml

但这里必须写出它与 110 电话的根本差异：

`知道 110 + 任意可打电话终端`
不等于
`有智能手机 + 有网络 + 有微信 + 已关注公众号 + 已实名认证 + 找到菜单入口`。

所以它不是“替代 110”，而是一个高带宽的补充层。

### 5.2 2019 重庆“急视救”：定位与视频补上 120 语音链的缺口

重庆市政府 2019 年材料记录，重庆 120 的“急视救”系统可以通过 App、微信小程序，以及在拨打 120 后由短信唤起定位/图文/视频。一个同期交通事故案例中，同行者因语言障碍、路段表述不清和伤情难描述，通过视频把现场和路段传给急救系统。

截至 2019-08-15，官方报道口径称系统已收到 1300 余次报警，189 起涉及视频指导并出车，另有 110 次针对位置说不清的报警通过短信唤起定位及图文沟通。

证据等级：**B（同期政府媒体报道；数量为项目方/机构口径，不外推总体效果）**。

来源：https://cq.gov.cn/ywdt/bmts/201908/t20190827_8655379.html

鞍山 2018 年“互联急救”App 的上线说明同样明确说，传统 120 工作中会遇到呼救者报不清地址、拨通后无法继续说话等情况，App 试图把定位和预先登记信息直接推给调度台。

来源：https://news.cnr.cn/native/city/20180121/t20180121_524106990.shtml

这使 2015–2019 的机制不再只是“入口越来越多”，而是：

**过去由一个高度紧张的人用语言完成的描述劳动，开始被摄像头、GPS、账号资料和地图共同承担。**

## 6. 2020–2022：偶发型未来——“一个手机号能不能自动告诉 120 我在哪里”仍不是全国统一事实

2022 年江苏张家港上线的 120 呼救定位系统，可在呼救同时把位置显示到调度地图；当地负责人说，其网络定位大致可到建筑物附近。

证据等级：**B（同期省级媒体报道）**。

来源：https://news.jstv.com/a/20220613/1655104467880.shtml

同月《健康时报》随机致电二十多个城市急救中心后报道，超过一半尚未实现 120 自动定位。该调查不是全国抽样统计，不能换算全国覆盖率，但足以推翻“智能手机时代 120 自然都能知道来电人位置”的想当然。

证据等级：**B（同期媒体便利调查，非统计抽样）**。

来源：https://www.jksb.com.cn/html/news/hot/2022/0614/176981.html

2022 年广泛讨论的河南大学学生急救事件又非常残酷地暴露了一个系统边界：人在身体状况已经影响表达时，仍可能被要求提供精确校区/道路位置或操作微信定位。本文只把它作为**位置接口失败的公开制度案例**，不将个体苦难做成猎奇，也不据单案推断全国 120 表现。

因此这一阶段的结论不是“疫情以后急救数字化了”，而是：

**数字社会已经让普通人习惯‘我的手机知道我在哪’，但公共紧急系统是否能即时取得、合法使用并正确解释这个位置，仍取决于城市、运营商、调度平台和具体系统。**

## 7. 2023–2026：防守型未来——不再要求人在危急时刻先学一个新 App

### 7.1 5G 可视报警把高带宽入口重新包回“拨 110”习惯

2024 年广东惠州的同期报道记录，一名报警人在公路上无法清楚描述具体地址和现场，110 在原有语音通话后主动发起视频，报警人拍摄附近标志性建筑帮助确认位置。该方案强调无需提前安装 App 或启动小程序。

证据等级：**B（同期《人民日报》报道）**。

来源：https://society.people.com.cn/n1/2024/0523/c1008-40241543.html

江苏 2025 年全面推进的 5G 可视 110 同样把视频能力嵌入既有拨号入口：在符合网络和终端条件时可用视频；视频未接通仍能继续语音。

证据等级：**A/B（同期省级官方/通信主管部门说明）**。

来源：https://www.miit.gov.cn/xwfb/gxdt/dfdt/art/2025/art_edcaac28d7cb4110a0a331aa98330671.html

这里出现了一个和仓库此前“接口再物质化”类似、但方向更明确的新机制：

### familiar-interface preservation / 熟悉接口保留

成熟数字基础设施不一定要求普通人在最紧张的时刻切换到最复杂的新界面。它可以把新的视频、定位和数据通道藏在旧动作后面：

**仍然先拨 110。**

这是一种防守型设计：不是要求每个人提前学会所有数字能力，而是尽量让已有身体记忆继续有效。

## 8. 四个时期的新比较轴

| 时期 | 主问题 | 新增能力 | 新摩擦 |
|---|---|---|---|
| 2005–2012 扩张型 | 更多人、更多场景能否进入求助系统 | 三台合一；短信报警；公共位置编码 | 短信时延/丢失；地方覆盖不一；仍需描述位置 |
| 2015–2019 拥堵型 | 信息已经很多，能否直接把现场和坐标带进系统 | 微信/APP 视频；GPS；图文；预登记信息 | 安装、账号、实名、网络、入口发现等前置条件 |
| 2020–2022 偶发型 | 普通流程失效时，系统有没有冗余 | 部分城市自动定位；110/120 联动 | 城市间能力不均；“手机有位置”不等于调度台有位置 |
| 2023–2026 防守型 | 能否降低人在危急时刻的操作负担 | 5G 直拨视频；语音兜底；多模态定位 | 终端/网络差异仍在；隐私、误报、覆盖需要治理 |

与天气、票务等专题不同，这里的“未来”尺度往往只有几分钟。防守型未来在这里表现得最极端：**不是安排更多活动，而是给一个可能突然失效的人留出被找到的路径。**

## 9. 与标准人生脚本的关系

传统公共服务常隐含一个“标准求助者”：

- 知道自己所在地址；
- 能持续说话；
- 使用主流语言；
- 有家属或同伴；
- 在熟悉的住宅或工作地点；
- 有稳定电话；
- 能听见回话；
- 能等待并在门口接应。

现实生命历程却不断让人偏离这些条件：

- 第一次去大学校园；
- 夜班后独自回家；
- 异地打工；
- 长途车/高速旅行；
- 独居；
- 老年阶段；
- 听力、言语或行动能力变化；
- 一个人突然失去继续解释的能力。

因此紧急通信系统是否真正“普遍”，不能只数覆盖人口，而要问：**人在最不像标准用户的时候，系统还能不能接住她。**

## 10. 海外对照告诉我们的共同变化与差异

### 10.1 共同变化

美国 911 和中国 110/120 都显示：

1. 统一短号码先把组织复杂度藏到后台；
2. 手机普及又使“人和固定地址脱钩”，位置成为新瓶颈；
3. 自动号码/位置、短信、视频等技术不断把原先由人承担的描述劳动转给基础设施；
4. 听力/言语障碍者推动了“语音不是唯一合法入口”的制度变化。

FCC 1997 E911 文件尤其说明，这不是“中国 App 时代才出现的问题”：美国无线 911 在 1990s 同样因为无法自动显示准确位置而需要重新建设位置基础设施。

### 10.2 不能直接类比的地方

- 美国 E911 的 PSAP、运营商义务、定位精度和时间表不能直接套到中国；
- 中国 110、119、120、122 的组织边界与“三台合一”也不能套成美国 911 的单一制度；
- “12110 是全国统一号码”不等于 2009 年全国所有地区已经开通；
- “某地可视 110”不等于全国所有手机、所有运营商、所有系统都支持。

## 11. 证据风险与反例

### 11.1 技术存在 ≠ 使用

有短信平台、App、微信公众号、视频报警，不意味着普通人知道入口，也不意味着危急时刻能找到它。

### 11.2 自动位置 ≠ 精确事故地点

手机可能在建筑内、道路旁、移动载具上；设备位置也可能不是需要救助者的位置。定位是线索，不天然是最终权威。

### 11.3 多媒体 ≠ 更快

视频可能增加网络依赖和操作步骤。因此 2025 江苏方案“视频失败仍回到语音”本身是重要的系统设计证据。

### 11.4 案例可见性偏差

媒体天然更容易报道严重事故、极端调度成功或失败。大量“普通人拨通、说清、派车/派警、顺利到达”的日常成功事务反而很少留下可搜索文本。

### 11.5 不把苦难做技术演示

单个伤亡案例只能证明某类状态差真实存在；不能把人的死亡压缩成“产品痛点”，也不能据此给某一城市整个系统下总体结论。

## 12. 对核心矩阵的贡献

| 矩阵维度 | 本轮新增 |
|---|---|
| 迁移 | 到陌生城市后仍能通过统一入口求助；但位置描述能力下降 |
| 照护 | 独居与无同伴时，自动定位/回拨/视频的重要性提高 |
| 长期中断 | 身体状态突然改变时，标准交互能力可能瞬间消失 |
| 证件与记录 | 视频/微信入口可能要求实名；电话入口通常具有不同身份门槛 |
| 通信方式 | 固话→移动语音→SMS→App/微信→直拨视频，多模态并存而非简单替代 |
| 信息获取 | 重点不是“知道知识”，而是把现场事实送进机构 |
| 线上/线下身份 | 账号身份、号码身份、现实报警人、现实需要救助者可能不是同一个对象 |
| 历史可见性 | 公共号码/宣传页容易保存，真正的接警、定位、派遣和到达状态多为私密记录 |
| 未来预期 | 最短尺度的防守型未来：为未来几分钟可能发生的失能/失联保留出口 |

## 13. 它改变了我们对“人怎么活着”的哪一点理解

前几轮很多对象都在问：人如何把未来订下来、把钱带走、把路线计划出来。

这一轮补上的，是更底层的一种自由：

**一个人可以离开熟悉家庭、去陌生城市、独自居住、深夜工作、长途旅行——前提之一，是当她突然无法继续独立行动时，仍有一种公共系统能够找到她。**

统一短号码先把“我到底该找哪个派出所、消防队、急救站”从普通人的认知负担里拿走；移动电话又让人可以从几乎任何地方开口求助，却同时拆掉了固定地址；短信让一部分不能或不敢出声的人进入系统；GPS、地图和视频再逐步把“请你自己准确说出现在在哪”从人的肩上搬回基础设施。

因此真正成熟的紧急通信，不是让每个人学会更多 App，而恰恰可能是：**在一个人最慌乱、最虚弱、最不像理想用户的几分钟里，要求她做的事情越来越少。**
