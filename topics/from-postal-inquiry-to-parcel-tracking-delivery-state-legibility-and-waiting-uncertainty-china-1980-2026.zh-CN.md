## 0. 这次研究的不是“快递史”，而是等待怎样变得可见

一个物件离开寄件人、尚未到收件人手里时，会出现一个很特殊的生活状态：

> **东西确实存在，也已经在路上，但收件人此刻既不能使用它，也不知道它什么时候真正到。**

邮政、电话和人工查询早就可以缓解这种不确定性。互联网后来改变的，不只是“查得更快”，而是逐步把一件现实物体变成一个可以凭单号反复查询的数据库对象。

本稿把这一能力称为：

- **delivery-state legibility / 投递状态可见性**：普通人能否知道在途物件此刻被系统记为什么状态；
- **object-in-transit addressability / 在途物品可寻址性**：运单号/条码把一个包裹映射成可查询对象；
- **waiting-uncertainty externalization / 等待不确定性外包**：不必完全靠估算、打电话或一直等人，而可以把部分“它到哪了”的记忆交给物流数据库；
- **tracking-refresh labor / 物流刷新劳动**：可查询并不等于自动安心，人会反复刷新、打客服、在购物平台和承运商之间核验；
- **status–possession gap / 状态—占有缺口**：系统显示“妥投/签收/已送达”，并不等于购买者或指定收件人已经实际控制该物品；
- **last-100m choice / 末端一百米选择权**：送上门、门卫、前台、代收点、快递柜、指定位置并非同一种生活结果；
- **movement exhaust / 物品移动轨迹排放**：扫描、查询、签收与通知在帮助人行动的同时，也把物件—地址—手机号—消费关系变成可处理数据。

最小边界是：

```text
寄件/下单
!= 已生成运单号
!= 承运商已实际收件
!= 已发生一次扫描
!= 后台已更新
!= 用户已看到状态
!= 包裹正在连续被定位
!= 已到本地网点
!= 正在派送
!= 已妥投/签收
!= 指定收件人已经拿到
```

这与仓库已有的“可投递性”研究互补：收货地址回答“东西有没有现实末端可以送”；本稿回答“在还没送到以前，普通人能知道多少，以及状态文字何时开始改变等待行为”。

## 1. 前互联网与前大众互联网：查询不是 Web 才发明的

### 1.1 1980/1984：EMS 业务存在，不等于普通人已经拥有现代 tracking

现有 EMS 历史材料把中国国际邮政特快专递业务的开办时间记为 1980 年，国内特快专递为 1984 年。这里能证明的是速递服务与运输网络已经存在，不能由此倒推出后来那种网页逐节点跟踪已经存在。

参考：

- 中国邮政 EMS 发展历程的后期汇总版本（本轮只作企业历史线索，不当作同时代 Web 证据）：<https://wapbaike.baidu.com/item/%E4%B8%AD%E5%9B%BD%E9%82%AE%E6%94%BF%E9%80%9F%E9%80%92%E7%89%A9%E6%B5%81%E8%82%A1%E4%BB%BD%E6%9C%89%E9%99%90%E5%85%AC%E5%8F%B8/6597081>
- evidence: **C/B-low，后来的企业历史汇总；精确日期应继续追原始邮政资料**

当时普通人若想知道一件信件或包裹是否到达，更现实的路径仍可能是：等待、询问寄件人/收件单位、电话或邮政窗口查询。互联网后来改变的是查询接口与频率，不是“查询”这件事从无到有。

### 1.2 1994-01-18：必须把“跟踪查询网”与“公众 Web”分开

多份后来的 EMS 历史资料都记载：1994 年 1 月 18 日开通“邮政特快专递跟踪查询网”，实现快件的网上跟踪查询。

这条日期值得保留，但必须严格限制解释：

> **“跟踪查询网”存在，不等于 1994 年中国普通家庭已经能通过公众 World Wide Web 在家查询快件。**

1994 年 4 月中国才完成全功能接入国际互联网这一更广为确认的网络史节点；而商业互联网、家庭终端和大众上网又更晚。当前证据没有给出 1994 年 1 月该“查询网”的终端、协议、访问主体、是否面向营业人员还是公众、是否需要专线等技术细节。

因此本稿把它标为：

```text
1994: postal tracking-query network exists
public-Web interface: NOT established by this evidence
ordinary-household access: NOT established
```

这正是用户要求的“中国前互联网/科研或专网/正式互联网/大众可及”分层在物流领域的一个具体例子。

## 2. 海外对照：Web tracking 之前，物件先被条码化

FedEx 的企业历史记载，1986 年引入 SuperTracker 手持条码扫描系统；1994 年 `fedex.com` 上线，并被公司称为首个提供在线包裹状态跟踪的运输网站。2009 年 FedEx 自己回顾称，1995 年网站日均已有约 9,000 次 tracking request。

来源：

- FedEx, *Our History*: <https://www.fedex.com/en-us/about/history.html>
- FedEx Newsroom, *FedEx Refreshes Web Tracking Tools* (2009): <https://newsroom.fedex.com/newsroom/united-states-english/fedex-refreshes-web-tracking-tools>
- evidence: **A/B for corporate chronology and company-reported request counts; not a representative household survey**

这条海外线索说明一个跨国共同顺序：

```text
物件获得机器可读身份（条码/单号）
→ 网络内部形成扫描事件
→ 客服/企业内部可查
→ 公共 Web 把部分状态开放给寄件人/收件人
```

互联网最关键的变化之一，是把原来主要属于承运商后台的状态，逐渐开放成普通人自己可以随时发起的查询。

## 3. 2005—2012：扩张型未来——“东西还没到，但我已经能看见它在路上”

### 3.1 2005：EMS 查询入口已经进入普通 Web 用户的“在线查询工具箱”

2005 年 11 月，博客园一篇《在线查询大全》在地图、列车、学历、邮编等工具旁列出：

- EMS 全球快递邮件号查询：`http://www.ems.com.cn/ems/index.jsp`

来源：

- <https://www.cnblogs.com/Qia_sky/archive/2005/11/17/278192.html>
- evidence: **A/B：同时代公开博客/工具清单；证明 URL 被普通 Web 作者识别和传播，不证明使用率**

2007 年 7 月 Google Groups 的一份转贴、同年 51CTO 博客也继续保存同一 URL：

- <https://groups.google.com/g/zhong1985624/c/RFyCqZ1uUCM>
- <https://blog.51cto.com/zjhwin/43402>

这至少把“公众 Web 上存在可传播的 EMS 查件入口”压到了 2005 年，而不是把 1994 年“查询网”直接偷换成 Web 首页。

### 3.2 2006：知道有 tracking，不等于相信它一定可用

2006 年一段华人论坛讨论在谈当当网购买经历时，有用户问 EMS 是否有 tracking number，另一名用户贴出 `ems.com.cn/ems/index.jsp`，但同时表示并不确定是否真的能查到。

来源：

- <https://huaren.us/showtopic.html?topicid=210057>
- evidence: **A：同时代论坛第一人称/即时讨论；仅代表少数发帖用户**

它特别适合提醒我们：

> **功能入口可见 ≠ 普通用户已经形成稳定心智模型 ≠ 每一个单号都能产生有用结果。**

### 3.3 2007：“妥投”第一次反而让状态—现实冲突变得清楚

2007 年 8 月红网报道保存了网友“雀雀•魅”的一段同时代投诉。朋友从北京寄急件到长沙后，收件人在 EMS 网站查询到非常精确的处理节点和时间，并进一步打客服确认；但实际仍迟迟没有拿到。第二天，网站状态已经显示“妥投”，实际物件却被送到了同楼的报社收发室，收件人本人没有即时取得。

来源：

- 红网/新浪转载，2007-08-22：<https://news.sina.com.cn/o/2007-08-22/215712431390s.shtml>
- evidence: **B：同期媒体保存用户投诉与采访；具体个人经验不可外推总体**

这条材料改变了“tracking 只会降低焦虑”的直线叙事。它证明状态可见性还能制造新的核验劳动：

```text
网页说已到本地处理中心
→ 用户预期马上收到
→ 没收到
→ 再查网页
→ 打热线
→ 状态说正在投递/妥投
→ 现实仍没拿到
→ 继续追问真实末端在哪里
```

因此：

> **可见性降低了一类不确定性，却也把“系统说到”和“我真的拿到”之间的矛盾变得可观察。**

### 3.4 2010—2011：从“记住每家快递网址”到跨承运商统一查询

2011 年报道中的“快递100”已经允许用户在一个互联网应用里查询多家快递/物流公司的订单流向；报道现场描述，用户在百度搜索“快递查询”即可直接进入查询组件。该报道引用产品方数据称，上线约八个月累计近 4,000 万次查询，并有约 600 家合作伙伴；这些规模数字应视为企业/媒体口径，不能独立当作人口普及率。

来源：

- DOIT，2011-04-20：<https://www.doit.com.cn/p/73407.html>
- evidence: **B：同期行业媒体；功能观察较强，规模数字主要来自企业**

这里出现了第二层外包：

```text
第一层：承运商替人记录包裹状态
第二层：聚合器替人记住“这个单号应该去问哪家承运商”
```

包裹的现实移动并没有因此更快，但查询入口从“每家公司一个网站”开始向跨承运商状态层收敛。

## 4. 2015—2019：拥堵型未来——“知道到了”以后，问题变成“到底送到哪里”

### 4.1 tracking 进入购物平台背景，刷新劳动仍没有消失

2018 年 5 月中新网/新华网采访中，北京的王女士说，以前经常收到短信通知包裹在柜子里，最糟时连短信都没有，需要自己去购物平台查询物流；她把这类经历称作“被签收”。

来源：

- 新华网（来源：中国新闻网），2018-05-10：<https://www.xinhuanet.com/politics/2018-05/10/c_1122809417.htm>
- evidence: **B：同期采访第一人称**

这已经不是 2005 年“有没有网页可以查”的问题。状态入口已经嵌入购物平台和短信，但普通人仍需承担：

- 有没有通知；
- 哪一个平台状态最准；
- “签收”是谁签的；
- 包裹现在具体在柜、门卫、代收点还是别处。

### 4.2 快递柜解决时间错配，也可能把投递劳动转给收件人

快递柜/代收点的重要性不能只用“懒人快递”解释。它确实解决了一个结构问题：工作日白天收件人不在家，快递员又无法长时间等待。2018 年同一调查中，快递员就直说，常跑小区上班族多，工作日即使先询问，很多最终还是放柜里。

但一旦柜/站从可选 fallback 变成默认，生活成本会改变归属。另一名有一岁孩子的陆女士说，频繁下楼取快递会使照护变得麻烦；她即使知道新规，仍遇到包裹直接进柜。

同年上海张女士根据物流详情看到“拍照签收”，实际并未获得物件，数天后才收到入柜短信，最终因为取件密码问题到 2 月 25 日才拿到。

来源：

- 新华网，2018-05-10：<https://www.xinhuanet.com/politics/2018-05/10/c_1122809417.htm>
- 解放日报/新浪，2018-03-07：<https://news.sina.com.cn/o/2018-03-07/doc-ifxwcyap1623424.shtml>

因此必须同时保留两条：

> **locker can reduce synchronized waiting**；
>
> **locker can also shift last-100m labor from courier to recipient.**

### 4.3 2019：选择权开始被制度化

2019 年发布的《智能快件箱寄递服务管理办法》明确要求，使用智能快件箱投递快件应征得收件人同意；收件人不同意时，应按约定名址投递。

来源：

- 中国经济网转国家邮政局办法，2019-07-19：<https://www.ce.cn/xwzx/gnsz/gdxw/201907/19/t20190719_32671800.shtml>
- evidence: **A/B：同期法规文本转录**

这说明末端状态已经从单纯“系统能不能标成 delivered”转成一个权利问题：

> **谁有权决定 delivered 的现实端点。**

### 4.4 城市的“可追踪”不等于农村的“可到手”

2019 年关于农村快递二次收费的报道中，四川宜宾一名范先生说，自己的地址在派送范围内，却仍被要求每件另付取件费；相关调查还记录了“自己去城里取”或被加收保管费等情况。

来源：

- 每日经济新闻，2019-08-15：<https://www.nbd.com.cn/articles/2019-08-15/1363064.html>
- evidence: **B：同期调查与第一人称；地区性问题，不外推全国所有农村**

因此：

```text
tracking page says arrived at local network
!= service reaches village household
!= recipient can obtain without extra travel/cost
```

这是仓库方法论要求“preserve distribution”的一个具体例子。

## 5. 2020—2022：偶发型未来——trackable 不等于 movable，物流恢复本身成为“生活恢复”的证据

### 5.1 2020：交付状态第一次显式包含“怎样避免见面”

2020 年 2 月，无锡市民陈先生在收到配送短信后得知快递员将采取“无接触配送”，包裹可以按用户需要放在指定位置；短信还包含配送员的防护/体温信息。陈先生随后评价这种做法让他感觉防疫更专业。

来源：

- 深圳新闻网，2020-02-02：<https://www.sznews.com/tech/content/2020-02/02/content_22820188.htm>
- evidence: **B：同期企业实践报道 + 用户反应；不能推出所有快递均如此**

这时最后一百米的状态不再只是：

`到了 / 没到`

而开始包含：

`怎样交接 / 放在哪里 / 是否接触 / 怎样通知`。

2020 年 3 月发布的“无接触配送”团体规范甚至建议配送员送达后拍摄包含商品和存放位置的图片并通知消费者。

来源：

- 北京日报/央视网，2020-03-17：<https://news.cctv.com/2020/03/17/ARTIvtGnwG6YHSV4WEarH65R200317.shtml>

这把 proof-of-delivery 从传统签字进一步扩成“位置证据”。

### 5.2 系统断裂时，网页状态不能替代道路、网点和人

疫情期间，物流网络一度受到人员、车辆、网点和社区出入条件影响。即使订单和单号仍然存在，状态可见也不能使一个停住的网络自动恢复。

这轮最重要的反例是：

> **trackable != movable != receivable.**

2022 年上海恢复生产生活秩序后，市民齐进说，6 月 2 日给孩子买的玩具从汕头发货，6 月 4 日早上收到，他把这种速度直接感受为“如常生活真的回来了”。

来源：

- 新华社/央视网，2022-06-10：<https://news.cctv.com/2022/06/10/ARTIJ1efRyOZhwk6hl1GiDrn220610.shtml>
- evidence: **B：同期第一人称，单人体验；与同期行业复工现场交叉**

另一名上海市民张女士在 2022 年 6 月 2 日收到 7 个包裹时，也把它描述成疫情以来第一次重新收到送货上门的包裹。

来源：

- 第一财经，2022-06-07：<https://www.yicai.com/news/101435793.html>

对普通人来说，物流不只是消费基础设施；在极端中断以后，**物件重新按承诺穿过城市**本身就可以成为“日常秩序回来了”的感知指标。

## 6. 2023—2026：防守型未来——包裹要可寻址，但人不必因此完全裸露

早期 tracking 的工程目标是让一个包裹越来越容易被识别、扫描和查询。成熟以后，问题出现反转：如果每一张面单都永久、明文地带着姓名、手机号、详细住址和消费信息，那么“物件可寻址”也会把人暴露给整个流转链。

2024 年《检察日报》报道中，北京市人大代表宋婷婷描述，过去收到快递后会先撕碎或涂黑面单，因为担心姓名、电话、地址、购买内容等被重新组合识别；在隐私面单推广后，部分姓名、手机号和地址被遮蔽，快递员可以通过扫描订单号发起联系，她不再需要自己处理面单。

来源：

- 检察日报/江苏检察机关转载，2024-11-26：<https://njls.jsjc.gov.cn/wenhua/202411/t20241126_295899.shtml>
- evidence: **A/B：同期制度实践报道 + 具名第一人称；受访者身份特殊，不代表全体消费者**

这代表一种新的基础设施方向：

```text
parcel remains machine-addressable
while person becomes less human-readable on the label
```

也就是：

> **机器仍然能把包裹送到正确的人，路上的每一个陌生人却不必都看到完整的人。**

这是“防守型未来”很典型的变化：不再只是追求更细的 tracking，而是要求状态可见、末端可控、身份暴露更小。

## 7. 这条历史怎样改变四种“未来”

### 2005—2012：扩张型未来

未来想象偏向“更多东西可以远程买、远程寄，而且我不必盲等”。精确节点、在线查询、跨承运商聚合让远处的物件提前进入日常认知。

关键词：

`visibility / speed / coverage / aggregation`

### 2015—2019：拥堵型未来

包裹量和末端压力增加以后，问题从“能不能知道到哪了”转为“状态写着签收，可是谁签的、放哪里了、为什么要我去拿”。

关键词：

`volume / default handoff / locker / pickup labor / consent`

### 2020—2022：偶发型未来

系统外部条件突然改变。单号和网页还在，物流网络却可能不能执行。与此同时，无接触交付把“怎样交给你”也做成状态与协议。

关键词：

`network interruption / contactless handoff / recovery`

### 2023—2026：防守型未来

重点逐渐包括：真正送到约定端点、减少不必要的末端劳动、保护姓名/电话/住址、不让便利本身形成新的暴露。

关键词：

`choice / fallback / privacy / minimization`

## 8. 与“普通人到底有多少种活法”的交叉矩阵

| 维度 | 本轮新增理解 |
|---|---|
| 教育 | 录取通知书、教材、证件等现实物件的远程到达可被跟踪；但本轮未单独研究教育专件 |
| 就业 | 上班时不在家推动柜/站成为时间错配的解决方案，也产生下班后的取件劳动 |
| 住房 | “家”从唯一末端变成家门、前台、门卫、柜、站等多种交付端点 |
| 婚姻家庭/照护 | 有幼儿或照护责任的人，下楼取件的成本与无照护者不同；给家人购买物品也依赖跨地物流 |
| 迁移 | 一个稳定手机号/地址/末端网络让人在陌生城市仍能接收远方物件 |
| 非正规劳动 | 代收点、门卫、小店等可能成为物流系统事实上的末端劳动层 |
| 长期中断 | 疫情说明数据库状态可以存在，而现实网络暂时不可执行 |
| 证件与记录 | 运单号把现实包裹转换成制度可寻址对象；实名寄递又把包裹连接到身份记录 |
| 通信方式 | 电话/热线、网页查询、短信、购物平台、App 通知叠加，而不是一代完全替代一代 |
| 信息获取 | 查询从“问邮局/客服”转成自主反复查看，再转成平台主动通知 |
| 社交关系 | 收件可以委托前台、门卫、家人、同事；“签收者”与真正使用者可以分离 |
| 未来预期 | ETA/节点状态把“什么时候能用到这件东西”变得更可规划，但状态错误也会制造新的落差 |
| 线上/线下身份 | online order/shipment identity 与 physical parcel/recipient possession 必须区分 |
| 平台消失与记忆 | 历史 tracking 记录常受后台保留期、登录、动态查询、单号复用影响，网页壳比真实状态更容易幸存 |

## 9. 反例：tracking 不等于“更轻松”

1. **精确信息可能增加焦虑。** “已经到本地”“正在派送”会缩短心理预期；现实没到时，用户更容易开始刷新与投诉。
2. **扫描点不是 GPS。** 一个包裹两个扫描事件之间可能继续移动；没有新事件不能证明物件静止。
3. **快递柜不是单纯退步。** 对白天无人家庭，它确实减少必须在家等待的同步成本；问题在于是否成为未经同意的默认。
4. **城市经验不能外推农村。** 同一个“到站/到网点”状态，在农村可能意味着额外几十公里或额外费用。
5. **“签收”不是占有。** 前台、门卫、柜、代收点甚至错误投递都可能生成终态文字。
6. **更安全的隐私面单不是“信息更少所以系统退化”。** 它体现的是把人类可读明文减少，同时保留机器路由能力。

## 10. 后见之明风险

- 不把 1994 年“邮政特快专递跟踪查询网”写成普通家庭公众 Web tracking；
- 不把 2005 年网页 URL 的存在写成全国网民已形成查件习惯；
- 不把 2007 年一个投诉个案写成 EMS 普遍服务水平；
- 不把“扫描时间精确到秒”写成物流系统拥有连续、厘米级位置真值；
- 不把 2018—2019 快递柜争议写成所有用户都反对柜/站；
- 不把 2020—2022 的特殊配送协议直接延长成永久日常；
- 不把当前隐私面单覆盖情况倒投到 2015 实名制刚实施时。

## 12. 尚未确定 / 下一步

本轮仍不知道：

- 1994 年 1 月“邮政特快专递跟踪查询网”的准确协议、终端、访问对象与网络边界；
- `ems.com.cn/ems/index.jsp` 在 2005—2007 的真实 DOM、charset、form method、验证码与结果页结构；
- 早期顺丰、申通、圆通等自有 Web tracking 的第一批可验证历史页面与普通用户采用率；
- 2005—2010 普通消费者究竟多大比例会主动查询、平均查询几次；
- carrier 后台事件写入、更新时间与用户页面显示之间的典型延迟；
- 快递100 等聚合器早期如何归一化不同承运商的“揽收/中转/派送/签收”语义；
- 城乡、职业、年龄、是否独居/照护等条件怎样系统性改变“快递柜是便利还是额外劳动”。

这些缺口都比再补一条“某公司何年成立”更值得下一轮深挖。

## 13. 这一轮改变了我们对“人怎么活着”的哪一点理解

一件在路上的东西，过去很容易只存在于两种状态：**寄出去了 / 到了。** 中间几天只能靠经验估算、电话询问和等待。

条码、运单数据库和 Web tracking 把中间过程切成了一串可见事件。普通人第一次可以在身体还没拿到物件时，就把它纳入当天的计划：今天大概会到、下午也许要接电话、下班顺路去柜里拿、如果状态异常就找客服。

但成熟以后，新的问题不再是“能不能看见包裹”，而是：

> **系统说的那个状态，究竟对应谁的现实劳动、谁的地址、谁的时间，以及最后到底是谁真正拿到了东西。**

于是 tracking 并没有消灭等待，只是把等待从纯粹的未知变成了一种可以被不断查询、核验、委托、争议和重新分配的生活状态。
