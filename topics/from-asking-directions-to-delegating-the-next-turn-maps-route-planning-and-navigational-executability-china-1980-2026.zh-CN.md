# 从“到了再问路”到“把下一步交给导航”：地图、路线规划与陌生城市的可执行性（中国，1980—2026）

## 研究问题

一个普通人能不能去一个自己从未去过的地方？

这不是一个纯粹的交通问题。铁路、公路、公交或医院即使真实存在，一个人仍然可能面对另一层约束：

- 不知道入口在哪里；
- 不知道应该坐哪一路车；
- 不知道换乘点在哪；
- 不知道同名地点到底是哪一个；
- 不知道地图是否已经过时；
- 不知道今天这条路是不是堵、封、限行；
- 不知道到达一座陌生城市以后，下一步应该往哪走；
- 即使知道目的地，也未必知道一次面试、看病、探亲、租房或旅行在时间上是否真的可执行。

因此，本专题研究的不是“电子地图产业史”，而是一个普通生活能力：

> **一个人不依赖本地熟人陪同，能否把“我想去那里”变成一条现实中可以执行的路径？**

这会直接影响：

- 求职与面试；
- 异地看病；
- 搬家与租房；
- 通勤半径；
- 旅游；
- 返乡；
- 探亲访友；
- 陌生城市里的独立生活；
- 夜间或紧急情况下的行动；
- 一个人敢不敢把“另一个地方”纳入自己的现实人生菜单。

本专题新增八个分析变量：

- **navigational executability / 导航可执行性**：目的地不仅“存在”，而且个人能独立抵达；
- **route-uncertainty budget / 路径不确定预算**：为迷路、问路、找站、看错地图、错过换乘预留的时间和认知余量；
- **pre-visit computability / 到访前可计算性**：出门以前能否估计路线、换乘、时间和可达性；
- **human fallback layer / 人类后备导航层**：售票员、站务员、路人、亲友、“活地图”、电话咨询等在人机系统失效时承担的路线解释；
- **map–world lag / 地图—现实时间差**：道路、站点、线路、限行、施工已经变化，而地图数据尚未同步；
- **route-choice delegation / 路径选择外包**：从“地图告诉我道路在哪里”转为“系统替我决定下一步走哪条路”；
- **geographic identity resolution / 地点身份解析**：文本地名、地图 POI、坐标、真实入口和用户真正想去的地方并非同一状态；
- **map-as-opportunity-filter / 地图作为机会过滤器**：通勤时间、交通方式和空间距离被提前计算后，工作、住房、医疗或社交机会会在真正出发前就被纳入或排除。

核心边界：

> `目的地可搜索 ≠ 地点解析正确 ≠ 路线计算成功 ≠ 道路今天可通行 ≠ 用户理解路线 ≠ 用户实际按路线行走 ≠ 最终安全抵达。`

以及：

> `地图数据存在 ≠ 普通人有设备/网络可访问 ≠ 使用已经普及 ≠ 现实行为已经围绕导航重组。`

## 1. Internet 以前：找路早已有完整的信息基础设施，只是它往往是纸、人和公共设施的组合

### 1.1 纸地图不是“落后的 GPS”，它承担的是当时最现实的可携带空间记忆

北京地图收藏研究留下了一个很具体的物质锚点：1980 年的《北京交通图》已经包含地铁示意图；1995 年出版的《北京市区立交桥行车导向图》专门处理城市立交桥容易让驾驶者走错的问题，定价 3.50 元、印数 10 万张。后来的回顾还指出，在没有手机导航的条件下，这类专用导向图对驾驶员非常实用。[北京青年报/人民网，2018-12-17](https://culture.people.com.cn/n1/2018/1217/c1013-30470907.html)。

这是一份**后来的物质史回顾（C，地图实物本身若另行核验可升为 A）**。它不证明每个北京家庭都买过交通图，但提醒我们：

```text
陌生城市可达性
不是从 GPS 出现才开始
```

当时的基础设施包括：

- 折叠交通图；
- 公交线路手册；
- 电话簿中的公交信息；
- 公交站牌；
- 路边交通图；
- 车站售票员与站务员；
- 出租车司机；
- 路人和熟人；
- 事先抄在纸上的地址与换乘说明。

上海 1990—1996 年的公交资料回顾中仍能看到“1990 年乘车手册”“1992 年交通指南”“1993 年电话簿公交信息”“1994 年交通指南”等不同纸质入口。[上海公交历史资料整理，2023](https://finance.sina.cn/2023-05-20/detail-imyukzcx0796407.d.html)。

这些后来的整理不是普通家庭采用率数据，但它们证明：**在 Web 以前，城市路线信息已经可以被外置到纸张和公共信息设施，而不是只能寄存在本地人的脑子里。**

### 1.2 纸地图也存在 `map–world lag`

北京地图收藏者魏有华特别指出，地图内容会滞后于真实交通变化；他每年购买新版地图，正是因为城市道路和轨道网络持续改变。[浙江省交通运输厅转载北京青年报，2018-12-17](https://ct.zj.gov.cn/art/2018/12/17/art_1652991_35098866.html)。

因此今天常被当作“导航 App bug”的一类问题，其实有更长的历史：

```text
现实道路已经改变
→ 信息载体尚未更新
→ 用户根据旧状态做出错误路线判断
```

数字地图后来缩短了更新周期，却没有消灭这个结构。

## 2. 中国网络边界必须严格拆开：1994 之前并非“没有数字通信”，1994 之后也并非普通家庭立刻在线查地图

中国在 1994 年 4 月 20 日通过 64K 国际专线实现与 Internet 的全功能连接；CNNIC 的历史大事记同时记录，此前后已有科研网络、电子邮件、`.CN` 域名和校园网络建设。[CNNIC，1994—1996 大事记](https://www3.cnnic.cn/n4/2022/0401/c87-912.html)。

因此本专题使用以下阶段：

1. **Internet 全功能接入之前**：纸地图、公交手册、电话、公共站牌、熟人和已有科研数字网络并存，但普通人的找路事务主要不依赖全球 Internet；
2. **1994 全功能接入**：国家网络能力发生关键变化，但不等于家庭地图使用立刻数字化；
3. **1997—2001 的光盘/信息亭/早期 Web 地图**：部分城市用户开始直接查询电子地图；
4. **2000s desktop Web 路线规划**：地点搜索、公交换乘和路线计算逐渐成为浏览器任务；
5. **2000s 后期手机/GPS**：路线信息开始随身体移动；
6. **2010s 智能手机实时导航**：路线从“出发前查”变成“途中持续重算”；
7. **2020s 地图平台化**：地图不只回答“怎么走”，还叠加疫情、招聘、打车、景区、实时公交、限行、拥堵和生活服务。

后面的变化不能反向证明 1990 年代早期普通人已在网络地图上生活。

## 3. 1997—2001：电子地图先从光盘、信息亭和昂贵的 Web 查询进入日常生活

### 3.1 光盘电子地图是一个重要的中间态

北京日报历史资料回顾记载，1997 年推出的“北京通”光盘提供可缩放的大比例尺电子地图，可查询 3136 条有名街道、胡同和 1130 个居民小区；到 2001 年，相关地图服务又进入 Web，可按“路名＋门牌号”“小区名＋楼号”等方式定位。[北京日报“温故”，2025](https://xinwen.bjd.com.cn/content/s67bfa0a8e4b068c68f104f2d.html)。

这个中间态特别重要：

```text
纸地图
→ 本机光盘数据库
→ 联网地图数据库
```

它说明“电子化”和“联网化”不是同一天发生的。

光盘已经可以让一个人搜索，而不只是凭视觉在整张纸上找；但地图更新仍需要重新发行介质。

### 3.2 2000 年的同时代报道已经看到 Web 地图，同时也明确记录了它的可及性边界

2000 年 8 月《中华读书报》介绍中国早期网上电子地图时写到：成立于 1999 年 5 月的图行天下（Go2Map）已为新浪、114China 等网站提供嵌入地图服务，并开展城市 POI、公交换乘和门牌号码调查；但报道同时明确指出，网上电子地图普遍速度不快，而当时上网费用仍高，对“钱包不鼓”的网民来说，在线查地图“还显得有些奢侈”。[《数字时代的网上电子地图》，光明网，2000-08-02](https://www.gmw.cn/01ds/2000-08/02/GB/2000%5E311%5E0%5EDS1704.htm)。

这是非常重要的**同时代 B 级材料**，因为它同时保存了“功能存在”和“普通使用仍有成本”两件事。

不能写成：

> 2000 年中国人已经可以随时上网查路线。

更准确的是：

> 一部分联网用户已经获得新的路线查询方式，但速度、上网费用、设备和网络覆盖仍决定它是否值得为一次问路而使用。

### 3.3 早期数字地图也可以通过公共终端而非家庭 PC 到达普通人

2007 年长沙的同期报道提出，在车站、医院、商场等公共地点设置电子地图触摸屏，公众可查询路线与周边生活信息，规划到 2008 年布设大量终端。[潇湘晨报，2007-01-01](https://news.sohu.com/20070101/n247356316.shtml)。

这提醒我们继续保留 **service access** 这一层：

```text
家庭没有电脑/宽带
≠
完全没有机会使用数字地图
```

公共信息亭、单位电脑、网吧和手机可以形成不同的接入路径。

## 4. 海外前史：路线计算并不是 World Wide Web 发明的

### 4.1 法国 Minitel 在 1988 年已经提供道路行程计算

法国科学传播机构 Espace des sciences 的 Minitel 史料指出，1986 年 8 月已经安装超过 185 万台 Minitel；1988 年 `Iti` 服务开始提供道路 itinerary 计算，后来演化为 Mappy。[Espace des sciences，2011](https://www.espace-sciences.org/sciences-ouest/292/actualite/le-minitel-a-30-ans)。

《Le Monde》后来回顾 1980 年代 Minitel 用户使用 `3615 iTi` 的经验时指出，用户可以获得路线细节，甚至打印或要求通过邮政寄送。[Le Monde，2020-11-03](https://www.lemonde.fr/economie/article/2020/11/03/avec-le-rachat-de-mappy-la-ratp-s-offre-un-navigateur-numerique-a-la-francaise_6058320_3234.html)。

这形成了一个非常有意思的混合信息链：

```text
在线终端计算路线
→ 打印 / 邮寄到纸
→ 人带着静态路线出门
```

因此“在线计算、离线执行”比 Web 更早。

### 4.2 MapQuest 再把服务器端路线计算交给 Web 浏览器

MapQuest 的企业谱系可以追到 1960s 的纸质/数字制图业务，1996 年 `MapQuest.com` 上线后把在线地图和路线规划推向大众 Web。[Washington Post，2015-05-22](https://www.washingtonpost.com/business/economy/does-mapquest-still-exist-as-a-matter-of-fact-it-does/2015/05/22/995d2532-fa5d-11e4-a13c-193b1241d51a_story.html)。

这里的跨国共同机制不是“大家同时发明地图网站”，而是：

> **城市流动性增加以后，普通人越来越需要在真正抵达陌生地点以前，就把路线变成可计算对象。**

法国 Minitel、美国 MapQuest 与中国 Go2Map 的技术和市场环境不同，但都在压缩同一种不确定性。

## 5. 2004—2010：路线查询从“看地图”变成“输入起点和终点，系统给出路径”

### 5.1 Go2Map 已经跨 Web、电话中心、手机和 PDA，而不是单一网页产品

搜狐 2005 年收购 Go2Map 的官方材料称，其地图信息平台可服务于 Internet/Intranet、手机、call center 与 PDA，数据库覆盖 200 个城市 POI。[Sohu SEC 文件，2005-04-12](https://www.sec.gov/Archives/edgar/data/1104188/000119312505075385/dex991.htm)。

这条 **A 级公司同期文件**可以证明平台当时的能力与渠道设计，但不能单独证明普通人规模采用。

它再次说明：

```text
网络地图基础设施
可能在一个从未打开地图网站的人身后工作
```

例如电话坐席可以替来电者使用同一套空间数据库。

### 5.2 纸、电话与 Web 在 2008 年仍然并行

广州 2008 年准备向家庭发放大量免费公共交通指南，同时通过“坐车网”和免费电话 `96900` 提供公交路线查询。[信息时报/新浪，2008-05-09](https://news.sina.com.cn/c/2008-05-09/040615498644.shtml)。

这条材料非常适合反驳线性“技术替代史”：

```text
印刷指南
+ 电话咨询
+ Web 路线查询
```

并不是三个互相排斥的时代，而是同一个普通家庭在同一年可以使用的冗余栈。

### 5.3 2008 年的“公交活地图”证明人类并没有因为 Web 存在而退出系统

《新京报》报道，北京天通苑 28 岁居民穆青因为熟悉公交路线，经常接到邻居电话问路；他还花数月实地调查错误站名与线路信息，自制公交导航图。[新京报/新浪，2008-12-29](https://news.sina.com.cn/c/2008-12-29/023216940597.shtml)。

这是一条**同时代人物材料（B，含同期自述）**。它说明：

> `online map available ≠ all local knowledge already encoded correctly`。

一个熟悉路线的人仍可能是数字系统的 fallback，甚至是纠错者。

### 5.4 搜索引擎逐渐成为“找地图”的入口

2009 年杭州的一篇同期生活报道里，作者描述同事先在 Google 搜“杭州公交”来设计从滨江去市中心的公共交通路线。[都市快报，2009-04-22](https://news.sina.com.cn/s/2009-04-22/062715508313s.shtml)。

这件小事很重要：

以前是：

```text
我先知道应该买哪一本交通图
```

后来变成：

```text
我只需要知道自己要解决“怎么去”
→ 搜索引擎替我找到公交/地图服务
```

空间信息的入口本身也被重新外包。

## 6. 旧 Web 的真实技术边界：地图页面不是一张可以完整存下来的图片

### 6.1 2008 年北京公交路线页留下了 JSP、参数化查询与 Flash/IE 风险

2008 年一篇关于北京公交网站安全问题的同期报道描述，用户进入 `bjbus.com` 后可以在页面右侧输入起点和终点查询路线；报道还记录了类似 `busmap/map.jsp?...Start=...&End=...` 的动态查询 URL，并称页面当时涉及 `.swf` 子资源与 IE 安全风险。[赛迪网，2008-06-26](https://news.sohu.com/20080626/n257759756.shtml)。

这对旧网考古非常关键：

一个“公交地图页面”可能同时依赖：

- JSP/服务器端查询；
- 起点终点参数；
- 路线数据库；
- JavaScript；
- Flash 子资源；
- 浏览器安全模型；
- 服务器当时的动态响应。

所以 archive 今天只留下 HTML shell，并不等于当年一次路线查询事务已经保存。

### 6.2 2009 年百度地图还使用 Flash 展示地铁线路

2009 年百度地图升级的同期报道提到搜索建议、道路/地点搜索，以及 Flash 地铁线路图等功能。[每日经济新闻，2009-08-25](https://tech.sina.com.cn/i/2009-08-25/02283372291.shtml)。

因此现代浏览器今天打开同一历史页面，即使正文仍在，也可能完全失去当时用户看得到的交互层。

这正是 old-web 方法里“浏览器也是史料环境”的典型对象。

## 7. 2010 年的强反例：GPS 在手，也仍然可能因为现实更新快于地图而迷路

2010 年全国高速公路编号调整后，浙江在线/《今日早报》记录了一名网名 `chunyise` 的用户经验：他在高速路上看到新的 `G2` 等编号时，车载 GPS 还无法识别，一度怀疑自己是否走错，只能再打电话问朋友。[浙江在线/搜狐，2010-04-14](https://news.sohu.com/20100414/n271504031.shtml)。

这是一条很好的**同时代第一人称材料（B，媒体引用论坛自述）**。

它把现代导航的三层现实分开：

```text
GPS 能定位设备
≠
地图数据库已经知道新编号
≠
用户能把现实路牌与屏幕路线对应起来
```

所以：

> **“带着导航”并不等于“不再需要知道自己在哪里”。**

这类 `map–world lag` 在纸地图时代存在，在联网导航时代也继续存在，只是更新周期缩短了。

## 8. 2005—2012 的扩张型未来：陌生地方第一次更容易在出发前被纳入现实菜单

这一时期的“扩张”不应该写成“年轻人因为有地图所以更乐观”。更窄、更可验证的变化是：

> **一个陌生地点可以先被计算，再决定要不要去。**

以前一次异地机会可能需要：

```text
先知道地址
→ 找纸地图
→ 问熟人/车站
→ 到附近再继续问
→ 给迷路预留很多时间
```

Web 地图以后逐渐可以：

```text
输入地址
→ 看附近道路/公交
→ 估计换乘
→ 打印/抄下路线
→ 再决定出发时间
```

这会降低以下机会的**前置不确定性**：

- 去不熟悉城区面试；
- 去陌生医院；
- 去新租房处看房；
- 和网上认识的人线下见面；
- 去从前没去过的景点；
- 去一个距离看似很远但实际换乘方便的地点。

这并不意味着机会本身变多，而是某些原本模糊的机会变得**更容易判断是否可执行**。

## 9. 2015—2019 的拥堵型未来：地图从“告诉你怎么走”升级为持续管理通勤与路线冲突

### 9.1 2018—2019 年的地图已经不是静态参考，而是一个实时路径管理器

2018 年百度地图发布的服务已经强调出行前预测拥堵、提醒出发时间、出行中调整路线等能力。[人民网，2018-09-20](https://auto.people.com.cn/n1/2018/0920/c1005-30304752.html)。

2019 年高德又推出“通勤地图”，在上下班前主动提供通勤时长、实时公交、路况和突发事件等信息。[中国日报网，2019-03-04](https://tech.chinadaily.com.cn/a/201903/04/WS5c7cc69fa31010568bdcd46f.html)。

于是路线信息从：

```text
需要时主动查一次
```

变成：

```text
每天重复的上下班未来
被系统持续预测并推送
```

这是一种新的时间结构：**rolling route future / 滚动路线未来**。

### 9.2 路线甚至成为司机和乘客之间需要协商的“可见决策”

2019 年滴滴开始试行让乘客在上车前或行程中从最多三条路线中选择，并显示预计时间、距离、路况与红绿灯数量；平台明确把减少司乘因路线选择发生的纠纷列为目的之一。[中新网/人民网，2019-03-04](https://industry.people.com.cn/n1/2019/0304/c413883-30956987.html)。

这意味着地图不再只是“方向工具”，而变成一次服务交易里的**争议协调界面**。

过去：

```text
司机说这条更快
乘客凭经验怀疑绕路
```

后来：

```text
平台展示候选路线
→ 乘客选择
→ 选择同步到司机端
```

这里出现了 **route-choice delegation** 的第二阶段：不仅路线交给算法计算，连人与人之间“为什么走这条”的责任分配也开始由界面记录。

### 9.3 大规模使用不能只靠厂商口号证明

QuestMobile 数据经中新网报道显示，2019 年 9 月高德地图月活跃用户超过 4.8 亿。[中新网，2019-10-31](https://www.chinanews.com.cn/m/it/2019/10-31/8994589.shtml)。

这可以证明移动地图已进入大规模使用阶段，但仍应注意：

- MAU 是设备/账户层平台指标，不等于 4.8 亿独立普通人；
- 使用地图 App 不等于每天都导航；
- 驾车导航、公交查询、步行、打车、景区导览是不同使用场景；
- 城乡、年龄和设备能力仍有差异。

## 10. 2019 的一个反例：功能落地并不等于用户知道、会用、愿意用

2019 年《新京报》实地探访北京医院院内导航，发现部分医院已经有 App、小程序或导诊机，但知晓率不高、部分患者不会使用、室内信号也会影响体验；很多患者仍直接问工作人员。[中新网转载《新京报》，2019-06-27](https://www.chinanews.com.cn/sh/2019/06-27/8876365.shtml)。

这再次验证：

> `导航功能存在 ≠ 普通患者独立完成院内找路。`

对老人、视力障碍者、不会用智能手机的人来说，人工问询台并不是“数字化还没做完”的残余，而是系统的 **human fallback layer**。

## 11. 2020—2022 的偶发型未来：地图突然不只回答“怎么走”，还回答“那里现在是否值得去”

### 11.1 疫情把空间本身变成一种不断变化的风险状态

2020 年 2 月，百度地图等地图服务把发热门诊、病例活动场所、疫情小区等信息叠加到空间界面。人民日报海外版/新华网留下了一条很好的同期第一人称材料：准备从山东老家返京的李颖因为担心北京住处周边疫情，在百度地图“疫情小区”中查询附近病例与人流聚集地点后才稍感放心。[新华网，2020-02-19](https://www.xinhuanet.com/politics/2020-02/19/c_1125593566.htm)。

这里发生的是一次重要转折：

```text
地图：那里在哪里？
→
地图：那里现在是什么状态？
```

路线规划第一次大量吸收了通常不属于地图本身的社会状态。

这正符合“偶发型未来”：原本稳定的目的地 suddenly 变成条件式的——

> **我不是只想知道怎么回北京，而是想知道我现在回去以后，周围是什么情况。**

### 11.2 地图也开始把工作机会直接变成空间筛选

泰兴 2020 年 12 月上线“智慧就业地图”，把本地企业、招聘岗位、电话沟通、线上面试和一键导航放进同一套服务。[江苏省委新闻网/泰州日报，2021-01-06](https://www.zgjssw.gov.cn/shixianchuanzhen/taizhou/202101/t20210106_6938168.shtml)。

这里产生了 `map-as-opportunity-filter`：

```text
岗位是什么
+
它在哪里
+
我怎么去
```

不再需要由求职者自己在几个系统之间手工拼起来。

它没有证明全国求职在 2021 年都“地图化”，却展示了一条新的可执行路径。

## 12. 2023—2026 的防守型未来：当导航已经成为默认基础设施，新的能力是给算法设边界、检查异常和保留退路

### 12.1 防守不等于不用导航，而是把“别让我走错”看得比“功能更多”更重要

2025 年上海车主高先生向媒体反映，他在地图 App 中启用了“避开限行”等设置，却仍被导航带入限行高架并收到处罚；后续维权时平台又称后台没有查到相应记录。[扬子晚报/紫牛新闻，2025-08-12](https://www.yzwb.net/news/sh/202508/t20250812_249124.html)。

这是一条**同期第一人称纠纷材料（B）**，不能由此推断导航普遍不可靠，但它非常适合证明一种新的依赖结构：

```text
用户把法规约束输入系统
→ 系统给出路线
→ 用户把“是否合法”部分外包给导航
→ 现实处罚仍由用户承担
```

因此：

> `avoid-restriction option enabled ≠ every computed route legally valid`。

当路线选择越来越外包，用户需要的“防守能力”反而包括：

- 核对关键限制；
- 对异常路线保持怀疑；
- 保留截图/订单/轨迹等证据；
- 知道人工申诉渠道；
- 在网络/定位失效时仍有备用办法。

### 12.2 地名解析本身也可能把一个人的现实路线送到完全不同的地方

2024 年底发生、2025 年报道的一起网约车事件中，用户原本要前往广东深圳至汕尾一带的同名目的地，却选中了山东日照的同名地点，订单价格因此达到数千元；平台后续识别异常并冻结了司机提现。[红星资本局经 IT之家转述，2025-01-12](https://www.ithome.com/0/824/573.htm)。

这个案例最值得研究的不是猎奇，而是 **geographic identity resolution**：

```text
用户输入一个名字
≠
系统知道用户脑中指的是哪一个地方
```

现代地图把“找到地方”做得极其容易以后，同名地点、错误 POI、错误入口、园区内部位置反而成为新的边界问题。

### 12.3 “防守型未来”的空间形式：先把通勤和退出成本算清楚

今天租房、换工作、选择城市时，“通勤多少分钟”越来越容易在真正签约前被计算。这里应谨慎：地图不是住房选择变化的唯一原因，也没有证据证明所有年轻人都因此变得更保守。

更可靠的表述是：

> **当一个人已经倾向于给未来保留退路时，数字地图提供了一种把空间风险提前量化的方法。**

以前“离公司有点远”需要本地经验；现在它可以被转成 42 分钟地铁、一次换乘、最后 1.3 公里步行。

这让“不要把每天两小时押给通勤”成为一个更容易执行的个人规则。

## 13. 四种未来时间感在地图里的可比较形式

| 时段 | 主要机制 | 典型地图关系 | 不能偷换成什么 |
|---|---|---|---|
| 2005–2012 扩张型未来 | 陌生地方变得可在出发前计算 | Web 路线、公交换乘、打印/抄路线、GPS | 不是“年轻人整体更乐观” |
| 2015–2019 拥堵型未来 | 每日通勤与拥堵变成持续优化对象 | 实时路况、通勤预测、语音导航、路线协商 | 不是“算法解决了城市拥堵” |
| 2020–2022 偶发型未来 | 地点本身突然获得风险/开放状态 | 疫情小区、发热门诊、出行政策、就业地图 | 不是“危机期功能代表永久偏好” |
| 2023–2026 防守型未来 | 将规则、风险、时间和退出条件提前写入路线 | 避限行、实时提醒、异常检查、通勤阈值 | 不是“所有人都悲观或不愿出门” |

这四段不是互斥的文化人格，而是同一种路线基础设施在不同外部条件下承担的任务发生了变化。

## 14. 互联网真正改变了哪些生活行为？

### 14.1 没有改变：人仍然必须穿过真实空间

地图无法替你完成：

- 走最后一公里；
- 穿过医院楼群；
- 识别临时封路；
- 处理信号盲区；
- 发现错误入口；
- 面对一个现实里已经撤掉、改名或关闭的站点。

### 14.2 改变之一：把迷路从“到现场以后才暴露的问题”提前成“出发前可以计算的问题”

这会影响一个人预留多少时间，以及他是否敢去。

### 14.3 改变之二：把熟人的地方知识变成可查询公共知识

过去：“问住在那边的人。”

后来：“搜地点、看公交、看评论、看入口。”

这降低了对本地熟人的依赖，但没有把人类 fallback 完全消灭。

### 14.4 改变之三：把路线从静态说明变成实时决策

Web 地图最初告诉你“应该怎么走”；手机导航越来越直接告诉你“下一步右转”。

这让路线认知从：

```text
先在脑中建立整体地图
```

转向：

```text
持续接收下一步指令
```

从生活史角度，这是一种认知劳动外包。

### 14.5 改变之四：把空间距离变成人生选择里的即时变量

求职、租房、看病、社交、旅游都能更快回答：

> “从我现在住的地方过去到底要多久？”

这不一定扩大选择；有时它反而让一个人更早排除不值得承受的路线。

## 15. 反例与纠偏

### 反例 A：有地图不等于不问路

2019 年北京医院智能导航已经存在，患者仍大量询问工作人员。技术与人工可以长期共存。

### 反例 B：有 GPS 不等于地图最新

2010 年高速编号更新造成 GPS 数据与现实路牌脱节。

### 反例 C：路线计算成功不等于路线合法或可通行

限行、施工、临时管制和现场条件可以让“数学上有一条路”失去现实可执行性。

### 反例 D：大规模 MAU 不等于每个人都获得同样的导航能力

老人、残障者、低端设备用户、无数据网络区域、地下/室内空间仍可能需要额外 fallback。

### 反例 E：越精准的导航不必然让人拥有更多自由

它也可能让一个人每天围绕“最快路线”“少几分钟”持续优化，把城市拥堵转化成个人注意力负担。

## 16. 历史可见性：我们最容易保存“地图产品”，最难保存“一次普通人的真实找路”

旧 Web 留下的往往是：

- 地图网站首页；
- 产品发布新闻；
- 城市列表；
- 查询表单；
- 教程；
- 厂商宣称的覆盖率。

最容易消失的却是：

- 用户那天输入的起点和终点；
- 当时返回的具体路线；
- 当时道路数据库的版本；
- 地图 tile；
- Flash/JS 子资源；
- 用户打印出来后手写的补充；
- 打电话问朋友的最后一步；
- 路口临时封路；
- 走错以后现实中怎样纠正；
- 没有使用地图的人。

所以：

> **historian-visible map service ≠ historical route experience。**

而且这是一个隐私上有必要的缺口：普通用户的起终点查询、家庭住址和移动轨迹本来就不应该为了“考古完整”被批量重新公开。

## 18. 后见之明风险

### 风险 1：把纸地图写成“等待被手机淘汰的旧技术”

错误。纸地图在它的成本、续航、离线性和公共可得条件下可能是当时更可执行的方案。

### 风险 2：把 1999 Go2Map 存在写成中国家庭普遍在线导航

错误。2000 年同期报道自己就强调速度和上网费用门槛。

### 风险 3：把 GPS 定位写成“系统知道道路现实”

定位、地图数据、道路状态和用户目的地是四层不同信息。

### 风险 4：把 2020 疫情地图倒推成地图长期主要功能

危机期是异常 substitution / augmentation，不能代表长期偏好。

### 风险 5：把路线推荐当成中立数学结果

“最快”“最短”“少收费”“少红绿灯”“避限行”都包含不同目标函数；普通人可以有完全不同的偏好。

## 19. 尚未确定

1. 1997—2001 北京“北京通”、Go2Map、早期公交 Web 查询的家庭/网吧实际使用分布仍缺乏强分母；
2. 2000s 早期地图查询中，用户打印、抄写、短信转发路线各占多大比例，尚未建立；
3. 早期 WAP/手机地图的资费、终端兼容和真实使用率还需更多运营商材料；
4. 农村、县城和低线城市在路线数字化中的时间差仍不够；
5. 老人、视障者等群体的地图可执行性与现有无障碍专题如何交叉，还需要独立证据；
6. 地图服务如何改变异地求职、看房、就医的**实际成功率**目前没有因果证据；
7. 历史地图 tile、动态查询结果和服务端路线图数据库的可保存性需要与 `old-web-archaeology` 继续联合验证。

## 20. 这一专题改变了什么理解？

过去我们容易把“一个人能不能去另一个地方”理解成交通供给问题：有没有公路、公交、地铁、火车。

但现实生活里还存在一层更细的基础设施：

> **我知不知道自己下一步该往哪里走。**

一张纸地图已经可以把陌生城市的一部分知识从本地人脑中拿出来；光盘让地点可以搜索；Web 让起点和终点被计算；GPS 让坐标跟着身体走；手机导航最后开始持续决定下一步。

于是现代迁移和城市独立生活获得了一种很不起眼的能力：

> **一个人不必先认识那里的人，才敢去那里。**

但当路径越来越交给系统以后，自由的边界又重新移动。今天的新问题不再只是“我会不会迷路”，还包括：系统解析的是不是我真正想去的地方、道路状态是不是最新、它给我的路线是否合法，以及当它错了以后，我是否还有别的办法。

地图没有消灭陌生世界。它只是把一部分“我不知道怎么去”的不确定性，转换成了“我愿不愿意相信这一条计算出来的路”。
