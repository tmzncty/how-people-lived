# 从车站排队、电话订票到 12306：铁路可购票性、返乡可执行性与移动选择权（中国，1996–2026）

> 研究问题：一条铁路已经存在、一个人也想回家，并不等于这趟回家已经成为现实选项。对于外出务工者、学生、探亲者和普通家庭来说，什么时候才能把“我春节想回去”转换成一张真正拿得到、付得了、能进站、而且列车实际运行的票？

## 0. 范围与结论预览

这不是中国铁路发展史，也不是 12306 产品史。本专题只研究普通生活里的一个狭窄接口：**出行意愿怎样变成可执行的铁路移动。**

它与本仓已经完成的汇款专题正好形成一组互补问题：钱能否不跟着身体一起回家，是迁移生活的一面；身体本身能否在需要时回家、返城、返校，则是另一面。

本专题提出几个工作概念：

- **ticketability / 可购票性**：并非“有火车”，而是特定日期、区间、席别和乘车人能够找到、锁定、支付并取得有效运输权利；
- **return-home executability / 返乡可执行性**：单位/学校放假、路线、车票、身份证件、车站接入和列车运行同时成立，返乡意愿才真正可执行；
- **mobility scheduling horizon / 移动计划视野**：一个人能提前多久把“以后要走”变成有保障的运输安排；
- **queue displacement / 排队迁移**：数字化可能把售票厅前的身体排队转移成电话占线、网页并发、验证码、刷新和候补队列，而不是消灭稀缺；
- **route decomposition / 路径拆分**：直达票不可得时，把旅程拆成若干区间，通过中转重新获得移动可能；
- **socially distributed booking labor / 社会化购票劳动**：家人、工友、同学、公司、第三方平台共同承担搜索和抢票，而不是每个乘客独立完成；
- **scarcity-queue formalization / 稀缺队列正式化**：从不断刷新、反复拨号，到候补系统明确记录“未来若释放席位，我排在队列中”；
- **mobility option value / 移动选择权**：改签、退票、候补、多日期/车次需求、特殊预约等功能，不只卖一张票，也保存以后改主意或遭遇变化时的选择；
- **allocation-rule visibility gap / 票额规则可见性差**：页面“无票”并不必然等于列车在所有区段物理上没有空席，它也可能来自区段票额分配和销售策略。

核心结论是：

> **迁移成为一种可长期重复的生活方式，不只因为铁路把两地连起来，也因为普通人逐渐能在离车站很远的地方，把下一次返乡和下一次返城提前变成一项较可预测的权利。**

与此同时，售票数字化从未等于运力充足。它不断重写的是“怎样排队、谁能提前计划、谁替谁操作，以及计划失败时还有多少退路”。

## 1. 永久保留的状态链

不要把“买到火车票”写成一个瞬间。至少区分：

```text
need / desire to travel
!= work / school leave available
!= route and date known
!= train scheduled
!= sales channel accessible
!= inventory allocated to that origin-destination segment
!= query renders availability
!= identity / passenger eligibility accepted
!= order request accepted
!= inventory actually held
!= payment instruction accepted
!= payment settled
!= ticket / transport entitlement issued
!= required paper / ID usable at station
!= train operates as planned
!= passenger reaches station in time
!= gate accepts passenger
!= passenger actually boards
!= connection succeeds
!= final destination reached
```

还要长期保留下列边界：

- `rail line exists != a useful train is scheduled`
- `train scheduled != ticket sellable to this origin-destination pair`
- `query shows seat != order can still lock it`
- `order submitted != ticket issued`
- `bank debited != ticket issued`
- `ticket issued != train operates`
- `Web purchase != paperless boarding`
- `account registered != identity verified`
- `ID accepted online != station supports direct ID entry`
- `refund status displayed != money returned`
- `no ticket displayed != no physical seat anywhere on the train`
- `service available != user knows it != user can operate it != user chooses it`

这套状态差能防止我们把“铁路信息化”直接写成“普通人出行已经无摩擦”。

## 2. 1996–2004：铁路售票先在柜台后面数字化

2012 年铁路客票系统建设者的同期说明，把系统源头追溯到 1996 年列入“九五”国家科技攻关计划，并区分了几个版本：1.0 用计算机售票替代人工硬板票，2.0 实现区域联网，3.0 实现全国联网售票，之后又加入清分清算、席位复用、实名制、电子客票和电子支付。到 2012 年，这一核心系统已经同时支撑车站窗口、代售点、自动售票机、电话订票和互联网售票。

来源：

- **A/B / near-contemporary railway-system account**：人民网稿，CNTV 留存，2012-01-13。  
  https://jingji.cntv.cn/20120113/115500.shtml

这条历史最重要的生活史意义不是“1996 年大家开始网上买票”，恰恰相反：

> **后台全国联网可以先改变一个售票窗口能看见什么，而普通旅客仍然完全站在实体柜台前。**

当“本窗口只能卖本地有限票种”逐步变成“窗口可以查询和销售更大范围的全国席位”，首先扩大的其实是 **ticket inventory addressability / 票额可寻址性**。

这与邮政电子汇兑的路径类似：普通人的界面仍可能是一块玻璃后的工作人员，真正改变可执行性的网络已经藏在柜台后面。

### 后见之明风险

- 不能把 1996 年客票系统立项日期写成全国联网完成日期；
- 不能从铁路内部网络化推出家庭 Internet 可及；
- 不能从“全国联网售票”推出所有窗口、所有车次、所有区段在同一天具有同样能力；
- 不能把后来 12306 的字段和交易状态倒投回 1990s。

## 3. 海外前 Web 对照：法国 Minitel 已经证明“远程订座”不等于“没有稀缺”

法国铁路提供了一个非常有用的前 Web 对照。法国参议院 1988 年收到的质询及 1989 年政府答复明确说，TGV 订座当时可以通过车站窗口、旅行社、快速售票设备和 **Minitel** 完成，而这些渠道连接的是同一个中央订座服务器；没有哪一个渠道拥有一套独立的“网上票额”。电话或 Minitel 订座若没有按时取票，席位还可能在开车前重新释放。

来源：

- **A / official contemporaneous parliamentary record**：French Senate, question 1988 / response 1989。  
  https://www.senat.fr/questions/base/1988/qSEQ881202718.html

1990 年《世界报》又记录法国部分地区试验通过 Minitel 查询、订座并直接支付 SNCF 车票，但需要芯片卡和专用读卡设备，设备价格被认为过高，采用并不理想。

来源：

- **B / contemporaneous press**：Le Monde, 1990-02-21。  
  https://www.lemonde.fr/archives/article/1990/02/21/monetique-les-dispositifs-anti-fraudeurs-se-multiplient-pour-payer-par-minitel-en-toute-securite_3957116_1819218.html

这个对照至少说明三件事：

1. 家庭远程订铁路票早于 World Wide Web；
2. 新渠道可以减少去窗口的次数，却不能凭空创造席位；
3. `技术可实现` 与 `设备负担得起、普通家庭真的采用` 仍然是不同层级。

中国后来出现的电话订票、12306 和移动端，应放进这一更长的“远程访问稀缺运输权利”的历史，而不是写成 Web 独有发明。

## 4. 2005–2012：扩张型未来——排队从车站向电话和网页迁移

### 4.1 电话订票：身体不用到售票厅，但“队”还在

2000s 中后期，春运电话订票让一部分旅客能够在住处或工作地先争取运输权利，再到指定点取票。它减少的是售票厅前的身体占位成本，却会把同一批同步需求压进有限电话线路。

2012 年铁路方面回顾当年电话客服时仍能看到这种结构：仅 1 月 1–11 日人工电话呼入合计 206 万人次，接通 90.2 万个，接通率 43.9%；互联网和电话并行以后，电话仍然存在明显“打不进去”的时段。

来源：

- **A/B / near-contemporary system account**：人民网稿，CNTV 留存，2012-01-13。  
  https://jingji.cntv.cn/20120113/115500.shtml

因此更准确的表达不是“电话消灭了排队”，而是：

```text
station-body queue
→ remote call-attempt queue
```

这就是本专题的 **queue displacement**。

### 4.2 2008 张高阳：直达票消失以后，路线本身被重新设计

2008 年 1 月《东方早报》记录工人张高阳的第一人称返乡经历。他原本计划从上海直接回洛阳，在车站排了几个小时后才得知直达票已经没有，一度准备给父母打电话说春节回不去了。工友随后建议从徐州中转，他先买到了上海到徐州的票，并把这种选择理解成“多走一步就离家近一点”。

来源：

- **T1 / B / contemporaneous first-person interview**：东方早报，2008-01-30，新浪留存。  
  https://news.sina.com.cn/o/2008-01-30/041113350724s.shtml

这条材料非常重要，因为它显示：**票额不仅决定“走不走”，还会改变普通人的路线算法。**

当一个旅程不能作为一个完整商品获得时，人会主动把它拆成：

```text
上海 → 徐州
徐州 → 更接近家乡的下一段
→ 洛阳
```

这就是 `route decomposition`。现代搜索界面里的“中转方案”后来把一部分原本由工友经验承担的认知劳动正式化了。

### 4.3 2008 农民工往返票：第一次把“节后还要回来”提前变成售票对象

2008 年铁路首次在部分地区集中办理农民工往返票。规模达到 100 人以上的企业可以为职工办理返乡和节后返城硬座票，返程日期被提前纳入春节前的安排。

来源：

- **B / contemporaneous report**：工人日报，2008-01-09。  
  https://news.sohu.com/20080109/n254534722.shtml

这不应写成“所有农民工都能提前锁定返程”，因为它有企业规模、地区、车次和组织资格限制。它真正扩大的是 **mobility scheduling horizon**：

> 对一部分劳动者来说，回家以前就能把“过完年我怎样重新进入城市劳动市场”一起安排。

这种基础设施直接连接了家庭日历与工作日历。

### 4.4 工作市场变差，也会提前改变返乡日期

2008 年 11 月金融危机背景下，同期报道中的外出务工者已经把“活不好找、钱不好赚”和“早点回去，免得春运挤不上车”放在同一个决定里。

这是一条很值得保存的未来想象样本：**未来一个月的车票稀缺，会反向改变今天是否继续留在城市等工作的选择。**

它提醒我们，交通不是在“决定返乡以后”才开始发挥作用。对工资不高、假期有限、家很远的人，未来运力本身就是今天劳动决策的一部分。

### 4.5 2011：12306 把查询、实名、支付和订单带进家庭浏览器

铁路方面 2012 年的系统回顾称，12306 客服网站 2010 年 1 月先上线时主要提供运输方案、时刻、正晚点、余票查询；2011 年 6 月开始分线路开通互联网售票，到年底扩展到全部旅客列车。互联网售票占比在半年多内从不足 1% 上升到约 11%。

来源：

- **A/B / near-contemporary system account**：  
  https://jingji.cntv.cn/20120113/115500.shtml

但“网上买到了”仍不等于“以后什么都不用做”。2011 年石家庄等站尚不能让所有网上购票旅客直接刷二代身份证进站，网上生成的电子记录仍需兑换纸质票。

来源：

- **B / contemporaneous local report**：燕赵晚报 / 中新网，2011-09-30。  
  https://www.chinanews.com/cj/2011/09-30/3365703.shtml

所以必须保留：

```text
Web purchase
!=
paperless travel
```

### 4.6 浏览器本身一度就是铁路可及性的组成部分

2011 年《新京报》实测当时网上购票时，客服称网站按 IE 标准开发、支持 IE6 以上版本；记者测试 Chrome、Firefox、Safari、Opera 时遇到登录、乱码或无法正常购票等问题。

来源：

- **B / contemporaneous browser test**：新京报，2011-06-15，新浪留存。  
  https://news.sina.com.cn/c/2011-06-15/084622643844.shtml

同年公开用户技术记录还留下了更具体的浏览器切换：有人在 Firefox 完成部分流程、再切到 IE 支付，并记录 HTTP/HTTPS、证书、日历和短信状态的不一致。

来源：

- **T0 / B / contemporaneous user technical note**：2011-11-22。  
  https://www.cnblogs.com/longware/archive/2011/11/22/13382228.html

这些个人记录不能代表所有用户，却足以证明：当时的“会不会用 Internet”还不是完整条件，**电脑、浏览器、证书、网银也会进入 ticketability。**

### 4.7 2012 春运：支付和出票第一次大规模暴露为不同状态

2012 年春运高峰，12306 每日点击量一度超过十亿次。铁路方面承认网络拥塞可能导致银行已经成功支付、网站却未完整收到支付结果，于是出现“扣款成功但购票未成功”的支付偏差；客服投诉也集中在支付成功但订票失败、退票后票款未到账等问题。

来源：

- **A/B / near-contemporary system account**：  
  https://jingji.cntv.cn/20120113/115500.shtml

从普通生活视角看，这揭示了此前在售票窗口容易被压缩成一个动作的状态链：

```text
钱离开账户
!=
铁路订单持有席位
!=
运输权利已经生成
```

当交易分布在浏览器、银行、铁路后台之间以后，这些中间态开始直接进入普通人的焦虑。

## 5. 2015–2019：拥堵型未来——“会网上买票”以后，竞争转向同步、验证和队列

### 5.1 身份、手机、验证码成为新的摩擦层

到 2015 年，12306 已经通过身份核验、手机双向核验、图形验证码等机制应对实名、账户安全和自动化抢票问题。

这些机制不能只写成“安全升级”。它们也意味着：

```text
registered account
!= identity state accepted
!= phone state accepted
!= CAPTCHA solved in time
!= order submitted before inventory changes
```

对熟练用户只是几十秒的步骤，对不会识图、手机换号、证件状态异常、网络慢的人，却可能直接决定能否进入购票队列。

来源示例：

- **B / contemporaneous report**：新华网/人民网，2015-12-02，12306 手机双向核验。  
  https://money.people.com.cn/n/2015/1202/c42877-27882454.html

### 5.2 2018：车站前的通宵长队减少，不等于竞争消失

2018 年 12306 改版报道已明确提到，互联网购票在铁路购票中占比超过七成，过去售票窗口前通宵排队的场景大幅减少。

来源：

- **A/B / government-carried Xinhua report**：2018-11-03。  
  https://app.www.gov.cn/govdata/gov/201811/03/431423/article.html

但需求最集中的春节仍然会在同一个放票时刻同步进入网络。于是“拥堵”从候车大厅和售票厅迁移到：

- 提前算放票时间；
- 多设备登录；
- 选日期/车次/席别组合；
- 反复刷新余票；
- 使用第三方抢票；
- 请朋友帮忙；
- 支付额外的“加速”服务费。

### 5.3 2019：购票劳动开始明显社会化

2019 年同期调查里，第三方平台已经把“朋友圈帮加速”做成明确功能。一名用户说自己先在抢票软件预定，并通过朋友圈让几十个朋友“帮加速”；还有人连续数日帮同事抢热门线路仍未成功。

来源：

- **T1 / B / contemporaneous interviews**：人民日报转载调查，2019-01-15。  
  https://finance.people.com.cn/n1/2019/0115/c1004-30537809.html

这不是“朋友真的在铁路队列里各自多出一个正式席位”，但它说明购票已经成为一种 **socially distributed booking labor**：一个人的返乡安排可能动员同事、群聊、朋友圈、付费平台和多台设备。

### 5.4 候补购票：把“刷票”改写成正式等待权

2019 年春运试点候补服务时，12306 允许售罄后提交候补需求，按订单顺序在出现退票或新增余票时兑现。首轮春运售票中，12306 已占总售票量 83.9%。

来源：

- **B / contemporaneous report**：国家应急广播，2019-01-08。  
  https://www.cneb.gov.cn/2019/01/08/ARTI1546902224307670.shtml
- **B / contemporaneous report**：新京报，2019-01-04。  
  https://news.sina.com.cn/c/2019-01-04/doc-ihqhqcis2993764.shtml

这不是创造新座位，而是改变等待稀缺资源的规则：

```text
sold out
→ repeated refresh / third-party polling
```

开始被部分替换为：

```text
sold out
→ explicit waitlist claim
→ future released inventory matched by queue order
```

因此候补的生活意义可以理解为 **scarcity-queue formalization**：用户不必一直亲自盯着页面，系统替她保存“如果未来有票，我仍然想走”的意愿。

## 6. 2020–2022：偶发型未来——买到票以后，日历本身也可能失效

2020 年初是这套状态链最清楚的一次压力测试。1 月 23 日起，铁路针对特定疫情情形不断扩大免费退票安排；部分线路随后暂停运行。与此同时，2020 年铁路电子客票又快速扩展到大量普速线路和 2400 多个车站。

来源：

- **A / railway notice**：12306，2020-01-23。  
  https://www.12306.cn/mormhweb/zxdt/202001/t20200123_27893.html
- **A/B / government-carried report**：2020-06-20，电子客票覆盖扩展。  
  https://app.www.gov.cn/govdata/gov/202006/21/459904/article.html

这一阶段最重要的不是“疫情促进数字化”这种过度简单的因果，而是：

> **transport entitlement != executable journey。**

即使订单、付款、身份证和车票记录全都正确，列车运行、地区政策、工作复工日期和个人健康风险仍可能让原计划失效。

而春节后务工流和学生流被延长到远超传统春运日历，也说明所谓“春节返乡—正月返城”的周期并不是自然时间，而是一套由企业、学校、交通和家庭共同同步出来的制度时间。

### 一条回顾性个人材料的边界

2020 年采访中，一名在广州工厂工作近十年的 30 岁劳动者回忆，刚外出打工时曾在售票厅排一天仍买不到票，因此有几年干脆不回家；后来丈夫和工友帮助购票以后，春节返乡才变得更稳定。

这属于 **C/T3 回顾性材料**，适合说明个人记忆中的生活转折，不应拿来测量 2010 年前后的总体购票难度。

## 7. 2023–2026：防守型未来——不是保证计划永远不变，而是让变化有出口

成熟数字票务阶段，最值得研究的新变化已经不只是“手机上能不能买”。越来越多功能开始保存用户的备选方案。

### 7.1 特殊预约把学生和务工人员的未来需求提前进入系统

2024 年春运，12306 面向学生和务工人员设置预约专区。完成实名核验的务工人员可以在通常预售期之外更早提交未来购票需求，由系统在随后时点尝试兑现。

来源：

- **A/B / government report**：重庆市政府，2024-01-11。  
  https://www.cq.gov.cn/ywdt/jrcq/202401/t20240111_12808627.html

这与 2008 年企业集中办理农民工往返票形成一个很有意思的二十年对照：

- 2008：企业规模、书面材料、组织身份帮助职工提前锁定返程；
- 2024：实名个人可以在 App/网站的特殊专区提前提交需求。

数字化没有把“群体身份”完全消除，反而把某些特殊生活节奏重新编码进平台。

### 7.2 2026：“无票”本身被证明是一种分配状态，而不是物理事实

2026 年春运，12306 技术负责人解释“长途有票、短途无票”时明确说明，长途列车实行“长途优先、兼顾中短途”的票额策略，会按区段预分并动态调整票额。

来源：

- **A/B / Xinhua interview with 12306 technical center**：2026-02-15。  
  https://news.cctv.cn/2026/02/15/ARTIgCDtEGPKJFGxhnY9tMic260215.shtml

因此旧网和生活史研究都必须永久保留：

```text
“该区段页面无票”
!=
“整列车所有未来区段都不存在可销售空席”
```

网页向用户展示的是**某一时刻、某一区段、某套分配规则下的可销售状态**。

### 7.3 防守型未来的真正核心：保存 option value

2020s 的候补、多日期/多车次选择、误购后的快速退票、改签范围扩大、学生与务工人员提前预约，并不保证一个人的未来一定稳定。

它们做的是另一件事：

> **当工作、家庭、天气、身体或计划变化时，不必因为一次早先选择就把整趟未来锁死。**

这与本仓其他“防守型未来”样本里的现金缓冲、职业双轨、证据储备很接近：真正被保护的是改主意和重新安排的能力。

## 8. 四种未来感放在同一条铁路上

| 时段 | 典型时间感 | 铁路接口上的表现 | 不应过度概括为 |
|---|---|---|---|
| 2005–2012 扩张型 | “以后应该越来越容易把远方接起来” | 电话订票、全国后台、12306、网上支付把更多步骤从车站搬到远程 | “从此不缺票” |
| 2015–2019 拥堵型 | “选择更多，但要同时管理更多门槛和竞争” | 实名、验证码、放票时刻、抢票软件、朋友帮抢、候补 | “大家只是更焦虑” |
| 2020–2022 偶发型 | “已经订好的日历也可能突然失效” | 免费退票、停运、复工/返校时间漂移、电子客票继续扩展 | “疫情才发明线上购票” |
| 2023–2026 防守型 | “不要假设未来不变，要提前保留替代方案” | 候补、多车次、特殊预约、更灵活改退、票额动态调整 | “年轻人只想稳定” |

### 一个关键修正

所谓扩张、拥堵、偶发、防守，不应理解成四种单纯情绪，而应理解成：**普通人怎样把未来的不确定性变成可执行计划。**

铁路恰好能把这种时间感看得非常具体：

- 什么时候知道放假；
- 什么时候开始卖票；
- 能不能提前锁定返程；
- 直达不行时是否会拆路线；
- 需要多少人一起“抢”；
- 计划取消时损失多少；
- 没买到时是否能进入一个正式候补队列。

## 9. 与“普通人到底有多少种活法”的关系

### 9.1 就业与迁移

一个离家 1000 公里的工作，只有当“去”“回”“再去”都足够可执行时，才真正成为可长期重复的生活路径。

这尤其提醒我们：

```text
job exists in distant city
!=
distant-city job is a sustainable life option
```

如果每年回家都要求请很多天假、提前在车站通宵、承担买不到票的高概率、并且返城日期也无法保障，那么同样工资的远方工作和本地工作并不是同一种现实选项。

### 9.2 婚姻家庭与照护

返乡票影响的不只是“过年团聚”。它还影响：

- 能不能参加婚礼、葬礼和家庭事件；
- 能不能在父母生病时回去；
- 孩子和外出父母多久见一次；
- 春节后谁先返回城市；
- 一个人是否愿意继续下一年外出。

### 9.3 非正规劳动与请假权

正式白领也许可以先确定假期再买票；计件、日结、工厂旺季、临时工和平台劳动者却可能在放票时还不知道老板哪天准走。

因此 ticketability 还和 **leaveability / 可请假性**相乘：

> 有票没假，与有假没票，都不会产生一次真实旅行。

### 9.4 社交关系

购票劳动本身会形成临时协作：公司统一订票、工友提供中转经验、家人代抢、朋友圈帮加速。交通基础设施因此也会重新调用社会关系。

### 9.5 记录与身份

实名制、手机号、账户、身份证和订单号让出行越来越可记录，也让“谁能代表谁买票”“证件状态是否一致”成为新的制度接口。

## 10. 证据等级、反例与后见之明风险

### 已证实或高置信

1. 1990s 中国铁路客票后台已经开始计算机化、区域联网和全国联网建设；Web 不是售票计算机化的起点。
2. 2000s 电话订票能减少去窗口的需求，但会形成电话拥塞。
3. 2008 年存在同时代第一人称“直达无票→工友建议中转”的返乡路径。
4. 2008 年企业办理农民工往返票，把节后返城提前纳入春节前的售票计划。
5. 2011 年 12306 分阶段把互联网购票扩展到铁路旅客列车，且部分车站仍要求兑换纸票。
6. 2011–2012 浏览器兼容、支付回执、订单和退票结算确实可能分裂成不同状态。
7. 2018–2019 互联网已成为主要购票渠道，第三方“帮抢”和官方候补同时存在。
8. 2020 年证明“已出票”与“旅程仍可执行”不是同一状态。
9. 2020s 的预约、候补、改退规则越来越多地保存未来备选。
10. 2026 年铁路明确解释区段票额策略，证明页面“无票”是一种受分配规则影响的可销售状态。

### 反例与限制

- 电话、Web、App 都不能消除运力稀缺；
- 网上售票普及不等于每个劳动者独立数字操作，企业、家人、工友和第三方仍可能代为完成；
- 2008 年雪灾说明“拿到票”仍可能无法按计划出发；
- 2011 年同样叫“电子票”，不同车站能否直接刷身份证仍有差异；
- 2019 年朋友圈加速是平台营销与代购机制的一部分，不能直接解释成铁路官方队列优先权；
- 2020 年电子客票扩展与疫情同年发生，不能凭时间相邻就写成疫情单一导致；
- 2024–2026 的务工人员专区说明成熟平台并非纯粹“人人同一接口”，仍会把学生、务工人员等制度类别重新编码进系统。

### 主要后见之明风险

1. **不要用今天 App 的体验回看 2011 网页。** 当时浏览器、证书、网银和换纸票都是交易的一部分。
2. **不要把物理排队写成“落后”、数字排队写成“无排队”。** 队列只是改变了承载介质。
3. **不要把“春运”天然化。** 春运高峰是学校、企业、春节家庭义务与全国交通共同同步出来的时间结构。
4. **不要把农民工只写成被动受困者。** 同时代材料里他们会提前返乡、改路线、中转、托工友找票、利用企业团票，也会在成本不值得时放弃某些渠道。
5. **不要从一次个人成功或失败推总体概率。** 第一人称材料主要用来重建选择、感受和操作链。

## 11. 与 Internet 前史 / 大众化 / 平台化的阶段关系

这条线可以非常清楚地区分三层：

### Internet 前 / 非公共 Internet 的后台联网

- 铁路内部计算机与全国售票网络；
- 窗口和代售点仍是普通人界面；
- 电话进一步把查询/预订从车站搬走。

### 大众 Web 化

- 余票、时刻、订单、实名、支付进入浏览器；
- 家庭/宿舍/办公室第一次可以直接争取席位；
- 浏览器、网银和数字身份也成为新的门槛。

### 平台化 / 移动化

- 手机成为主要界面；
- 候补、通知、改签、身份、特殊预约在同一账户下持续保存；
- 第三方平台围绕官方库存形成自己的“加速、提醒、社交助力”市场；
- 官方又逐渐把等待队列与复杂备选方案吸收到正式系统里。

这不是“线下→线上”的单向替代，而是后台联网、窗口、电话、Web、App、企业团购、特殊预约长期叠加。

## 12. 仍未解决

1. 1990s 全国联网售票真正到不同地区、不同车站的铺开速度还需要更细的一手资料；
2. 2005–2008 电话订票在不同铁路局的号码、预售期、取票期限与实际接通率差异尚未系统整理；
3. 2007–2010 同时代第一人称“为了春节票怎样安排辞工/请假/返乡日期”样本仍可继续补；
4. 2011–2012 12306 历史原始 HTML、表单、脚本、证书链和浏览器实测需要 `old-web-archaeology` 的 M1 capture；
5. 互联网售票普及后，家庭内部“谁替谁买票”的年龄、性别、数字技能分工缺乏量化；
6. 候补系统是否长期改变第三方轮询、用户心理和实际购票时间成本，需要独立评估；
7. “没买到票于是不过年/晚回/不再外出”的长期生命史，目前公开一手材料仍很碎。

## 13. 这改变了我们对“人怎么活着”的哪一点理解

标准迁移叙事很容易写成：

> 找到城市工作 → 离开家乡 → 在城市生活。

但真正的迁移生活往往是循环的：

```text
城市工作
→ 春节/照护/家庭事件返乡
→ 再返城
→ 换工作
→ 再回家
→ 再出发
```

如果其中任何一次“回”或“再走”都高度不可预测，那么所谓迁移就不只是一份工资和一张地图，而是一种不断承担交通风险的生活。

铁路售票基础设施真正改变的一点，是**让未来的身体移动越来越能够被提前写进日历**：先是窗口背后的全国网络，再是电话，再是 Web，再到正式候补和特殊预约。它没有让距离消失，也没有创造无限座位；它逐渐让一个远方工作的人更容易回答一个非常普通、却决定生活能否持续的问题：

> **我什么时候能回家，以及回去以后，我还有没有把自己重新送回生活下一站的办法？**
