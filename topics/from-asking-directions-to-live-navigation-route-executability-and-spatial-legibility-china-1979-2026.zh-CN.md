> Status: research note / cross-repo life-history slice
>
> Date: 2026-09-09
>
> Cross-repo technical companion: `tmzncty/old-web-archaeology/docs/WEB_MAP_POI_ROUTE_QUERY_TRANSIT_DIRECTIONS_TILE_AND_NAVIGATION_STATE_GAPS_1999_2015.md`

## 0. 研究问题

地图通常被当成“交通工具史”或“互联网产品史”中的一个小功能，但从普通生活史看，它解决的是更基础的问题：

> **一个机会即使存在、我也知道它存在，我能不能真的走到那里？**

一份工作、一次面试、一所学校、一家医院、一场婚礼、一间出租屋、一个陌生城市里的朋友、一处公共服务机构，都可能在信息层面已经可见，却因为“我不知道怎么去”“不知道该在哪一站下”“不知道这个门从哪边进”“不知道今天这条路还通不通”而仍然不完全可执行。

因此本稿不把地图简化成“知道地理位置”。它研究的是 **route executability / 路线可执行性**：

```text
机会/目的地存在
→ 我知道它存在
→ 我知道大致在哪里
→ 我能得到一条路线
→ 路线数据仍然有效
→ 我能理解路线
→ 我能在途中判断自己是否走对
→ 路况/公交/入口仍然可用
→ 我抵达正确地点
→ 我还能完成那件本来要做的事
```

任何一层都可能失败。

这一问题与本仓已有专题相邻，但不重复：

- `communication-and-the-cost-of-living-far-away.md` 研究远距离关系的通信成本；
- `moving-city-as-career-strategy-...` 研究迁移成为职业策略；
- 招聘、住房、医疗、教育专题研究机会本身如何出现或被执行；
- 本稿只问：**当人已经决定要去一个陌生地方时，谁替他完成本地知识？**

由此引入几个工作概念：

- **wayfinding externalization / 寻路认知外包**：把“记路、认地标、问人、判断转弯”逐步交给纸图、查询机、Web route engine、GPS/navigation；
- **geographic cold-start cost / 陌生城市冷启动成本**：刚到一座城市时，为建立“哪里是什么、怎样过去、哪些路可信”所付出的时间与社交成本；
- **route executability / 路线可执行性**：一个目的地从“可见”变成“实际可抵达”的程度；
- **operational map / 运行态地图**：不仅告诉你道路几何，还告诉你此刻拥堵、封闭、公交满载、检查点、核酸点、入口等状态；
- **spatial legibility / 空间可读性**：陌生人是否能把地址、地名、站点、建筑物和真实空间对应起来；
- **movement exhaust / 移动轨迹排放**：当导航、搜索、到店和轨迹被平台记录后，普通人的移动行为本身成为新的数据对象。

## 1. 先固定中国网络史边界：地图前史不等于 Internet 前史

本专题涉及 1970s—1990s 的纸图、公共问路、光盘 GIS，也涉及 2000s Web 地图和 2010s 移动导航。必须先把中国互联网阶段分开。

### 1.1 1994 以前不能写成“完全没有网络”

2003 年 CNNIC 大事记的同期转述记录，CANET 在 1980s 已通过国际公用分组网络建立电子邮件节点；1988 年 CNPAC X.25 分组交换网覆盖多个城市，清华、高能物理所等也已有电子邮件或国际远程联网实验。

来源：

- 中国新闻网转引 CNNIC 《中国互联网发展大事记》，2003-07-17：<https://www.chinanews.com/n/2003-07-17/26/325209.html>
- 中国互联网协会关于 1987 国际邮件节点的回顾：<https://www.isc.org.cn/article/10236.html>
- evidence: B/C，后来的机构性历史整理；其中网络节点与通信方式有档案核验背景

这能证明：

> **1994 以前中国已经有科研、电子邮件、X.25、专用/实验联网。**

不能证明：

> **普通家庭已经能通过全球 Internet 使用 Web 地图。**

### 1.2 1994-04-20 才是全功能 Internet 连接的明确节点

中国科学院计算机网络信息中心记录，1994-04-20，NCFC 通过一条 64K 国际专线实现与 Internet 的全功能连接。

来源：

- 中国科学院计算机网络信息中心：<https://www.cnic.cas.cn/zxgk/>
- 中国科学院，2024-04-19：<https://www.cas.cn/cm/202404/t20240419_5012095.shtml>
- CERNET 历史整理：<https://www.cernet.edu.cn/xxh/fei/zxz/201408/t20140807_1161522.shtml>
- evidence: A/C（机构历史记录；事件本身为已稳定核验节点）

仍然不能把这个日期写成：

> “1994 年普通家庭就可以随时上网查地图。”

真正的生活扩散还需要商业服务、接入费用、家庭/网吧/单位终端、网站覆盖和地图数据等后续条件。

本稿因此使用以下分层：

```text
前互联网/非 Internet 的寻路系统
→ 科研/专线数字通信存在
→ 1994 全功能 Internet
→ 商业 Web 与公众接入
→ 在线地图可用
→ 多地点/多终端实际使用
→ 手机 GPS/移动数据导航
→ 实时运行态地图
```

## 2. Internet 以前：本地知识本来就由很多人和物共同承担

### 2.1 1979 北京游览图：纸图已经把交通系统压缩成可随身携带的对象

荷兰国立博物馆馆藏一份 1979 年 3 月出版的北京游览图，由地图出版社出版、新华书店北京发行所发行。馆藏说明明确记录它包含公共交通、终点站/旅行社列表，并附郊区公交与长途汽车线路图。

来源：

- Rijksmuseum, *Tourist map of Beijing*, 1979：<https://www.rijksmuseum.nl/nl/collectie/publicatie/Tourist-map-of-Beijing--12c88bf17d672791a79c08bdb0879e77>
- evidence: A，实体出版物馆藏 metadata

这只能证明产品存在与内容形态，不能证明 1979 年所有来京者都拥有或会正确使用它。

但它说明一件基础事实：

> **在网络以前，陌生城市已经可以被压缩成一件随身携带的“离线查询设备”。**

纸图的弱点同样明确：

- 不会自动知道你现在在哪里；
- 不会判断你是否走错；
- 不知道今天封不封路；
- 公交改线以后不会自行更新；
- 复杂立交、站内出口和小胡同仍需要额外本地知识。

### 2.2 1982—1983：有时真正的导航系统是一个熟悉城市的人

《北京日报》2025 年利用集团历史报刊数据库回溯了多种寻路服务，并给出对应原报日期。

其中：

- 1982 年，北京站出站口设“地名询问服务点”，测绘/地名工作人员现场替旅客把旧地名翻译成新地名，再告诉具体公交换乘；
- 1983 年，北京 44 路公交一个车组为担心坐过站的郊区、外地乘客制作带灯的到站预告牌，并走访沿线 340 多个单位，制作“沿线主要单位介绍图”和“换车线路图”。

来源：

- 北京日报客户端，2025-02-27（回引 1982-03-29、1983-03-30 原报）：<https://xinwen.bjd.com.cn/content/s67bfa0a8e4b068c68f104f2d.html>
- evidence: C/B，后来报社数据库整理；原始报纸日期、版面和标题已定位，但本轮未直接取得原版扫描

这类“活地图”非常重要，因为它提醒我们：

> **寻路从来不是纯粹读取地理几何，而是把地址、旧地名、公交规则、单位入口和真实生活经验连接起来。**

地图数字化以后，这些工作并没有消失，而是逐步进入 POI database、route graph、用户纠错、实时交通和室内地图。

### 2.3 问路是一种真实但容易从历史记录中消失的社会基础设施

纸质地图并不能完全取代：

- 问售票员；
- 问警察；
- 问商店；
- 让朋友在纸上画一张小图；
- 按“看到某某楼后左转”的地标式描述走；
- 到车站以后再问下一段。

这些行为留下的档案远少于正式地图出版物。

因此必须防止一种 archive bias：

> **地图容易保存，不代表普通人的实际寻路主要靠地图。**

很大一部分“本地知识调用”发生在人和人的短暂对话里，本来就不会留下可检索记录。

## 3. 1990s—2004：电子地图先不依赖大众移动 Internet

### 3.1 CD-ROM、公共交通图和公共信息亭都是重要中间层

北京日报的历史整理显示：

- 1995 年公交候车亭已有交通图；
- 1997 年出现“北京通”城市地理信息光盘，可查询大量街道、胡同和居民小区；
- 2001 年“北京通”网站/首都之窗数字地图已经能够按路名+门牌号、小区名+楼号等查询位置；
- 2001 年以后数字北京信息亭提供电子地图；
- 2004 年正式开通的信息亭达到 312 个，可查公交并打印路条。

来源：

- 北京日报客户端历史数据库整理：<https://xinwen.bjd.com.cn/content/s67bfa0a8e4b068c68f104f2d.html>
- evidence: B/C；准确报纸日期和标题被保留，但应继续向原报和历史 Web capture 深挖

这条线防止我们把历史写成：

```text
纸地图 → 手机地图
```

实际存在很多中间状态：

```text
纸图
→ 公共站牌/信息牌
→ CD-ROM 电子地图
→ 公共查询终端
→ 桌面 Web 地图
→ 可打印路线
→ 手机地图
→ GPS 实时导航
```

对没有家用电脑的人而言，**公共信息亭也是“服务可及”的一种数字接口**。

### 3.2 这改变的是“陌生城市冷启动”，而不是让本地知识瞬间消失

如果刚到一座城市，一个人必须先学会：

- 站名与真实地点怎么对应；
- 哪些公交能换乘；
- 哪些旧地名和新地名其实指同一片地方；
- 从火车站出来以后往哪边走；
- 哪些单位藏在大院、园区、胡同或复杂立交后面。

公共地图和数字查询终端让其中一部分知识可以在没有熟人的情况下取得。

这就是 **geographic cold-start cost** 的第一次明显下降。

## 4. 2005—2012：扩张型未来——“去陌生地方”开始成为可查询、可试错的任务

### 4.1 2006：路线查询已经被做成非常低门槛的桌面行为

2006-07-20，Mapbar 发布只有 264KB、无需安装注册的“小Me”桌面地图查询工具，宣传功能包括公交线路、驾车路线和地图信息查询。

来源：

- 新浪科技，2006-07-20：<https://tech.sina.com.cn/other/2006-07-20/15061047598.shtml>
- evidence: B（同期媒体/产品稿，功能存在可用；不能独立证明使用规模）

2008 年行业报道则显示，Mapbar、Mapabc、51ditu、搜狗/Go2Map 等在线地图已经形成明显竞争，行业关注点从“有没有在线地图”进一步转向 POI 数量、实时路况、360°实景、API 和无线导航。

来源：

- 信息周刊/泰伯网，2008-04-10：<https://www.taibo.cn/p/4670>
- evidence: B；市场份额、市场规模为 iResearch/企业材料，应视为行业估计而非人口普及率

这里必须坚持：

> **online-map traffic share != 中国人口中地图使用率。**

### 4.2 2008 第一人称：真正的用户不是“信一个地图”，而是在几个不完整数据库之间交叉验证

2008-04-24，博客园用户 KymoWang 留下了一条很好的同期操作记录。他回忆自己最早用 668map，后来常用 Mapbar 和 Mapabc，但认为二者公交更新不如 8684；当天查北京酒仙桥时又第一次发现 City8 的 360°实景，并期待未来出现真正三维的地图。

来源：

- KymoWang，博客园，2008-04-24：<https://www.cnblogs.com/Kymo/archive/2008/04/24/1170077.html>
- evidence: A，公开的同时代第一人称；单个技术型用户，不具代表性

这条材料同时保存了三件事：

1. **数据新鲜度已经是使用体验的一部分**：地图“有公交信息”还不够，更新快慢会改变能否执行；
2. **一个人会主动多源核验**：当时没有任何单一服务天然被认为完整；
3. **2008 的未来想象仍然偏扩张**：更多实景、更立体、更完整，而不是先讨论怎样减少追踪或离线备份。

这比后来“以前大家都靠地图网站”的怀旧叙述更有价值，因为它保留了当时真实的不完整性。

### 4.3 2009 第一人称：地图降低的是出门前的不确定，不是把迷路从世界上删除

2009-05-06，中关村在线编辑刘菲菲试用 MSN 的地图共享功能时，自述自己是“路痴”，去陌生地方以前通常先上网查地图，但即使这样与朋友约见时仍会找不到；她因此对“两个好友在同一张在线地图上共同搜索、浏览和标注”的功能感兴趣。

来源：

- 中关村在线，2009-05-06：<https://soft.zol.com.cn/131/1319968_all.html>
- evidence: B/A（同期产品实测 + 作者第一人称；不是总体样本）

这里的路线执行链是：

```text
约会/办事地址
→ Web 查询
→ 在离开电脑前形成路线记忆/打印/抄写
→ 出门
→ 实际街景出现偏差
→ 仍可能需要电话/问路/共同标记
```

所以 Web map 的第一阶段并不是“实时导航”，而是 **pre-trip planning / 行前规划**。

### 4.4 2009 海外对照：从“出发前看路线”到“路上持续纠错”是跨国共同转折

Google 官方地图博客在 2009-10-28 宣布 Android 2.0 上的 Google Maps Navigation，并明确对比此前 driving directions 只是书面列表；新系统使用手机 Internet、GPS、语音引导、自动重新规划、实时交通、搜索和较新的地图/商业数据。

来源：

- Google Maps official blog, 2009-10-28：<https://maps.googleblog.com/2009/10/google-maps-navigation-comes-to-android.html>
- evidence: A（厂商同期公告；可证明产品能力声明，不能证明大众采用）

MapQuest 今天的官方历史也把 1990s Web 时代的典型体验概括为打印 turn-by-turn directions 放在车里；这一材料是企业回顾，应仅用于补充产品谱系。

来源：

- MapQuest official history：<https://platform.mapquest.com/about>
- evidence: C/company retrospective

这条海外对照说明真正的共同机制不是某个中国平台特有，而是：

```text
route plan as document
→ route plan as live service
```

后者第一次允许系统在“你已经走错了”以后继续工作。

### 4.5 2011—2012：地图开始把“哪里有机会”和“怎样去机会”放进同一个对象

2011 年春节后，北京在人流集中的火车站/长途客运站向来京务工人员发放“北京市求职地图”，上面不仅有公共职介机构位置，还有联系电话、乘车路线、劳动维权和社保知识。报道特别说明，没有明确岗位的来京务工人员可以按图去居住地附近的公共职介机构。

来源：

- 新京报，2011-02-10（新浪转载）：<https://msn.finance.sina.com.cn/cjyw/20110210/025411055.html>
- evidence: B，同期新闻

2012 年哈尔滨进一步推出可上网、在公共查询机和有线电视入口使用的“就业地图”，放入 8000 多个信息点和多类求职服务。

来源：

- 新华网，2012-11-28：<https://www.xinhuanet.com/politics/2012-11/28/c_113828487.htm>
- evidence: B，同期新闻

这类对象很好地连接了 life-course 与 infrastructure：

> **“城市里有工作”与“一个刚下火车、没有本地熟人的人能把自己移动到正确求职节点”是两件不同的事。**

地图并不创造岗位，却可能把部分“空间上存在、行动上不可达”的机会变得更可执行。

## 5. 2015—2019：拥堵型未来——不再问“有没有地图”，开始问“哪张地图现在最可信”

### 5.1 2018：陌生城市里，路线价格也成为可执行性的一部分

腾讯地图 App Store 保存一条 2018-07-18 的同期用户评论。该用户自称“天然路痴”，认为地图让出门更容易，但在陌生城市打车时，希望不同路线同时给出价格比较，因为不知道线路和价格会增加不确定性。

来源：

- Apple App Store, Tencent Maps reviews：<https://apps.apple.com/cn/app/id481623196?platform=ipad&see-all=reviews>
- evidence: A-ish platform-hosted contemporaneous self-report；身份与经历无法独立核验，不可外推

这提醒我们：

> **route executability 不是纯空间问题，还包含成本可预期性。**

一条“能去”的路线如果费用不可判断，仍然可能不是现实选项。

### 5.2 2018：成熟依赖以后，地图的失效开始被直接感受到

同一 App Store 页面保存 2018-10-04 的评论：用户称自己喜欢语音识别和免手操作，但批评实时数据更新慢，举例说同一封堵路段相较另一地图晚约一周反映。

来源：

- Apple App Store, Tencent Maps reviews，同上
- evidence: A-ish contemporaneous user report；具体“一周”是单个用户观察

到了这个阶段，地图的生活角色已经与 2008 很不同：

2008 的问题是：

> “这个网站有没有我要找的地方？”

2018 的问题是：

> “它知不知道今天这条路已经不能走了？”

### 5.3 2019：大路已经成为 commodity，差异转移到小路、园区、村庄和入口

2019-08-22，一名腾讯地图 App Store 用户描述自己同时比较百度和腾讯：大地方导航区别不大，但园区、村庄和小路覆盖有差异，有些区域在另一个地图里仍然空白。

来源：

- Apple App Store, Tencent Maps reviews：<https://apps.apple.com/cn/app/id481623196?platform=ipad&see-all=reviews>
- evidence: A-ish contemporaneous user report；不可推成全国地图覆盖结论

这条材料特别重要，因为它暴露了地图普及后的**分布不平等**：

- 城市主干路可能已经高度可读；
- 小村、小区内部、工业园、医院院区、校内路仍可能有数据空白；
- “地图已经普及”不等于所有空间同等被看见。

因此需要一个新问题：

> **谁生活在 map-complete 的空间里，谁仍生活在 map-edge 上？**

## 6. 2020—2022：偶发型未来——地图从“怎么去”变成“今天还能不能这样去”

### 6.1 疫情把 route graph 临时变成 operational graph

2020-03-10，经济日报/人民网采访北京市民“小范”。她描述自己早餐时查看疫情信息，出门前看目的地人流热力图、公交地铁满载率，再决定出行方式，并选择标注测温消毒的车辆。

来源：

- 经济日报/人民网，2020-03-10：<https://travel.people.com.cn/n1/2020/0310/c41570-31626149.html>
- evidence: B + 同期受访者第一人称

报道同时引用平台数据称，2 月 10 日陆续复工后，“人才市场”的地图搜索量明显上升。平台数据只能证明其自身用户行为变化，不能外推整个就业市场。

真正重要的结构变化是：

```text
道路存在
!= 今天允许通过

公交线路存在
!= 今天正常运营

目的地存在
!= 今天开放

物理上可抵达
!= 制度上可进入
```

地图因此叠加了：

- 人流/拥挤；
- 交通恢复；
- 检查点；
- 防疫政策；
- 核酸点；
- 入口/开放状态。

这就是 **operational map / 运行态地图**。

### 6.2 “正常生活恢复到哪里”本身也开始由地图行为衡量

2020 年武汉解除离汉通道管控当天，人民网用高德交通数据描述早高峰拥堵恢复；同年其他报道也以导航/通勤行为观察复工。

来源：

- 人民网，2020-04-08：<https://finance.people.com.cn/n1/2020/0408/c1004-31666127.html>
- evidence: B；底层指标来自平台，不等于全体人口移动

这出现了一个新的 historical visibility：

> **过去普通人的“我今天又开始上班了”主要留在个人日记、单位记录、车票里；现在大规模匿名化的导航/通勤痕迹也可以成为社会恢复的代理指标。**

但平台观测得到的是“被该平台看见的移动”，不能自动代表所有人。

## 7. 2023—2026：防守型未来——越依赖实时导航，越需要处理故障、离线和轨迹保管

### 7.1 2025 第一人称：导航失效在陌生高速路段不再只是“不方便”

高德地图 App Store 保存 2025-07-07 的一条用户评论，报告车机导航黑屏、GPS 信号丢失以及高架附近误判偏航，并特别说在高速和陌生路段会带来安全风险。

来源：

- Apple App Store, Amap reviews：<https://apps.apple.com/cn/app/id461703208?platform=iphone&see-all=reviews>
- evidence: A-ish platform-hosted contemporaneous self-report；具体故障无法独立复现

这说明成熟阶段产生了新的 dependency reversal：

> **早期地图是“额外帮助”；当本地路感被大量外包以后，导航突然失效反而会制造新的脆弱性。**

这并不意味着“纸图更好”，而是说明成熟基础设施需要 fallback：

- 记住大方向；
- 保留关键地址/电话；
- 离线地图；
- 多源交叉检查；
- 道路标牌仍可独立工作；
- 必要时重新向人问路。

海外当前产品也把 offline maps 重新做成正式能力。Apple Maps 当前说明中明确提供离线地图与离线逐步导航。

来源：

- Apple Maps App Store：<https://apps.apple.com/cn/app/id915056765>
- evidence: A，当前产品能力；不能证明大众实际使用比例

防守型未来因此不是“倒退回纸图”，而是：

> **在一个高度联网的系统里重新购买一点断网以后仍然能动的能力。**

### 7.2 2026：地图开始直接编排标准人生转场

2026-08-27，高德上线“大一新生开学指南”，公开材料称已覆盖 1300 多所高校，并把证件/行李清单、报到时间、到校公交/地铁/打车、校园内宿舍/教学楼/食堂/图书馆/医务室以及城市探索放进同一个入口。

来源：

- 新浪科技，2026-08-27：<https://finance.sina.com.cn/tech/shenji/2026-08-27/doc-iniptnux9039006.shtml>
- 中关村在线，2026-08-27：<https://news.zol.com.cn/1238/12388489_all.html>
- 高德地图 App Store 当前活动说明：<https://apps.apple.com/cn/app/id461703208?platform=ipad>
- evidence: A/B，当前产品说明与同期报道

这条材料和本仓核心问题直接相交：

过去，“去外地上大学”这一标准人生节点需要家庭、学校通知书、火车站、纸质地图、迎新人员、老生经验和本人试错共同完成陌生城市冷启动。

今天平台开始把它打包成：

```text
我要带什么证件
→ 什么时候报到
→ 怎样到学校
→ 进哪个门
→ 宿舍/食堂/医务室在哪里
→ 周围怎样生活
→ 这座城市还能去哪里
```

地图因此已经不只是 route engine，而开始成为 **life-transition orchestration / 人生转场编排层**。

这不意味着所有新生都依赖它，也不意味着过去没有学校迎新与纸质指南；它只证明，一家地图平台已经把“进入大学生活”当成可直接产品化的完整状态转换。

### 7.3 同时，移动行为本身变成平台可以再利用的证据

高德地图当前 App Store 产品说明称，“扫街榜”会使用真实用户的导航、搜索、到店等行为数据，并结合其他信号形成本地商户榜单。

来源：

- 高德地图 App Store 当前说明：<https://apps.apple.com/cn/app/id461703208?platform=ipad>
- evidence: A（厂商当前公开声明；只能证明其宣称的数据利用逻辑，不能独立验证算法效果/公平性）

这产生了整条历史线最明显的反转：

1979：

> 地图告诉我“别人已经画出的城市是什么样”。

2008：

> 地图网站告诉我“怎样去酒仙桥”。

2018：

> 实时导航根据很多人的移动状态告诉我“现在怎样去更快”。

2026：

> **我自己导航、搜索、到店的行为，又可以反过来成为下一张“什么地方值得去”的地图的一部分。**

这就是 `movement exhaust / 移动轨迹排放`：使用地图不再只是读取空间，也在持续产生空间数据。

## 8. 这四种“未来时间”在地图上怎样变化

| 时段 | 主要未来语法 | 地图/寻路的典型作用 | 新的不确定性 |
|---|---|---|---|
| 2005–2012 扩张型 | “更多地方可以去，陌生地方也可以自己查” | Web 查询、公交换乘、实景、多端移动导航 | 覆盖不全、更新慢、出门后失去交互 |
| 2015–2019 拥堵型 | “目的地很多，关键是今天哪条路线最有效” | 实时路况、多模式路线、地图对比、园区/小路覆盖 | 数据新鲜度、拥堵优化、平台间差异 |
| 2020–2022 偶发型 | “道路在，但今天未必能照常去” | 人流、交通恢复、检查点、测试点、开放/安全状态 | 物理可达与制度可进入分离 |
| 2023–2026 防守型 | “我依赖它，所以还要考虑失效、离线、隐私与退出” | 离线导航、实时纠错、人生转场服务、行为数据再利用 | 导航故障、轨迹保管、平台代理过深 |

这张表不是说每个人都经历同一种时间感。出租车司机、盲人、骑手、老年人、乡村居民、通勤白领、刚下火车的务工者和第一次离家上大学的新生，会面对完全不同的路线问题。

## 10. 反例：不要把“有导航”写成“地点自由”

### 10.1 交通与时间成本仍然是真约束

地图可以告诉一个人某份工作距离 32 公里，不能把 32 公里的通勤变成 5 公里。

路线优化只改变信息摩擦，不消灭：

- 票价；
- 油费；
- 通勤时间；
- 夜间无车；
- 身体行动能力；
- 城乡公共交通差异。

### 10.2 地图覆盖本身有地理分布

2019 用户对园区、村庄小路覆盖差异的观察表明，地图“普及”以后仍有 map-edge。

因此：

> **digital map availability != equal spatial legibility.**

### 10.3 地图可能把不确定性藏进一个看起来很确定的蓝线

路线 UI 常给出一条精确到分钟、转弯和入口的结果，但它背后可能依赖：

- 过时 POI；
- 错误道路等级；
- 暂时封闭；
- 不适合步行/机动车的实际入口；
- GPS 漂移；
- 用户定位误差；
- 公交班次变化。

因此“系统给了路线”不能等于“路线真实可执行”。

### 10.4 问人没有消失

即使在实时导航时代，医院院区、市场内部、地下通道、校园楼内、临时施工区等仍可能需要问保安、工作人员、路人。

更准确的历史不是：

> 人类本地知识 → 被地图替代。

而是：

> **本地知识中越来越大的常规部分被数据库化；边缘、例外和最新变化继续由人补洞。**

## 11. 历史可见性：地图同时制造了新的档案，也制造了新的隐私缺口

### 11.1 过去最难保存的是“我怎么走到这里的”

纸图能保存道路，报纸能保存公交线，但一个普通人真正的路线：

- 第一次来北京站后问了谁；
- 面试当天在哪个路口走错；
- 为省一块钱多换了一趟车；
- 因为怕黑选择另一条路；
- 谁在电话里给他一步步指路；

通常不会留下档案。

### 11.2 今天相反：路线可能比人的解释保存得更多

移动平台能够产生：

- 搜索；
- 起终点；
- 路线偏好；
- 实际轨迹；
- 到店；
- 收藏地点；
- 位置共享。

这让研究者未来有可能看到过去从未有过的 aggregate mobility，但同时也意味着普通人的日常空间生活进入了高度敏感的数据域。

因此本项目应坚持：

> **研究“路线系统怎样工作”不需要重新公开真实个人的细粒度轨迹。**

聚合数据、公开第一人称、产品状态和匿名化流程证据通常已经足够。

## 12. 海外比较：哪些是中国特有，哪些是互联网时代共同变化

### 12.1 共同变化

美国/全球 Web 路线服务同样经历：

```text
纸图 / 人工方向说明
→ Web 生成路线
→ 打印 turn-by-turn
→ 手机地图
→ GPS + Internet 连续导航
→ 实时交通 + 自动改道
```

MapQuest 的 1990s printable route 与 Google 2009 Internet-connected navigation 都说明，这种变化不是中国特有。

共同机制是：

> **路线从静态 representation 变成持续更新的 service。**

### 12.2 中国材料的特殊组合

中国城市高速扩张、巨大流动人口规模、快速建设的公交/地铁/道路、新旧地名、院落/园区型空间，以及 Web/移动互联网极快的扩张，使“地图数据是否及时跟上现实城市”特别突出。

2011 的“求职地图”还说明，对大量刚到城市、社会网络较弱的劳动者来说，地理信息与就业服务可以直接结合。

但不能把这种结合说成中国独有：其他国家的 Craigslist、MapQuest、Google Local、transit planners 同样把工作、住房、商户与路线叠加在空间界面中。

真正需要比较的是：

- 城市公共交通密度；
- 地址制度；
- 手机数据成本；
- 地图数据开放/许可；
- 城乡覆盖；
- 平台集中度；
- 公共机构是否直接把办事/就业入口地图化。

## 14. 后见之明风险

### 风险 1：把 GPS 智能手机当成 Web 地图的必然终点

2008 的用户期待 3D，并不意味着他已预见今天的实时手机导航、平台轨迹或本地生活推荐。

### 风险 2：把 1994 全功能 Internet 连接写成 1994 大众生活立即联网

必须保留科研连接、商业服务、家庭可及、网吧/单位使用、移动普及之间的时间差。

### 风险 3：把地图市场规模写成全民行为

厂商和行业咨询数据只能证明其统计口径内的市场/访问，不等于人口比例。

### 风险 4：把“路痴被技术解放”浪漫化

导航可能减少认路劳动，也可能让人更依赖定位、电池、网络和平台数据。

### 风险 5：把疫情地图功能写成永久制度转折

2020—2022 的运行态地图有特殊危机背景。部分实时状态能力留下，具体防疫图层并不必然持续。

## 15. 尚未确定

1. 1999—2003 的中国在线地图站点中，哪些真正支持端到端公交/驾车 route generation，而不是只做 POI/地图浏览？
2. Go2Map、Mapbar、Mapabc 早期页面的 historical capture 是否还能完整回放 route form、AJAX/CGI endpoint 和地图切片？
3. 2005—2012 不同人群中，打印路线、抄路线、手机 WAP 地图、车载 GPS、问路之间的真实使用比例如何？
4. 网吧用户是否会在出门前查地图并打印/手抄？目前缺少足够强的普通用户样本。
5. 乡镇/农村、小工业园、城中村等 map-edge 的长期改善速度如何量化？
6. 地图降低陌生城市冷启动成本以后，是否能在统计上观察到面试范围、求职半径、城市探索范围改变？当前只有机制证据，不能给因果结论。
7. 导航依赖是否真的降低长期空间记忆能力？需要认知研究，不应凭直觉写。
8. 轨迹/到店数据的长期保存、导出和删除权如何随平台变化？需要另一个隐私/数据保管专题。

## 17. 本轮改变了我们对“人怎么活着”的哪一点理解

以前讨论迁移、求职、上大学、看病时，很容易默认：

> “既然那座城市里有这个地方，人到了城市以后当然能找到。”

历史材料说明，这个“当然”本身是后来被基础设施做出来的。

一个 1980s 第一次到北京的人，可能真的需要在车站找“活地图”，把旧地名翻译成新地名，再听一遍公交换乘；一个 2008 年的人可以在办公室电脑上把 Mapbar、Mapabc、8684、实景图一起打开，尽量在出门前把未知压低；一个 2020 年的人不只要知道路，还要知道人多不多、车满不满、今天是否能进去；一个 2026 年的新生甚至可以从“该带什么证件”一路被同一个地图入口带到宿舍、食堂和第一次城市探索。

因此地图真正改变的不是“人终于知道东南西北”，而是：

> **它让一个没有本地熟人的人，更有可能先行动，再在路上纠错。**

这会降低迁移、面试、求学、旅行和照护中的 geographic cold-start cost，使某些原本“理论上存在、但陌生人很难执行”的人生路径更接近现实选项。

但成熟后的问题也反了过来：

> **当我们越来越不必认识路，路线本身开始认识我们。**

导航故障因此变得更危险；搜索、轨迹、到店又变成平台可以保存和再利用的生活记录。

从“问路”到“实时导航”的历史，不只是更方便的交通史，也是普通人怎样把陌生世界变得可执行、又把自己的移动变得更可观察的一段生活史。
