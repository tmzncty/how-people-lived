# 从“问熟人哪家馆子好”到“在陌生城市反向找 3.5 分”：餐馆口碑、地方知识可携带性与城市可读性——中国，1982–2026

> 状态：研究笔记；用于 `how-people-lived` 的 communication / migration / social relations / information / consumption / Internet / future-expectation 交叉研究。
>
> 核心问题：**一个普通人在自己不熟悉的城市、商圈或社交场景里，怎样知道“去哪儿吃”？当餐馆名称、地址、电话、价位、菜系、照片、点评、评分、榜单、排队状态逐渐进入电话数据库、纸质指南、Web、本地生活平台和移动地图以后，原本依赖亲友与长期居住经验的“本地知识”有多少可以被带走、搜索和借用？又有哪些判断并不能被一个分数替代？**

仓库已有：

- `meal-provisioning-food-delivery-and-kitchen-optionality-china-1993-2025.zh-CN.md`：研究一顿饭怎样通过食堂、电话送餐、网站、外卖平台等获得，核心是 meal provisioning、delivery radius、meal latency 与 kitchen optionality；
- 与城市迁移、地图、同城匹配、搜索引擎、住房、关系可迁移性有关的专题；
- `old-web-archaeology` 也已有 `ONLINE_FOOD_ORDERING_MENUS_SERVICE_AREAS_AND_DELIVERY_OUTCOME_GAPS_2004_2010.md`。

本文故意不重复“怎么把饭送到我手里”。

本文停在另一个问题：

> **在我决定出门吃饭之前，我怎样把一座城市里成千上万家店压缩成今晚真正可能去的两三家？**

所以研究对象是 **dining-place choice infrastructure（外出就餐选择基础设施）**，重点是：

```text
发现餐馆
→ 判断是否适合这次场景
→ 判断价格 / 菜系 / 距离 / 氛围
→ 借用陌生人的经验
→ 判断点评是否可信
→ 到达实体店
→ 发现线上信息和现场是否一致
```

而不是下单配送。

# 一、这条生活史真正新增了什么

## 1. local-knowledge portability：地方知识可携带性

传统城市生活中，“知道哪儿有一家便宜、安静、适合十个人坐下来的店”是一种非常具体的地方能力。

这种能力通常来自：

- 长期居住；
- 同事、亲友和邻居；
- 单位聚餐积累；
- 报纸生活版、广播电视；
- 电话簿、114；
- 纸质餐饮指南；
- 亲自踩过很多次坑。

它有一个重要特征：**很难随人迁移。**

一个在上海生活十年的人搬到北京，原有“哪家店靠谱”的知识大部分会失效。

本文把 Web / 本地生活平台带来的变化暂称为：

> **local-knowledge portability（地方知识可携带性）**：
> 一个人不必先在当地住很多年，也可以临时调用其他人积累的城市消费经验。

它不是“地方知识消失”。

更准确的是：

```text
过去：我知道，是因为我住得久 / 有熟人
后来：我也可以知道，因为别人把经验留下来并被索引
```

这会降低迁移、旅行、新工作、约会、朋友聚会进入陌生街区时的启动成本。

---

## 2. dining-place addressability：餐馆可寻址性

一家餐馆“现实中存在”，和“陌生人能够找到它”不是一回事。

至少要分开：

```text
店存在
店名可被知道
电话号码可查
地址可查
菜系可查
价格大致可查
营业状态可查
用户体验可查
地图能定位
能看出是不是同名分店
能知道今天是否仍然开门
```

本文把这组能力称为 **dining-place addressability（餐馆可寻址性）**。

电话查号主要解决“号码在哪里”；
纸指南解决“有哪些值得去的地方”；
Web 目录开始把菜系、地区、氛围、价格和评价组合起来；
移动互联网进一步把“我现在在哪”也放进查询条件。

---

## 3. weak-tie reputation infrastructure：弱关系口碑基础设施

熟人口碑的优势是：

- 我知道推荐人的口味；
- 我知道他有没有去过；
- 我可以追问；
- 信任关系先于推荐存在。

缺点是覆盖窄。

Web 点评反过来：

- 覆盖极广；
- 很多人彼此完全不认识；
- 经验能够累计；
- 推荐人和被推荐人之间没有原有社会关系。

因此本地生活点评可以视为一种 **weak-tie reputation infrastructure（弱关系口碑基础设施）**：

> 大量彼此不认识的人留下低强度、可搜索的消费痕迹，使下一位陌生人可以借用这些经验。

但这种机制天然带来新的鉴别劳动：

`陌生人很多 ≠ 样本代表所有食客 ≠ 点评都真实 ≠ 评分适合我的口味`。

---

## 4. city legibility：城市可读性

一座大城市原本对于新人可能是：

> 到处都有店，但我不知道哪一家是什么。

本地生活数据库把城市逐渐变成：

```text
商圈
菜系
人均价格
氛围
适合聚餐 / 约会 / 家庭
距离
评分
最近评论
榜单
照片
```

因此它产生了一种 **city legibility（城市可读性）**。

这不等于城市被完整数字化。

恰恰相反，最应该保留的边界是：

> **可见于平台的城市，只是现实城市的一种投影。**

没有线上页面、很少有人写点评、主要服务熟客的小店，并不会因为搜索结果靠后就现实中不存在。

# 二、前互联网：中国普通人并不是“没有本地搜索”

## 5. 1980s–1990s：电话、114、黄页、报刊与熟人口碑

在大众 Web 以前，普通人的城市信息系统已经很多层。

1982 年全国市话查号台统一使用三位数 `114` 后，电话查号成为一种重要的公共信息入口。这里不能直接推出“1982 年普通人已经普遍打 114 找餐馆”；本轮没有找到足够强的同期餐馆查询量材料。

但可以确定：

- 商业机构可以通过公共电话号码体系变得可查询；
- 到 1990s，114 的数据库已经是城市机构信息的重要索引；
- 纸质电话簿和黄页仍是企业名称—号码—行业分类的重要载体。

1999 年 9 月，北京 114 开始试运行网上查询时，《北京晨报》明确说新 Web 服务是在**原有查号台数据库**上建立，已有 230 多万个号码资源，并可按行业类别同时查询同类单位。

来源：

- 《北京114查号台提供网上查询服务》，北京晨报，1999-09-15：
  https://news.sina.com.cn/society/1999-9-15/14567.html

### 证据等级

**B：同期媒体对 114 新服务与既有数据库的报道。**

这条材料最重要的不是“1999 年已经能上网查号码”，而是它证明：

> **Web 并不是从零造出城市商户目录，而是把已有电话信息基础设施重新暴露给用户。**

---

## 6. Web 前的“推荐”与“查询”不是同一种服务

电话簿 / 114 最擅长回答：

> “某某饭店电话号码多少？”

它并不天然回答：

> “我今晚想和三个朋友吃 60 元左右的川菜，附近哪家更合适？”

2006 年《新经济导刊》介绍大众点评时，用同期记者的概括明确把变化描述为：过去找好餐馆往往借助亲朋好友口碑，现在可以按菜系、地区、氛围筛选，并按网友评分排序。

来源：

- 《大众点评网：让吃饭变得更讲究》，新经济导刊 / 新浪科技，2006-10-20：
  https://tech.sina.com.cn/i/2006-10-20/16121195439.shtml

### 证据等级

**B：2006 年同期媒体对当时新旧行为的概括。**

不能拿这一句推成“2003 年以前所有人都只问亲友”。

它更适合说明信息类型变化：

```text
号码目录：谁在这里、怎么联系
熟人口碑：值不值得去
Web 点评：尝试把两种东西叠在同一个索引上
```

# 三、海外前史：用户评分早于 Web，Internet 改变的是传播与更新

## 7. 1979–1983 Zagat：先有纸上的“群众点评”

Zagat 的历史非常适合做反例。

2009 年 Forbes 对 Tim 与 Nina Zagat 的采访中，两位创办人回忆：1979 年一次聚餐后，他们让朋友参与餐馆调查，第一轮约 200 人评价纽约约 100 家餐馆，结果先以纸张在年轻专业人士之间流传；1983 年开始自己出版年度指南。

来源：

- Robert Reiss, “Turning A Hobby Into A Global Brand,” Forbes, 2009-12-31：
  https://www.forbes.com/2009/12/31/zagat-survey-crowdsourcing-leadership-careers-restaurants.html

### 证据等级

**C/B 混合：创办人 30 年后第一人称回顾；由同期出版史和后续材料交叉支持。**

这说明：

> **把很多普通食客的意见聚合成餐馆声誉，并不是 Web 发明的。**

Web 真正降低的是：

- 调查回收成本；
- 更新周期；
- 搜索成本；
- 地理扩展成本；
- 用户追加意见的门槛。

---

## 8. 1992–1999：纸指南 → 商业联机服务 → Web

2000 年 Forbes 的同期报道回顾，Zagat 的数据在 1992 年已经进入 CompuServe 和 Prodigy，1996 年进入 AOL 等服务，1999 年才正式推出自身完整 Internet 网站。

来源：

- “Zagat takes a big byte,” Forbes, 2000-02-08：
  https://www.forbes.com/2000/02/08/mu2.html
- “Zagat online,” Forbes, 1999-01-09：
  https://www.forbes.com/1999/01/09/feat_side.html

1999 年那篇同期报道还特别说明，Zagat 纸质指南已经是纽约本地人和外地访客常用的找餐馆工具；网站计划把完整数据库、地址、电话、平均餐费和多维交叉索引带到线上，并让用户直接在线提交评价。

### 比较意义

全球侧应写成：

```text
熟人讨论
→ 纸质聚合调查
→ 年度指南
→ CompuServe / Prodigy / AOL 等联机系统
→ Web 可搜索数据库
→ 在线评价
→ 移动位置服务
```

而不是：

`Yelp / 大众点评出现 → 人类第一次知道陌生餐馆好不好。`

# 四、2003–2006：中国餐馆第一次系统地变成“可检索的公共口碑对象”

## 9. 2003：Dianping 的关键不是“餐饮网站”，而是把消费经验做成数据库

大众点评 2003 年 4 月在上海建立。

2006 年同期媒体回顾其模式时指出，创办者参考 Zagat，但把原来邮寄问卷收集评价的方式换成 Internet；网站以用户点评作为主要内容，并为活跃点评者建立个人页面。

来源：

- 《大众点评网：Web2.0成熟时》，新经济导刊 / 新浪科技，2006-04-10：
  https://tech.sina.com.cn/i/2006-04-10/1421897310.shtml

同期报道还保存了一名用户名 `Cina` 的用户案例：其已在平台点评 191 家餐馆，拥有个人页面。

### 证据等级

**B：同期媒体直接观察平台和公开用户页面。**

此处只用于证明：

- 当时确有公开用户点评；
- 点评可以跨许多实体餐馆累计；
- 个人用户的“吃过哪里”开始形成可见记录。

不能由此推出用户真实身份、全国代表性或所有点评都可靠。

---

## 10. 一个餐馆第一次得到“持续存在的公共声誉页”

传统熟人口碑通常随着谈话结束而消散。

Web 点评的变化之一是：

> 某家店可以长期挂着一个公共页面，后来的人不断往同一对象上追加经验。

于是餐馆获得一种 **reputation persistence（声誉持续性）**。

但它必须和实体连续性分开：

```text
店名相同
≠ 地址相同
≠ 老板相同
≠ 厨师相同
≠ 菜单相同
≠ 这条 2004 年评论仍能描述 2009 年的店
```

这会成为 old-Web 侧的重要 state gap。

---

## 11. 2005–2006：评价已经反过来影响餐馆，并产生真实性治理

2005–2006 年，多家餐馆因大众点评用户的负面评论提起诉讼，成为很早的证据：线上口碑已经不只是食客之间的闲聊，而会被商户视为影响现实声誉与经营的公开内容。

来源：

- 《“孔家花园”再告网站 网友“老饭桶”也成被告》，东方网 / 新浪，2005-11-08：
  https://news.sina.com.cn/c/2005-11-08/01147387128s.shtml
- 《中国餐饮业网民商誉侵权第一案》，2006-01-05：
  https://finance.sina.com.cn/manage/commanage/20060105/15252251591.shtml

2006 年报道还描述平台要求注册、提供联系方式、人工审核，并对点评数量 / 质量进行分级；这些属于当时平台治理说法，不能直接证明审核实际有效。

### 新边界

> **review published ≠ review true；merchant dislikes review ≠ review false。**

一旦弱关系口碑成为基础设施，“谁有资格评价、平台怎样核验、商家能否施压删除”就从边缘问题进入普通消费决策本身。

# 五、2007–2012：扩张型未来——陌生城市开始变得“可以临时学会”

## 12. 2007：不是所有城市人都马上需要点评网站

一篇 2007 年 12 月的上海个人博客提供了一个很好的反例。

作者说自己住在上海市中心，却很少主动在外面寻找美食：公司中午长期组织固定餐馆就餐，周末又更愿意自己做饭；而一位女性朋友经常浏览“美食”“大众点评”类网站，因此还把作者调侃成“原始人”。

来源：

- 《釜山料理吃烧烤》，博客园，2007-12-06：
  https://www.cnblogs.com/Sonne/archive/2007/12/06/984640.html

### 证据等级

**A/B 边界：带明确日期的同期个人博客；本轮未取得独立 WARC / Wayback capture。**

这条材料的重要性在于反对技术决定论：

> **Dianping 可用 ≠ 每个城市人都需要用。**

如果单位食堂 / 固定餐馆 / 家庭烹饪已经替一个人稳定解决“去哪儿吃”，本地搜索的边际价值可能很低。

---

## 13. 2008：平台评价开始被媒体重新打包成“城市美食榜”

2008 年 1 月的同期报道记录，大众点评把 2007 年用户对北京餐馆的评价整理成年度榜单，榜单依据用户点评和口味、环境、服务等指标形成。

来源：

- 《2007年度大众美食榜单揭晓》，新浪饮食，2008-01-16：
  https://bj.sina.com.cn/danone/art/2008-01-16/180635002.shtml

平台声称参与规模很大；这些人数应作为**平台 / 活动方口径**，不能未经独立统计直接当作全国食客行为。

但功能变化是清楚的：

```text
单条评论
→ 商户页
→ 多维评分
→ 城市排行榜
```

用户不必读完所有评论，平台开始替用户进一步压缩决策。

## 14. 2009：点评已经和“预算管理”叠在一起

2009 年大众点评发布的上海消费报告称，其站内电子优惠券浏览、下载显著增加；同年一季度报告还把“外卖”等词的搜索变化与消费趋势联系起来。

来源：

- 《大众点评网发布2009年度上海生活消费报告》，2010-01-11：
  https://article.pchome.net/content-1040396.html
- 《大众点评网发布一季度生活消费报告》，2009-04-13：
  https://article.pchome.net/content-857837.html

### 证据等级

**B/C：同期转载的平台数据报告；数字按平台口径使用。**

这时本地生活搜索已经不只是“哪家好吃”，而是：

> **哪家合适 + 现在有没有优惠。**

因此一张餐馆页开始同时承载：

- 声誉；
- 价格预期；
- 促销；
- 地址和电话；
- 用户经验。

现实城市里的“小道消息”正在变成结构化字段。

## 15. 2010：一个旅行者真的可以拿着点评和地图逐店去找

2010 年 6 月一篇厦门旅行个人博客提供了本轮最直接的 life-history 材料之一。

作者明确写道，自己一行人依据大众点评上的美食点评，拿着地图一家家找过去；其中一家热门海鲜排档距离酒店约 10 分钟步行，但到店后仍排了约 45 分钟。

来源：

- 《2010厦门之旅-美食篇》，51CTO 博客，2010-06-20：
  https://blog.51cto.com/jackiechen/336161

### 证据等级

**A/B 边界：带明确日期的同期个人博客；当前页面仍可见，但本轮未验证 2010 年 archive capture。**

这一条直接支持 `local-knowledge portability`：

> 人到了陌生城市以后，可以临时借用当地大量陌生食客过去留下的经验，而不必先认识厦门本地朋友。

但它同时给出一个重要反例：

> **reputation can create congestion。**

一个页面越能把陌生人导向同一家店，等待本身越可能成为新的时间成本。

所以：

`被找到 ≠ 能立即吃到`。

## 16. 2010：PC 查询 → 手机位置查询，决策被推迟到更靠近行动的时刻

2010 年中关村在线作者在介绍 Android 大众点评客户端时，用第一人称说明自己原本经常先上网站查吃饭地点；有手机客户端以后，不必每次在吃饭前回到电脑查询，可以结合 Google Map 定位周边场所，在外地时再配合 12580 电话查询。

来源：

- 《美食搜罗全攻略 安卓版大众点评更新下载》，中关村在线，2010-05-06：
  https://4g.zol.com.cn/176/1768520.html

### 证据等级

**B：同期产品评测中的第一人称使用描述。**

这里新增的不是“点评更多”，而是 **decision-latency compression（决策时延压缩）**：

```text
PC时代：出门前查 → 记地址 / 打印 / 抄下电话 → 到现场
移动时代：人在街上 → 读取当前位置 → 查附近 → 直接走过去
```

本地知识不只可携带，而且开始**随身**。

---

# 六、2015–2019：拥堵型未来——选择更多以后，时间被重新堵在“判断”和“排队”里

## 17. 2018：口碑、榜单和排队开始连成同一个决策链

2018 年 App Store 当前页面仍展示“美味不用等”若干明确标记为 2018 年 9–10 月的用户评论。

其中一名用户描述过去去热门餐馆常要现场排一小时；使用在线排号后，可以下班前一小时先取号，到店后接近直接入座。另一名用户把“用户口碑形成的餐厅推荐榜”视作找店工具。

来源：

- Apple App Store，“美味不用等”评论页（当前页面保留 2018-09-29、2018-09-30、2018-10-10 等日期的评论）：
  https://apps.apple.com/cn/app/id979857479

### 证据等级

**B/A 边界：当前平台展示的带历史日期用户评论，不等于已经验证的 2018 App Store 页面 capture。**

这段材料提示：

> 在移动本地生活系统成熟以后，问题会从“找到一家店”继续推进成“找到一家店以后怎样把等待塞进别的时间里”。

这和扩张型未来的差异很明显。

2005–2012 更像：

> “终于能找到更多地方。”

2015–2019 则越来越像：

> “地方太多、热门店太挤，我得同时管理推荐、价格、距离、等位时间。”

---

## 18. 2018–2019：网红与榜单把“被看见”本身变成经营变量

2018 年餐饮行业观察已经把部分网红餐厅描述成可在很短时间冲上点评热门榜、又很快跌落的对象。

来源：

- 《最in网红餐厅三大隐形症状，暴露致命伤》，界面 / 众郝餐饮咨询，2018-07-10：
  https://www.jiemian.com/article/2296721.html

2019 年大众点评“必吃榜”进一步把海量用户评价压缩成跨城市榜单。

来源：

- 《2019大众点评必吃榜：1463家必吃餐厅……》，2019-07-06：
  https://ishare.ifeng.com/c/s/7o5ByRLLYjI

这些材料不能证明榜单对每一家店的因果影响，但可以证明一个新的经营环境：

> **restaurant visibility（餐馆可见性）已经部分平台化。**

餐馆不只竞争门口人流、熟客和传统媒体版面，也开始竞争搜索结果、点评数量、榜单和推荐流。

---

## 19. 2019：弱关系口碑一旦重要，作弊市场也会跟着长出来

大众点评 2020 年 1 月公布其 2019 年“清风行动”数据，称 2019 年处理了大量违规评价、违规账号和商户，重点对象包括黑产、刷好评、免费体验换好评、商户要求删差评等。

来源：

- 《大众点评：去年处理黑产、刷好评等违规商户逾3万家》，IT之家，2020-01-20：
  https://www.ithome.com/0/469/397.htm

### 证据等级

**B：平台治理数据经媒体报道；数量为平台口径。**

这条证据不是为了证明“大部分评价是假的”。

相反，它说明评分成为决策基础设施以后，新劳动出现了：

- 平台反作弊；
- 商户维护线上口碑；
- 消费者鉴别刷评；
- 差评者处理商户联系 / 骚扰；
- 评价者判断自己的评价会不会伤害小店。

于是“选择更多”的另一面是 **reputation-verification labor（口碑核验劳动）**。

---

# 七、2020–2022：偶发型未来——过去的好评突然不能回答“今天还能不能进去”

## 20. 2020：历史声誉和实时营业状态第一次大规模脱钩

2020 年 2 月 19 日的同期报道记录：海底捞部分城市外送开始恢复，但报道查看大众点评时，北京地区门店仍显示暂停经营，堂食并没有同步恢复。

来源：

- 《餐企逐渐恢复堂食业务 外卖仍是“主力军”》，中国商网 / 中国网，2020-02-19：
  https://food.china.com.cn/2020-02/19/content_75720608.htm

这把一个一直存在但平常不显眼的 state gap 放大了：

```text
这家店历史上口碑很好
≠ 今天开门
≠ 今天允许堂食
≠ 今天允许外送
≠ 所有分店状态相同
```

于是普通人对本地平台的需求从“长期声誉数据库”临时转向“**实时状态数据库**”。

---

## 21. 2020–2022：venue-state volatility——店铺状态本身变得不稳定

2020 年 4 月的餐饮行业材料记录，多地咖啡馆、茶饮店在疫情后出现停业、复工、门店优化和永久关店混杂的状态；有消费者发现自己常去多年的咖啡馆没有撑过 3 月。

来源：

- 《数据复盘：咖啡、茶饮4%闭店率背后，疫情不是最大杀手》，36氪，2020-04-09：
  https://36kr.com/p/1725399728129

2020 年 7 月，新京报记者又通过电话和平台搜索核实某高端素食品牌多家店暂停营业、改名或数量减少。

来源：

- 《米其林餐厅大蔬无界多店暂停业……》，新京报 / 新浪，2020-07-22：
  https://news.sina.cn/gn/2020-07-22/detail-iivhuipn4507795.d.html

本文把这种状态称为 **venue-state volatility（场所状态波动）**。

在这种时期，十年累计的五星好评甚至不如一条“今天是否营业”的新信息有执行价值。

这也是“偶发型未来”的一个很具体的表现：

> 未来不再只是“以后去更多店”，而是“我原本默认下个月还在的地方，可能突然消失；我要在行动前重新确认”。

---

# 八、2023–2026：防守型未来——成熟用户开始学会“不把分数当答案”

## 22. 2024：3.5 分反向寻店，不是放弃平台，而是开始解释平台

2024 年《工人日报》采访的栾女士平时周末常和朋友聚会，选餐厅前会网上查看网友推荐、图片和评分；但经历高评分餐厅不符合预期以后，她开始认为高分未必好、低分也未必差。

另一名经常外出就餐的张先生则说，附近餐馆大多分数都很高，反而很难选择。

来源：

- 《“勇闯”低评分餐厅，消费者为何舍高就低？》，工人日报 / 人民网，2024-01-08：
  https://finance.people.com.cn/n1/2024/0108/c1004-40154630.html

### 证据等级

**B：同期媒体采访；个体材料不能外推所有年轻人。**

这是一个重要的阶段变化：

```text
早期：没有信息 → 想要评分
成熟期：评分到处都是 → 学会怀疑评分
```

这不是“平台失效”。

更像是 **defensive interpretation（防守型解释）**：

- 看近期评价而不是总分；
- 看差评在抱怨什么；
- 看照片是否匹配；
- 区分“环境服务低分”和“味道低分”；
- 判断自己与评分者的偏好是否一致；
- 有时故意绕开已经被算法过度放大的热门对象。

普通人开始学习的，不再只是“怎么搜”，而是“怎么读评分”。

---

## 23. 2024：低分小店还揭示另一种平台盲区

2024 年《人民周刊》调查指出，一些街边小店有稳定熟客，但老顾客不习惯写线上评价，商家也不完全依赖线上引流；店铺线上分数因此不必然等于线下真实客群忠诚度。

来源：

- 《“低分餐厅”迎来“反向打卡”》，人民周刊，2024-02-07：
  https://www.peopleweekly.cn/html/2024/tebieguanzhu_0207/196266.html

这给出一个非常重要的反例：

> **platform visibility ≠ local embeddedness。**

一个店在互联网里很弱，可能在社区关系里很强。

因此城市的“平台投影”不能代替城市本身。

---

## 24. 2025：平台开始为“不要逼我给好评”增加防守接口

2025 年 5 月，大众点评宣布增加针对“送礼换好评”等违规促评的投诉入口，并上线“差评骚扰举报”。媒体报道还给出了五一期间用户投诉量以及平台复核结果；这些数字都应视为平台口径。

来源：

- 《吃饭遇到硬要好评、强删差评怎么办？大众点评推出全民监督机制》，北京商报 / 新浪财经，2025-05-14：
  https://finance.sina.com.cn/jjxw/2025-05-14/doc-inewqans0740300.shtml

这说明成熟口碑系统的目标已经不只是：

> “让更多人写评价。”

还包括：

> “让用户可以在不被商户交换利益或施压的情况下留下评价。”

于是 **review autonomy（评价自主性）** 也成为基础设施的一部分。

---

## 25. 2026：规模继续扩张，但“真实”本身已经成为需要持续维护的公共承诺

2026 年 6 月的“必吃榜”报道援引大众点评口径称，本轮榜单覆盖 264 座城市及地区、4279 家餐厅；平台继续强调真人、真实评价，并把大量用户历史评价作为榜单基础。

来源：

- 《“必吃榜”十周年揭晓……》，凤凰网转钛媒体，2026-06-25：
  https://finance.ifeng.com/c/8uFkfhrswTg

数量必须明确按平台口径使用。

它的历史意义不在于证明榜单“绝对客观”，而是：

> 到这个阶段，平台已经不能只证明自己“信息多”，还必须反复证明“为什么这些信息值得信”。

这正是防守型未来：

**扩张问题变成可信度维护问题。**

# 九、四阶段未来比较

## 26. 2005–2012：扩张型未来——“我不认识本地人，也可以学会这座城市”

核心经验：

- 店铺越来越可检索；
- 用户评价越来越多；
- 纸指南、Web、优惠券、手机定位并存；
- 新城市可以通过“点评 + 地图”临时学习；
- 未来想象更接近“选择会更多、城市会更透明”。

新增能力：

> **把陌生人的地方经验带在身上。**

风险尚未消失：

- 热门店带来排队；
- 评价真假难辨；
- 同名 / 换店 / 菜单变化；
- 没上平台的小店仍然不可见。

---

## 27. 2015–2019：拥堵型未来——“选择太多以后，还要管理注意力和等待”

核心经验：

- 榜单越来越多；
- 网红店、排队、在线取号叠加；
- 商家开始把评分 / 曝光当作经营资源；
- 刷好评、恶意差评、删差评与反作弊成为系统日常。

未来问题从：

> “哪里有好吃的？”

变成：

> “这么多高分店，我怎么知道哪一个是真的适合我，而且值不值得排两小时？”

---

## 28. 2020–2022：偶发型未来——“过去的信息可能还对，但今天的状态已经变了”

核心经验：

- 堂食、外卖、暂停营业可以分别变化；
- 同一品牌不同门店状态不同；
- 老店可能突然消失；
- 实时营业信息暂时比长期平均评分更重要。

因此：

> **reputation freshness（口碑新鲜度）和 operational freshness（营业状态新鲜度）被强行分开。**

---

## 29. 2023–2026：防守型未来——“不再追求一个万能分数，而是保留判断权”

核心经验：

- 用户开始有意识读低分、反向找店；
- 评分过度集中会降低辨别力；
- 平台必须治理诱导好评、差评骚扰与黑产；
- 本地熟客型小店可能长期低在线可见；
- “真人真评价”从默认假设变成需要不断证明的承诺。

成熟的生活策略不是退出数字平台，而是：

> **把平台从裁判重新降级为一个证据源。**

---

# 十、对“普通人到底有多少种活法”的影响

## 30. 迁移：少一种必须依赖本地熟人的启动成本

刚搬进一座城市的人，以前常需要：

- 问同事；
- 跟着室友；
- 在附近反复试；
- 记住一两家固定店。

本地生活平台不能替他建立朋友关系，却可以让一些生活事务先跑起来。

因此：

> **social capital 仍重要，但部分地方实用知识不再只能从已有 social capital 获得。**

这会让独自迁移、短住、差旅、临时项目、外地求学更容易执行。

---

## 31. 社交：聚餐地点本身成为一种协调问题

“和谁吃”与“去哪吃”本来就相互影响。

不同场景需要不同约束：

```text
两个人快速吃完
多人同事聚餐
第一次约会
带老人孩子
朋友生日
异地朋友来访
预算紧张
需要安静说话
有人忌口
```

点评网站把这些原本需要熟人解释的场景，部分翻译成“环境、口味、人均、包间、适合聚会、照片”等字段。

因此它提供的不是单纯消费信息，而是**社交场景的预协调信息**。

---

## 32. 非主流路线：一个人吃、临时吃、陌生城市吃，都更容易

标准家庭脚本里，吃饭常被想象成：

> 家庭厨房 / 固定单位 / 熟悉社区。

现实生命则有：

- 刚搬家；
- 独居；
- 出差；
- 夜班；
- 转岗；
- 临时住酒店；
- 一个人旅行；
- 朋友关系变化后重新建立生活圈。

能够快速读懂“这里有什么地方可以进去坐下吃一顿”，会降低这些状态的摩擦。

这与已有 `kitchen optionality` 不同：

- meal provisioning 讨论“这顿饭怎么获得”；
- 本文讨论“城市里可去的地方怎样变得可理解”。

---

# 十一、反例与后见之明风险

## 33. 不能写成“互联网以前只能靠熟人”

错误。

前互联网已有：

- 电话 / 114；
- 黄页；
- 报纸；
- 广播电视；
- 纸质指南；
- 酒店前台 / 旅行社；
- 单位、邻里、亲友。

Internet 的新增是把其中若干层重新组合成大规模可搜索数据库。

---

## 34. 不能写成“评分取代了本地知识”

评分本身就是一种抽样后的地方知识。

而且它会系统性漏掉：

- 不爱写评论的老顾客；
- 不做线上营销的小店；
- 新开店；
- 已经换老板但保留旧页面的店；
- 不同语言 / 年龄 / 收入群体的偏好。

---

## 35. 不能把今天的 4.8 / 3.5 评分语义倒投回 2006

评分算法、星级分布、权重、反作弊、点评量、移动端入口都可能变化。

因此：

> **同一个数字在不同平台时代可能不是同一种历史对象。**

研究历史评分必须同时记录：

- 评分尺度；
- 计算规则（若公开）；
- 当时点评量；
- 页面时间；
- 排名维度；
- 是否由当前后台重算。

---

## 36. 不能把榜单因果化

一家店上榜以后生意好，不等于榜单单独造成增长。

可能同时有：

- 地段；
- 媒体曝光；
- 短视频；
- 团购；
- 节假日；
- 新店效应；
- 原本就很强的线下口碑。

因此本文最多说“榜单成为可见性资源”，不直接把经营结果归因于榜单。

---

# 十二、历史可见性：平台让餐馆更可见，也让某些店更难被历史看见

## 37. visibility bias：越会被评价的店，越容易进入历史

今天研究 2008 年城市餐饮时，很容易找到：

- 点评很多的店；
- 上榜店；
- 引发争议的店；
- 网红店；
- 连锁店。

最难找到的是：

- 只服务附近熟客的小店；
- 没有网站和点评页的店；
- 几年后悄悄关门的店；
- 菜单、价钱从未数字化的店。

因此 archive 中“互联网热门餐厅很多”不能推出现实城市当时主要由热门店组成。

---

## 38. platform success / local invisibility inversion

本文新增一个以后可复用的 archive bias：

> **platform success / local invisibility inversion**。

一个平台越成功地成为主流城市指南，研究者以后越容易把“平台收录的城市”错当成“当时完整的城市”。

但真正现实中的城市始终还有平台之外的：

- 熟客网络；
- 社区小店；
- 临时摊点；
- 单位内部食堂；
- 仅电话可达服务；
- 已经在平台上僵尸化的旧店页面。

因此平台数据是城市史的重要源，但不是城市的 census。

---

# 十三、与 old-web-archaeology 的交叉

配套研究包：

`tmzncty/old-web-archaeology/docs/RESTAURANT_DIRECTORY_REVIEW_RATING_RANKING_COUPON_AND_VISIT_STATE_GAPS_1999_2015.md`

old-Web 侧重点不是写“大众点评商业史”，而是恢复这些状态边界：

```text
real venue exists
→ listing exists
→ metadata current
→ review submitted
→ review published
→ aggregate rating computed
→ rank/search result rendered
→ user sees page
→ user calls/navigates/downloads coupon
→ restaurant is actually open
→ user arrives
→ table available
→ meal occurs
```

以及：

`page survived ≠ rating snapshot survived ≠ ranking survived ≠ restaurant survived`。

# 十四、证据等级总表

## A / A-B：同期个人使用痕迹

# 十六、这一轮改变了什么理解

以前很容易把“会不会用本地生活 App”理解成一个消费便利问题。

这一轮以后，更准确的说法是：

> **一个人有多少种城市生活路线，还取决于她能不能在没有当地熟人、没有多年踩点经验的情况下，快速把陌生空间变成可执行的生活地图。**

Web 以前，一个人在本地住得久，本身就是资产：她知道哪家店不坑、哪里安静、哪里能带十个人、哪家周日晚还开。

早期点评网站把这部分资产第一次大规模沉淀成可以被陌生人搜索的弱关系公共知识；移动互联网又把它装进口袋。

这让旅行、独居、迁移、换工作、跨城见朋友都少了一点必须先“找本地人带路”的依赖。

但成熟以后，问题又倒过来了。

当几乎每家店都有分、每个城市都有榜、每次聚餐都能先看几十条评价时，普通人不再缺一个答案，而是需要重新获得**不被单一分数替自己做决定的能力**。

所以这条生活史不是：

`信息越来越多 → 人越来越会生活。`

更像：

```text
地方知识难获得
→ 地方知识被平台化、可携带
→ 平台评价成为日常决策基础设施
→ 评分 / 排名产生拥堵与博弈
→ 成熟用户重新学习怎样质疑、拆分和校准这些数字
```

真正支持“更多活法”的基础设施，最终不是告诉所有人同一家店最好，而是让一个刚到陌生城市的人**先有足够信息能够自己做选择，同时仍保留走进一家没有高分、没有热榜、但很适合她自己的小店的权利。**
