## 0. 为什么还需要这一条

仓库已经有：

- `from-scheduled-to-ambient-information.md`：信息怎样从定时到达、目的地式上网变成环境式持续到达；
- 搜索/目录专题：一个人怎样第一次找到未知信息；
- bookmark 专题：已经找到的地方以后怎样回去；
- 在线状态、短信、日历等专题：消息、时间和可联系性怎样进入日常。

RSS/Feed 仍然形成一个不同的生活动作：

```text
我今天选择一个来源
→ 系统记住它
→ 来源未来发布新内容
→ 阅读器自动发现更新
→ 更新进入我的个人队列
→ 我以后再处理
```

搜索是“我现在去找”；书签是“我以后再回去”；订阅则是：

> **我今天给未来的信息入口写规则，让尚未出现的内容以后主动进入我的阅读范围。**

因此本条研究的不是“RSS 是否先进”，而是一条更长的历史：

```text
邮局/发行机构按期投送报刊
→ 广播电视按节目表到达
→ 邮件列表/Usenet 等网络化连续信息
→ 网站逐个访问
→ RSS/Atom 按来源自动聚合
→ 在线阅读器跨设备维护未读状态
→ 社交关注流/公众号/新闻客户端
→ 算法主动决定排序与追加内容
→ 2020s 一部分用户重新寻找可控信源、有限队列和可导出的订阅图
```

必须固定：

> **订阅了 ≠ 更新被成功抓取 ≠ 条目进入阅读器 ≠ 用户看见 ≠ 用户读完 ≠ 用户相信 ≠ 用户据此行动。**

## 1. 新概念

### 1.1 future-information addressability / 未来信息寻址

普通人不只可以给“人”留下地址，也可以给“未来的信息”预先写地址。

例如：

- 订一份报纸；
- 订一期刊；
- 订一个邮件列表；
- 订一个 newsgroup；
- 把某个博客的 RSS 加进阅读器；
- 关注一个公众号/账号；
- 允许一个 App 根据行为继续推荐。

这些机制的共同点是：今天的选择影响未来什么东西会进入自己的注意力。

但控制权不同。

### 1.2 subscription graph / 订阅图

RSS 阅读器里的核心资产不只是“文章”，而是：

```text
source A
source B
source C
...
→ folder/tag/category
→ polling state
→ unread/read/star/tag/share/note state
```

这是一份个人长期建立的“哪些世界值得持续回来”的地图。

### 1.3 subscription-graph portability / 订阅图可携带性

OPML 允许一批 feed URL 被导出、再导入另一阅读器。

因此：

> **reader account can die while source graph may survive.**

但也必须反过来固定：

> **OPML 能带走 feed 列表，不等于能带走已读/未读、收藏、标签、备注、分享历史和抓取缓存。**

### 1.4 source sovereignty / 信源主权

这里不是抽象讨论“算法好不好”，而是问一个可操作的问题：

> **谁决定哪些来源有资格进入我的未来信息流？**

可能是：

- 编辑部；
- 邮政/发行体系；
- 我自己订阅；
- 我的社交关系；
- 平台排序与推荐算法；
- 我自己选择来源、算法只在这些来源内部排序。

这几种模式并不是线性替代，而会叠加。

### 1.5 reading-state custody / 阅读状态保管

当阅读器变成长期工具以后，“我订了什么”只是状态的一部分。

还有：

- 哪些读过；
- 哪些还没读；
- 哪些收藏；
- 哪些打标签；
- 哪些分享；
- 哪些写过备注；
- 某一条是否已经从服务器缓存。

这些状态往往比 RSS 协议本身更平台化。

### 1.6 unread debt / 未读债务

增加一个 RSS 源的即时成本非常低，未来更新却可能每天继续产生。

于是：

```text
增加订阅容易
→ 新条目持续产生
→ 未读数字增长
→ “以后要看”的未来义务累积
→ 阅读本身开始带来焦虑/清理劳动
```

这和 bookmark 的“收藏债”不同：bookmark 债来自保存大量静态候选；unread debt 来自**来源会继续生产新东西**。

### 1.7 bounded feed / 有尽头的信息流

一部分 2020s RSS 用户重新珍惜的不是“RSS 没有算法”本身，而是：

> 今天的未读队列可以读完，然后停止。

这给注意力一个停止条件。

它只是一些重度/技术用户的同时代自述，不能外推所有人，但它与无穷滚动的信息流形成明确机制差异。

### 1.8 feed-bridge fragility / 订阅桥脆弱性

当网站、公众号或平台不原生提供 feed，一部分用户会用 RSSHub、抓取器或第三方服务把封闭源转换成 RSS。

链条变成：

```text
封闭平台
→ 登录/接口/HTML
→ bridge/scraper
→ synthetic feed
→ reader
```

任一环节的反爬、登录策略、DOM 改版、限频或服务停运，都可能让“我的订阅”突然失去来源。

## 2. 前互联网中国：未来信息早已可以“订”，但到达节奏和入口不同

### 2.1 报刊订阅本来就是一种未来信息路由

国家统计局历史表显示，1980 年邮政通信体系已经记录“平均每百人每年订报刊数”为 16.7 份；1985 年为 28.8 份。这个指标不是“有多少独立个人订阅者”，因为一个人、家庭、单位都可能订多份，也可能存在公费/集体订阅；但它足以证明，**定期刊物通过邮政发行进入未来日常**并非 Internet 才有的机制。

来源：

- 国家统计局，《中国统计年鉴 2011》16-40 邮政通信服务水平
- https://www.stats.gov.cn/sj/ndsj/2011/html/P1640C.HTM
- 等级：A（官方统计；解释单位时必须谨慎）

山东地方志保存的发行制度又更具体：1980 年邮电部重新规定不同周期报刊的收订时间；1983 年山东自费订阅报刊占总期发数 29.6%，部分地区个人订户继续增长。

来源：

- 山东省情库，《发行方式》
- https://shandong-chorography.org/database/a/section/42/article/77/
- 等级：B/A（地方志基于邮电档案的后编资料）

这说明“我现在订，未来每一期自动到来”很早已经是一种生活机制。

但纸刊有硬边界：

- 到达频率由出版周期决定；
- 来源集合受发行渠道和价格约束；
- 投递地址通常是家庭/单位等物理地点；
- 换城市需要重新处理订阅；
- 没有自动的跨刊“未读计数”；
- 一期没读，不会在一个统一界面里不断增加红色数字。

### 2.2 广播电视：持续到达，但不是“我的源列表”

1982 Beijing Audience Study 对北京市区及周边 metropolitan area 的 2430 人样本显示，97% 每日听广播、92% 看电视、81% 读日报。

来源：

- Everett M. Rogers et al., `The Beijing Audience Study`, Communication Research 12(2), 1985
- https://journals.sagepub.com/doi/10.1177/009365085012002002
- 等级：B/A（1982 调查、1985 发表；只是北京 metropolitan 样本，不可外推全国）

它说明大众信息在 Internet 前已经可以非常高频地进入生活。

但这仍和 RSS 不同：

> **高频到达 ≠ 用户拥有可编程的来源清单。**

你可以换台、换报纸、换节目，但广播电视的基本流仍由频道和节目表组织。

## 3. 全球网络前史：从 newsgroup 选择到 Web syndication

### 3.1 1986 NNTP：网络已经在处理“哪些持续更新是我想要的”

RFC 977（1986）规定 NNTP，用于网络新闻数据库的分发、查询、检索与 posting。协议允许客户端询问新的 newsgroup、获取希望接收的组中有哪些新文章，并只传输需要且尚未拥有的文章。

来源：

- RFC Editor, RFC 977, `Network News Transfer Protocol`, February 1986
- https://www.rfc-editor.org/info/rfc977/
- 等级：A（协议原始文档）

它不能证明 1986 年普通家庭已经在用现代意义上的 RSS；它提供的是**工程谱系**：

```text
持续产生的远程信息
→ 用户/站点选择感兴趣的 group
→ 客户端询问新增
→ 只取尚未拥有的条目
```

### 3.2 1999 RSS 0.90：Web 页面之外出现机器可读取的“频道”

RSS Advisory Board 保存的 Netscape RSS 0.90 规范注明，该规范原由 Netscape 于 1999-03-15 发布，用于 My Netscape Network channel。

来源：

- RSS Advisory Board, `RSS 0.90 Specification`
- https://www.rssboard.org/rss-0-9-0
- https://www.rssboard.org/rss-history
- 等级：A（保存的原始规范/规范史）

这一节点说明：Web 不再只是“人逐页访问 HTML”；发布者也可以提供一种机器可轮询、可聚合的更新表示。

再次强调：

> **protocol exists != ordinary people use it != China has mass RSS adoption.**

## 4. 2005—2012：扩张型未来——“以后我不用再逐站巡逻”

### 4.1 2007 抓虾：把分散网站变成个人持续入口

2007-02-12 新浪科技关于抓虾的长篇同期访谈非常有价值，因为它同时保存了创业者、博客作者和实际用户的语言。

抓虾创办人徐易容回忆，公司 2005-12 成立、2006-04 产品上线，出发点就是网上好内容很多、分散在各处，人“上网以后也不知道该干吗”，希望把信息抓回来，再做筛选。

更重要的是同场韩磊的同期第一人称：他每天上网常打开两个站，一个是工作相关的 CSDN，一个是抓虾，用后者了解“世界上发生什么、别人写什么”。

来源：

- 新浪科技，2007-02-12，《抓虾创始人徐易容：RSS商业化为时过早》
- https://tech.sina.com.cn/i/2007-02-12/19041381851.shtml
- 等级：A/B（同期媒体实录；个人与创业者自述，不代表总体用户）

这让一条生活变化非常清楚：

过去：

```text
记住十几个网址
→ 逐个打开
→ 判断有没有更新
→ 没更新也花一次访问成本
```

RSS：

```text
订十几个源
→ 阅读器代替我轮询
→ 只有更新进入队列
```

RSS 不是让信息“更多”，而是把**检查是否有新东西**这项劳动外包给机器。

### 4.2 2007 的“未来想象”：同一份订阅应该跟着人穿过设备

同一访谈里，韩磊解释为什么赞同 online reader：他自己使用好几台电脑，并认为未来信息阅读一定会多元化，不可能只用电脑，手持设备也会加入，所以在线方式有优势。

这是一份罕见的 2007 同时代未来想象。

它不是后来的“智能手机必然史”，而是当时一个重度用户已经在期待：

> **来源列表和阅读状态应该属于我，而不是属于某一台 PC。**

来源同上，等级 A/B（同期个人自述）。

### 4.3 OPML：未来信息入口第一次变成可打包搬走的对象

2007-07-02，月光博客公开自己从 Google Reader 导出的 OPML：150 多个 feed，分目录整理，每天约产生 100—300 篇更新；该 OPML 可以导入 Google Reader、Bloglines、抓虾等阅读器。

来源：

- 月光博客，2007-07-02，《共享一下我的OPML订阅FEED》
- https://www.williamlong.info/archives/954.html
- 等级：A/C?（同期第一人称公开博客；可证明该作者自己的订阅结构，不可外推大众）

这里出现一个很重要的数字生活对象：

> **subscription graph can become a file.**

换阅读器不必重新回忆 150 个来源。

但这个例子同时显示另一面：每天 100—300 条更新已经足以制造新的时间压力。

### 4.4 2008 在线 Reader：跨电脑同步的不只是源，还有“读到哪儿了”

2008 年月光博客介绍 Google Reader 等 Web reader 时，强调不同电脑看到的是同一批 feed，已读/未读和标签也一致。

来源：

- 月光博客，2008-11-27，《五个最佳RSS新闻阅读器》
- https://www.williamlong.info/archives/1591.html
- 等级：B/A（同期技术博客；功能观察）

于是未来信息状态从：

`source list portable`

进一步变成：

`source list + read state + tags portable`。

这比简单 OPML 更强，也因此更依赖 hosted service。

### 4.5 反例：扩张型未来在 2008 年已经产生“未读债务”

2008-07-31，一名博客园作者主动“退订 RSS”。他的同期第一人称非常明确：订阅大量 RSS 后，业余时间大量消耗，相关链接不断展开，信息阻塞思考，最后产生“阅读焦虑”。

来源：

- 博客园 xjb，2008-07-31，《摆脱阅读黑洞，退订RSS》
- https://www.cnblogs.com/xjb/archive/2008/07/31/exit-rss.html
- 等级：A（同期第一人称；个体材料，不代表普遍性）

所以不要把 2005—2012 写成“人终于高效获得信息”。

更准确的是：

> **RSS 降低逐站巡逻成本，也降低增加一个未来信息义务的成本。**

这使“越订越多”很早就成为可能。

### 4.6 普及边界：RSS 并没有因此成为中国普通网民的默认入口

2007 年 Feedsky 创办人同期就承认 RSS 在中国仍不普及；2013 年 Google Reader 关闭后的行业回顾同样指出，RSS 长期偏重度/专业用户。

来源：

- 新浪科技，2007-05-16，Feedsky 创始团队相关访谈/报道
- 参见新浪科技 2013 RSS 回顾：
- https://finance.sina.com.cn/leadership/mroll/20130815/172716461070.shtml
- 等级：B（行业同期/近同期观察）

所以只能写：

> RSS 在 2000s 中文 Web 中形成了一条真实、成熟、对部分重度用户很重要的信息生活路径。

不能写：

> 2008 年中国年轻人普遍通过 RSS 获取新闻。

## 5. 2013—2015：关键中间转折——协议没死，替你保管状态的平台可以死

### 5.1 Google Reader 关闭把“协议”和“基础设施”强行分开

Google 2013-03 宣布 Google Reader 将于 7 月 1 日关闭，允许用户通过 Takeout 导出订阅等数据；同期报道指出，大量第三方 Reader 客户端依赖 Google Reader 的订阅与同步基础设施。

来源：

- 新浪科技，2013-03-14，《谷歌宣布7月1日关闭Google Reader》
- https://tech.sina.com.cn/s/2013-03-14/08368144866.shtml
- 新浪科技，2013-03-14，《谷歌关闭Google Reader将冲击第三方应用》
- https://tech.sina.com.cn/i/2013-03-14/09168144952.shtml
- 等级：B（同期媒体，引用 Google 官方公告与开发者生态）

这里必须固定：

> **Google Reader died != RSS died.**

Feed 标准、发布者 feed、OPML 都可以继续存在；死掉的是一个长期承担：

- 订阅列表；
- polling；
- read/unread；
- tags/stars/notes；
- 多客户端同步；
- 第三方 API backend

的 hosted service。

### 5.2 2013 同期第一人称：工具已经像“每天的报纸”

2013-07-01 新浪采访在美国学习的学生张昊。他说自己会在多种设备使用 Google Reader，接近每天读书看报纸一样的固定生活入口；他担心替代品不能同样完成同步、统一和跨平台。

来源：

- 新浪科技，2013-07-01，《Google Reader关闭 数十公司抢谷歌“剩饭”》
- https://tech.sina.com.cn/i/2013-07-01/02588494308.shtml
- 等级：A/B（同期个人自述；明确是重度用户，不能代表普通网民）

这说明 hosted reader 已经可以成为某些人的**日常信息基础设施**，而不仅是一个偶尔打开的网站。

### 5.3 迁移不只是“把 OPML 导出去”

关闭后的迁移潮很快暴露 operational failure。2013-07-05，Flipboard 因大量 Google Reader 用户迁移出现服务中断；报道还说此前一次故障发生在迁移订阅源进入自家服务时。

来源：

- 新浪科技，2013-07-05，《Flipboard服务中断：或因谷歌阅读器用户转移》
- https://tech.sina.com.cn/i/2013-07-05/16188512133.shtml
- 等级：B（同期故障报道）

因此：

`export available != migration complete != new backend stable`。

### 5.4 2015 抓虾关闭：中国本土 Reader 同样出现保管退出问题

2015-08-21 的同期行业报道说，抓虾已在 8 月 5 日通过邮件通知用户，将于 8 月 20 日关闭，并提醒备份数据。

来源：

- 速途网经搜狐保存，2015-08-21，《曾经，四大门户的颠覆者——抓虾，宣布关闭》
- https://www.sohu.com/a/28583951_114814
- 等级：B（同期行业报道；未取得原始停服邮件副本）

这意味着 2007 那份“我以后在任何设备都能接着看”的未来，到了 2013—2015 多了一条新的前提：

> **替我记住未来入口的公司也必须继续存在，或者我必须能撤离。**

## 6. 2015—2019：拥堵型未来——从“我订什么”走向“平台替我不断选什么”

### 6.1 算法推荐解决了另一种成本：不再要求用户维护 source graph

2019 年人民网刊载的传播学研究已经把个性化新闻推荐描述为一种算法把关：平台从巨大信息库中根据用户行为和画像做筛选，解决人工选择面对信息过载的效率问题。

来源：

- 人民网/《新闻爱好者》，2019-11-13，《个性化新闻推荐系统中算法把关的思考》
- https://media.people.com.cn/n1/2019/1113/c430698-31453063.html
- 等级：B（同期学术/传媒研究，不是个体生活调查）

RSS 的用户劳动是：

```text
我先找来源
→ 我决定订阅
→ 我维护来源
→ 阅读器负责抓取
```

算法 feed 的典型劳动结构更接近：

```text
我点击/停留/关注/跳过
→ 平台推断兴趣
→ 平台决定下一批来源与条目
```

所以它并不是单纯“RSS 更先进/算法更先进”，而是把选择劳动移到不同位置。

### 6.2 2019 同期第一人称已经把“看什么的控制权”说出来

2019-02 一篇少数派 RSS 新手指南开头就说，主流资讯 App 越来越强调算法，“我们看什么”越来越不完全由自己控制；作者同时承认算法推荐在信息爆炸环境里是主流且高效的阅读方式。

来源：

- 少数派，2019-02-23，《给新手写得 RSS 阅读指南》
- https://sspai.com/post/53032
- 等级：A/C（同期第一人称/教程型文章；技术用户，不能外推人口）

2019-11 的另一篇个人文章也把 RSS、编辑精选、微博/公众号/今日头条等放进同一个“信息过载怎样过滤”的问题中。

来源：

- 腾讯云开发者社区，2019-11-24，《算法推荐与 RSS 订阅》
- https://cloud.tencent.cn/developer/article/1543554
- 等级：A/C（同期个人技术文章）

这说明“信源主权”在 2019 已经不是我们今天倒推的词义：当时一部分用户已经主动把 RSS 与算法推荐作为两套信息选择机制比较。

### 6.3 拥堵的真正变化：更新不再只有“我主动订的那些源”

RSS 的未读债务来自自己增加 source；算法流的拥堵可以在**不新增显式订阅**的情况下继续产生。

因此有两种不同的未来信息压力：

```text
subscription overload:
我过去做的订阅决定持续生成未来义务

recommendation overload:
平台根据我过去的行为持续生成下一批候选
```

前者可以通过退订把边界缩小；后者通常还要面对模型、社交关系和平台商业规则。

## 7. 2020—2022：偶发型未来——本轮没有找到“疫情使 RSS 发生结构性转型”的强证据

这一时期不能因为我们的四阶段框架存在，就硬造一个 RSS 的“疫情革命”。

本轮检索到的材料更多显示：

- RSS 阅读器继续存在；
- OPML 导入导出仍被使用；
- dead feed 需要维护；
- 移动端、桌面端、自托管继续并行；
- 信息过载在疫情期当然存在，但暂时没有找到足够强的一手材料证明 **COVID-19 本身**让普通中国用户的 RSS 使用发生一个类似远程办公那样的基础设施突变。

因此本条把 2020—2022 记录为一个**重要负结果**：

> **not every infrastructure has a pandemic-specific phase transition.**

对这一对象而言，更强的结构变化仍然是 2013 hosted-reader collapse、2010s algorithmic feed rise，以及 2020s 的 source-control/self-hosting revival。

这也防止把所有生活史都机械套进同一四段叙事。

## 8. 2023—2026：防守型未来——不是“回到 RSS”，而是重新谈边界、终点和退出权

### 8.1 2023 第一人称：“有尽头”重新成为优点

2023-01-13 少数派一篇第一人称 RSS 文章明确说，在持续刷新的信息流中，RSS 的价值之一是每天可以只看 1—2 次，而且“有尽头”；作者希望停止不停刷新，把注意力重新转回生产。

作者还明确把 RSS 当作一种可自己扩展边界的输入方法，并使用 RSSHub、Telegram、YouTube、公众号桥、Podcast OPML 等多种源。

来源：

- 少数派，2023-01-13，《2023 年为什么我们还要使用 RSS？探索、聚合和专注》
- https://sspai.com/post/77802
- 等级：A（同期第一人称技术用户；不可外推总体）

这是一种非常典型的**防守型未来**语言：

2007：希望以后更多设备都能继续读；

2023：希望信息流今天能有一个结束点。

### 8.2 但“自己选源”本身也越来越需要维护基础设施

2024-11，一名少数派作者写自己长期把阅读系统分成 `RSS + 微信`，因为公众号生态难稳定纳入 RSS；RSSHub 微信路由可能 404，第三方订阅源也会停止运营。他尝试 WeWe RSS 后又遇到账号、刷新频率、验证码和项目维护寿命等问题。

来源：

- 少数派，2024-11-12，《WeWe RSS：更优雅的微信公众号订阅源》
- https://sspai.com/post/93845
- 等级：A（同期第一人称技术实践；不可外推普通用户）

这形成新的反例：

> **source sovereignty is not free.**

平台不提供开放 feed 时，“我要自己决定源”可能意味着：

- 自托管；
- 维护 Docker；
- 登录封闭平台；
- 处理验证码；
- 接受抓取失效；
- 等待 bridge 修复。

### 8.3 2026 的新折中：来源由我决定，排序可以交给本地/自托管算法

2026 当前的 Dibao 项目把产品思想明确写成：只在用户自己订阅的 RSS/Atom 来源范围内做个性化推荐，用户画像和行为数据可以保留在本地/自托管环境。

来源：

- Dibao 当前产品页（访问于 2026-09-09）
- https://dibao.app/zh/
- 等级：A（当前产品自述；只能证明产品设计，不代表采用规模）

这个例子不应写成“2026 RSS 主流复兴”。它更适合说明一个新的工程折中已经出现：

```text
source selection = user
ranking = algorithm
profile custody = local/self-hosted
```

也就是说，2020s 的选择不必只有：

`纯手工 RSS` vs `平台无限推荐流`。

可能出现第三条路：**保留信源主权，同时把排序劳动自动化。**

## 9. 这条历史怎样进入“普通人有多少种活法”

### 9.1 教育

一个学生可以：

- 只等课堂和教材；
- 去图书馆查期刊；
- 订专业报刊；
- 订博客/论文 feed；
- 加入社交群；
- 依赖推荐流发现材料。

不同机制决定“新东西怎样进入学习”。

### 9.2 就业与职业成长

2007 韩磊把 CSDN 和抓虾作为日常两类入口，说明职业信息不一定只通过正式培训或单位文件进入。

长期订行业 feed 可以形成一种低强度持续职业学习；但它同样可能制造“永远还有东西没看”的工作外延。

### 9.3 迁移

纸刊订阅绑定物理地址；桌面 RSS client 绑定一台机器；online reader 把 source/read state 放进账号；OPML 又让 source graph 可跨服务。

所以“搬家以后还能读同一批东西”本身也经历了基础设施变化。

### 9.4 照护与生活决策

健康、育儿、住房、消费等信息来源如果长期订阅，会变成生活决策背景；但这不自动意味着质量更高。

必须继续区分：

`source chosen != source trustworthy`。

### 9.5 社交关系

RSS 原本可以绕过“必须成为朋友/粉丝”的关系层直接订公开内容；后来的社交 feed 则把信息分发和 social graph 更深地绑在一起。

### 9.6 长期中断

如果一个人几年不读：

- 纸刊会物理堆积或停止续订；
- RSS reader 可能积累大量未读；
- hosted reader 可能停服；
- feed 本身可能死亡；
- OPML 仍在，但里面一批 URL 已经失效。

“重新回来”需要的是 source graph + 服务 + 活源 + 可理解的状态，而不只是一个账号密码。

## 10. 时代时间感：四种未来在“信息入口”上的不同语法

### 10.1 2005—2012 扩张型未来

典型语法：

> “网上这么多好东西，我想把更多来源收进来，而且以后换设备也能继续。”

关键词：

- 聚合；
- 跨设备；
- 发现更多源；
- 推荐朋友在读的内容；
- OPML；
- 多端同步。

### 10.2 2015—2019 拥堵型未来

典型语法：

> “信息已经太多，维护 source graph 本身都是劳动；算法可以帮我筛，但我开始不完全知道为什么会看到这些。”

关键词：

- 信息过载；
- 算法推荐；
- 无限 feed；
- 平台画像；
- RSS 成为小众工具；
- hosted reader 退出风险。

### 10.3 2020—2022 偶发型未来

本对象没有发现强的疫情专属跃迁，不能硬写。

更稳妥的是：

> 信息摄入体系继续运行，并进入一个“RSS/公众号/社交 feed/新闻 App/群聊长期叠加”的状态。

### 10.4 2023—2026 防守型未来

典型语法：

> “我不一定要少知道，但我希望知道信息从哪里来、今天什么时候算看完、以及平台没了以后还能不能带走我的源。”

关键词：

- 有尽头；
- 主动筛源；
- OPML/export；
- 自托管；
- bridge fragility；
- source sovereignty；
- 本地推荐/可解释排序。

## 11. 反例与不能写过头的地方

### 11.1 RSS 并没有成为 2000s 中国大众默认入口

抓虾、鲜果、Google Reader、Feedsky 等确实形成了真实生态，但同期业内自己已经反复承认 RSS 普及有限。

所以：

`important to some heavy users != mass norm`。

### 11.2 RSS 不等于“没有推荐”

抓虾本身就做热门/推荐；Google Reader 也有分享、社交状态；RSS reader 可以继续做 ranking。

真正区别是**来源集合、排序层和数据保管的控制结构**，不是一个简单的“算法/无算法”二元。

### 11.3 自己选源也会形成窄化

用户可能长期只订熟悉立场、熟悉领域和熟悉作者。

因此：

> source sovereignty != viewpoint diversity.

### 11.4 RSS 也会浪费时间

2008 的退订材料已经证明：用户自己选择的来源同样可以制造阅读焦虑。

### 11.5 算法推荐并非只有坏处

2019 的同期研究和个人文章都承认，算法在海量信息环境下确实降低筛选成本。

研究问题不是道德化地比较“好/坏”，而是：

> **筛选劳动被谁承担，目标函数是谁设定，用户能否观察、调整和退出。**

## 12. 历史可见性：最能说明一个人怎样读的状态，往往最不该被公开

公开 Web 很容易留下：

- RSS icon；
- Feed URL；
- reader 首页；
- 帮助页；
- OPML 格式说明；
- 公开分享的 OPML；
- 停服通知；
- 新闻报道；
- 博主自己的公开订阅列表。

但一个普通人的长期 subscription graph 可能非常敏感：

- 疾病；
- 宗教；
- 求职；
- 财务；
- 性/亲密关系；
- 家庭问题；
- 政治兴趣；
- 小众社群。

因此高质量生活史研究不应为了“知道 2008 年的人到底订了什么”而重新公开私人 reader 数据。

> **private subscription graph is historically valuable precisely because it is private.**

旧网考古更适合恢复：

- 数据模型；
- 状态机；
- 公开 demo；
- 协议；
- 导出格式；
- 停服迁移行为；
- 公开自愿分享的历史 OPML。

## 13. 本轮改变了我们对“人怎么活着”的哪一点理解

以前讨论信息时代，很容易只说：

> “以前信息少，后来信息多。”

这条研究让更细的变化浮出来了。

一个人的生活不只取决于**世界上有没有信息**，还取决于：

- 谁决定哪些来源持续进入他的未来；
- 他是否要每天亲自巡逻那些来源；
- 来源列表能否跨设备、跨城市、跨服务继续存在；
- 读不完时系统有没有终点；
- 平台停服后过去多年建立的阅读结构还能不能带走；
- 封闭平台是否迫使他重新承担抓取和维护劳动。

所以 Internet 真正改变的不是“人终于可以读很多东西”。

> **它先让普通人有机会亲自编写一份‘以后什么来找我’的清单；随后平台又学会根据行为替人不断改写这份清单。到 2020s，一部分人的防守不是回到纸张，而是在重新争取：来源最好仍由我决定，机器可以帮我排序，但不要替我悄悄决定整个世界。**

## 15. 下一步仍未解决

1. 能否取得 2006—2009 抓虾/鲜果/有道阅读的合格历史 memento，并核验 charset、HTML、feed autodiscovery、订阅表单、reader shell 与 AJAX/API 行为；
2. 能否找到更多 2007—2010 非技术圈第一人称，而不是博客作者/程序员；
3. 2010s 中国公众号、微博关注流与 RSS 之间究竟有哪些真实迁移路径；
4. OPML 迁移在中文 reader 之间实际保留了哪些 folder/category，哪些丢失；
5. 2013 Reader 关闭以后，stars/tags/notes/read state 的真实迁移损失还需要更细的一手包；
6. 2020—2022 是否存在疫情期特殊 RSS/邮件订阅材料，目前没有足够强证据；
7. 2020s “自托管/反算法”实践到底是很小的技术亚文化，还是可观察的更广趋势，需要用户调查而非案例堆叠。

本轮未达到饱和：新增了“未来信息寻址 / 订阅图可携带性 / 信源主权 / 未读债务 / feed bridge 脆弱性”这一组独立机制，并得到 2007、2008、2013、2019、2023、2024 的同期材料与 NNTP/RSS 海外前史。
