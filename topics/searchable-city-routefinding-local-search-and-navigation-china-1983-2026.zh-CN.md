# 当陌生城市变得可以搜索：问路、纸地图、网上地图、导航与“提前读懂一座城”

> 研究问题：一个普通人什么时候开始不必先认识当地人、背熟道路或亲自到场，就能知道“这家公司在哪”“这套房离单位多远”“从车站怎么到宿舍”“这家店附近有什么公交”“如果我搬去另一座城，日常路线大概会是什么样”？
>
> 核心判断：电子地图真正改变普通生活的地方，不只是“地图从纸变成屏幕”，而是逐步把陌生城市变成一个可以在到达之前搜索、计算和比较的对象。这个过程先后经历了**人工/纸质可读性 → Web 上的目的地可寻址性 → 路线计算 → 手机随身定位 → 实时路线修正 → 通勤约束直接进入住房与生活选择**。

本笔记不是“中国地图软件史”，也不把“某地图网站上线”写成普通人已经依赖它。它关心的是：**城市可读性怎样成为迁移、找工作、租房、旅行、社交和日常时间预算的一部分。**

---

## 0. 为什么这是普通生活史，而不只是 GIS 史

搬到一个陌生城市，至少要解决几类空间问题：

1. 找到一个地址；
2. 判断两个地点相距多远；
3. 知道公交、地铁、步行或驾车怎样连接；
4. 判断一份工作与一套住房能否组成可持续的日常；
5. 在道路、站点、商家变化后重新获得最新信息；
6. 到达以后，在实际街道中确认自己“此刻在哪”；
7. 在发生拥堵、施工、封闭或临时管制时修正原计划。

这些工作从未真正消失。历史变化主要是：**谁在做计算、在什么时候做、依赖什么资料、错误怎样暴露。**

因此建议把普通人的“空间劳动”拆成：

`知道目的地名称 → 找到地址 → 在地图上定位 → 找到附近交通节点 → 计算路线 → 判断时间/成本 → 实际出发 → 途中确认当前位置 → 应对偏航/封路 → 到达`。

一张地图只能覆盖其中一部分。

## 1. 先给概念：本轮新增的几个机制

### 1.1 pre-arrival legibility：到达前可读性

一个人还没有去过北京、上海、深圳，也可以先知道：

- 某个单位在城市哪一侧；
- 从火车站过去需要几次换乘；
- 某一片区附近有没有地铁；
- 两个候选住所哪个通勤更短；
- 一个陌生地名附近还有哪些熟悉地标。

这使城市第一次可以在**身体到达之前**被操作。

### 1.2 destination addressability：目的地可寻址性

纸地图擅长显示道路和地理关系，但早期网络地图开始把“医院、商店、写字楼、学校、饭店”变成数据库里的查询对象。

历史变化不是只有“看地图更方便”，而是：

> **一个普通地点开始像网页一样，可以通过名称、地址、电话、邮编等字段被找到。**

### 1.3 route externalization：路线计算外部化

过去路线知识可能掌握在：

- 本地居民；
- 公交售票员；
- 出租车调度员；
- 纸质交通图；
- 旅行指南；
- 自己多次走过形成的记忆。

路线搜索把部分工作交给数据库与算法。

这不是“人不再需要认识城市”，而是**路线知识从个人/地方性记忆迁入可调用基础设施**。

### 1.4 spatial-memory portability：空间记忆可携带

Web 时代早期，路线通常要在电脑前查完、记下或打印。

手机地图、账号收藏、云同步出现后，“家”“公司”“收藏地点”“历史搜索”开始能跨设备跟着账号移动。

于是空间记忆也部分变成账户状态。

### 1.5 time-budget spatialization：时间预算空间化

到 2010s 后期—2020s，地图不只是回答“怎么去”，还越来越直接参与：

- 我住哪里；
- 我是否接受这份工作；
- 两个人住在哪里能同时通勤；
- 房租便宜多少才能抵偿多 40 分钟路程；
- 哪一个未来方案保留更多可选性。

地图开始把**未来每天会损失多少时间**直接嵌进住房和职业选择。

## 2. Web 以前：城市知识已经是一套基础设施

不能把 1990s 以前写成“没有数字地图，所以只能瞎走”。

### 2.1 人本身就是导航基础设施

北京日报今天保存的一篇历史回顾，引用了 1983 年 3 月 30 日《北京日报》关于 44 路公共汽车 737 车组的同期报道：司售人员为不熟悉北京的乘客制作到站预告牌、“沿线主要单位介绍图”和“换车线路图”，还走访沿线 340 多个单位。

来源：
- 北京日报历史回顾（2025，内嵌 1983 年报纸图像与出处）：https://xinwen.bjd.com.cn/content/s67bfa0a8e4b068c68f104f2d.html

证据等级：**C/B 混合**。今天的网页是后来整理，但明确标出同期报纸日期、版次与图像；本轮尚未独立取得 1983 原版扫描全文。

它提醒我们一个重要事实：

> **陌生人的城市可读性长期由“知道路的人”提供。**

售票员不仅售票，也承担站名解释、换乘和地标翻译。

### 2.2 纸地图把部分地方知识物化，但搜索成本仍在使用者身上

1999–2000 年介绍网上地图的同期文章反复以纸地图为对照：纸图重要，但寻找具体目的地困难；道路、新建筑和施工变化会让地图迅速变旧。

来源：
- 《数字时代的网上电子地图》，中华读书报，2000-08-02：https://www.gmw.cn/01ds/2000-08/02/GB/2000%5E311%5E0%5EDS1704.htm

这里不能倒推“所有人都买交通图”，但可以确认：**网络地图当时被理解为对纸图搜索性与更新性的补充，而不是凭空创造城市信息。**

## 3. 1999–2000：城市第一次在中文 Web 上变成可查询数据库

### 3.1 1999：在线地图已经不只是静态图片

1999 年 11 月《中华读书报》介绍多个中文网上地图入口。其中“北京地图向导”可放大、缩小、移动，并按名称、地址、电话、邮编查询医院、饭店、书店、商场等地点。

来源：
- 《向您推荐几个网上地图的“家”》，中华读书报，1999-11-10：https://www.gmw.cn/01ds/1999-11/10/GB/ds%5E274%5E0%5EDS1314.htm

证据等级：**B（同期媒体对服务功能的观察）**。

这意味着至少在功能层面，城市已经开始出现：

`街道图 + POI 数据库 + 字段查询`。

“饭店在哪”不再只需要先知道街名并在纸上找格子，而可以直接从地点名称反查空间位置。

### 3.2 但“有在线地图”不等于普通人可以轻松使用

同一篇 1999 文章记录：深圳旅游电子地图需要先安装 **Autodesk MapGuide Viewer 3.0**。

到了 2000 年，《数字时代的网上电子地图》仍明确抱怨在线地图速度慢；文章甚至说，在当时上网费仍较高的环境里，在线查地图对不少网民可能显得“奢侈”。

来源：
- 1999 同上；
- 2000 同上。

因此 adoption ladder 至少要拆成：

`服务存在 → 有联网终端 → 能打开网站 → 插件/浏览器满足 → 页面加载完成 → 查到地点 → 结果够准 → 用户愿意下次继续用`。

### 3.3 1999–2000 的真正变化：地点数据开始可嵌入别的网站

2000 年报道提到，1999 年成立的 Go2Map（图行天下）把地图、专题图和地图功能封装后嵌入门户和专业网站；当时已经向安家、新浪、114china 等站点提供服务，并进行城市 POI 普查，包括政府机关、公司、旅游点、写字楼、大学、医院、影剧院、街区、公交换乘和门牌号。

来源：
- 《数字时代的网上电子地图》，2000-08-02。

这让地图开始从独立“地图网站”变成一种**其他生活网站可以调用的空间层**。

后面找房、黄页、旅游、招聘、商家搜索都可以把地点数据叠进去。

## 4. 2005：从“看图”到“问城市一个问题”

2005 年是本轮很重要的扩张节点。

### 4.1 地图搜索与本地搜索合流

搜狐 2005 年收购 Go2Map 的 SEC 附件明确称，Go2Map 的数据库覆盖约 200 个城市的 POI，并能通过 Internet/Intranet、手机、呼叫中心和 PDA 等多种渠道提供地图服务。

来源（公司同期正式文件，A 级平台能力证据）：
- SOHU 2005-04-12 press release filed with SEC：https://www.sec.gov/Archives/edgar/data/1104188/000119312505075385/dex991.htm

注意：公司说“覆盖 200 城”证明数据库/商业能力声明，不证明普通人实际使用率。

### 4.2 一份很有价值的同期第一人称体验

新浪科技 2005-06-07 刊登一名试用者对新浪本地搜索与搜狗地图的对比。

他实际描述了：

- 地图拖拽；
- 搜索结果用地图 pin 标注；
- 鼠标滑过可见名称、地址、电话；
- 可进一步点“公交换乘”“驾车路线”；
- 可以用“写字楼/小区名称”作起终点，由系统匹配附近公交站；
- 某些路线换乘过多，甚至出现方向错误；
- 商家数据还不够完整。

来源：
- 《网友抢先体验新浪本地搜索(组图)》，2005-06-07：https://tech.sina.com.cn/i/2005-06-07/1018628634.shtml

证据等级：**B/C：同期媒体平台上的第一人称测试**。它不是随机抽样用户，但比产品发布稿更接近实际操作。

最重要的不是“哪个产品快”，而是这份材料明确显示了新的交互形式：

> **用户不需要先知道正确公交站名，也能用生活中的地点名直接问路线。**

这就是 `destination addressability → route externalization`。

### 4.3 同一材料也保留了扩张型未来的味道

作者在 2005 年已经把未来想成“如果车载/卫星定位和地图结合，就能实时得到路线导航”。

这不是今天回头写“手机导航必然到来”，而是**当时用户已经在现有 Web 地图上看到下一步可能性**。

这类材料应进入“同时代未来想象”样本。

## 5. 2004–2008：速度与数据更新不是附属问题，而是可执行性的核心

### 5.1 Go2Map 的慢不是一句体验抱怨，而是技术结构问题

2006 年泰伯网一篇同期行业报道记录，Go2Map 早期访问速度慢；2004 年以后采用“预先生成地图”的技术路线，以降低服务器实时运算压力，但预生成又意味着并非所有信息源都能任意显示。

来源：
- 《搜狗整合Go2map 全面启动商业化标注服务》，2006-09-11：https://www.taibo.cn/p/1598

证据等级：**B（同期行业报道，含企业技术说明）**。

因此老地图页面的视觉形态不能只当“网页设计”。

生成方式本身会限制：

- 加载速度；
- 缩放层级；
- 哪些 POI 能显示；
- 更新速度；
- archive 最后能抓到哪些资源。

### 5.2 “地图上有”不等于“现实里还在那里”

同一篇 2006 报道直接把**数据更新和底图维护**称为地图服务的主要难题，并描述用户标注/纠错机制。

这产生一个永久状态边界：

`地图 pin 存在 ≠ 地点仍存在 ≠ 营业/开放 ≠ 名称仍相同 ≠ 入口没搬`。

## 6. 2008：普通用户已经会把陌生路线问题转交给网络，但网络仍与“问人”共存

### 6.1 百度知道：人问人，回答者把人送去地图

2008-01-06，一名用户在百度知道问“从沈阳中街小津桥到西塔打车多少钱、怎么走”。回答者给出价格判断，同时建议用百度地图或 51ditu 查公交路线。

来源：
- 百度知道同期问答：https://zhidao.baidu.com/question/43012527.html

证据等级：**A/B：平台可观察的同期公开问答**。它证明该问答与推荐行为存在，不代表所有用户习惯。

这说明新旧机制不是替换关系：

`问人 → 人给经验 → 人再把你指向数据库`。

### 6.2 跨地长途路线也开始被 URL 化

2008-08-30，百度知道一名用户问北京到承德的自驾路线。回答直接贴出一个包含起终点参数的 51ditu 导航 URL，让提问者自行查看。

来源：
- https://zhidao.baidu.com/question/66478393.html

这意味着“路线”第一次不仅是口述知识，也能变成一个可复制链接。

### 6.3 2008 旅游论坛材料：新建筑暴露“POI 新鲜度”问题

背包客栈 2008-03-14 的公开讨论中，一名准备去北京看鸟巢、水立方、798、草场地等新建筑的用户明确抱怨：传统景点信息多，但“新北京”的信息有限；她需要一个能输入景点并找到附近公交、地铁的网站。另一名用户推荐 51ditu。

来源：
- https://www.backpackers.com.tw/forum/archive/index.php/t-70149.html

证据等级：**A/B：同期公开论坛第一人称需求 + 他人回复**。

它特别适合说明：

> **搜索能力扩张得越快，数据“是不是今天的城市”就越重要。**

对于快速建设期城市，地图新鲜度本身就是生活可执行性的一部分。

### 6.4 平台也在主动简化“不会说正确站名”的问题

网易 2008 年有道地图发布稿称，产品允许用户直接输入生活地点作为起终点，不再要求先知道公交站名；当时称地图覆盖 400 多个城市、公交数据覆盖近 100 城。

来源（平台发布稿，仅用于功能/产品自述）：
- https://www.prnasia.com/story/13413-1.shtml

证据等级：**A（平台声明）**，不能由此推出使用规模或准确率。

## 7. 2011–2013：从“出发前查路线”到“路上持续知道自己在哪”

### 7.1 手机 GPS 改变的是导航发生的时间

2011 年同期软件文章直接把手机 GPS 的意义与纸图对比：手机可以实时给出当前位置，并在地图上不断刷新。

来源：
- 新浪科技/太平洋电脑网，2011-05-18：https://tech.sina.com.cn/s/2011-05-18/09065539245.shtml

这一步和 Web 地图有本质差异：

- Web 时代：`出发前查询 → 记忆/打印 → 现实执行`；
- 手机 GPS：`查询 → 出发 → 位置不断回传 → 路线随途中状态继续解释`。

### 7.2 使用规模开始变成独立问题

中新网经央视网转载的 2012 年行业数据称，到 2011 年底中国手机地图客户端累计账户数约 1.35 亿；高德、谷歌等进入大规模竞争。

来源：
- https://news.cntv.cn/20120204/101919.shtml

证据等级：**B（行业监测经媒体转述）**。

仍要注意：累计账户数 ≠ 月活 ≠ 每天导航 ≠ 全国人口普及率。

### 7.3 路线开始吸收实时路况

2013 年搜狗手机地图 V4.0 的同期发布材料把公交、自驾、步行整合，并称驾车路线会结合实时路况给出导航建议。

来源：
- https://www.taibo.cn/p/25251

证据等级：**A/B（企业发布经行业媒体）**。

这意味着路线从“静态图上的最短路径”继续向**当前时刻的交通状态**靠近。

### 7.4 地点也开始跨设备保存

2011 年诺基亚网页版地图的同期评测已经提到“手机电脑可双向同步”。2013 年腾讯地图 4.0 又明确支持微信登录、同步收藏，并把位置/街景分享到微信。

来源：
- 诺基亚地图评测，2011-12-14：https://www.taibo.cn/p/15119
- 腾讯地图 4.0，2013-12-12：https://news.mydrivers.com/1/286/286235.htm

这使 `spatial-memory portability` 成为现实：常去地点不必只存在纸条、浏览器历史或人的脑中。

## 8. 2015–2019：拥堵型未来——地图从“找路”进入“我该住在哪”

### 8.1 2019 的找房体验已经把城市变成分层地图

一篇 2019-02-27 的同期第一人称 App 评测中，作者自称北漂、正在重新找房。文章演示链家/贝壳的“地图找房”：先看北京各区域房源数量，再逐层缩放到具体位置，还能按地铁线和站点筛选附近住房。

来源：
- 我看App/搜狐转载：https://www.sohu.com/a/297909688_408876
- 另一镜像：https://www.weste.net/2019/02-27/121666.html

证据等级：**B/C：同期媒体作者第一人称使用，不等于独立消费者样本**。

重要变化是，租房者开始能同时看：

`租金/房源 → 地理位置 → 地铁 → 工作地点`。

城市不只是“哪些地方存在”，而是一个可以在屏幕上反复权衡的约束空间。

### 8.2 同期年轻人的真实代价提醒我们：地图优化不能消灭时间价格

《中国青年报》2019 年“地铁最后一站”报道里，一名到北京工作近三年的年轻人住在天宫院，因为交通便利、房租便宜而接受接近每天三小时的通勤；他自己把它换算成“每十天就有一天用于通勤”。

来源：
- 中国青年报，2019-11-20：https://zqb1.cyol.com/html/2019-11/20/nw.D110000zgqnb_20191120_1-05.htm

证据等级：**B：同期媒体第一人称访谈**。

这并不证明他用地图选房，但它给地图/住房技术提供了正确解释框架：

> **“能算出来”不会让通勤消失，只会让人更明确地知道自己在拿多少钱、多少平方米和多少生命时间互换。**

### 8.3 2019 数据媒体已经把租金直接画在城市地图上

DT 财经当时把北上广深租金空间化，并指出高租金区域与主要就业中心重叠。

来源：
- 澎湃转载，2019-03-29：https://m.thepaper.cn/newsDetail_forward_3213835

它不是个体行为证据，但说明“地理比较 + 成本比较”已经成为公众理解城市生活的常用形式。

## 9. 2020–2022：偶发型未来——路线算法第一次显得“不够”

疫情期间，路线是否真实可走不再只取决于道路图。

2020-01-25，北京出现“高速封路、只出不进”的网络传言。新京报记者核实时发现，部分地图导航显示某检查站方向封路，但电话询问现场工作人员后确认实际道路正常开放。

来源：
- 新京报/新浪转载，2020-01-25：https://news.sina.cn/gn/2020-01-25/detail-iihnzhha4608266.d.html

证据等级：**B：同期记者交叉核查**。

这提供了本专题最干净的状态边界之一：

`地图路网可计算 ≠ 地图状态最新 ≠ 行政允许通行 ≠ 检查站实际开放 ≠ 旅客最终可通过`。

危机把一种平时不容易看见的事实暴露出来：

> **路线引擎只是现实的一份模型。**

道路物理存在、交通管制、社区门禁、健康要求、班次取消都可能在算法图之外改变可执行性。

因此 2020–2022 的“偶发型未来”不只是“大家少出门”，而是**普通人失去“地图给出的正常路径明天仍然成立”的默认信心**。

## 10. 2023–2026：防守型未来——地图开始替人保存多个可接受生活方案

### 10.1 住房搜索从“离公司近”升级成“满足一组通勤约束”

相寓 App Store 的版本历史记录显示，2024-12 至 2025-03 的多个版本加入/强化“通勤找房”，可以根据**个人或两人通勤需求**匹配房源，同时改版地图找房。

来源：
- Apple App Store version history：https://apps.apple.com/cn/app/%E7%9B%B8%E5%AF%93-%E7%BE%8E%E5%A5%BD%E7%A7%9F-%E7%94%9F%E6%B4%BB/id1050933856

证据等级：**A：平台公开版本记录**。

它不能证明有多少人使用，但功能本身已经把一个很复杂的家庭问题显式化：

`房租 + 房源 + A 的工作地点 + B 的工作地点 + 两个人可接受的通勤时间`。

### 10.2 防守型未来的新空间逻辑

这可以称作 **future-intent spatial buffering（未来意图的空间缓冲）**：

一个人不一定马上决定“我必须住在 X 小区”，而是先规定：

- 到公司不超过 45 分钟；
- 到伴侣公司不超过 60 分钟；
- 租金不超过某阈值；
- 离地铁不超过某距离；
- 换工作后仍有一定交通可替代性。

地图的用途因此从“告诉我一条路”，变成“帮我保存一组还可接受的未来”。

这和仓库已有 `optionality-as-a-life-goal` 直接相连。

## 11. 海外对照：MapQuest 说明这不是中国特有的互联网效应

Computer History Museum 对 MapQuest 的展项说明：1996 年 MapQuest 把从 1980s 延续下来的计算机地图/软件基础适配到 Web，成为最早流行的消费者在线地图站之一。

来源：
- Computer History Museum, MapQuest exhibit：https://www.computerhistory.org/revolution/the-web/20/392/2345

MapQuest 自己的企业史则把晚 1990s 的核心体验概括为：在线交互地图与可打印的 turn-by-turn directions。

来源：
- MapQuest Platform — About：https://platform.mapquest.com/about

证据等级：
- CHM：**B+ 高质量博物馆史**；
- MapQuest 自述：**C/B 企业回顾**，用于确认企业对自身产品史的表述，不独立证明普及率。

跨国共同机制是：

`纸图/问人 → 在家/办公室预先计算路线 → 打印/抄写 → 出发执行 → 手机 GPS 途中持续修正`。

中国更值得单独追的则是：

- 1990s–2000s 公交体系和站名复杂性；
- 城市极速扩张导致的 POI 新鲜度问题；
- 网吧/单位/家庭宽带等不同 Web 接入路线；
- 本地搜索、114/黄页、门户和地图的结合；
- 超大城市住房—地铁—工作地点的强耦合。

所以这不是“中国人忽然学会看地图”，而是**现代大城市和数字网络共同把地方知识变成可查询基础设施**。

## 12. 四种未来：同一根“城市可读性”轴

| 阶段 | 地图/空间基础设施在生活里的主要作用 | 时间感 |
|---|---|---|
| 2005–2012 扩张型未来 | 更多地点、工作、商家和线路变得可以提前搜索；手机 GPS 开始把路线计算带到途中 | “陌生地方也能去；以后还会更方便” |
| 2015–2019 拥堵型未来 | 地图与住房、地铁、房租、就业中心叠加；路线可算，但通勤时间越来越成为成本 | “选择很多，但每个选择都有时间代价” |
| 2020–2022 偶发型未来 | 地图模型可能被封路、管制、班次变化、社区规则突然击穿 | “平时可执行的路，不保证明天仍可执行” |
| 2023–2026 防守型未来 | 通勤约束、双人通勤、地图找房等把生活方案变成可比较条件集 | “不一定选最远大目标，先保留几个还能运行的方案” |

这里必须避免把所有 2005 年的人写得乐观、所有 2025 年的人写得悲观。四个标签只是**证据聚类的时间感模型**，不是人格分类。

## 13. 这如何改变“搬到另一座城市工作”的解释

仓库 planned question 里有：

> when did moving city become an ordinary career strategy?

本笔记**不宣布该问题已经完成**。迁移正常化还需要工资、户籍/证件、住房、招聘、交通、家庭关系、社保、学校等更多证据。

但它增加了一个以前很容易漏掉的前置条件：

> **一座陌生城市必须先变得足够可读，普通人才更容易把“搬过去试试”当成可执行计划。**

设想两种同样的工作 offer：

### 世界 A

你只知道单位名称和城市名。

你必须：
- 到站后买图；
- 问人；
- 找公交站；
- 去单位附近再找房；
- 每一个新地点都重新建立本地知识。

### 世界 B

你还没出发已经能：
- 查单位位置；
- 看附近地铁；
- 搜周边租金；
- 算 40 分钟通勤圈；
- 收藏候选房；
- 到城市后手机继续带路。

工作机会本身没有变，但**尝试陌生城市的认知与执行成本**变了。

因此未来研究迁移时应把 `city legibility cost` 与票价、房租、证件成本一起纳入。

## 14. 历史可见性：地图是 Web 档案中特别危险的一类对象

一张保存下来的旧地图页面，可能只保住最外层 HTML。

真正的历史对象至少包括：

1. 页面壳；
2. 地图图片/tile；
3. POI 数据库；
4. geocoder；
5. 公交线路数据库；
6. route engine；
7. JavaScript/插件；
8. 用户 query 参数；
9. 当时的网络请求；
10. 当时地图数据版本；
11. 现实中的道路/站点/商家状态。

所以必须坚持：

`网页活着 ≠ 地图可交互 ≠ 查询可重放 ≠ 数据库仍在 ≠ 路线结果可复现 ≠ 当年现实状态被保存`。

## 16. 反例与纠偏

### 反例 1：地图存在，不等于不再问人

2008 百度知道和旅游论坛恰恰显示：人际问路与地图搜索长期混用。

### 反例 2：更“智能”的路线不一定更正确

2005 的实际测试已经出现换乘过多、方向错误；2020 的地图封路状态也能和现场真实状态错开。

### 反例 3：手机普及不等于地方知识完全失效

商家入口、校园小门、城中村内部道路、临时施工、地方称呼、楼栋出入口仍可能靠现场经验修正。

### 反例 4：可搜索城市不自动造成迁移

迁移还受工作、房租、制度接口、家庭、照护、教育与现金缓冲制约。

### 反例 5：数据丰富可能产生新的依赖

当生活越来越依赖 ETA、路线推荐和地图 POI，数据失真、服务关闭、账号丢失、定位异常反而会制造新的脆弱性。

## 17. 后见之明风险

1. 不把 1999 的网上地图写成“Google Maps 已经存在的早期版本”。插件、速度、拨号费用和界面完全不同。
2. 不把 2005 的路线搜索直接写成“实时导航”。大部分工作仍发生在出发前。
3. 不因为 2011–2012 手机地图账户数很大，就说每个人每天都用 GPS 导航。
4. 不把 2019 房租地图理解成“算法决定年轻人住哪里”；真实租金、看房、合同和社会关系仍在线下执行。
5. 不把 2025 “双人通勤找房”理解成所有伴侣都这样决策；目前只能证明平台把这种约束正式产品化。
6. 不把地图准确性当常数。不同城市、不同年份、不同 POI、不同交通方式的错误分布可能完全不同。

## 18. 这轮对“人怎么活着”增加了什么

此前我们已经知道：

- 网络降低远距离联系成本；
- 招聘网站提高机会可发现性；
- 租房网站提高房源可发现性；
- 网吧让人可以在没有设备所有权时进入网络；
- 家庭宽带让互联网变成住宅基础设施。

这轮新增的是另一层：

> **互联网与数字地图降低了“陌生地方本身不可读”的成本。**

一个人可以先找到工作，再在屏幕上理解附近住哪里；也可以先选房，再估算每天要交出多少通勤时间。

因此现代成年生活越来越像把几个可搜索图层叠在一起：

`工作地点 + 房租 + 地铁 + 学校 + 医院 + 家人位置 + 通勤时间 + 服务可达性`。

所谓“选择更多”，一部分正来自**空间信息先变得可查询**。

## 19. 下一步最值钱的证据：一条“城市可读性账本”

与其继续收集地图软件发布新闻，更值得寻找 1995–2015 一个真实迁移者的连续记录：

- 第一次到陌生城市前知道多少；
- 手里拿什么地图/地址；
- 下火车以后先问谁；
- 第一次独自坐错公交是什么原因；
- 什么时候第一次在网吧查电子地图；
- 什么时候开始把路线打印/抄进纸条；
- 什么时候第一次用手机定位；
- 什么时候开始不再记公交站名；
- 租房时什么时候开始直接按地铁/通勤时间筛选；
- 换城市时，哪些本地知识已经可以由平台带过去，哪些仍必须重新学。

这会让我们更精确地回答：

> **一个人究竟从什么时候开始，可以在还不认识一座城市的时候，就认真计划在那里生活。**

## 20. 已知 / 可合理推断 / 仍不知道

### 已知

- 1980s 城市公交人员仍会明确承担陌生乘客的方向/换乘解释；
- 1999 中文 Web 已存在可缩放、可按地点字段查询的在线地图；
- 1999 某些地图仍依赖专用 viewer 插件；
- 2000 同期媒体仍把速度与上网费用视为在线地图使用约束；
- 2005 本地搜索已把 POI、电话、公交换乘、驾车路线放在同一查询体验中；
- 2008 公开问答/论坛中普通用户已经把电子地图当成问路工具之一；
- 2011–2013 手机地图把位置与路线带入途中，并逐渐加入实时路况与跨设备状态；
- 2019 地图/地铁找房已经进入主流找房 App 的实际评测场景；
- 2020 危机中地图状态可以与现实道路状态脱节；
- 2024–25 平台已经把个人/双人通勤需求直接写入租房匹配功能。

### 可合理推断

- 在线地图降低了陌生城市的认知进入成本；
- 手机 GPS 把一部分路线记忆劳动转移给持续运行的定位/路由系统；
- 地图、租房、招聘和通勤数据的结合，使跨城迁移更容易在出发前形成可执行草案；
- 当城市日常越来越依赖导航，地图数据质量和服务连续性本身成为新的生活基础设施。

### 仍不知道

- 不同收入/年龄/地区人群究竟何时从纸图/问人转向 Web 地图；
- 网吧环境里电子地图使用的真实频率；
- 1999–2003 Go2Map 等站点的完整 historical capture、charset、插件、请求链与查询后端；
- 2005–2010 路线错误率到底多高、错误类型怎样分布；
- 一条个人 10–20 年“问路 → Web 查图 → 手机定位 → 实时导航”的连续生命史；
- 通勤找房功能对真实搬家选择到底影响多大；
- 地图外包空间记忆后，人的路线记忆与地方认知是否发生稳定、可量化的变化。
