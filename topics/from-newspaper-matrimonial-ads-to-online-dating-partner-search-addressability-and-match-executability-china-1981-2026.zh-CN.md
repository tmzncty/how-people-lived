# 从报纸征婚到婚恋平台与公益红娘：伴侣候选可寻址性、资料可读性与匹配可执行性（中国，1981—2026）

> 本稿研究的不是“婚恋网站行业史”，也不是判断哪一种婚恋观更先进，而是一个普通生活问题：**一个人想建立亲密关系时，究竟通过什么基础设施遇见原本不认识的人；她怎样判断对方是否真的符合页面上的描述；以及“候选人变多”为什么既可能扩大生活选择，也会把筛选、验证、隐私与退出成本重新交给个人。**
>
> 配套中文旧网技术/state-gap note 见 `tmzncty/old-web-archaeology`：`docs/ONLINE_DATING_PROFILE_SEARCH_MESSAGE_VERIFICATION_MATCH_AND_OFFLINE_RELATIONSHIP_STATE_GAPS_2003_2015.md`。

## 1. 为什么这一轮选这个对象

仓库已经讨论婚姻形成、父母介入、住房、是否生育、独居、迁移和标准人生脚本，但还缺一个更早的环节：

> **在“结不结婚”以前，一个人到底怎样找到可以认识的人。**

“认识对象”看起来像私人生活，实际上长期依赖信息基础设施：

- 亲友和媒人；
- 单位、学校、街道；
- 报纸征婚；
- 婚姻介绍所；
- 电话/录像/计算机匹配服务；
- BBS、聊天室、QQ；
- 婚恋网站；
- 微信公众号、社交平台、游戏、短视频；
- 线下相亲活动、相亲角和志愿红娘。

Internet 真正改变的不是“人类第一次可以认识陌生人”，而是候选人的**可检索规模、筛选字段、接触速度、联系成本与可见身份结构**。

## 2. 本轮新增概念

### 2.1 partner-search addressability / 伴侣候选可寻址性

一个城市里存在很多单身者，不等于其中任意两个人有办法相遇。

前互联网的“可寻址”可能来自：

- 亲友知道两个人都单身；
- 单位或学校有共同关系网；
- 报纸把个人条件压成一则公开广告；
- 婚介所把登记表放进一个人工可检索的候选池。

婚恋网站把这种关系进一步数据库化：

```text
城市
+ 年龄
+ 教育
+ 收入
+ 身高
+ 婚姻状态
+ 住房/职业等资料
+ 自我描述
→ 一个可以搜索、筛选和排序的候选集合
```

这意味着“我的生活里遇不到这种人”与“这座城市里不存在这种人”第一次更明显地分离。

### 2.2 profile legibility / 择偶资料可读性

平台把复杂的人压成字段以后，陌生人更容易被比较，但也会改变什么被认为是“可比较”的。

年龄、城市、学历、收入、职业、住房、婚史等适合结构化；家庭互动方式、情绪稳定、对照护的态度、长期生活节奏、价值观与吸引力则很难完全字段化。

因此：

> `profile is searchable != person is fully legible`。

### 2.3 profile-to-person executability / 资料到真人的可执行性

本轮永久保留以下状态差：

```text
平台上存在一个账号
!= 对应现实中的一个可确认的人
!= 资料字段都真实
!= 对方此刻仍然单身/仍在寻找关系
!= 对方会看到我的消息
!= 对方愿意回复
!= 双方交换站外联系方式
!= 真正线下见面
!= 开始约会
!= 建立稳定关系
!= 登记结婚
```

因此“平台有多少用户”“匹配度多少”“资料看起来合适”都不能直接当成婚姻结果。

### 2.4 choice-set expansion / verification burden tradeoff

Internet 扩大候选集，同时扩大验证负担。

候选人从“亲友熟人网络里的几个人”变成“数据库里的几千个人”以后，普通人获得更多选择，但也要自行处理：

- 谁是真的；
- 谁仍单身；
- 照片是否本人/近期；
- 学历收入是否可靠；
- 婚恋意图是否一致；
- 是否存在诈骗、骚扰或隐私风险；
- 哪些条件只是页面上看起来合适。

所以：

> **候选集扩大，不等于决策成本下降。**

### 2.5 search schema as life-script schema / 搜索字段作为人生脚本

婚恋网站的筛选器不是中性的数据库细节。

当一个平台把年龄、学历、城市、收入、住房等字段做成常用搜索条件时，它也在把某种“什么信息足以判断婚配可行性”的社会脚本编码进界面。

但个人实际判断可能会不断溢出这些字段，例如：

- 是否愿意与原生家庭保持多大距离；
- 是否想生育；
- 消费方式；
- 工作是否需要迁移；
- 对照护、职业、宠物或个人时间的态度；
- 是否愿意共同承担风险。

### 2.6 contact-channel escape / 联络链逃逸

婚恋网站往往只完成最初的相识：

```text
平台搜索
→ 平台消息
→ QQ / 手机 / 后来的微信
→ 线下见面
→ 私人关系
```

2011 年 Jiayuan 向美国 SEC 提交的 F-1 甚至明确说，公司自己的历史数据显示站内两人消息交换平均持续约 3.5 天，公司据此认为有继续交往意愿的用户会交换私人联系方式转到站外沟通。

这既是生活机制，也是历史保存机制：

> 最容易被旧网档案保存的是公开资料页，真正决定关系有没有发生的部分恰恰很快离开公开 Web。

### 2.7 matching / relationship / marriage separation

本轮严格区分：

```text
被介绍
!= 匹配成功
!= 双方开始聊天
!= 线下见面
!= 约会关系
!= 稳定伴侣
!= 婚姻
!= 生育
```

婚恋研究最容易犯的后见之明错误，是从“后来结婚”反推第一次匹配必然有效，或者从“很多人注册”推导平台已经成为主要成婚渠道。

## 3. Internet 以前：陌生择偶本来就有信息基础设施

### 3.1 1981：报纸把私人择偶第一次大规模做成公开文本对象之一

人民网 2019 年对中国相亲史的回顾称，1981 年 1 月 8 日《市场报》刊登丁乃钧征婚启事，列出未婚、年龄、身高、月薪并要求来函附近照；同文称 1982 年 11 月广州出现公办青年婚姻介绍机构。

**证据等级：B/C（后来的媒体历史综合；可作为年代线索，不冒充 1981 原报纸 capture）。**

来源：

- 人民网，《中国为什么会有“相亲角”？》，2019-10-24  
  https://politics.people.com.cn/n1/2019/1024/c429373-31417696.html

这件事的重要性不在于“从此人人报纸征婚”，而在于一种新接口：

> 一个普通人的择偶意愿可以脱离熟人关系网，变成全国/城市报纸里可被陌生人读取、保存并回信的记录。

候选集扩大了，但延迟仍以“投稿—见报—写信—邮寄—回信”计。

### 3.2 机构化婚介：数据库以前也可以有候选池

1980s 的婚介所依靠纸质登记、人工筛选和线下介绍，把多个互不认识的人集中进同一个中介系统。

因此 Web 之后常见的“填写资料—筛条件—推荐—见面”并不是完全新的逻辑；新的主要是：

- 检索速度；
- 用户自己筛选；
- 地域扩张；
- 资料持续在线；
- 联系延迟缩短；
- 规模增加以后出现新的真实性、隐私和排序问题。

## 4. 海外前 Web 对照：电子婚恋远早于 WWW

### 4.1 1982—1983：BBS / CompuServe 已经进入陌生人约会

1982 年《Washington Post》报道一个名为 microEncounters 的美国计算机单身网络：用户通过家用电脑/终端进入电子论坛，发布 personal ad 并发送消息寻找朋友、室友或伴侣。

1983 年同报又报道，地方 BBS 已有 dating service，通过个人广告与私信在见面前交流；CompuServe CB Simulator 上的参与者用网名进入电子“鸡尾酒会”，也有人从在线交流发展到长期关系甚至结婚。

**证据等级：A/B、T1（同时代媒体报道）。**

来源：

- Washington Post, “SINGLE MINDED”, 1982-10-21/22  
  https://www.washingtonpost.com/archive/lifestyle/1982/10/22/single-minded/19921b4b-e2f9-4ba6-a4ed-920d7d10525f/
- Washington Post, “INNOVATIONS: With This Modem, I Thee Wed”, 1983-09-09  
  https://www.washingtonpost.com/archive/lifestyle/1983/09/09/innovations-with-this-modem-i-thee-wed/8599464b-387b-4cdb-8b48-f19a623f0eff/

它说明：

> **“先和一个没见过的人文字交流，再决定是否见面”不是 Web 发明的。**

但当时需要电脑、调制解调器、联机服务费用与操作能力，可及性与 2000s 大众网站完全不同。

### 4.2 1988：Minitel 已经让匿名互动成为亲密关系研究对象

Gérard Neyrand 1988 年在 *Quaderni* 讨论法国 Minitel “messageries”时，已经把这种交互媒介与诱惑、匿名/身份、人与地域关系的变化联系起来。

**证据等级：A/B、T1（同时代学术观察）。**

来源：

- Gérard Neyrand, “Stratégies de séduction et fascination médiatique : le minitel squattérisé”, *Quaderni*, 1988  
  https://www.persee.fr/doc/quad_0987-1381_1988_num_5_1_1323

因此中国 2000s 婚恋网站最值得比较的不是“第一次网上找对象”，而是**严肃婚姻导向、结构化个人条件、城市/住房/学历等字段与中国特定人生脚本怎样一起进入网页。**

## 5. 2005—2012：扩张型未来——把“认识不到的人”变成可搜索候选

### 5.1 2008：时间稀缺与社会羞耻正在同时变化

2008 年同期报道记录，一名接近 27 岁的办公室职员李冰洋（化名）最初秘密注册婚恋网站，因为觉得“网上征婚”不够体面；后来发现同事也在使用以后，对这一渠道的看法发生变化。报道把城市白领工作忙、现实接触面有限与网络婚恋联系在一起。

**证据等级：B/T1（同期媒体采访；个人材料，不代表所有 20 多岁城市青年）。**

同期另一篇《新世纪周刊》报道了 30 岁北京公务员“凯文”：在多年家庭安排相亲之后购买百合网 VIP 服务，后台工作人员依据“婚恋类型测试”发现较高匹配度并与他联系，两人随后见面并很快登记。报道同时比较了百合的心理匹配、珍爱的人工红娘和佳缘的自主搜索模式。

**证据等级：B/T1。这个极端快速结婚案例只能证明“这种路径发生过”，绝不能当成平台平均结果。**

来源：

- 新浪转载《新世纪周刊》，《甜蜜的对抗：婚恋网站的模式之争》，2008-08-19  
  https://news.sina.com.cn/c/2008-08-19/115016140459.shtml

这里真正的新能力是：

> 一个人可以在晚间或工作空隙里先筛选大量陌生候选，而不必等亲友下一次“手里刚好有个人”。

### 5.2 2011 SEC F-1：网页把择偶流程拆成了机器状态

Jiayuan.com 2011 年向美国 SEC 提交的 F-1 是本轮最强的原始平台制度证据之一。

文件明确描述：

- 免费注册；
- 用户可发布个人资料和照片；
- 可浏览、保存偏好并发站内消息；
- 第一封消息可以发送，但要让收件人可读，发送方或接收方需要支付虚拟邮票/订阅；
- 可以付费提升搜索排名、消息优先级、资料展示；
- 可以付费提交年龄、收入、学历等证明，从而获得更高的资料评级；
- 自 2010 年 6 月起部分功能已能通过手机浏览器完成；
- 线下活动与 VIP 人工搜索服务和网站并行。

**证据等级：A（同期 SEC 公司申报文件）。公司对效果、行业地位和用户动机的判断仍然只是 company claim，不升级为独立社会事实。**

来源：

- Jiayuan.com International Ltd., Form F-1, filed 2011-04-20  
  https://www.sec.gov/Archives/edgar/data/1511683/000104746911003874/a2203517zf-1.htm

这说明 2010—2011 的在线婚恋已经不仅是“发个征友帖”，而是一个很复杂的状态机：

```text
注册
→ 填资料
→ 搜索
→ 排名
→ 看资料
→ 发消息
→ 解锁可读
→ 回复
→ 站外联系
→ 线下见面
```

平台还能把“我看过谁”“谁看过我”“最后登录时间”“资料证明”商品化。

### 5.3 认证没有消灭真伪问题

2011 年《每日经济新闻》调查婚恋网站虚假资料与诈骗问题时，世纪佳缘方面公开承认无法保证每条会员信息的真实性。

**证据等级：B/T1。**

来源：

- 《世纪佳缘会员频“受伤” 婚恋网站商业模式监管存空白》，2011-06-24  
  https://www.nbd.com.cn/articles/2011-06-24/577832.html

这使以下区别必须永久保留：

> `某一项资料提交过证明 != 整个账号的身份、婚史、意图和当前状态都真实。`

## 6. 2015—2019：拥堵型未来——选择更多以后，验证与家庭脚本同时涌入

### 6.1 2019：平台、父母、同事、相亲角不是替代关系，而是并行关系

2019 年《中国青年报》对 1972 名单身青年的在线调查中，78.8% 的该样本称注册过婚恋交友平台；但样本高度城市化（农村受访者仅 0.3%），不能外推全国单身人口。

更有价值的是同期个人材料：

- 27/28 岁左右的林鹏因为工作忙，会在婚恋网站按所在地、年龄筛选，认为能节省时间；
- 张晓性格腼腆，觉得网络主动联系没有回复时，比线下面对面更少“没面子”；
- 唐璇会通过平台测试理解自己的家庭边界和消费偏好，但她真正去线下见面的对象仍多数来自亲友介绍；平台认识的人很多只是加微信、偶尔聊天。

**证据等级：B/T1；调查样本有明显网络/城市选择效应。**

来源：

- 中国青年报，《78.8%受访单身青年在婚恋交友平台注册过》，2019-09-19  
  https://zqb.cyol.com/html/2019-09/19/nw.D110000zgqnb_20190919_1-08.htm

所以 2019 的“拥堵”不是简单地“平台不好用”，而是：

> 一个人可能同时面对家人介绍、单位同事介绍、线上平台、线下活动、微信群和自己的择偶标准，并要自己决定哪套渠道和哪套评价标准真正算数。

### 6.2 家庭匹配与个人匹配可能不是同一个目标函数

同年另一项《中国青年报》调查里，70.2% 的该样本表示不希望父母介入择偶，但仍有相当多人实际经历父母相亲安排；一名 95 后受访者同时承认父母介绍能扩大自己的现实社交范围，又强调最终意见应该属于自己。

来源：

- 中国青年报，《七成受访未婚青年不希望父母介入自己择偶》，2019-06-20  
  https://zqb.cyol.com/html/2019-06/20/nw.D110000zgqnb_20190620_2-08.htm

因此：

> “候选人条件很好”必须追问——**对谁的目标函数很好？**

父母可能优先看户籍、住房、稳定工作与家庭背景；本人还会看沟通、相互支持、家庭边界、职业迁移和生活方式。

### 6.3 资料越多，隐私负担也越大

2019 年同一调查系列里，73.0% 的该样本担心平台泄露用户信息，66.7% 担心用户信息不实；同期受访者还具体担忧高清照片、学历材料等认证资料的安全。

来源：

- 中国青年报，《73.0%受访单身青年担心婚恋交友平台泄露用户信息》，2019-09-19  
  https://zqb.cyol.com/html/2019-09/19/nw.D110000zgqnb_20190919_4-08.htm

这形成平台成熟期的一个结构性悖论：

> **越希望陌生人“可信”，平台越可能要求更多可识别资料；而资料越完整，一旦泄露或被滥用，代价也越高。**

## 7. 2020—2022：偶发型未来——线下不可达以后，关系形成被迫延长在线阶段

2021 年《中国青年报》调查 2001 名 18—35 岁单身青年，62.4% 的该样本称过去一年交友以线上为主，74.0% 每天用于线上相亲交友的时间超过一小时。样本同样高度城市化，不能解释为全国比例。

更重要的是生命史细节：

- 医护工作者王瑞因疫情工作忙、线下活动减少，通过交友公众号认识对方，并长期把主要交往放在线上；
- 事业单位职工程晖经同事和家人介绍加了多个微信联系人，但因为疫情反复，很长时间只能在线聊天，直到节后才第一次吃饭；
- 90 后刘璐在团队游戏里认识后来男友，游戏语音/聊天先承担了共同活动的功能。

**证据等级：B/T1。**

来源：

- 中国青年报，《疫情下的“网恋” 74.0%受访单身青年每天要花1小时以上“云交友”》，2021-02-25  
  https://zqb.cyol.com/html/2021-02/25/nw.D110000zgqnb_20210225_2-10.htm

这里真正的新机制不是“疫情发明网恋”，而是：

> **offline transition latency / 线下转化延迟**。

过去网上认识以后通常默认尽快见面；偶发事件使“已经聊了很久但现实里还没见过”变成一段可以持续数周或数月的中间状态。

同一调查系列还显示用户担忧网络人设滤镜、诈骗和跨平台不良行为，这说明当线下验证被推迟，**profile-to-person gap** 会在更长时间里影响关系判断。

## 8. 2023—2026：防守型未来——不是不找，而是更强调关系质量、边界与可退出性

### 8.1 2024：“我想找对象”与“不接受任意一个符合硬条件的人”可以同时成立

《中国妇女报》2024 年对 95 后的采访提供了很好的同时代材料。

29 岁的社交平台相亲博主“团团”（化名）明确说自己一直想找伴侣，但现实社交圈很难遇到想找的性格类型。疫情期间她分享自己的相亲经历，随后 300 多人主动联系，200 多人加私人联系方式；此后两年多，她每天晚上与这些陌生网友沟通条件并做公益介绍，出现了一个非常典型的新路径：

> **自己尚未匹配成功的人，也可以因为平台聚合能力成为别人的“志愿红娘”。**

29 岁的小贾五年见过 30 多名相亲对象。父母看重稳定工作、北京户口、住房等“适合结婚”的条件，而她还会调查家庭关系、个人成长和长期相处风险。

**证据等级：B/T1（同期媒体采访）。**

来源：

- 中国妇女报，《“95后”婚恋观实录》，2024-07-15  
  https://paper.cnwomen.com.cn/zgfnb/html/2024-07/15/nw.D110000zgfnb_20240715_1-5.htm

这修正了“防守型未来=年轻人不想结婚”的过度简化。更准确的机制可能是：

- 仍然想建立亲密关系；
- 但更不愿意仅因为年龄、房产、编制等外部时钟迅速进入一段高锁定关系；
- 更希望把家庭边界、互相支持、风险承担与生活方式先谈清楚。

### 8.2 成熟数字社会又重新建设线下/公共匹配接口

2024 年全国和地方妇联继续组织线下交友活动、志愿红娘和数据库式婚恋服务。它们与商业 App 并存，而不是被 App 淘汰。

来源示例：

- 中国妇女报，《全国妇联开展“幸福联线”婚恋交友联谊活动》，2024-05-16  
  https://paper.cnwomen.com.cn/zgfnb/html/2024-05/16/nw.D110000zgfnb_20240516_8-1.htm

因此成熟阶段又出现一种 **re-mediated matchmaking / 再中介化匹配**：

> 当纯自助搜索带来验证、隐私、选择疲劳和沟通成本以后，一部分人重新购买或接受“有人先帮我筛一下”的服务。

这不是回到旧媒人时代，而是人工中介重新嵌入数字数据库、社交平台和线下活动。

## 9. 四种未来的对照

### 2005—2012：扩张型未来

典型命题：

> **“我的现实圈子太小，但网上也许有更多可能。”**

新增的是搜索范围、时间自由和自主筛选。

### 2015—2019：拥堵型未来

典型命题：

> **“人很多、渠道很多、条件也很多，但我必须自己判断哪些资料可信、哪套标准真的是我的。”**

新增的是验证、隐私、家庭与个人目标函数冲突、平台之间的选择成本。

### 2020—2022：偶发型未来

典型命题：

> **“关系还能继续，但线下见面这一步不知道什么时候恢复。”**

线上不只是入口，而暂时承担了原本应该很快过渡到线下的关系阶段。

### 2023—2026：防守型未来

典型命题：

> **“我不是不要关系，而是不想为了赶一个社会时间表，把高成本、难退出的长期选择提前锁死。”**

防守保护的不是孤独，而是关系质量、个人边界与退出权。

## 10. 标准人生脚本因此发生了什么变化

过去常见脚本可以粗略写成：

```text
适婚年龄
→ 熟人/家庭介绍
→ 相亲
→ 婚姻
→ 生育
```

现代实际路径可以大量分叉：

```text
先有工作/迁移
→ 社交圈缩小
→ 家庭相亲 + 平台并行
→ 只聊天未见面
→ 朋友/游戏/社群自然转化
→ 长期约会但不婚
→ 婚姻但暂不生育
→ 主动退出平台
→ 多年后重新进入
```

这不表示旧脚本消失，而是更多人必须亲自管理脚本之间的接口。

## 11. 对重点矩阵的影响

| 维度 | 本轮新增 |
| --- | --- |
| 教育 | 学历既是人生经历，也是平台筛选/认证字段 |
| 就业 | 工作忙、异地工作与单位性质直接影响遇见人的渠道和择偶标准 |
| 住房 | 房产/独立住房可成为家庭和平台中的婚配条件，但不能等同关系质量 |
| 婚姻家庭 | “认识—约会—婚姻—生育”必须拆成多个可逆/不可逆状态 |
| 迁移 | 城市迁移扩大人口池，也可能切断原熟人网络，增加平台需求 |
| 照护 | 对父母边界、未来照护责任的态度越来越需要在关系形成前协商 |
| 长期中断 | 单身、分手、离婚后再进入择偶市场是一种递归生命历程，不是一次性青年任务 |
| 证件与记录 | 身份/学历认证只覆盖部分事实，不能自动证明婚姻状态和关系意图 |
| 通信方式 | 报纸信件→BBS/站内信→手机/QQ/微信，显著压缩陌生关系启动延迟 |
| Internet 平台 | 搜索字段、排序、消息权限、认证徽章与推荐都参与定义“谁能被看到” |
| 信息获取 | 候选集扩张同时制造真实性与隐私验证负担 |
| 社交关系 | 平台并未消灭亲友/父母/单位介绍，而是形成渠道组合 |
| 未来预期 | 从“什么时候结婚”进一步分化成“是否、和谁、用什么节奏建立关系” |
| 线上/线下身份 | 平台资料页不是完整真人，关系通常迅速逃逸到私域与现实 |
| 平台消失与记忆 | 公开 profile 可能比消息、QQ/微信和真实关系结果更容易被 archive 保存 |

## 12. 反例与后见之明风险

### 12.1 不要写成“Internet 让婚姻更自由”

它扩大自主搜索，但同时可能：

- 把年龄/收入/学历等条件硬字段化；
- 强化择偶比较；
- 产生付费排名与可见性差异；
- 增加诈骗、骚扰和资料泄露风险；
- 让家庭把“孩子资料”搬进微信群/相亲角数字化传播。

### 12.2 不要写成“过去都靠包办，现在都自主选择”

同一年里可能同时存在：

- 父母介绍；
- 朋友同事介绍；
- 单位活动；
- 婚恋 App；
- 社交平台；
- 游戏/兴趣社群；
- 公益联谊。

渠道多元化比单向替代更接近现实。

### 12.3 不要用平台注册量代替真实活人或成婚率

`registered account` 可能包含：

- 重复账号；
- 长期未登录账号；
- 已进入关系但未改状态的人；
- 资料不实账号；
- 只浏览未认真寻找关系的人。

### 12.4 不要把成功故事当平台平均效果

平台天然更愿意展示“牵手成功/结婚成功”的案例；失败、没有回复、只加微信后沉默、见一面就结束的路径更容易消失。

### 12.5 不要把今天的“晚婚/不婚”投射回 2008

2008 材料要按当时语境理解：大量受访者仍把结婚视为明确目标，只是在寻找更有效的路径。2024 材料则显示一些年轻人仍然希望关系与婚姻，同时提高对边界和质量的要求。

## 13. 历史可见性：Internet 最容易留下什么、最容易丢什么

最容易保存：

- 首页；
- 注册说明；
- 搜索字段；
- 公开个人资料页；
- 平台新闻稿；
- 成功故事；
- 媒体报道。

最容易丢失：

- 某一时刻的真实搜索排序；
- 私信；
- QQ/微信迁移后的关系；
- 未回复；
- 删除/拉黑；
- 第一次见面后的感受；
- 没有成功的长期尝试；
- 现实中的婚姻/分手结果。

因此 old-Web 留下来的世界会系统性夸大“资料存在”，低估“关系没有发生”。

## 14. 本轮结论

这一专题改变“普通人到底有多少种活法”的地方，不是发现了“网恋”本身，而是发现：

> **亲密关系的起点也有基础设施。**

一个人在工厂、机关、实验室、大学或大城市写字楼里生活时，她能遇见谁，并不只由人口数量决定，还由亲友网络、单位制度、报纸、婚介、网站搜索、手机和社交平台决定。

Internet 把陌生人的候选池做大以后，普通人第一次可以更主动地说“我想找什么样的人”；但数据库很快又把这个问题翻回来：**一个人究竟能不能被年龄、学历、收入、户籍、房子和几十个选择题充分描述？**

真正增加的不是一条取代旧路径的新路，而是更多并行生活方式：有人仍靠父母介绍，有人只在兴趣社群里自然认识，有人注册多个平台，有人长期不结婚但并不排斥亲密关系，也有人自己还没找到对象，却先借社交平台给两百个陌生人当起公益红娘。

这使“标准人生脚本”更难再用一个箭头概括：**认识一个人、爱上一个人、和她生活、结婚、生育，已经越来越需要分别观察，而不是默认它们会自动连续发生。**
