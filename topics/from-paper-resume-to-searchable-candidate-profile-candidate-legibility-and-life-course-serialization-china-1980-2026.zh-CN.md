# 从“拿着简历去见人”到“让数据库先读我”：候选人可读性、生命历程序列化与求职接口（中国，1980—2026）

> **研究问题：普通人的过去什么时候开始不仅要向一个具体面试官讲清楚，还要先被填进一套可搜索、可筛选、可排序的招聘数据结构；而这种结构怎样改变了非连续人生、跨城市流动、求职时间和未来想象？**

本专题不是一篇泛泛的“网络招聘史”。仓库已有专题已经研究：

- 为工作换城市时，互联网怎样把“先搬过去再找”部分改成“先搜索/投递再决定是否搬”；
- 职场空窗、照护、备考、疾病、零工等真实生命历程怎样被连续履历偏差压成“空白”；
- 旧网招聘页面、校园招聘和任务市场怎样改变机会发现与劳动匹配。

本专题只补一个此前没有独立建模的接口：

```text
真实人生
→ 被压缩成简历字段
→ 进入招聘网站/企业系统
→ 被索引、搜索、排序或解析
→ 被招聘者看到或根本没有看到
→ 进入后续申请状态
```

核心不是“简历从纸变成电子文件”，而是：

> **job seeker searches jobs 的同时，employer 也开始 search people。**

当后一条路径出现以后，一个人是否“在找工作”不再只由“我有没有主动投这一份”决定；只要自己的候选人记录处于可搜索状态，陌生雇主就可能先找到自己。

## 一、核心概念

### 1. candidate legibility：候选人可读性

一个人的真实生活要先被招聘接口“看懂”。

```text
真实经历
≠ 简历里有对应字段
≠ 字段被填写
≠ 平台正确索引
≠ 招聘者查询条件命中
≠ 招聘者按本人希望的方式理解
```

“可读”不等于“优秀”。它只意味着：这个人能够被当前招聘系统的字段、关键词、筛选器和时间格式表示。

### 2. life-course serialization：生命历程序列化

简历通常要求把人生切成可排序记录：

```text
学校 A：开始—结束
公司 B：开始—结束
岗位 C：开始—结束
技能 D：等级/年限
```

但真实生命还可能包含：

- 照护；
- 病休与康复；
- 备考；
- 创业试验；
- 非正规劳动；
- 多份并行工作；
- 没有正式机构名的长期项目；
- 多次迁移；
- 只在某些月份有收入的工作。

因此：

> **表格里的连续时间线不是人生本身，而是一种制度友好的序列化。**

这与已有专题中的 `continuity bias / 连续履历偏差` 直接相连，但本专题进一步追问：当招聘平台允许机器搜索和排序后，这种偏差怎样进入软件结构。

### 3. resume-schema pressure：简历字段压力

当系统把以下字段变成标准筛选条件时：

- 学历；
- 工作年限；
- 最近职位；
- 行业；
- 城市；
- 薪资期望；
- 到岗时间；
- 更新时间；

求职者就会获得一种新的表达压力：**不是只要把自己讲得真实，还要讲成系统可以命中的样子。**

### 4. passive discoverability：被动可发现性

传统投递通常是：

```text
我看到单位
→ 我把材料交给单位
```

在线候选人库增加另一条：

```text
我留下可搜索简历
→ 以后某个并不知道存在的雇主搜索条件
→ 命中我的记录
→ 对方先联系我
```

这使“求职”从一连串主动提交，也变成一个可以长期保持的**可被发现状态**。

### 5. resume freshness signaling：简历新鲜度信号

如果招聘端可以按“更新时间”筛选或排序，刷新简历就不再只是改内容，而可能成为：

> **“我现在仍然愿意被找”的时间信号。**

于是一个看似普通的 timestamp 开始参与劳动市场匹配。

### 6. application-state opacity：申请状态不透明

在线投递降低了提交成本，却不一定提高结果可见性。

```text
点击投递
≠ 服务器成功接收
≠ 简历进入正确职位池
≠ 解析成功
≠ 招聘者打开
≠ 招聘者认真阅读
≠ 被拒绝状态被写回
```

2008—2009 大量“网投后石沉大海”的同期材料，真正反映的是：**提交动作已经数字化，雇主侧的阅读与决策状态却仍然大量不可见。**

### 7. resume visibility custody：简历可见性保管权

一个在线简历至少有三种不同问题：

1. 我能否保存它；
2. 我能否用它投某一份工作；
3. 陌生雇主能否主动搜索它。

三者不应合并。

在成熟平台上，“完全保密 / 只对平台公开 / 对企业会员公开”这类状态说明：求职机会扩大以后，普通人还必须管理**谁可以知道我正在准备离开现在的工作**。

# 二、互联网以前：候选人早就需要被“格式化”，只是读取者主要还是现场的人

## 2.1 1980：公开招聘可以发生，但并不等于存在大众在线候选人库

1980 年《人民日报》报道北京高教局招聘外语人才考试时，100 多人参加竞争，一名自学多门外语的青年在考试中英语成绩列第四，随后获聘。

来源：
- **A（同期报纸）**：《人民日报》1980-09-06，《为青年成才创造条件》：https://cn.govopendata.com/renminribao/1980/09/06/1/

这说明在大众互联网以前，个人能力已经可能通过：

```text
招聘公告
→ 报名/考试
→ 成绩与其他材料
→ 单位选择
```

进入一种可比较的候选人结构。

但它和后来数据库式招聘不同：

- 候选人通常围绕一场具体招聘进入流程；
- 记录主要服务这次组织过程；
- 不意味着以后陌生单位能跨地区、跨月份不断搜索同一份个人资料。

## 2.2 1988 北京：双向选择扩大以后，实体招聘会仍是重要“查询接口”

北京日报后来利用原报图文数据库整理的 1988 年材料显示，北京首次高校毕业生分配咨询会上，1000 多家用人单位与近万名应届毕业生现场洽谈；一些学生现场填表表达工作意向。

来源：
- **B+（后来的报史整理，明确引用并展示 1988 原报材料）**：北京日报，2022，《大学生就业从“包办婚姻”到“自由恋爱”》：https://news.bjd.com.cn/2022/03/17/10056344.shtml

它提醒我们：

> **choice expanded before candidate databases became remotely searchable.**

当时求职者可以“向社会推荐自己”，但可见性仍强烈依赖：

- 是否来到现场；
- 是否找到正确咨询台；
- 是否填表/递交材料；
- 对方工作人员是否当场愿意继续谈。

所以互联网后来改变的不是“人第一次需要写个人经历”，而是**个人经历从一次性现场材料逐渐成为可远程、可重复查询的记录对象。**

# 三、海外前史：在 Web 以前，Usenet 已经暴露“机器怎样筛人”的问题

## 3.1 1980s–1994：公开 job/resume newsgroup 先出现，信息过量随后逼出格式约束

Usenet 的 `net.jobs` / 后来的 `misc.jobs.*` 提供了一个很好的海外前史：工作机会和求职材料在 Web 以前就能通过网络跨地点传播。

保存下来的 Jobs FAQ 明确区分：

- `misc.jobs.offered`：职位；
- `misc.jobs.resumes`：简历与求职材料。

来源：
- **B/A-like preserved technical-community artifact**：Jobs FAQ, `misc.jobs.offered` / `misc.jobs.resumes`：https://stason.org/TULARC/society/job-offers/1-1-What-isn-t-misc-jobs-offered.html

更重要的是，同一 FAQ 记录：1994 年 12 月两周内，`misc.jobs.offered` 有 8824 篇，`misc.jobs.resumes` 有 4286 篇；作者已经明确说，数量太大以后，人不可能合理地逐条阅读，因此 Subject 中需要稳定放入 location 和简短 job description，以便计算机先筛。

来源：
- https://stason.org/TULARC/society/job-offers/2-misc-jobs-offered-Why-have-posting-guidelines.html

证据等级：**B+（历史 FAQ 的后续公开保存；其中统计值归因于当时 uunet stats）。**

这个前史非常重要：

> **机器筛选并不是“AI 招聘”才突然出现。只要候选人与职位数量超过人工逐条阅读能力，格式、字段和关键词就会开始参与谁先被看到。**

但必须限制外推：1990s 早期 Usenet 用户高度偏向高校、科研、技术与有网络接入的人群，不能当成当时普通美国人的普遍求职方式。

## 3.2 1997–2003 Monster：简历从“公开文章”进一步成为受限搜索数据库

1997 年 Microsoft 与 The Monster Board 的官方合作公告已经允许申请人在线申请、建立在线简历，并按资格收到新职位更新。

来源：
- **A（同期公司公告）**：Microsoft, 1997-10-14：https://news.microsoft.com/source/1997/10/14/microsoft-and-the-monster-board-offer-exclusive-resource-to-recruit-skilled-candidates-for-41000-jobs-in-microsofts-channel/

2003 年 Monster 母公司的 SEC 文件把状态描述得更完整：求职者可以保存简历、cover letter 与 application，查看自己的简历被潜在雇主看过多少次；简历进入一个 confidential / searchable / access-restricted database，付费雇主可以用关键词等条件搜索。

来源：
- **A（同期监管文件）**：TMP Worldwide / Monster, SEC filing 2003：https://www.sec.gov/Archives/edgar/data/1020416/000104746903037619/a2121724zs-3a.htm

这提供了一个与中国可以比较的共同变化：

```text
public/one-shot self-presentation
→ persistent candidate record
→ employer-side query
→ candidate-side visibility of some employer activity
```

这不是“中国招聘网站模仿某一个美国产品”的因果证明；它只说明“候选人数据库化”是更广泛的 Web 招聘转折。

# 四、1999–2004：中国网络招聘不是“纸消失”，而是纸与数据库并行

## 4.1 51job 2004 SEC 文件：最好的证据恰好反驳“互联网一来传统渠道就没了”

51job 2004 年 IPO 文件称：

- `www.51job.com` 自 1999 年上线；
- 网站允许求职者发布简历；
- 企业通过 `eHire` 管理、组织在线简历与候选人审阅；
- 截至 2004-06-30，公司口径称约有 690 万注册 job user accounts、约 460 万份在线简历；
- 同时，2003 年公司收入中，纸质招聘广告仍占 62.3%，在线招聘约占 26.2%。

来源：
- **A（同期 SEC prospectus；用户量与市场地位均为公司口径）**：https://www.sec.gov/Archives/edgar/data/1295484/000114554904001289/u99016a6e424b4.htm

更重要的是，同一文件自己承认：当时中国私人部门招聘仍大量依赖个人介绍和大型招聘会，使用招聘广告仍属相对较新的实践；其纸质 `Career Post Weekly` 还被公司用来覆盖不易接入 Internet 的中低收入求职者。

这正好提供一个方法论边界：

```text
51job online resume database exists in 2004
≠ every worker has Internet access
≠ every occupation uses online recruitment
≠ print/job fair/referral has disappeared
```

因此 1999–2004 应理解成**候选人数据库作为新接口加入混合招聘系统**，而不是单线替代。

## 4.2 投递之外，平台还开始托管“申请状态记忆”

51job 2004/2005–2006 的监管文件还把求职者工具写得很具体：

- 搜索职位；
- 接收匹配个人 profile/preference 的职位邮件；
- 直接提交简历；
- organize and track job-related information and applications；
- 获取招聘会与职业信息。

来源：
- **A（同期 SEC filing）**：https://www.sec.gov/Archives/edgar/data/1295484/000114554906000915/h00614e20vf.htm

这里新增了一个小但重要的生活变化：

> **“我投过哪些单位、现在等哪些回复”开始可以由账号替人记住一部分。**

这与仓库已有 calendar / bookmark / contact list 研究同构：个人未来的另一类小状态开始从纸和脑子迁入平台。

# 五、2005–2012：扩张型未来——我不仅能找到职位，还能让职位来找我

## 5.1 2008：网投很方便，但“提交成功”仍不等于“有人认真读”

2008 年浙江在线的同期报道采访到一名两年前毕业的小王。他认为网投省下设计、打印纸质简历的时间和费用，并认为至少比现场散发材料更容易进入 HR 的处理路径。

来源：
- **B（同期媒体采访，一名用户，不代表总体）**：浙江在线，2008-03-26：https://zjnews.zjol.com.cn/05zjnews/system/2008/03/26/009347406.shtml

同年 CCTV 报道却留下相反经验：受访学生每天花数小时网投，自己都记不清投了多少，真正收到的优质职位面试很少。

来源：
- **B（同期媒体采访）**：CCTV/新浪，2008-12-02：https://news.sina.com.cn/c/2008-12-02/133016767875.shtml

广州高校招聘会的 2008 同期报道甚至同时出现两种“海投”：

- 现场排队数小时，一次只能递出少数纸质简历；
- 有学生在招聘网站投出上百份，却没有回音。

来源：
- **B（同期报道）**：广州日报/中新网，2008-11-24：https://www.chinanews.com.cn/edu/zphxx/news/2008/11-24/1460407.shtml

这组反例告诉我们：

> **Internet 大幅降低了 submission cost，但没有同步降低 review scarcity。**

于是“扩张”首先发生在可尝试的数量：一个晚上可以投的岗位远多于一个下午在招聘会能排到的展位；但这也制造了新的 `application-state opacity`。

## 5.2 2009：候选人已经会主动管理“能不能被搜到”

2009 年前程无忧对外说明其简历有三种公开状态：

- 完全保密：不能被搜索；
- 对无忧公开：平台人员可检索；
- 完全公开：企业会员与平台人员可读取。

来源：
- **A/B（平台同期公告 + 同期商业媒体转述）**：https://www.prnasia.com/story/18318-1.shtml
- 上海商报/新浪，2009-03-31：https://tech.sina.com.cn/i/2009-03-31/16592959638.shtml

这说明“上传简历”已经不是单一动作。求职者开始管理：

```text
存一份简历
→ 用它主动投递
→ 是否允许平台内部搜索
→ 是否允许企业会员主动找到我
```

这尤其重要于仍在职的人：**想保留跳槽选项，不等于想让现单位知道自己在找工作。**

## 5.3 2009 recruiter-side first person：一套真实的筛选器会怎样塑造简历

2009-10-30，一名博客园作者记录自己因为公司需要招人，第一次使用中华英才网企业账号搜索候选人。他列出的招聘端流程包括：

```text
设置简历筛选器
→ 分页浏览
→ 打开单份简历
→ 下载/导出
→ 通知面试
```

而他实际看到的列表/简历字段包括：

- 更新日期；
- 行业；
- 职位；
- 工作年限；
- 学历；
- 地点；
- 姓名/性别/年龄；
- 职业目标；
- 求职意向；
- 期望薪水；
- 到岗时间；
- 工作经验；
- 教育；
- 技能。

更关键的是，他明确说招聘端可以按更新时间排序，因此建议求职者经常刷新；关键词在标题中的可见性也会影响搜索。

来源：
- **B（2009 同期 recruiter-side 第一人称操作记录；非平台官方，不代表所有公司）**：博客园，2009-10-30：https://www.cnblogs.com/over140/archive/2009/10/30/1592961.html

这是本轮最关键的一手生活材料之一，因为它把一个抽象概念落到了界面：

> **人生从“面试时讲给一个人听”变成“先通过一套 filter”。**

此时 `resume freshness` 也成为一种劳动：即使经历没变，求职者仍可能为了告诉数据库“我还活跃”而重复刷新。

# 六、2015–2019：拥堵型未来——可被找到，也意味着自己的职业历史越来越像长期暴露的数据资产

## 6.1 2018：“更新简历”已经可以成为跳槽行动本身

智联招聘 2018 春季白领跳槽调查（平台样本）中，56.7% 受访者处于“已更新简历正在求职”状态。

来源：
- **B（平台调查经中新网报道；样本不代表全部劳动者）**：2018-03-17：https://www.chinanews.com.cn/cj/2018/03-17/8469923.shtml

这里最值得保存的不是百分比外推，而是状态语言本身：

> **“更新简历”已经足以成为“开始行动”的一个可观察节点。**

传统跳槽可能从请假去人才市场、寄信开始；平台化以后，一个人甚至可以在没有投出具体岗位前，先把候选人记录重新变成“新鲜”。

## 6.2 2019：可搜索简历的价值和危险来自同一个结构

2019 年中国青年报调查到刚毕业的郭钰：她在网上向数家公司投简历后，开始频繁收到与原求职意向并不对应的陌生电话和短信；另一名正在换工作的律师则担心简历流出会让当前单位知道自己准备跳槽。

来源：
- **B（同期调查报道 + 同期第一人称）**：中国青年报/人民网，2019-09-20：https://society.people.com.cn/n1/2019/0920/c1008-31363093.html

同年新华社还调查智联招聘相关简历泄露与销号困难：平台记录一旦形成，普通人并不一定能清楚知道谁看过、谁复制过、退出以后哪些副本仍然存在。

来源：
- **B（同期调查）**：新华社/人民网，2019-07-12：https://finance.people.com.cn/n1/2019/0712/c1004-31231346.html

于是出现一个关键反转：

```text
早期问题：怎样让陌生雇主能找到我？
成熟问题：怎样只让真正相关的雇主找到我，而且在我不找工作后停止扩散？
```

这就是 `resume visibility custody`。

### 反例：在线可见性并未消除线下筛选与制度偏见

2019 年一名河南求职者通过招聘 App 投递后，简历被查看很短时间即因地域因素被标为“不合适”，后来进入诉讼。

来源：
- **B（后续 2020 报道 2019 事件与裁判）**：https://hn.ifeng.com/a/20200518/14219382_0.shtml

这说明：

> **candidate database can make selection faster without making selection fairer.**

可读性提高与公平并不是同一变量。

# 七、2020–2022：偶发型未来——当线下招聘突然停摆，结构化候选人记录变成应急基础设施

2020 年疫情把原本混合存在的招聘渠道强行推向线上。

教育部推出 24365 等全天候网上就业服务；一项当时对 1923 名应届生的调查中，92.2% 表示进行了线上求职。该调查只能代表其样本，不能当作全国毕业生完整普及率。

来源：
- **B（同期调查报道）**：中国青年报/界面，2020-04-02：https://www.jiemian.com/article/4204203.html

更有生活感的是个人材料。

2020 年 3 月，应届生小鹏说原定的线下招聘会取消/延期后一度焦虑，后来视频面试逐渐出现，他短期内已经进行十场面试。

来源：
- **B（同期第一人称）**：新京报，2020-03-03：https://finance.sina.com.cn/chanjing/cyxw/2020-03-03/doc-iimxxstf6044122.shtml

同年另一个典型流程是：学生在空中双选会平台注册、填写简历，系统根据专业和兴趣自动推送企业，再在线投递与面试。

来源：
- **B（同期人物报道）**：人民日报海外版/中新网，2020-05-19：https://www.chinanews.com.cn/cj/2020/05-19/9188176.shtml

而机械专业学生陈彬留下了反例：疫情期间他“疯狂网投”70 多份，仍有大量石沉大海或条件不合，线下招聘恢复后又回到现场与 HR 长谈。

来源：
- **B（同期第一人称）**：中山日报，2020-06-20：https://www.zsnews.cn/video/index/view/cateid/10000/id/546755.html

因此偶发型未来不应写成“线上终于完全取代线下”。更准确的是：

> **当身体暂时不能移动时，candidate record + remote interview 成为维持求职链不断裂的 fallback。**

但一旦线下恢复，一些人仍会重新使用现场沟通，因为“能提交记录”与“能建立互相判断的关系”不是一回事。

2022 年的一个受访毕业生又从另一面说明远程接口怎样扩大地理选项：人在湖南，也可以线上面试北京、上海、广东企业，最后获得广州公司的 offer。

来源：
- **B（同期第一人称）**：中新社，2022-11-20：https://www.chinanews.com.cn/cj/2022/11-20/9898422.shtml

这与仓库已有“search-first move / 先搜工作再迁移”专题形成直接交叉。

# 八、2023–2026：防守型未来——人开始学习怎样让 AI 读懂自己，同时又担心自己被系统读得太简单

## 8.1 2024–2025：招聘接口继续从“字段筛选”向“自动评价”移动

2024 届毕业生高雅鑫在春招中参加多次 AI 面试；她会先在网上搜索 AI 面试流程与问题并反复练习。另有求职者描述第一次 AI 面试缺少自然反馈、问题追问机械，因此更喜欢人与人的交流。

来源：
- **B（同期人物报道）**：经济观察报，2024-05-09：https://www.eeo.com.cn/2024/0509/659849.shtml

2025 年央视报道中，应届毕业生任思禹说自己面试五家企业，其中两家使用 AI 面试，系统会根据简历继续追问。

来源：
- **B（同期采访）**：央视网/人民网，2025-04-19：https://finance.people.com.cn/n1/2025/0419/c1004-40463533.html

这意味着传统链条：

```text
简历是面试之前的静态门票
```

正在进一步变成：

```text
简历字段
→ 自动生成/选择问题
→ 机器采集回答
→ 结构化评价
→ 人或系统继续筛选
```

但目前公开报道仍不足以证明所有行业都如此，也不能从厂商“覆盖率”口径直接推出全国企业普及。

## 8.2 2026：求职者自己也开始用 AI 重写“机器可读的我”

2026 年中国青年报记录昆明理工大学会计学毕业生赵棒棒：他最初向上百家公司投递几乎没有回应，后来使用学校 AI 求职系统，把专业、活动经历等填入结构化系统；系统帮助生成简历框架、针对岗位二次优化，并推荐了他原本没有设想到的供应链/生产管理方向。他最终获得多家面试和三个 offer，并选择其中一份。

来源：
- **B+（2026 同期第一人称 + 校方系统介绍；单个案例）**：中国青年报，2026-03-31：https://news.cyol.com/gb/articles/2026-03/31/content_6z8jb8FjpG.html

这个个案不应被写成“AI 普遍提高求职成功率”。它真正证明的是一种新生活路径已经存在：

> **求职者不只是修改表述去适应已有岗位；系统也可能根据一个人的经历重新提出“你也许可以成为谁”。**

这可以称作：

## algorithmic option expansion（算法式选项扩展）

它与算法收窄并存。推荐系统可能打开没想过的职业，也可能因为训练数据、字段和目标函数把不标准经历排除在常见类别之外。

## 8.3 防守型未来的另一个信号：求职者开始担心的不是“有没有选择”，而是“什么工作以后还存在”

前程无忧 2026 年针对 2040 名 2026 届毕业生的调查（平台调查，不是全国人口调查）显示：大量受访者使用生成式 AI 润色/定制简历；同时，约三分之一受访者把“岗位的 AI 抗替代性”纳入职业选择，部分人担忧基层入口岗位减少。

来源：
- **B（平台调查经工人日报报道；样本与问卷设计需保留限制）**：2026-04-09：https://www.workercn.cn/c/2026-04-09/8776433.shtml

所以四阶段的时间语义可以更细地写成：

```text
2005–2012 扩张型：
“我可以投更多城市、更多公司，也可以让企业来找我。”

2015–2019 拥堵型：
“我的简历一直在线、竞争者很多、要不断刷新/优化；被看见和被骚扰共用同一条数据管道。”

2020–2022 偶发型：
“线下突然断了，至少我还能靠候选人记录和远程面试保持进入下一份工作的可能。”

2023–2026 防守型：
“我得让机器读懂我，也要学会检查机器怎样定义我；我甚至开始把‘这份工作以后会不会被机器替代’写进职业选择。”
```

# 九、这怎样连接“标准人生脚本”与非连续生命历程？

最重要的关系不是“ATS 歧视空窗”这种未经本轮直接证明的宽泛断言，而是一个更基础的结构事实：

> **任何招聘系统都只能检索它先有办法表示的东西。**

对标准脚本：

```text
本科 4 年
→ 公司 A 3 年
→ 公司 B 2 年
→ 求下一份同类工作
```

数据库很容易得到：

- 学历；
- 年限；
- 职称；
- 最近公司；
- 行业；
- 稳定日期段。

对非标准脚本：

```text
毕业
→ 照护一年
→ 临时项目
→ 考试
→ 半年零工
→ 跨城迁移
→ 再进入正式岗位
```

问题首先不是“这个人有没有能力”，而是：

- 照护填在哪？
- 没有公司名称的项目怎样被索引？
- 并行工作如何序列化？
- 断断续续的技能使用怎么算“工作年限”？
- 空窗是否只能留白？

所以应把 `resume-schema pressure` 加到仓库核心矩阵的“长期中断 / 非正规劳动 / 照护 / 证件与记录”交叉层。

# 十、反例与禁止的后见之明

## 10.1 不要写“招聘网站发明了简历”

纸质简历、报名表、求职信、考试记录和人才市场登记都更早存在。

网络真正新增的是：

- 持久候选人数据库；
- 跨时间/跨地点搜索；
- employer-side filtering；
- 可见性设置；
- 更新时间排序；
- 申请状态与推荐状态的账号化。

## 10.2 不要把 2004 年 460 万简历写成“普通中国人都开始网上求职”

这是 51job 公司口径的累计 posted resumes；同一份监管文件自己还说大量招聘依赖个人介绍、招聘会，并用纸媒覆盖不易上网者。

## 10.3 不要把“海投无回音”自动解释成 ATS 淘汰

2008–2009 材料只能证明：

- 提交数量很大；
- 很多申请没有可见回复；
- 招聘端使用筛选器、更新时间、关键词等字段。

它不能告诉我们某一份简历究竟在哪一步消失。

## 10.4 不要把 AI 招聘写成单向自动化

2024–2026 已经是双向工具化：

```text
求职者 AI 优化/定制/模拟
↔
雇主 AI 匹配/筛选/面试
```

因此真正值得研究的是**双方如何重新制造“机器可读性”**，而不是简单写“机器替代 HR”。

## 10.5 不要浪漫化“被动可发现”

被雇主主动找到可以降低求职搜索劳动；同一结构也会扩大骚扰、简历倒卖和现雇主获知跳槽意图的风险。

# 十三、交叉研究：写回 old-web-archaeology 的对象

本专题对应的旧网页对象不是“招聘网站首页长什么样”，而是：

```text
candidate profile form
→ resume database record
→ visibility state
→ refresh/update timestamp
→ employer search/filter
→ result list
→ resume detail
→ download/export
```

尤其需要 old-Web 侧长期保留以下硬边界：

```text
resume form captured

resume submitted

application status page captured
!= employer internal decision state

final resume survives
!= earlier versions survive
```

# 十四、它改变了我们对“普通人怎样活着”的哪一点？

过去“找工作”常常要求身体、纸张和机会在同一个地方相遇：人来到人才市场，把一份材料交给一个具体单位，再等对方决定。

在线招聘出现以后，一部分人的职业过去变成了一个**可以在本人不在场时继续被检索的对象**。这显著扩大了可能性：人还住在 A 城市，B 城市的企业已经可以找到他；他还没有辞职，下一份工作也许已经通过搜索出现。

但新的自由同时要求普通人做一种以前很少存在的劳动：

> **把自己活过的人生不断翻译成系统能够检索的字段。**

如果人生很标准，这很容易；如果中间有照护、疾病、备考、零工、跨城、失败项目和长期中断，真实生活就可能比表格复杂得多。

到 2026 年，这件事甚至开始变成“机器写给机器看”：求职者用 AI 从经历里提取关键词、按 JD 改写简历，雇主又用算法筛选、追问和排序。于是这一时期真正稀缺的能力不只是“有经历”，而是**既能让机器读懂自己，又不让机器的字段成为自己人生唯一的解释。**
