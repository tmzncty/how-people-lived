# 有偿家务、照护外包与家政劳动路线：中国，1996–2025

> 状态：研究笔记；用于 `how-people-lived` 的 household / work / care / migration / communications / life-course 交叉研究。
>
> 核心问题：**一个家庭什么时候可以通过“购买别人的时间”来维持双职工、育儿、养老、清洁与日常生活？与此同时，谁把自己的劳动时间卖进别人的家庭，这又怎样形成一种与工厂、办公室、商店不同的就业路线？电话、社区中介、Web、论坛、App 与信用平台分别改变了匹配、信任和执行中的哪一层？**

---

## 0. 本篇新增的不是“保姆行业史”

仓库已经分别讨论过：

- 家庭照护与祖辈时间；
- 职业中断与重新进入；
- 婚姻、住房、迁移与分布式家庭；
- 求职平台与工作机会可发现性；
- 同城匹配、合租、远程工作；
- 就医导航与 care proxy；
- Internet 前后的信息可及性。

但这些专题仍然容易默认：

> 家务、育儿和养老，要么由本人做，要么由配偶、父母、祖父母等亲属做。

现实还有第三种路线：

> **家庭从市场购买另一位普通人的时间。**

而对劳动者来说，家政又可能是：

- 下岗后的转岗；
- 农村—城市迁移后的就业；
- 餐饮、保安等工作之后的转行；
- 退休后的有偿劳动；
- 钟点式的多雇主劳动；
- 春节等时期的短期替工；
- 照护技能培训后的专业化路线；
- 在中介、员工制企业与平台之间切换的工作路线。

所以本篇研究的不是“家政越来越专业”这一条单线故事，而是：

> **有偿家务怎样改变一个家庭的可执行生活菜单，同时又为另一群人创造一种并不完全符合标准雇佣脚本的工作菜单。**

---

## 1. 新变量一：household-labor externalization

这里暂用 **household-labor externalization（家庭劳动外部化）** 描述：

> 原本必须由家庭成员亲自完成的部分家务或照护，被转移给家庭外的有偿劳动者。

常见内容包括：

- 做饭；
- 清洁；
- 洗衣；
- 买菜；
- 接送儿童；
- 婴幼儿照护；
- 老人陪伴与生活照料；
- 病人日常陪护；
- 部分短时上门服务。

它的生活史意义不是“少做一点家务”这么简单。

对一个具体家庭，是否能稳定获得这些服务，可能直接决定：

```text
母亲 / 父亲能否按时复工
+ 两人能否同时全职工作
+ 成年子女能否异地工作
+ 老人能否继续居家生活
+ 是否必须与祖辈同住
+ 是否必须有人退出劳动力市场
```

因此可以把它看成一种 **purchased household time（购买来的家庭时间）**。

---

## 2. 新变量二：care-capacity substitution

家庭并不只是购买“清扫两小时”。

很多时候，真正购买的是一个时间段内的 **care capacity（照护容量）**。

例如：

```text
工作日 08:00–18:00
```

如果婴儿、老人或病人需要持续有人在场，那么这个时间段必须由某个人覆盖。

可能的覆盖来源包括：

```text
本人
配偶
祖父母 / 亲属
邻居 / 熟人
托育 / 机构服务
家政员 / 育儿嫂 / 护老人员
若干来源拼接
```

所以：

> **paid domestic service ≠ simple consumption.**

它有时是一种让另一份工作、一次迁移或一个独立居住安排得以成立的基础设施。

但反过来也必须坚持：

> **domestic worker available ≠ household can afford one.**

价格、稳定性、居住空间、信任和工作内容都会改变真实可及性。

---

## 3. 新变量三：household as workplace

家政劳动有一个与普通单位工作非常不同的结构：

> **工作场所就是另一个家庭的私人住宅。**

因此工作关系与家庭边界会叠在一起：

- 工作时间与休息时间；
- 是否住家；
- 吃住由谁承担；
- 私人物品与家庭物品；
- 照护、清洁、做饭的职责边界；
- 雇主家庭中的老人、孩子与其他成员；
- 节假日是否留岗；
- 是否允许外出；
- 发生冲突后由谁调解；
- 工资是家庭直接付，还是企业代发；
- 服务员究竟是家庭雇佣、企业员工，还是由中介介绍的独立劳动者。

所以同样写着“家政员”，现实的 employment topology 可以完全不同。

# 第一部分：大众 Internet 以前，匹配已经是一套劳动基础设施

## 4. 1996：下岗以后，“去别人家工作”成为一条重新编码职业身份的路线

1996 年 10 月 22 日《人民日报》关于下岗女工再就业的同期报道记录，上海已有一批下岗女工进入家庭服务领域；报道写到，两小时内曾有 345 名下岗女工自愿报名。一名女工解释，想到自己是家政服务公司的“职工”、经过正规培训并持有上岗证，她在去别人家工作时会更安心。

数字化人民日报文本入口：

<https://cn.govopendata.com/renminribao/1996/10/22/10/>

### 证据等级

- 报道本身是 **同期新闻**；
- 本轮取得的是公共数据库中的数字转录，不是原报影像；
- 暂按 **B：同期媒体转录** 使用；
- 女工的话属于 **同时性第一人称嵌入 B 级报道**。

### 4.1 这不是单纯“找了一份新工作”

它改变了标准职业脚本的可读性。

对一些原来有国有 / 集体企业岗位的人，路线变成：

```text
工厂 / 单位职工
→ 下岗
→ 培训
→ 家政公司 / 社区服务组织
→ 进入私人家庭劳动
```

这不是“从正规劳动跌入没有工作的状态”。

更准确的描述是：

> **工作地点、服务对象、职业声望、劳动关系和技能证明同时被重新组织。**

报道中“公司职工”“培训”“上岗证”之所以重要，说明 **institutional legibility（制度可读性）** 本身就是转岗的一部分。

### 4.2 身份与声望不是小问题

同一时期材料反复讨论“面子”和“择业观”。

这意味着：

> `job exists ≠ worker sees it as an acceptable job`

家庭服务可以有真实需求，却仍可能因为职业身份、性别化劳动和社会评价而难以吸收潜在劳动者。

这也是后面所谓“保姆荒”不能只按总人数解释的原因之一。

## 5. 1998：没有 Web，社区也能建立一套双边匹配系统

1998 年 12 月 5 日《人民日报》的一篇武汉报道非常适合作为 Internet 前边界。

报道说，武汉市妇联针对中年下岗女工就业困难，在万松园街试办家政服务。街道和妇联工作人员骑自行车挨家挨户做调查，用两天摸清：

- 哪些家庭需要服务；
- 哪些女工愿意做家政。

随后“巾帼家政服务队”成立，一上午有 20 多户家庭签订合同，聘请下岗女工做钟点工。

数字化报道：

<https://cn.govopendata.com/renminribao/1998/12/05/7/>

### 证据等级

**B：同期媒体数字转录。**

### 5.1 Internet 前的 matching stack

这里已经存在一套很完整的服务匹配链：

```text
家庭需求
→ 街道 / 妇联上门调查
→ 记录供需
→ 组织培训 / 服务队
→ 家庭签约
→ 钟点服务
```

所以绝不能写：

> “Internet 出现以后，家庭第一次能找到陌生家政员。”

更准确的是：

> Internet 后，原来由街道人员、电话、中介门店和人工名册完成的一部分搜索与筛选，逐渐可以由用户自己远程完成。

### 5.2 一个很重要的共同体差异

1998 这种社区组织匹配还带有明显的 **bounded trust domain（有边界的信任域）**：

- 街道知道家庭；
- 妇联 / 服务队知道劳动者；
- 家庭通过组织而不是完全陌生的个人进入交易。

后来开放 Web 扩大搜索半径时，也会削弱这种“共同组织认识双方”的条件。

# 第二部分：2005–2007，Web 进入家政，但没有替代电话和线下

## 6. 2005：“网上预定 + 电话咨询 + 现场挑选”同时存在

2005 年 7 月 21 日《北京晨报》答读者问，介绍一批经培训后进京的四川家政服务员时，明确写到北京市民可通过三种方式选择：

- 网上预定；
- 电话咨询；
- 现场挑选。

报道还给出了两个公司网站。

新浪保存的同期报道：

<https://news.sina.com.cn/c/2005-07-21/04106487323s.shtml>

### 证据等级

**B：同期媒体。**

### 6.1 新的不是“线上完成雇佣”

这条证据特别适合堵住一个常见误读。

2005 年 Web 已进入搜索 / 预约链，不能因此写成：

```text
网页
→ 点击
→ 保姆自动上门
```

更真实的结构是：

```text
网站 / 报纸 / 介绍
→ 电话 / 网上预定 / 到店
→ 查看候选人
→ 面谈
→ 协商工作内容和工资
→ 入户
```

这是一种 **hybrid matching stack（混合匹配栈）**。

Internet 的作用是增加一个入口，而不是把整个劳动关系变成网页交易。

---

## 7. 2005：网页标价甚至可能比电话市场慢半拍

2005 年 1 月，北京一篇同期报道写到，记者查看几家家政公司网站时，页面仍标着普通家政服务月薪 600–800 元；但记者再打电话询问，公司已经回答“涨价了”，具体价格需由雇主与服务员另行协商。

来源：

<https://finance.sina.com.cn/roll/20050113/00001289970.shtml>

### 证据等级

**B：同期媒体实际进行网站查看 + 电话询问。**

### 7.1 新变量：price-state freshness

这个小案例非常重要：

> **published web price ≠ contemporaneous executable wage**

网站是公开可见的，却可能更新得比电话、门店和实际议价慢。

因此普通人的真实选择成本要看：

- 网站价格；
- 当季供需；
- 春节等时间节点；
- 工作强度；
- 住家 / 不住家；
- 老人 / 婴儿 / 普通家务；
- 最终协商结果。

“网页上写多少钱”只是一个状态，不是最终交易价格。

## 8. 2006：人开始被做成可以浏览的“家政 profile”

2006 年 1 月 17 日，浙江在线记者写到，自己登录杭州下城区“文晖新干线”，看到新增“保姆推荐”栏目，其中出现保姆照片、简介、“明星保姆”“星级保姆”等分类；报道还记录了不同星级对应的技能描述与工资范围。

来源：

<https://zjnews.zjol.com.cn/05zjnews/system/2006/01/17/006446359.shtml>

### 证据等级

**B：同期记者对网站的直接观察。**

本轮没有取得该栏目当日可验证的历史 HTML / archive capture，因此不把报道描述冒充 A 级页面原件。

### 8.1 worker legibility

家政员开始被拆成一组可以远程阅读的字段：

- 照片；
- 年龄；
- 学历；
- 技能；
- 证书；
- 服务经验；
- 星级；
- 期望工资。

这形成 **worker legibility（劳动者可字段化）**。

但必须固定：

```text
profile visible ≠ worker currently available
credential listed ≠ skill independently verified
star level ≠ durable household fit
```

尤其家政的“合适”包含很多网页很难编码的东西：

- 生活习惯；
- 沟通方式；
- 对老人 / 孩子的接受程度；
- 家庭成员之间的边界；
- 实际劳动强度；
- 是否愿意长期住在雇主家。

## 9. 2007：“拼保姆”说明家庭也可以共同购买照护容量

2007 年 5 月，中国经济网报道回龙观等社区出现“拼保姆”。记者在回龙观社区网亲子论坛搜索“合雇保姆”“拼保姆”，能看到近期帖子；其中一位有 3 个月大婴儿的用户希望找不住家保姆，只在每周一、三、四白天来，并询问是否有邻居愿意合雇。

来源：

<https://finance.ce.cn/xf/main/zx/200705/17/t20070517_11388894.shtml>

### 证据等级

- **B：同期媒体对论坛可观察内容的记录**；
- 帖子内容属于 **同时性用户自述嵌入 B 级报道**；
- 本轮没有把普通用户旧 ID / 联系方式重新公开到仓库。

### 9.1 新生活路径：care co-purchase

这不是普通“请保姆”的缩小版，而是 **care co-purchase（照护共同购买）**：

```text
家庭 A 只需要部分时段
家庭 B 只需要另一部分时段
→ 两家共享同一劳动者
```

它证明 household / worker 的关系不一定是：

```text
1 worker ↔ 1 household ↔ full month
```

也可以是：

```text
1 worker ↔ multiple households ↔ segmented schedule
```

这会改变：

- 小家庭是否付得起家政；
- 家政员是否能拼出完整收入；
- 同一社区中的家庭是否需要协调时间；
- 服务失败时谁承担替补问题。

### 9.2 Internet 的具体作用

这里网络真正增加的是：

> **让原本互不相识、但住得很近且时间需求互补的家庭发现彼此。**

它与“找一个家政员”不同，是在做 **demand-side matching（需求方之间的匹配）**。

# 第三部分：四种未来时间感中的家政劳动

## 10. 2005–2012：扩张型未来——购买别人的时间，也扩大自己的生活组合

这一阶段不能写成“人人都请得起保姆”。

恰恰相反，2005 年上海工薪家庭的同期报道已经有人按家庭预算计算，发现住家保姆的价格接近家庭剩余现金，因而“请不起”。

来源：

<https://news.sohu.com/20050319/n224762077.shtml>

因此家庭劳动外部化一直具有明显的收入分层。

但对能够承担费用的家庭，它确实增加了新的组合：

```text
双职工
+ 婴儿 / 老人
+ 家政员 / 钟点工
```

这意味着：

> **家庭形成以后，并不是只有“谁退出工作”一个解法。**

与此同时，对原本工作路线收窄的人，家政本身又形成新的就业入口。

所以扩张不是只有一侧：

- 雇主家庭购买 care capacity；
- 劳动者出售自己的时间、技能与迁移能力。

两边的 optionality 相互依赖。

---

## 11. 2019：拥堵型未来——“有阿姨、有雇主”仍可能匹配失败

2019 年 12 月，钱江晚报 / 央视网对杭州朝晖家政市场的现场调查提供了一组非常好的同时性第一人称材料。

市场负责人明确反对简单的“阿姨紧缺”叙事：现场每天仍有等待雇主的人，真正的问题是双方匹配越来越难。

报道中：

- 一位 50 多岁男子为 75 岁母亲找陪伴型住家保姆，月薪 3300 元，现场多名服务员都不愿接；
- 服务员讨论一份 5 层别墅、做饭、清洁、看小孩的 6000 元工作时，认为强度太高；
- 62 岁的韩阿姨等待多日仍没被选中，她认为年龄让雇主担心效率和健康风险；
- 一名男家政员从保安工作回来重新找家政，希望找长期岗位，但又面对家庭对男性家政员的接受度问题；
- 柯阿姨同时考虑自己直接找雇主，或通过中介签协议，因为她认为没有协议“没保障”。

来源：

<https://news.cctv.com/2019/12/30/ARTIJyHkNNWf25TjNYx43mQR191230.shtml>

### 证据等级

**B：同期现场调查，包含多条同时性第一人称。**

### 11.1 新变量：match-fit congestion

因此要加入：

> **nominal supply ≠ matchable supply**

一个“岗位”和一个“待岗家政员”之间还隔着：

- 工资；
- 工作强度；
- 老人 / 孩子 / 家务类型；
- 年龄；
- 性别；
- 是否住家；
- 节假日；
- 地点；
- 雇主与劳动者的相互偏好；
- 合同 / 中介保障。

这就是 **match-fit congestion（匹配适配拥堵）**。

2015–2019 的“拥堵型未来”因此又多了一层：

> 选项在纸面上很多，但要同时满足所有约束，真正可执行的组合可能很少。

### 11.2 “互联网平台”与实体市场同时存在

同一报道还说，年轻夫妻更多通过互联网平台寻找家政，一些年轻劳动者也会挂靠平台；而实体家政市场来访者更偏年长。

这不是“线上取代线下”，而是 channel segmentation：

```text
实体家政市场
+ 电话 / 中介
+ 互联网平台
```

同时服务不同年龄、信任习惯和劳动者群体。

## 12. 2019：employment legibility 仍没有自动解决

2019 年《工人日报》报道上海部分家政企业试行“员工制”。

其中 31 岁的周旋说，她来上海后原来做餐饮，收入约 4000 元且不稳定；参加母婴护理培训以后，家政收入起点更高。报道同时记录，一些企业尝试通过三方协议、工资卡和第三方银行代发收入，让现金支付变得更可记录。

但报道也明确指出：社保由谁承担、企业是否真正形成完整劳动关系，仍存在现实难题。

来源：

<https://society.people.com.cn/n1/2019/0814/c1008-31294355.html>

### 证据等级

**B：同期行业报道 + 同时性劳动者第一人称。**

### 12.1 新变量：employment-interface ambiguity

对家政劳动必须区分：

```text
agency introduces worker
≠ agency employs worker
≠ household directly employs worker
≠ enterprise pays salary
≠ full social-insurance employment relation
```

所以一个人每天都在真实劳动，并不代表她的劳动关系在制度上只有一种清晰形态。

这与仓库已有的 `performed work ≠ institutionally legible employment` 直接相连，但家政把这个问题推得更尖锐，因为工作发生在私人家庭，劳动者又可能频繁更换雇主。

---

## 13. 2020–2022：偶发型未来——匹配成功以后，人仍然可能进不了家门

2020 年疫情把家政劳动的物理属性暴露得非常清楚。

中国青年报 2020 年 5 月的同期报道记录：一些家政员结束隔离、公司也开始复工后，仍可能因小区门禁而无法进入；来自湖北宜昌的育婴师赵贤菊已经从业 8 年，上一单连续做了 3 年，2020 年初回家后很长时间接不到新的入户订单。即使后来找到技能和经历都满意的雇主，对方仍因疫情风险继续等待。

来源：

<https://www.xinhuanet.com/politics/2020-05/12/c_1125972352.htm>

### 证据等级

**B：同期媒体 + 同时性劳动者自述。**

### 13.1 新变量：enterability

这里需要增加一个比 matching 更晚的状态：

> **enterability（可入户性）**

因此：

```text
worker discovered
→ interviewed
→ matched
→ agreement reached
→ permitted to enter community
→ permitted to enter household
→ service begins
```

疫情期间，中间两步第一次变成大规模、反复变化的制度变量。

于是有硬边界：

> **matchability ≠ enterability**

### 13.2 数字化能把哪一步搬走

2020 年 3 月北京商报记录，一些家政公司把“面对面”改成“屏对屏”：通过微信发送简历与评价、视频面试、在线签约和付款；一个案例从接单到线上确定月嫂约一个多小时。

但报道同时清楚写出，线上流程完成后还要：

- 健康状态确认；
- 返回城市；
- 隔离；
- 小区 / 家庭允许进入；
- 真正上户。

来源：

<https://www.bbtnews.com.cn/2020/0303/339380.shtml>

所以疫情并不是“家政变成远程服务”。

它更像：

> **information and contracting moved online while labor remained irreducibly physical.**

这正符合 2020–2022 的“偶发型未来”：合同已经签了，也不能假定下周现实流程仍能按日历运行。

---

## 14. 2023–2026：防守型未来——信任越来越被做成可查询记录

2025 年安徽“放心家政”报道保存了两边的同期第一人称：

- 一名家庭用户说，有平台诚信分以后选择更容易；
- 一名家政员说，客户扫码即可看到自己的信用记录和以往评价，沟通更容易建立信任。

报道还描述，平台可展示健康证、技能证书、客户评价，并把诚信分与展示 / 接单机会联系起来。

来源：

<https://news.sina.com.cn/zx/gj/2025-09-23/doc-infrmiez3049684.shtml>

国家层面到 2025 年也已持续建设家政服务信用信息平台、“家政信用查”App / 小程序和电子化上门服务证。

来源：

<https://credit.pds.gov.cn/contents/22/29287.html>

### 证据等级

- 用户 / 家政员表述：**B：同期媒体第一人称**；
- 平台制度与功能：**A/B：政府发布 / 政策性平台信息**。

### 14.1 新变量：credentialized trust

这形成 **credentialized trust（凭证化信任）**：

原来大量依赖：

```text
街道介绍
熟人推荐
中介口碑
面对面判断
```

后来增加：

```text
实名
服务证
培训 / 技能记录
健康信息
历史评价
平台信用
```

但绝不能写：

> “有信用分以后就能知道一个人是否适合自己的家庭。”

因为：

```text
identity verified ≠ skill verified
skill verified ≠ household fit
positive reviews ≠ future performance guaranteed
platform record ≠ complete work history
```

### 14.2 防守型未来的一个窄机制

这里可以谨慎提出一个 2023–2026 的候选机制：

**verification-before-entry（入户前验证）**变得更显性。

因为家庭要把一个陌生劳动者带进私人住宅、接触老人、孩子和大量私人物品，风险防御本来就强；平台与公共信用系统把这种“先确认再进入”的倾向进一步字段化。

这不等于当代人整体更不信任别人，只能说明家政这一特殊场景中，验证劳动被越来越多地制度化。

# 第四部分：海外对照——Internet 以前，同样的问题已经存在

## 15. 1995 Dallas：电话簿、朋友转介和中介公司

1995 年 12 月，美国 Dallas 的 D Magazine 刊登了一篇第一人称“Operation Nanny Hunt”。

作者与丈夫都有全职工作，一个 3 岁孩子即将上 preschool，同时又将有新生儿，于是决定雇 nanny。她描述自己的寻找顺序是：

```text
需要照护
→ 翻电话簿找 nanny agency
→ 打电话
→ 因朋友的朋友曾有尚可经历而选择一家
→ 支付 retainer
→ 填表
→ 与中介筛出的多人见面
→ 再邀请候选人到家复试
→ 自己继续核 references
```

来源：

<https://www.dmagazine.com/publications/d-magazine/1995/december/families-operation-nanny-hunt/>

### 证据等级

**A/B：1995 同时代第一人称杂志文章；可直接证明作者自己的搜索路径，不代表 Dallas 所有家庭。**

### 15.1 共同机制

这个案例说明，在 1995 年的美国城市：

- 家庭劳动外部化已经可以支撑双职工育儿；
- 电话簿和中介可以完成陌生人发现；
- “中介做过筛选”仍不等于家庭愿意放弃自己核验 references；
- 费用、税务、保险、合同和长期稳定性都没有因为中介存在而消失。

这与 2005–2006 中国 Web 家政的结构非常接近：

> **网络改变 search interface，不会消灭 intimate-work trust problem。**

### 15.2 不应把 1995 美国写成“网络招聘已经普及”

Pew 1996 年回顾调查显示，1995 年 6 月约 14% 的美国公众称从工作、学校或家里上网；在线人口在随后一年继续增长，而且在线用户明显更年轻、更富裕、教育程度更高。

来源：

<https://www.pewresearch.org/politics/1996/12/16/online-use/>

这与上面的第一人称案例可以互相校正：

> Internet 在美国已经存在并增长，不代表一个 1995 年普通 nanny search 必须从 Web 开始。

# 第五部分：这改变了“普通人怎样活”的哪些地方

## 16. 家庭不是只在“自己做 / 不做”之间选择

家庭照护和家务至少存在：

```text
自己做
→ 配偶分担
→ 亲属 / 祖辈做
→ 邻里互助
→ 机构服务
→ 有偿家政
→ 若干方式混合
```

所以研究双职工、育儿、养老和迁移时，都要增加一项：

> **这个家庭能否稳定、可负担地购买外部 household labor？**

---

## 17. “独立小家庭”有时依赖另一个家庭的劳动者

一个核心反直觉点是：

> 核心家庭变得更“独立”，不代表它减少了对外部劳动的依赖。

一对夫妻能够不和祖辈同住、双方继续工作，可能恰恰是因为另一位劳动者：

- 从别的地区迁入；
- 离开自己的家庭；
- 在他们家中承担清洁或照护。

因此 household independence 有时是 **inter-household labor dependence（家庭之间的劳动依赖）**。

这条依赖不能被浪漫化，也不能被道德化；需要研究的是：

- 钱如何支付；
- 时间如何安排；
- 谁承担离家与迁移成本；
- 谁获得职业连续性；
- 谁的照护义务又被留在原家庭。

---

## 18. 标准人生脚本会在两端同时改变

### 对雇主家庭

可能出现：

```text
结婚
→ 生育
→ 不必由一人长期退出职业
→ 购买育儿 / 家务时间
→ 双方继续工作
```

也可能因为家政太贵或找不到合适的人而反向变化：

```text
生育
→ 找不到 / 请不起稳定照护
→ 一人减少工作或离职
```

### 对家政劳动者

可能出现：

```text
原行业工作
→ 下岗 / 辞职 / 迁移
→ 培训
→ 家政
→ 更换家庭 / 专业化
```

也可能：

```text
家政
→ 保安 / 餐饮等其他工作
→ 再返回家政
```

2019 年“老张”从家政转去做保安、又希望回到家政，就是一个明确反例：职业路线不是单向升级。

---

## 19. 核心矩阵更新

| 维度 | 本轮新增理解 |
|---|---|
| 教育 | 培训 / 上岗证 / 技能认证可以改变家政工作可读性，但证书不等于现实 household fit |
| 就业 | 私人家庭本身可以成为工作场所；中介介绍、直接雇佣、员工制、平台接单不能混成一种劳动关系 |
| 住房 | 住家家政把“住房”与“工作地点”叠在一起；雇主家庭的空间也是劳动者日常空间 |
| 婚姻家庭 | 双职工、婴幼儿与老人照护可以通过购买外部时间重新组合 |
| 迁移 | 大量家政工作以跨地区劳动力流动为前提；春节返乡会直接改变服务供给 |
| 照护 | unpaid kin care 之外增加 paid care；照护容量可以购买、共享和拼接 |
| 非正规劳动 | 钟点、多雇主、短期替班、直接找雇主等路线长期存在 |
| 长期中断 | 家政可成为其他职业中断后的重新进入路线，也可能再次退出再返回 |
| 证件与记录 | 上岗证、培训证、服务证、平台信用记录逐渐承担 trust interface |
| 通信方式 | 街道上门调查 → 电话 → Web → 论坛 → App / 视频 → 扫码信用查询，多渠道长期并存 |
| 互联网平台 | 首先扩大可发现性，后来增加 profile、评价、在线面试、签约、支付与记录 |
| 信息获取 | 网站标价可能滞后于电话与实时议价，公开页面不是最终市场状态 |
| 社交关系 | 邻居可通过论坛共同雇佣同一劳动者；熟人推荐仍与平台共存 |
| 未来预期 | “是否能持续买到照护时间”会影响复工、生育、养老与跨城工作的可规划性 |
| 线上 / 线下身份 | profile、星级、服务码提高可读性，但实际家庭相处仍无法完全字段化 |
| 平台消失与记忆 | 公开 profile 容易幸存，真正发生在家庭内的劳动过程和关系持续时间反而最不可见 |

# 第六部分：证据边界、反例和后见之明风险

## 20. 不能把家政需求增加写成“女性解放的单一结果”

家庭劳动外部化确实可能帮助某些人维持职业连续性。

但不能因此写成：

> “一个女性不做家务了，所以另一个女性来做，这是线性进步。”

这种叙述会抹掉：

- 劳动者自己的家庭；
- 跨地区迁移；
- 工资和休息；
- 社保与合同；
- 职业声望；
- 不稳定匹配；
- 雇主家庭的收入门槛。

本篇只描述具体生活组合如何成为可能，不给它自动贴上“进步”或“倒退”。

---

## 21. “保姆荒”必须拆开

2019 杭州现场材料明确表明：

```text
有待岗劳动者
+ 有找人的家庭
```

也可以同时存在大量未匹配。

所以以后看到“缺口”“荒”时至少问：

- 哪个城市；
- 哪个季节；
- 住家还是钟点；
- 育儿还是老人；
- 工资区间；
- 年龄 / 性别要求；
- 是否要求节假日留岗；
- 数据来自公司库存、招聘发布还是真实上户。

`market shortage headline ≠ homogeneous labor shortage`。

---

## 22. 不能把“互联网平台”写成完整就业关系

平台或网站可能只完成：

- 展示；
- 推荐；
- 联系；
- 预约；
- 评价。

真正劳动关系可能仍由：

- 家庭直接形成；
- 中介介绍；
- 企业三方协议；
- 服务协议；
- 平台订单。

因此：

> **digital matching ≠ employer identity**

---

## 23. 公开记录存在明显历史可见性偏差

最容易保存的是：

- 公司网站；
- 服务分类；
- profile；
- 星级；
- 招聘 / 需求广告；
- 价格表；
- 平台宣传。

最难保存的是：

- 第一次进门后的真实劳动；
- 雇主与家政员如何重新协商职责；
- 夜间是否真正休息；
- 一份工作实际做了几天 / 几年；
- 私下涨薪；
- 节日红包；
- 争执、辞工、再找；
- 家庭成员与劳动者形成的真实情感关系。

所以：

> **public matching visibility can rise while lived-work visibility remains low.**

---

## 24. 尚未确定

本轮仍缺：

1. 1990s 更完整的城市间比较：上海 / 武汉经验是否具有代表性；
2. 2005–2010 原生家政网站的可验证 historical capture，而不是只有同期新闻描述；
3. 同一个普通家政员跨多个雇主、多个年份的连续记录；
4. 同一个家庭从祖辈照护 → 家政 → 托育 / 机构服务之间切换的连续生命史；
5. 真实工资、工时、住家条件和劳动者原家庭照护之间的长期组合；
6. 平台信用记录与实际雇佣持续时间之间到底有多强关系。

---

# 第七部分：下一步最值得找的连续链

## 25. 一条真正高价值的 life history

下一轮如果继续这一主题，不应只找“平台有多少阿姨”。

最高价值对象是同一个劳动者或家庭的连续链，例如：

```text
工厂 / 餐饮 / 农村家庭
→ 下岗 / 迁移
→ 街道 / 中介 / 培训
→ 第一户雇主
→ 换户 / 涨薪 / 失配
→ 节假日返乡
→ 再就业
→ 网站 / 平台接单
→ 技能升级或退出行业
```

或者家庭侧：

```text
生育 / 老人需要照护
→ 祖辈先顶上
→ 找钟点工 / 保姆
→ 电话 / Web / 平台筛选
→ 第一次入户
→ 更换服务员
→ 孩子入园 / 老人状态变化
→ 不再需要或改用另一种服务
```

只有这样的多时点证据，才能回答：

> **“请一个阿姨”究竟只是一次消费，还是把一家人的工作、育儿、迁移与未来安排重新拼了一遍。**

---

## 26. 本轮结论

本轮新增了一个此前没有被单独建模的交叉机制：

> **paid household labor is both household infrastructure and someone else’s employment route.**

Internet 并没有发明这种关系。

可观察到的转折更接近：

```text
社区 / 妇联 / 人工调查与名册
→ 电话 / 家政门店
→ Web 预定 + 电话 + 现场混合
→ 可浏览 worker profile
→ 社区论坛进行需求方匹配
→ 平台化筛选 / 评价 / 视频面试
→ 信用 / 服务证 / 记录可查询
```

但最终执行始终发生在一个非常物理、非常私密的地方：

> **另一个人的家。**

这也是为什么数字化越深入，真正的生活史反而仍然不能只从网页恢复。
