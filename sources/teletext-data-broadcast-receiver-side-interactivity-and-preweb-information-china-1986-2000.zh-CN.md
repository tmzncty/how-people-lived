# 在浏览器之前“翻页”：图文电视、数据广播与单向数字信息，中国 1986—2000

> 研究性质：通信/信息基础设施生活史切片；重点不是证明图文电视在中国“很流行”，而是恢复一种常被 Web 中心史观遗漏的信息取得方式：数据已经数字化、可以按页选择、可以存储和打印，但用户端未必有任何回传网络。
>
> 本文初稿由 AI 辅助整理；事实判断均按下列来源与证据边界单独标注。

## 0. 为什么值得单独研究

如果把普通人的数字信息生活写成：

`报纸/电视 → 1994 Internet → Web → 手机`

会遗漏一整类中间系统。

图文电视（teletext / data broadcasting）把文字、图形或计算机数据附着在电视广播信号中。用户若拥有兼容接收设备，可以在电视机或计算机上选择、显示，某些接收方案还可以保存、分析、打印这些数据。

它不是 Internet：

- 没有必要为每个家庭建立 IP 连接；
- 接收者通常没有向广播端发请求的回传通道；
- 信息由广播端循环发送，而不是服务器收到请求后单独返回；
- 用户能做的“交互”主要发生在接收端：选择某一页、等待它在广播循环中到达、在本机显示或缓存。

但它也已经不是传统意义上的“只能按节目表看电视”：

- 同一广播信号里可以存在大量编号页面；
- 用户自己决定此刻看哪一页；
- 页面可以比电视节目更频繁更新；
- 数据可以进入计算机，成为可储存、分析、打印的文件。

因此它提供了一个重要的历史中间态：

> **数字信息已经可选择，但网络还可以是单向的。**

## 1. 先把中国时间线拆开

### 1.1 1986—1989：先有制式研究，不等于先有家庭用户

电子科技大学后来整理顾德仁科研经历时记载：1986 年，他提出中国图文电视广播采用代码制而非图形制的方案；此后团队完成 CPLPS 图文电视广播系统，1989 年通过部级鉴定，后获科技进步奖。

来源：

- 电子科技大学成电新闻网，《顾德仁：博学多德 仁者必寿》：<https://news.uestc.edu.cn/info/1010/12850.htm>

证据等级：**C / 后来机构回顾，用于技术史定位**。

这条材料只能证明：

- 中国在 1980 年代已经存在图文电视制式与系统研发；
- 相关部门曾认真把它视作广播电视技术的一条发展路线。

它不能证明：

- 1989 年普通家庭已经能购买兼容电视机；
- 有多少电视台持续播出；
- 有多少人实际看过；
- 用户是否已经形成日常查询习惯。

这正是本仓方法论里的“发明/原型/制度存在 ≠ 服务可及 ≠ 家庭拥有 ≠ 大众常态”。

### 1.2 1994-04-20：中国全功能接入 Internet，是另一条时间线

中国科学院计算机网络信息中心的互联网大事记记载，1994 年 4 月 20 日，NCFC 的 64K 国际专线开通，实现与 Internet 的全功能连接。

来源：

- CNNIC/人民网整理，《1994年～1996年互联网大事记》：<https://www3.cnnic.cn/n4/2022/0401/c87-912.html>
- 中国科学院 2024 年 30 周年回顾：<https://www.cas.cn/cm/202404/t20240419_5012095.shtml>

图文电视不能被拿来淡化这个节点，也不能被写成“1994 年前中国其实已经有 Internet”。

更准确的分层是：

1. **广播数据/图文电视研发与有限服务已经存在；**
2. **科研与其他数字通信网络已经存在；**
3. **1994-04-20 才出现全功能国际 Internet 连接这一明确节点；**
4. **此后公共 Internet、商业 Internet、家庭可及和大众普及仍是另外几个阶段。**

### 1.3 1994-09：同时代报纸已经把图文电视写成正在运行的信息分发方式

1994 年 9 月 27 日《人民日报》第 11 版刊出《图文电视广播悄然兴起》。文中解释，图文电视数据广播把数据信号插入正常电视信号中；专用图文电视机可显示图文电视页和计算机文件。

它还列出两个明确的当时用途：

- 中央电视台利用图文电视向新疆、西藏等地区传送新闻稿件；
- 中央台经济部门向全国发送经济信息。

为了扩大接收，广电部科研院与企业推出图文电视微机接收卡。报道说明，这种 PC 卡可以从视频信号中分离数据，恢复广播端传送的文件，并进行存储、显示、分析和打印。

来源：

- 《人民日报》1994-09-27 第 11 版数字转录，《图文电视广播悄然兴起》：<https://cn.govopendata.com/renminribao/1994/9/27/11/>

证据等级：**A- / 同时代报刊文本；当前取得的是数字转录，不是本轮重新核验的纸版扫描。**

这条证据足以支持：

> 1994 年中国已经存在实际运行的广播数据用途，而且数据可以进入个人计算机接收卡。

它仍不足以支持：

> 1994 年普通家庭普遍把图文电视当作日常信息工具。

报道自己正因为“为了让更多的人快速获得信息”而介绍新接收卡，这反而提示接收端仍是扩散瓶颈。

### 1.4 1994-11-28：中央台“正式播出”的日期来自较晚媒体史回顾

搜狐 2003 年《电视百年》专题写道，中央电视台于 1994 年 11 月 28 日正式播出图文电视节目；文中还列出中央台、北京及多个省级广播电视机构的图文节目，并指出需要特殊接收装置，接收设备不足使其难以普及。

来源：

- 搜狐《电视百年》：<https://media.news.sohu.com/77/44/news209404477.shtml>

证据等级：**C / 2003 年回顾性媒体史材料。**

因此本轮不把 1994-11-28 当作“无争议的一手开播日期”；它是目前可定位的较强后来材料，下一轮如要提高等级，应找 1994 年中央台节目报、广电年鉴或技术公报交叉核验。

## 2. 新机制一：receiver-side interactivity / 接收端交互

### 2.1 “单向”不等于“用户没有选择”

图文电视最容易被今天的人误写成一种“电视台把字幕塞进电视”的被动媒介。

实际上，它的用户动作可以是：

1. 打开电视或兼容接收器；
2. 进入图文电视模式；
3. 输入页号；
4. 接收器从正在广播的数据流中识别所需页面；
5. 页面到达时显示；
6. 如有本地缓存，用户可以继续翻页或保存。

关键在第 3—5 步：

**输入页号不是把 query 发回电视台。**

广播端不知道某户人家此刻选了 101、301 还是 888 页。所有页面本来就在按某种循环发送；接收机只是在本地挑出用户想看的那一页。

因此可以把这种能力写成：

> **receiver-side interactivity：交互发生在终端选择，而不是网络往返。**

这与后来 Web 搜索框的逻辑不同：

`teletext: broadcaster continuously sends → receiver filters`

`Web: user requests → server selects/produces response → network returns`

这种差异会改变用户对“信息系统”的直觉。

### 2.2 海外对照：Ceefax 证明这种生活方式可以真的大众化

英国 Ofcom 在 Ceefax 50 周年回顾中记录：

- Ceefax 1974 年上线；
- 每一页有自己的编号；
- 用户用电视遥控器按键进入具体页面；
- 内容后来扩展到数百页；
- 高峰时每周用户达到约 2200 万；
- Internet 普及前，足球观众会盯着页面刷新比分。

来源：

- Ofcom, “Marking 50 years since Ceefax…” (2024-09-23): <https://www.ofcom.org.uk/tv-radio-and-on-demand/bbc/marking-50-years-since-ceefax-the-horse-drawn-internet-was-launched>

这条海外材料的重要性不是证明“中国也一样普及”。恰好相反，它提供了一个**分布反例**：

- 同一种“一对多数据广播 + 本地页选择”架构，在英国最终进入了数千万人的家庭日常；
- 本轮找到的中国材料则更清楚地证明了技术、机构用途和接收设备开发，却没有同等级的家庭用户规模证据。

因此不能从技术相似推出社会扩散相似。

## 3. 新机制二：carousel latency / 轮播等待

Web 的常见时间感是：

> 我点击 → 等服务器/网络回来。

图文电视的时间感更像：

> 我已经选择 → 等那一页下一次从广播循环里经过。

Teletext Archaeologist 的现代复原工具甚至专门模拟这种历史行为：页面按当年广播顺序“flick by”，关闭缓存时必须等目标页真正再次被广播到。

来源：

- Teletext Archaeologist, Software / Teletext Player: <https://teletextarchaeologist.org/software/>

这说明用户等待不是偶然的“设备慢”，而是架构的一部分。

可以把它记为：

> **carousel latency：延迟由页面轮播周期决定，而不是由一次请求—响应的网络往返决定。**

对日常生活来说，这意味着：

- “最新”仍可能是几分钟一轮的最新；
- 热门页可以被安排得更频繁；
- 页面越多，若带宽不变，轮播等待可能越长；
- 本地缓存会显著改变体验。

所以研究旧信息系统时，“更新速度”至少要拆成：

1. 编辑端何时改了内容；
2. 新页面何时进入广播循环；
3. 用户的接收器何时碰到该页；
4. 用户本人何时真的看见。

## 4. 新机制三：broadcast database / 广播式数据库

1994 年《人民日报》最值得注意的一句不是“电视上能看文字”，而是 PC 接收卡可以把数据恢复成文件，再储存、显示、分析和打印。

这意味着对部分用户而言，电视信号可以承担一种很奇怪的“数据库分发”角色：

- 中央端不断把一组数据广播出去；
- 终端只接收，不需要逐户建立电话连接；
- 本地电脑把收到的数据重新变成文件；
- 用户在本地做后续处理。

可以称作：

> **broadcast database：数据的分发是广播式的，查询/处理可以是本地的。**

它非常适合：

- 同一份新闻稿发给很多机构；
- 行情、天气、节目表等一对多信息；
- 网络线路昂贵、回传并非每户都需要的环境。

它不适合：

- 每个人都问不同问题；
- 用户生成内容；
- 双方即时对话；
- 交易、账户、个性化状态。

所以 Web/Internet 后来真正改变的，并不是第一次让“信息数字化”，而是把**回传、个性化寻址和用户端发送**变成普通架构的一部分。

## 5. 设备门槛：家里有电视 ≠ 家里能用图文电视

这是本轮最需要防止的统计偷换。

1994 年《人民日报》说需要专用图文电视机或 PC 接收卡；2003 年搜狐回顾同样说图文电视需要特殊接收装置，并把接收设备不足列作难普及的原因之一。

因此不能用普通电视拥有率来估计图文电视可及性。

至少要拆开：

1. 当地能否收到承载图文数据的电视信号；
2. 家里是否有电视；
3. 电视是否内置兼容解码器；
4. 如果没有，是否有外置解码器/PC 卡；
5. 用户是否知道该服务存在；
6. 用户是否知道页码和操作方法；
7. 内容是否足以让人形成稳定使用习惯。

英国 Ceefax 也经历同样的设备门槛。Ofcom 说服务刚推出时，只有很少家庭拥有可以显示它的电视；随后高规格电视普及，用户才扩大到大规模水平。

这给中国研究提供一个重要对照：

> **同样的广播覆盖范围，不等于同样的信息可及人口。接收器的功能配置本身就是数字鸿沟。**

## 6. 找工作：海外材料证明图文电视可以直接进入生活机会

用户要求本项目不能只研究“通信技术本身”，还要问它怎样进入找工作、社交、获取信息和想象远方。

英国 Central Television 的 Jobfinder 提供了一个直接对照。Rewind 保存的电视档案说明，1986 年 Central 在正常节目结束后播出基于 teletext 的工作信息服务；档案中还能看到 1986-09-30 的 Jobfinder 页面/播出片段。

来源：

- Rewind, Central closedown / Jobfinder, 30 September 1986: <https://rewind.thetvroom.com/24367/channel-presentation/central-closedown-30th-september-1986/>

这条材料的重要性在于，它证明 teletext 并不只是天气、比分和“技术玩具”。

在一种已经大众化的社会环境里，一台电视可以成为：

> **工作机会的家庭信息终端。**

本轮没有找到同等级的中国普通求职者使用图文电视的同期证据，因此不能把英国的用途倒灌进中国。

## 7. 1994 的中国不是“没有 Internet”，也不是“Internet 已经进入普通家庭”

图文电视恰好能帮助我们保持时间线精度。

同一年里可以同时成立：

- 1980 年代开始的图文电视技术研发已经成熟到部级鉴定；
- 电视台已经用广播数据发送新闻稿和经济信息；
- 1994-04-20 中国实现与 Internet 的全功能连接；
- 1994-05 中国已经有 Web 服务器；
- 图文电视接收器仍然是普及瓶颈；
- 普通家庭大规模上 Internet 仍然远未发生。

所以“一国有没有网络”不是一个二元变量。

更好的问题是：

> **这个具体的人，在这个具体地点，有哪一种终端？她能接收什么？能不能回复？一次信息取得要花多少设备、费用、知识和等待？**

## 8. 与 2005—2026 四种“未来时间感”的关系

本轮没有把图文电视硬拉成长周期主线，也没有找到足够可靠的 2007—2010、2018—2019、2023—2026 普通中国用户第一人称材料来支撑“图文电视时代未来想象”的跨期比较。

这应被记录为缺口，而不是用后来怀旧补上。

它对现有四阶段框架的贡献主要是一个**基准线校正**：

### 2005—2012 扩张型未来

当 Web、搜索、即时通信和手机信息服务扩张时，用户获得的不只是“更多内容”，而是逐渐从：

`广播端决定发送全集 → 我在本地挑一页`

转向：

`我主动提出查询 → 远端系统为我的请求返回结果`。

扩张的一部分，因此是**查询空间和回传能力的扩张**。

### 2015—2019 拥堵型未来

成熟平台把这种请求—响应进一步变成持续账户状态、推荐、位置和交易。机会更多，但执行链也更长。

这不是本轮的新一手结论，只是说明 teletext 可作为架构基线；不把它计入本轮新增机制之外的证据。

### 2020—2022 偶发型未来 / 2023—2026 防守型未来

本轮没有得到足以改变既有判断的新材料，不进行延伸叙事。

## 9. 历史可见性：为什么这种生活很容易从“互联网史”里消失

图文电视尤其容易被 Web 档案压暗，因为它的原始 representation 根本不是 HTTP 页面。

Teletext Archaeologist 对英国 teletext 的保存说明提供了一个非常有价值的反例：

- 广播端的页面通常会被新内容覆盖；
- 广播机构保存下来的完整页面并不多；
- 一些历史页来自当年 PC 解码卡用户的本地保存；
- 大量后来恢复的页面，竟然是从普通家庭 VHS/Betamax 录像带的电视信号中重新提取出来的。

来源：

- Teletext Archaeologist 首页：<https://teletextarchaeologist.org/>
- Archive：<https://teletextarchaeologist.org/the-archive/>
- Rewind, “Teletext recoveries”：<https://rewind.thetvroom.com/39095/features/teletext-recoveries/>

其公开目录已经列出从 1970s、1980s 到 1990s 的大量“整套 teletext service snapshot”，包括 1995 年 BBC、Channel 4 等服务。

这提醒 HPL：

> **“今天能搜到什么”不是“当年人能看到什么”的无偏样本。**

HTTP/Web 的存档生态很强，于是 Web 看起来会比同一时代的广播数据、呼叫台、BBS 离线信包、传真和专用联机系统更“真实、更丰富”。这可能只是保存介质不一样。

## 10. 核心机制表

| 机制 | 含义 | 生活后果 |
|---|---|---|
| `receiver-side interactivity` | 用户本地选择页面，不向广播端发 query | 单向网络也可以有“我自己查”的体验 |
| `carousel latency` | 等待目标页在广播循环中再次出现 | 信息延迟取决于轮播周期，不是网络 RTT |
| `broadcast database` | 同一数据全集一对多广播，本机筛选/处理 | 不需要给每户建立双向数据线路 |
| `decoder-gated access` | 有电视/有信号不等于有解码器 | 接收终端配置形成独立可及性门槛 |
| `broadcast-to-PC bridge` | PC 卡把电视数据还原成文件 | 广播与个人计算机并非两个完全分离的世界 |
| `non-Web archive shadow` | 当年存在的信息页难被 HTTP 档案保存 | 今天的可见史会系统性偏向 Web |

## 11. 它改变了我们对“人怎么活着”的哪一点理解

此前仓库已经证明：

- 人可以通过 114 把查询委托给接线员；
- 人可以通过 CFido 把社区下载到本地再离线阅读；
- 人可以通过寻呼让“有人找你”先追上身体；
- 人可以在 Internet 普及前拥有公共电子信箱。

图文电视再补上一条完全不同的生活路径：

> **一个人可以在没有 Internet 会话、没有拨号、没有向远端发请求的情况下，坐在电视机前主动“翻”一个不断更新的数字信息库。**

所以 Internet 到来的生活意义不能写成“以前只能被动接收，后来终于能选择信息”。

选择早就可以存在。

更准确的变化是：

> **从接收端选择一个共同广播的信息全集，走向每个用户都能把自己的请求送回远端系统。**

## 12. 反例与后见之明风险

### 反例 1：不能把 teletext 写成“Internet 的幼年版”

它是一种不同的架构，擅长一对多更新，不需要回传线路。它不是必然向 Web 演进的“不完整 Internet”。

### 反例 2：中国有技术，不等于中国有英国式 Ceefax 大众生活

英国 2200 万周用户是英国的证据。当前中国证据没有提供可比的家庭渗透率。

### 反例 3：电视拥有率不能代替图文电视拥有率

专用接收装置是独立门槛。

### 反例 4：1994 年后图文电视存在，不意味着它与 Internet 是互斥代际

两种系统可以重叠运行；同一机构甚至可能同时通过广播、专网和 Web 分发信息。

### 后见之明风险

今天很容易因为 Web 最终胜出，就把图文电视描述成“注定失败的岔路”。1994 年的同时代报道恰恰显示，它当时仍被视作扩展数据分发能力的一条现实技术路线。

## 14. 我们知道什么

1. 1980 年代中国已经有图文电视制式研发；
2. 1994 年 9 月的同期报道确认中央电视台已经把图文电视用于新闻稿和经济信息分发；
3. 当时已经有 PC 接收卡方案，可把广播数据变成可存储、分析、打印的文件；
4. 这套系统与 1994 年全功能 Internet 接入是不同技术/服务层；
5. 接收装置是独立门槛，不能用普通电视拥有率代替；
6. 海外 Ceefax 证明“单向广播 + 本地页选择”可以进入大众日常，甚至用于体育信息和工作机会。

## 15. 我们可以合理推断什么

1. 对一部分机构和早期计算机用户，1994 年的“数字信息”并不必然通过 Internet 获取；
2. 图文电视的用户时间感与 Web 不同，目标页需要等待广播轮播；
3. 1990s 的信息现代化存在多条并行架构，而不是所有用途都向 TCP/IP 单线收敛；
4. 现代 Web 档案会系统性低估非 HTTP 数字生活的内容丰富度。

## 16. 我们仍然不知道什么

1. 中国 1994—2000 每年实际有多少兼容图文电视机/解码器/PC 卡；
2. 城市、单位、家庭之间的使用分布；
3. 中央台与各地方台的具体页号、页面数量、轮播周期和更新频率；
4. 哪些普通家庭真正用它查新闻、天气、股票、求职或交通信息；
5. 1994-11-28“正式开播”是否能由 1994 同期节目表/广电年鉴直接复核；
6. 是否仍有中国家庭录像带、PC 接收卡文件或广播机构磁带保存了原始数据流；
7. 中国图文电视何时从实际用户生活中退出，以及退出是否主要因接收器、Web、移动互联网、数字电视还是运营方策略。

## 17. 下一轮最高价值动作

不是再写一篇“图文电视发展史”，而是找**中国原始 artifact**：

- 1994—1999 广播电视年鉴中的具体台站/页数/用户/设备数据；
- 早期图文电视机、解码器、PC 接收卡说明书或广告；
- 当年的页码表、页面照片、屏幕录像；
- 电视台/高校/证券用户的同期操作说明；
- 国内 VHS/Betamax 原始录像是否可能保留可恢复数据；
- 1995—2000 同一新闻内容在图文电视、ChinaMail 与 Web 之间的多渠道投影。

若找不到这些，应该把“家庭日常使用”明确留空，而不是由英国 Ceefax 代填。
