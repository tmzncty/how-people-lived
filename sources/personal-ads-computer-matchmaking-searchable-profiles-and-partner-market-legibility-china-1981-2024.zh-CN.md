# 同时代材料包：从报纸征婚、电脑红娘到可搜索资料库——择偶路线、陌生人可达性与“条件”的结构化（中国，1981–2024）

> 类型：source / evidence pack。
>
> 目的：补 family-life-course 矩阵中尚未单独建模的一类人生路线：**一个人怎样在亲友、单位和既有熟人圈之外，主动寻找未来伴侣；媒介又怎样把“我是谁、我想找谁”压缩成可刊登、可计算、可搜索、可筛选的字段。**
>
> 本包不写“互联网让人更容易恋爱”的泛论，也不把征婚、婚介、电脑配对、婚恋网站、社交 App 当成同一种东西。

## 0. 去重与范围

仓库已经覆盖：

- 婚姻意愿与实际婚育行为；
- 家庭照护、分址家庭、迁移与住房；
- 通信成本和远距离关系；
- 证件、资格和可验证记录；
- 2005–2012 / 2015–2019 / 2020–2022 / 2023–2026 的未来时间感。

本材料包只补一个更窄的问题：

```text
潜在伴侣原本主要来自既有社会网络
→ 报刊 / 婚介把陌生人变得可联系
→ 电脑数据库把择偶条件变得可计算
→ Web 把候选人资料变成可自行搜索的数据库
→ 移动平台继续把条件、推荐、验证和线下见面编排进同一套界面
```

核心不等式：

```text
候选人更多
!=
更容易建立关系

可搜索
!=
可信

字段可见
!=
字段已验证

平台推荐
!=
当事人愿意线下见面
```

## 1. 新生活路径：mediated stranger partner search / 经媒介的陌生人择偶

传统熟人介绍并不会因为新媒介出现而消失。新增的是另一条路线：

```text
本人或家庭提出择偶需求
→ 把自己压缩成一组公开 / 半公开资料
→ 媒介把需求暴露给原本互不认识的人
→ 对方写信 / 留言 / 发消息
→ 再进入电话、见面、家庭协商和婚姻登记等后续阶段
```

这条路线最重要的变化，不是“爱情被机器决定”，而是 **陌生人第一次可以在没有共同亲友的情况下，被一个中介系统变成可发现、可比较、可联系的潜在伴侣。**

可以暂称：

**`stranger-searchability / 陌生人可搜索性`**。

## 2. 1981–1984：报纸和杂志先把私人婚事变成可公开检索的“短资料”

### 2.1 1981：《市场报》征婚——从熟人介绍到全国陌生来信

人民网 2019 年对中国式相亲的历史回顾记录：1981-01-08，人民日报社主办的《市场报》刊登丁乃钧征婚启事。启事公开了婚姻状况、年龄、身高、工资等，并要求应征者来函联系、附近照。

来源：

- 人民网，2019-10-24，`中国为什么会有“相亲角”？`  
  https://politics.people.com.cn/n1/2019/1024/c429373-31417696.html
- 东北网 / 双鸭山新闻网，2007-08-02，采访当年编辑和相关人员：  
  https://shuangyashan.dbw.cn/system/2007/08/02/050918628.shtml

**证据类型：后来的历史回顾 / 当事人回访。**

**证据等级：B/C。** 本轮没有直接取得 1981-01-08《市场报》原版扫描，因此不能把当前网页当作原始版面 artifact；但多个来源对刊登事件、媒体、日期和基本字段相互印证。

### 2.2 1984：《中国妇女》“鹊桥”把资料字段和单位证明写进流程

全国妇联体系 2024 年回顾《中国妇女》“鹊桥”栏目时，保留了 1984 年栏目说明中的操作要求：来信者应实事求是写明职业、年龄、爱好、身高、有无生理缺陷等，并由所在单位证明所述情况属实；同时说明希望寻找什么样的对象、是否愿意刊登照片，以及通信地址。

同一回顾保存了 1984 年煤矿工朱俊芳的征婚内容：年龄、籍贯 / 家庭、住房、职业、月工资、文化程度、健康、身高，以及愿意到女家落户、承担养老责任等。

来源：

- 中国妇女网 / 婚姻与家庭，2024-09-30，`“鹊桥”栏目创办40周年，《中国妇女》记录下的大龄青年婚恋变迁`  
  https://www.womenofchina.com/jiatin/2024/0930/15704.html
- 新京报经新浪保存的 2008 回顾，`第87期：首个征婚启事`  
  https://news.sina.com.cn/c/2008-11-10/141716623973.shtml

**证据等级：B（机构回顾 + 历史内容转录）。**

### 2.3 这里已经出现了“资料化择偶”

1984 的关键变化不只是把“我要找对象”公开出来，而是把一个复杂人生压缩成一个短资料包：

```text
职业
年龄
身高
健康
收入
文化程度
住房 / 家庭
婚姻状态
迁居 / 入赘意愿
照护责任
希望对象条件
```

这些字段显然不是人的全部，却是媒介认为足以完成第一次筛选的信息。

可暂称：

**`partner-profile compression / 伴侣资料压缩`**。

它是后来数据库 profile 的前史，但不能因此说 1984 报刊已经“像 dating app 一样”。纸媒仍然是编辑把关、版面稀缺、邮件反馈、长时延。

## 3. 1982–1991：机构和计算机在大众 Internet 之前就已进入择偶流程

### 3.1 广州青年婚姻介绍所：卡片数据库与机构撮合

人民网历史回顾称，1982-11-15 广州市青年婚姻介绍所成立；至 1984 年 6 月已撮合 1400 多对。中国妇女报 2018 年对该机构的回访更具体说明，早期服务包括：

- 卡片供来访者查阅；
- 由工作人员按条件推荐；
- 组织联谊、郊游等线下活动。

来源：

- 人民网，2019-10-24：  
  https://politics.people.com.cn/n1/2019/1024/c429373-31417696.html
- 中国妇女报回访，经新浪保存，2018-12-10：  
  https://news.sina.cn/2018-12-10/detail-ihprknvu1032562.d.html

**证据等级：B（机构历史回顾）。**

这里已经存在：

```text
登记资料
→ 形成可翻阅的候选集合
→ 工作人员 / 本人进行条件筛选
→ 线下接触
```

它说明 **database-like partner search 并不要求互联网。**

### 3.2 1991：《中国妇女》“电脑红娘”——正式 Internet 以前的计算机配对

全国妇联体系保存的 1991 年历史材料尤为重要。

1991 年 10 月，《中国妇女》发布《“电脑红娘”启事》，解释因为版面有限、征婚来信积压，杂志与有关科研部门合作，在继续“鹊桥”纸媒栏目的同时，新增“电脑择偶（择友）服务”，并宣传其“保密性强、反馈迅速、准确”。

1992 年 3 月《“电脑红娘”致读者》又直接讨论申请者填写的择偶条件：有些人要求“博士”“年收入万元”“海外人士”等，编辑劝其根据本人情况扩大条件范围。

来源：

- 中国妇女网 / 婚姻与家庭，2024-09-30：  
  https://www.womenofchina.com/jiatin/2024/0930/15704.html

**证据等级：B。** 当前取得的是官方体系 2024 年对 1991/1992 刊物内容的转录与图文回顾，本轮尚未取得 1991 原期刊整页高分辨率扫描、申请表或匹配程序。

### 3.3 关键边界：computer matchmaking != Internet dating

因此中国时间线至少要明确：

```text
1980s 报刊 / 婚介登记
→ 1991 电脑择偶服务
→ 1994 全国全功能 Internet 接入
→ 1990s 后期 / 2000s 专业 Web 婚恋服务扩张
```

1991 “电脑红娘”可以说明：

- 个人资料已经可以被结构化录入；
- 计算机可以在后台帮助筛选 / 匹配；
- 普通用户不需要自己上网；
- 用户界面可能仍是纸质表格、邮件、机构柜台或电话。

不能根据“电脑择偶”四个字反推出：

- 存在 TCP/IP 网络；
- 用户有个人计算机；
- 存在浏览器；
- 用户可以自行搜索完整候选数据库；
- 算法细节已知。

## 4. 海外对照：1965 Operation Match 说明“把亲密关系做成数据”远早于 Web

1965-04-19，《Harvard Crimson》同期报道 Operation Match：7800 多名新英格兰大学生参加，填写 75 项问卷，组织者把问卷送入 IBM 1401 处理，然后参与者收到匹配对象。

同期报道保留的问题包括：安全、声望、权力、金钱何者更重要，以及对外貌、家庭关系等的偏好。

来源：

- The Harvard Crimson, 1965-04-19, `'Operation Match' Draws 32 Cliffies; Pairings of Computer Cupid in Mail`  
  https://www.thecrimson.com/article/1965/4/19/operation-match-draws-32-cliffies-pairings/
- The Harvard Crimson, 1965-11-03, `Operation Match`  
  https://www.thecrimson.com/article/1965/11/3/operation-match-pif-you-stop-to/
- TIME, 1965-11-19, `Youth: My IBM Baby`  
  https://time.com/archive/6628489/youth-my-ibm-baby/

**证据等级：A/B（同期校园报 + 同期全国媒体）。**

### 4.1 可比点与不可比点

可比的是：

```text
复杂的人
→ 问卷字段
→ 机器比较
→ 输出候选人
→ 人在线下继续决定
```

不可比的是：

- 1965 Operation Match 面向特定大学生群体；
- 1991 中国“电脑红娘”的人群、数据库规模、算法和机器环境本轮并不清楚；
- 两者都不能等同于后来用户自己实时浏览 profile 的 Web dating。

因此，**“算法 / 计算机进入择偶”不是 Internet 时代才出现的现象；Internet 真正增加的是用户端持续访问、自己搜索、即时通信和大规模数据库可见性。**

## 5. 2008：扩张型未来——候选人数据库开始成为普通城市青年可主动尝试的路线

2008-08-19，《新世纪周刊》同期报道经新浪保存。受访者“凯文”，30 岁、北京公务员，经历多年家人安排的相亲后转向婚恋网站；他使用百合网付费服务和“婚恋类型测试”，与平台工作人员小雨在线接触并迅速线下见面、登记。

两人在报道中讨论的现实条件包括：

- 都是北京人；
- 都有独立住房；
- 消费观相近；
- 对婚礼 / 钻戒的花费态度相似。

来源：

- 新浪转载《新世纪周刊》，2008-08-19，`甜蜜的对抗：婚恋网站的模式之争`  
  https://news.sina.com.cn/c/2008-08-19/115016140459.shtml

**证据类型：同期媒体个案。**

**证据等级：B。** 它说明 2008 年用户确实把婚恋网站视为家人安排相亲之外的一个可执行入口，但单一“闪婚”案例不能用来证明平台通常如此高效。

### 5.1 扩张不只是“人更多”，而是 route space 增加

当时普通人的择偶路线可以并存：

```text
亲友介绍
+ 单位 / 校友联谊
+ 婚介所
+ 报刊 / 电视
+ BBS / IM / SNS 的非正式认识
+ 专业婚恋网站
+ 网站组织的线下活动
```

所以 2005–2012 的扩张型未来在婚恋上可以写得更具体：

**未来不是只剩一条正确路线，而是“我还可以换一个入口再试”。**

## 6. 2011：第一方监管文件把“可搜索婚姻数据库”结构写得非常清楚

世纪佳缘 2011 年赴美上市 F-1 文件，是这一轮最强的第一方业务结构证据之一。

文件说明：

- 免费注册后，用户可以立即完整搜索数据库；
- 发送第一条消息本身免费，但要让对方读到，发送者或接收者需购买 2 元虚拟邮票（或相应套餐）；
- 第一条消息读过后，双方后续站内通信免费；
- 可以购买更精细搜索、提高搜索排名、优先消息、照片 / profile 展示等服务；
- 2010 年起部分功能可通过移动浏览器使用；
- 2011-03，有 94 个城市至少拥有 1 万 active user accounts；
- 平台鼓励用户提供年龄、收入、教育等证明；提交证明并付费后，资料在数据库中可获得更高 rating；
- 注册以后，身高、工资、教育程度等部分基础信息若要“向更好方向修改”，需要验证。

来源：

- U.S. SEC, Jiayuan.com International Ltd., F-1, filed 2011  
  https://www.sec.gov/Archives/edgar/data/1511683/000104746911003874/a2203517zf-1.htm

**证据等级：A（第一方监管申报文件）。**

公司文件对自身竞争优势、用户质量和市场地位当然存在商业动机，因此其中“最好 / 最大 / 更受信任”等评价必须降权；但服务流程、收费结构、验证规则、功能描述属于高价值运营证据。

### 6.1 新机制：search cost collapse / 搜寻成本下降

纸质征婚需要：

```text
等一期杂志
→ 浏览少量刊出的启事
→ 写信
→ 等邮递
```

Web 数据库则把第一步改成：

```text
打开数据库
→ 按条件筛选大量候选资料
→ 发消息
```

这显著降低**发现候选人**的成本。

但：

```text
search cost collapse
!=
trust cost collapse
!=
relationship cost collapse
```

平台越能快速生成候选人，身份真假、线下安全、关系磨合和家庭协商反而越成为新的瓶颈。

## 7. profile schema：平台不只“记录条件”，还会让条件变得显眼

一个在线 profile 往往把连续的人生压缩成离散字段：

```text
年龄
所在地
婚姻状况
身高
学历
收入
职业
住房 / 资产（视平台和时期而定）
兴趣
照片
自我介绍
理想对象
```

平台一旦允许按字段搜索，这些属性就从“见面以后也许会聊到的背景”变成**进入候选集合以前就可以作为门槛的过滤器**。

本包把这种机制称为：

**`profile-schema salience / 资料字段显著化`**。

不要把它写成“平台创造了功利择偶”。1984 的征婚广告已经包含职业、工资、住房、身高、文化程度和家庭责任；平台真正新增的是：

- 字段标准化；
- 选项化；
- 排序 / 搜索；
- 自动推荐；
- 验证徽标；
- 付费提升可见性。

## 8. 2019：拥堵型未来——入口很多，但从“可搜到”到“愿意见面”仍然大量漏损

2019-09-19，《中国青年报》报道一项 1972 名单身青年的问卷调查并采访多名用户。

同期第一人称材料中：

- 27 岁唐璇既经历家人 / 亲戚、单位同事、相亲角等传统渠道，也注册平台；
- 28 岁科研人员林鹏表示，平台会按所在地、年龄等需求筛选，节省浏览时间；
- 事业单位工作的张晓同时尝试家人安排、校友联谊、婚恋平台和平台线下活动；
- 唐璇说，平台认识的人常常只加微信、偶尔聊天，真正见面的反而更多仍来自他人介绍。

来源：

- 人民网转载《中国青年报》，2019-09-19，`78.8%受访单身青年在婚恋交友平台注册过`  
  https://media.people.com.cn/n1/2019/0919/c40606-31361024.html

**证据等级：B。** 问卷由中国青年报社会调查中心与问卷网实施，不是全国概率样本，因此 78.8% 不能外推成“中国单身青年总体平台注册率”；第一人称访谈则可以证明多路线并用的生活实践。

### 8.1 拥堵不是“候选人不够”

这一组材料提示：

```text
可浏览资料很多
→ 可加微信的人很多
→ 可持续聊天的人变少
→ 愿意见面的人更少
→ 能发展长期关系的人更少
```

因此“拥堵型未来”在婚恋领域可以表现为：

**选择入口扩张，但从资料库到真实关系的转化链条很长。**

## 9. 2020–2022：偶发型未来——线下入口突然受限，线上从补充路线变成应急主路线

2021-02-25，《中国青年报》对 2001 名 18–35 岁单身青年的调查显示，疫情时期 62.4% 的受访者称近一年交友以线上为主；报道同时采访青年说明，旅行、聚会、联谊等线下机会受限，微博、微信、交友 App 等承担更多交友功能。

同日另一篇采访中，受访者又明确指出：线上资料可能存在“朋友圈人设”、照片与实际不同、工作信息不实等问题。

来源：

- 人民网转载《中国青年报》，2021-02-25，`疫情下的“网恋”：超7成受访者每天花1小时“云交友”`  
  https://health.people.com.cn/n1/2021/0225/c14739-32036323.html
- 人民网 / 中国青年报，2021-02-25，`过半受访单身青年指出“云交友”需注意网络人设滤镜`  
  https://sn.people.com.cn/n2/2021/0225/c378296-34592103.html

**证据等级：B。** 同样不能把问卷比例当总体人口参数。

### 9.1 偶发性改变的是渠道权重，不是信任问题

疫情证明：

```text
线下见面能力骤降
→ 线上候选发现 / 聊天能力仍然存在
```

但：

```text
profile remains available
!=
person becomes fully knowable
```

因此危机可以把平台从“更多选择之一”抬升成主要入口，却不能消灭验证和线下相处的必要性。

## 10. 2024：防守型未来——从“下一个会更好”到降低搜索期待、寻找可共同生活的人

2024-04-09，北京日报客户端的深度调查提供了非常好的同时代第一人称材料。

### 10.1 罗先生：候选人很多以后，反而不再相信“下一个一定更好”

33 岁的罗先生从 2019 年开始相亲，线上聊过四五十人、线下见近二十人。他说年轻 / 刚开始相亲时容易觉得“下一个更好”，多年以后逐渐认为不可能每方面都合意，现任女友未必是“最好的”，但性格适合“踏踏实实过日子”，双方已见父母。

报道还记录他的基本筛选条件：照片、年龄、本科、稳定工作、本地人等；他自己明确说学历、身高、收入、家庭情况是相亲中默认会写的信息。

### 10.2 张女士：平台字段本身改变了“我会不会在意这个条件”

27 岁的张女士使用相亲软件三四年。她说，现实社交中有些“硬件”自己并不会特别在意，但软件要求填写各种信息以后，她会开始希望找一个“比自己条件好一点，或者差不离”的人。

来源：

- 北京日报客户端 / 京报网，2024-04-09，`调查｜从“下一个更好”，到“把握好现在”，相亲者正在变化`  
  https://news.bjd.com.cn/2024/04/09/10742288.shtml

**证据等级：A/B（同期深度采访；个案不代表总体）。**

### 10.3 这条材料第一次给 profile-schema salience 提供了直接当事人口述

这里不能推成“所有人都被 App 变得更看重条件”。但至少可以确认一条真实机制：

```text
平台先把某个属性做成显眼字段
→ 用户在搜索 / 比较时反复看到它
→ 原本未必是核心要求的属性
→ 有机会变成明确筛选条件
```

这与 1992 年“电脑红娘”编辑劝申请者不要把条件填得过窄，形成了非常好的历史回声。

**数据库扩大选择空间，同时也可能把生活脚本变成越来越容易勾选的门槛。**

## 11. 四阶段未来时间感：同一基础设施，不同使用逻辑

### 11.1 2005–2012：扩张型

```text
熟人介绍失败
→ 还可以上网站
→ 数据库里还有更多候选人
→ 网站还会办线下活动
```

核心感觉：**route space 在增大。**

### 11.2 2015–2019：拥堵型

```text
入口和候选很多
→ 筛选更多
→ 聊天更多
→ 真正见面 / 建立关系仍稀缺
```

核心感觉：**candidate abundance != relational progress。**

### 11.3 2020–2022：偶发型

```text
线下入口突然关闭或受限
→ 线上候选发现与聊天继续工作
→ 但真实性和见面验证无法完全替代
```

核心感觉：**平台成为 continuity infrastructure。**

### 11.4 2023–2026：防守型

2024 深访里出现的是：

- 工作和生活圈越来越窄；
- 主动扩大社交范围；
- 长期搜索后降低“下一个更好”的期待；
- 更重视稳定工作、能共同生活、能承担责任；
- 同时反思过度条件化。

这不是“现在的人更悲观”的心理断言，而是一条同期材料显示出的策略变化：

**从无限继续搜索，转向判断“这个人是否足够适合一起过日子”。**

## 12. 这条历史线改变了哪些矩阵格

| 矩阵维度 | 本包新增内容 |
|---|---|
| 婚姻家庭 | 婚姻形成之前还有一整套 partner-search route space |
| 非主流生命路径 | 离异 / 丧偶 / 大龄未婚者可绕开熟人网络重新进入伴侣搜索 |
| 迁移 | 报刊 / 数据库让跨地域陌生人变得可联系，但现实迁居成本仍在 |
| 信息获取 | 从编辑筛选的少量启事变成用户自己查询数据库 |
| 社交关系 | 从已有强 / 弱关系介绍，扩展到平台制造的陌生连接 |
| 证件与记录 | 单位证明、年龄 / 收入 / 教育证明、平台 verification 进入亲密关系市场 |
| 互联网平台 | profile、search、ranking、message fee、verification badge 成为基础设施 |
| 未来预期 | “还有更多候选人”与“把握一个足够合适的人”形成时期差异 |
| 线上 / 线下身份 | profile 是结构化自我，但线下见面仍是不可省略的验证层 |
| 历史可见性 | 纸质广告、表格、数据库字段、动态 profile 的保存概率完全不同 |

## 13. 反例与边界

### 13.1 新媒介没有取代旧媒人

2019 的同期材料仍显示：亲友介绍、单位、相亲角、网站、社群和平台线下活动同时使用。

因此：

```text
new partner-search technology
!=
old social mediation disappears
```

### 13.2 “条件化”并非 Internet 发明

1984 的征婚资料已经高度条件化；1992 “电脑红娘”已经出现“博士 / 年收入 / 海外人士”等筛选要求。

Internet 的新增能力主要是：

- 大规模；
- 快速；
- 自助搜索；
- 排序；
- 多字段过滤；
- 验证和 ranking；
- 可持续重复尝试。

### 13.3 资料越完整，不代表对人的了解越完整

一份 profile 可以详细到学历、身高、收入、住房、家庭，却仍然不能直接告诉用户：

- 对方如何处理冲突；
- 是否诚实；
- 实际照护责任；
- 是否愿意共同迁移；
- 是否能在长期生活中相处。

因此：

**`legibility != intimacy`**。

### 13.4 平台自报用户数不能等同于人口使用率

SEC 的 registered account、active account、paying account 都是平台自己的业务口径；一个人也可能拥有多个账号。不要把账号数直接除人口。

## 15. 后见之明风险

### 风险 1：把“电脑红娘”自动写成“早期互联网婚恋”

错误。1991 明显早于中国全功能 Internet 接入；其用户端也未必是电脑。

### 风险 2：把结构化条件解释成“今天的人更功利”

错误。1980s 的纸质征婚已经公开职业、工资、住房、身高和家庭责任。

### 风险 3：把选择增多写成婚姻形成更容易

错误。2019、2024 的材料都显示大量筛选、聊天和一次性见面。

### 风险 4：把 verification badge 当成整个人生真实性

错误。平台只能核验它实际取得并验证的字段；证明了学历，并不等于证明人格、关系意愿和未来行为。

### 风险 5：把当前平台字段倒推到 2008

错误。字段、选项、必填规则、默认值、验证、排序权重都可能变化。

## 17. 对核心问题的修正

这一轮最重要的不是“婚恋网站出现了”。

更准确的历史是：

> 普通人寻找伴侣的世界，先从熟人网络扩到报刊和机构提供的陌生人，再在 Internet 之前就开始被卡片和计算机数据库结构化；Web 后来真正改变的，是让本人可以持续进入那个数据库，反复搜索、筛选、排序和发消息。

与此同时，媒介不只是把既有偏好原样搬上去。**它决定哪些人生属性被做成字段、哪些字段能被搜索、哪些字段值得验证、哪些资料排在前面；这些设计也会反过来影响人们在择偶时注意什么。**

因此这条线为“普通人到底有多少种活法”增加的不是一种婚姻，而是一个此前被忽略的前置空间：

**一个人可以有多少种办法，去遇见那个原本不在自己生活圈里的人。**
